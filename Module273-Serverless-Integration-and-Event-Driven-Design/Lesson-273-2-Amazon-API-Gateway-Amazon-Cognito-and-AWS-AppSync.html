Introduction

A Lambda function has no public address of its own that clients should call directly, and it should not check every token itself. An API layer handles HTTPS, authentication, throttling, and versions in one place, and an identity service handles the users. 1. What Amazon API Gateway Is

Problem Statement

FlashCart moved its order logic to Lambda in Lesson 273.1. Now the website, the mobile app, and two partner companies must call it over HTTPS. The team needs one front door that handles authentication, throttling, versions, and monitoring, so that each function does not have to do it again.

1.1 What Amazon API Gateway Is

  • Amazon API Gateway is a fully managed service to create, publish, maintain, monitor, and secure APIs at any scale. It is the "front door" for applications that call your backend.
  • It offers REST APIs, HTTP APIs, and WebSocket APIs.
  • The backend can be AWS Lambda, Amazon ECS, Amazon EKS, AWS Elastic Beanstalk, EC2 instances, other AWS services, or any HTTP endpoint.
  • With Lambda, API Gateway gives you an API with no infrastructure to manage.
  • Built-in features include monitoring and logging with Amazon CloudWatch, authentication and authorization, throttling, API keys, response caching, versions and environments, OpenAPI (Swagger) import, request and response transformation and validation, SDK generation, and AWS WAF integration.
  • This design is highly available and scalable, has no infrastructure to manage, has no infrastructure cost when there is no traffic, and is paid per request.

1.2 REST APIs, HTTP APIs, and WebSocket APIs

2. Integrations and Endpoint Types

Problem Statement

FlashCart has customers on four continents, an internal inventory service on EC2 instances behind a private load balancer, and an order queue in SQS. The architects must decide how API Gateway reaches each backend, which endpoint type serves global customers best, and how to publish the API at api.flashcart.example.

2.1 Integration Types

An integration defines how an API method connects to and invokes its backend.

IntegrationWhat it does
LambdaInvokes a Lambda function, the easiest way to build a serverless REST API. With Lambda proxy integration, the whole request is passed to the function.
HTTP and HTTP proxySends the request to an HTTP endpoint, such as an on-premises API or an Application Load Balancer. API Gateway adds rate limiting, caching, authentication, and API keys in front of it.
AWS serviceCalls an AWS service API directly, with no code: send a message to SQS, publish to SNS, start a Step Functions workflow, put records in Kinesis, write to DynamoDB, or put events in EventBridge.
MockReturns a fixed response without a backend, for demos and tests.
VPC linkConnects privately to resources inside a VPC (2.4).

2.2 Endpoint Types

Endpoint typeHow it worksBest for
Edge-optimized (REST APIs, the default)Requests are routed through CloudFront edge locations. The API itself still lives in one Region.Clients all over the world.
RegionalThe API is deployed in one Region, and clients call it there. You can put your own CloudFront distribution in front of it for more control over caching.Clients in the same Region, or your own CDN.
PrivateReachable only from your VPC through an interface VPC endpoint (AWS PrivateLink). A resource policy controls the access.Internal, service-to-service APIs that must not be public.

2.3 Custom Domain Names

  • By default, an API has an AWS domain name, such as https://{{api-id}}.execute-api.{{region}}.amazonaws.com/{{stage}}.
  • You can use your own custom domain name, such as api.flashcart.example, with an SSL/TLS certificate from AWS Certificate Manager (ACM).
  • For an edge-optimized API, the domain is deployed through CloudFront, so the certificate must be in us-east-1.
  • For a Regional REST API or an HTTP API, the certificate must be in the same Region as the API.
  • Point the domain to the API with a Route 53 alias record or a CNAME record.

2.4 Private Backends With VPC Links

  • API Gateway is a public service that sits outside your VPC. It reaches backends through their public DNS names, so it cannot reach private resources directly, such as private EC2 instances or an internal load balancer.
  • A VPC link creates a private connection from API Gateway to a load balancer inside your VPC. The targets behind it can be EC2 instances, ECS tasks, or on-premises servers reached through hybrid connectivity.
  • The course slides describe VPC link V2 as connecting to an Application Load Balancer, and the older VPC link V1 as supporting a Network Load Balancer. Check the API Gateway documentation for the API type that you use.

3. Securing APIs

Problem Statement

FlashCart has three kinds of callers: its own Lambda functions and ECS tasks, signed-in customers of the mobile app, and partners that already have tokens from their own identity provider. The security team also wants to block one country and allow the admin API only from the office IP range.

3.1 Authentication and Authorization Options

OptionHow it worksUse it for
IAM authorizationThe caller signs the request with Signature Version 4 (SigV4). IAM policies allow or deny execute-api:Invoke on the API resources.Internal APIs, and calls from AWS services such as Lambda, Step Functions, or ECS tasks.
Amazon Cognito user pool authorizerThe user signs in to a Cognito user pool and gets JWT tokens. API Gateway validates the token, and returns 401 Unauthorized if it is invalid.External users of web and mobile apps.
Lambda authorizerAPI Gateway invokes a Lambda function that validates a token or request parameters and returns an IAM policy and a principal ID.Third-party identity providers, custom tokens, and fine-grained custom logic.
JWT authorizer (HTTP APIs)An HTTP API validates JSON Web Tokens from Cognito or any OpenID Connect provider.Simple token validation on HTTP APIs.

3.2 Resource Policies

  • A resource policy is a JSON policy attached to the API, like an S3 bucket policy. It controls who can reach the API before authentication and authorization run.
  • It can allow or deny access by AWS account, IAM principal, source IP range, VPC endpoint, or AWS Organizations.
  • It is required for private APIs, to limit access to specific interface VPC endpoints, and it is useful to restrict a public API to certain IP ranges or accounts.
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": "*",
    "Action": "execute-api:Invoke",
    "Resource": "arn:aws:execute-api:us-east-1:111111111111:api-id/*",
    "Condition": { "IpAddress": { "aws:SourceIp": "203.0.113.0/24" } }
  }]
}

3.3 Other Protections

  • API keys identify clients and work with usage plans for throttling and quotas. They are not a security control on their own.
  • AWS WAF protects REST APIs from common web exploits, such as SQL injection and cross-site scripting, and can block IP addresses or countries and limit request rates.
  • Mutual TLS on a Regional custom domain makes clients present a certificate.
  • API Gateway serves all endpoints over HTTPS. For browsers on another domain, enable CORS.

Scenario: Partners call a company API with tokens issued by their own third-party identity provider, and the API must apply custom rules based on the partner and the token claims. Which authorization option fits best?

  • A. API keys.
  • B. IAM authorization with SigV4.
  • C. A Cognito user pool authorizer.
  • D. A Lambda authorizer.
Show Answer and Explanation

Correct answer: D. A Lambda authorizer can validate third-party tokens and apply custom logic, and it returns an IAM policy for the request.

OptionResultReason
AIncorrectAPI keys identify clients but do not authorize them.
BIncorrectPartners outside AWS do not sign with IAM credentials.
CIncorrectThe tokens come from another provider, not a Cognito user pool.
DCorrectIt handles custom tokens and rules.

Remember these points:

  • IAM = internal and AWS callers (SigV4). Cognito = app users with JWT. Lambda authorizer = third-party or custom tokens.
  • API keys are not authentication. They identify clients for usage plans.
  • Block countries, SQL injection, or IP addresses on a REST API = AWS WAF. Allow only an IP range or account = resource policy.

IAM for AWS, Cognito for users, Lambda for everything custom, WAF for attacks.

4. Stages, Throttling, and Caching

Problem Statement

FlashCart releases a new version of the order API every week. The team needs separate dev, test, and prod environments, a safe way to try the new version on a few users, per-partner request limits, and faster responses for the product catalog, which changes only once an hour.

4.1 Stages, Versions, and Canary Releases

  • A deployment is a snapshot of the API. A stage is a named reference to a deployment, such as dev, test, or prod, with its own URL, settings, logging, throttling, and stage variables.
  • Stage variables are like environment variables for a stage. For example, a stage variable can point the prod stage to the prod alias of a Lambda function.
  • Publish breaking changes as a new version, such as /v1 and /v2, so that clients can upgrade safely.
  • A canary release on a REST API stage sends a percentage of the traffic to the new deployment, so you can test it before promoting it.

4.2 Throttling and Usage Plans

  • By default, API Gateway allows 10,000 requests per second per account per Region, with additional burst capacity, shared across REST, HTTP, and WebSocket APIs. The rate can be increased.
  • You can set lower throttling limits per stage and per method.
  • A throttled request gets 429 Too Many Requests, and the client should retry with exponential backoff.
  • Usage plans with API keys give each client its own throttling limits and request quotas, for example 1,000 requests per day for a free plan.
  • Remember that Lambda has a default concurrency of 1,000 per Region, which can be lower than the request rate of the API.

4.3 Caching

  • A REST API stage can have a cache, which returns stored responses without calling the backend, to reduce latency and backend load.
  • The default time to live (TTL) is 300 seconds, and you can set it from 0 to 3,600 seconds. You can override it per method.
  • You choose the cache capacity, and you pay for the cache by the hour.
  • A client can ask for fresh data with the Cache-Control: max-age=0 header, if it is authorized to invalidate the cache.

4.4 Limits to Know

4.5 Common API Gateway Errors

4XX errors mean a problem with the client request, and 5XX errors mean a problem on the server side.

CodeMeaningTypical cause and fix
400 Bad RequestThe request is not valid.The request fails request validation, or it has a wrong format. Fix the client request.
401 UnauthorizedThe caller is not authenticated.A missing, expired, or invalid token for a Cognito or Lambda authorizer. Sign in again or refresh the token.
403 ForbiddenThe caller is not allowed.An IAM policy or a resource policy denies the call, AWS WAF blocks it, or the request goes to a wrong path or stage. Check the policies, WAF rules, and URL.
413 Request Too LargeThe payload is too large.The request is over the 10 MB payload limit. Upload large files to S3 with a presigned URL (4.6).
429 Too Many RequestsThe request is throttled.The account, stage, or method rate limit, or a usage plan quota, is exceeded. Retry with exponential backoff, or raise the limits.
502 Bad GatewayThe backend returned a response that API Gateway cannot use.Often a Lambda proxy integration that returns a response in the wrong format, or a Lambda function error. Return the statusCode, headers, and body in the expected format.
503 Service UnavailableThe backend is not available.The backend is overloaded or down. Check its health and capacity.
504 Gateway TimeoutThe integration did not answer in time.The backend took longer than the integration timeout, 29 seconds by default for REST APIs. Make the backend faster, or use the asynchronous pattern (4.6).

4.6 Patterns for Large Payloads and Long-Running Requests

Large uploads and downloads with S3 presigned URLs

  • API Gateway accepts at most 10 MB per request, so large files should not go through the API.
  • The client calls the API, and a Lambda function returns an S3 presigned URL: a temporary URL, signed with the permissions of the function, that allows one upload or download for a limited time.
  • The client uploads the file directly to S3 with the URL. An S3 event notification can then trigger Lambda to process the file.
  • This removes the payload limit, reduces the cost and load of the API, and keeps the bucket private.

Long-running requests with an asynchronous pattern

  • A REST API integration times out after 29 seconds by default, and an HTTP API after 30 seconds. Work that takes longer must not keep the client waiting on the API.
  • The API puts the job in an SQS queue or starts an AWS Step Functions workflow, often with an AWS service integration, and returns at once with a job ID, for example with HTTP status 202 Accepted.
  • Workers process the job in the background, for minutes or hours.
  • The client gets the result by polling a status endpoint with the job ID, or by receiving a notification over a WebSocket API or AppSync subscription.
  • For Regional and private REST APIs, the integration timeout can also be raised above 29 seconds, but this can lower the account throttle quota, so the asynchronous pattern is usually the better design.

4.7 Monitoring

  • CloudWatch metrics include the request count, latency, integration latency, 4XX errors, 5XX errors, and cache hits and misses.
  • Execution logs and access logs go to CloudWatch Logs.
  • AWS X-Ray traces requests through API Gateway and the backend.

5. Amazon Cognito

Problem Statement

The FlashCart mobile app needs sign-up and sign-in with email or Google, multi-factor authentication for sellers, and a way for each user to upload photos directly to their own folder in S3 without going through the API.

5.1 What Amazon Cognito Is

  • Amazon Cognito gives the users of your web and mobile applications an identity. It provides secure sign-up, sign-in, and access control, as a managed identity provider.
  • It has two main parts: user pools for sign-in, and identity pools for AWS credentials.
  • Exam keywords for Cognito instead of IAM users: "hundreds of users", "mobile users", and "authenticate with SAML".

5.2 Cognito User Pools

  • A user pool is a serverless user directory for your web and mobile apps.
  • It provides sign-in with a username or email and a password, password reset, email and phone number verification, and multi-factor authentication (MFA).
  • It supports federated identities: users can sign in with Google, Facebook, Apple, Amazon, SAML, or OpenID Connect providers.
  • After sign-in, the user gets JSON Web Tokens (JWT).
  • User pools integrate with API Gateway, which validates the token, and with the Application Load Balancer, which can authenticate users in a listener rule before it forwards the request.

5.3 Cognito Identity Pools

  • An identity pool (federated identities) gives users temporary AWS credentials, so they can access AWS services directly, such as S3 or DynamoDB, or through API Gateway.
  • The users can come from a Cognito user pool or from third-party logins, such as Google, Facebook, SAML, and OpenID Connect.
  • Cognito applies IAM roles to the credentials: one for authenticated users and one for guest (unauthenticated) users.
  • The policies can use the identity of the user for fine-grained control, for example row-level security in DynamoDB, where each user can access only the items whose key matches their identity.
{
  "Effect": "Allow",
  "Action": ["dynamodb:GetItem", "dynamodb:PutItem", "dynamodb:Query"],
  "Resource": "arn:aws:dynamodb:us-west-2:123456789012:table/MyTable",
  "Condition": {
    "ForAllValues:StringEquals": {
      "dynamodb:LeadingKeys": ["${cognito-identity.amazonaws.com:sub}"]
    }
  }
}

This policy lets each user read and write only the DynamoDB items whose partition key is the user's own Cognito identity.

5.4 User Pools Compared With Identity Pools

User poolsIdentity pools
Answers the questionWho is this user? (authentication)What AWS resources can this user use? (authorization to AWS)
ResultJWT tokens.Temporary AWS credentials, through IAM roles.
Typical useSign-in to an app, then call API Gateway or an ALB.Direct access from the app to S3, DynamoDB, or other AWS services.

6. AWS AppSync

Problem Statement

The FlashCart mobile home screen needs the product, its stock, its reviews, and the price from three different services. With REST, the app makes four calls and downloads fields it never shows. The product team also wants the stock count to update live on every open screen.

6.1 What AWS AppSync Is

  • AWS AppSync is a fully managed service for GraphQL APIs and real-time Event APIs.
  • GraphQL is a query language for APIs. The client asks for exactly the fields that it needs, and one request can combine data from several sources.
  • A GraphQL API has a schema with three kinds of operations: queries read data, mutations change data, and subscriptions push changes to clients in real time.
  • Resolvers connect each field to a data source: Amazon DynamoDB, Amazon Aurora, Amazon OpenSearch Service, AWS Lambda, HTTP endpoints, and Amazon Bedrock.
  • You can create a GraphQL API directly from a DynamoDB or Aurora table, and merge several GraphQL APIs into one merged API.

6.2 Real-Time Data

  • GraphQL subscriptions push updates to connected clients over WebSockets, for example when a mutation changes the stock of a product.
  • AppSync Events is a pub/sub service: you create an Event API with channels, and clients publish and subscribe to real-time events, such as scores, locations, chat messages, and price changes, independently of GraphQL.
  • With the AWS Amplify libraries, mobile and web apps can also work offline and synchronize their data when they reconnect.

6.3 Security and Features

  • AppSync supports several authorization modes: API keys, IAM, Cognito user pools, OpenID Connect, and Lambda. One API can use more than one mode.
  • It supports private APIs, AWS WAF integration, custom domain names, and server-side caching.
  • You pay for the API operations, the real-time connection minutes, and the data transfer, and AppSync handles the scaling.
  • AWS Amplify is a set of tools to build and deploy full-stack web and mobile apps. It can create the Cognito, AppSync, API Gateway, S3, and Lambda backends for you.

6.4 AppSync Compared With API Gateway

7.2 Lowering the Cost

  • Use an HTTP API instead of a REST API when you do not need REST features.
  • Use caching when it saves more backend cost than it adds.
  • Use AWS service integrations instead of a Lambda function that only forwards the request to SQS, Kinesis, or DynamoDB.

8.4 Lesson Summary

This lesson covered the following points:

  • API Gateway is the managed front door for APIs, with REST, HTTP, and WebSocket APIs, and integrations with Lambda, HTTP endpoints, AWS services, mocks, and VPC links.
  • Endpoints are edge-optimized, Regional, or private. Custom domains use ACM certificates: us-east-1 for edge-optimized, and the API Region otherwise.
  • APIs are secured with IAM, Cognito user pools, Lambda authorizers, JWT authorizers, resource policies, and AWS WAF. API keys identify clients but are not security.
  • Stages, stage variables, and canary releases manage versions. Throttling starts at 10,000 requests per second per Region, usage plans set per-client quotas, and REST APIs can cache responses. 429, 502, and 504 point to throttling, a bad backend response, and a timeout. Presigned URLs handle large files, and asynchronous jobs handle long requests.
  • Cognito user pools sign users in with JWT tokens, and identity pools give them temporary AWS credentials.
  • AppSync provides managed GraphQL and Event APIs with many data sources, real-time subscriptions, and several authorization modes.

Memory Hook

API Gateway for REST, Cognito for users, AppSync for GraphQL and real time.

9. Knowledge Check

Answer each question in your own words before you open the model answer.

Question 1: Compare REST APIs, HTTP APIs, and WebSocket APIs in API Gateway, and give a use case for each.

Maps to: Objectives 1 and 2 (Comprehension).

REST APIs have the most API management features: API keys and usage plans, request validation, caching, AWS WAF, private endpoints, and canary releases, for example a partner API. HTTP APIs have minimal features at a lower price and support JWT authorizers, for example a simple proxy to Lambda. WebSocket APIs keep a persistent, two-way connection, for example a chat app. REST and HTTP payloads are up to 10 MB, and the default REST integration timeout is up to 29 seconds.

Question 2: Explain the three endpoint types and the certificate rule for custom domain names.

Maps to: Objective 2 (Comprehension).

An edge-optimized endpoint routes requests through CloudFront edge locations for global clients, while the API stays in one Region. A Regional endpoint serves clients in the same Region, and you can add your own CloudFront distribution. A private endpoint is reachable only from a VPC through an interface VPC endpoint, controlled by a resource policy. An edge-optimized custom domain needs an ACM certificate in us-east-1, and a Regional API or HTTP API needs it in the same Region as the API.

Question 3: Compare IAM authorization, Cognito user pool authorizers, and Lambda authorizers, and explain the role of API keys and resource policies.

Maps to: Objective 4 (Analysis).

IAM authorization uses SigV4-signed requests and IAM policies, for AWS services and internal callers. A Cognito user pool authorizer validates the JWT tokens of app users. A Lambda authorizer runs custom code to validate third-party or custom tokens and returns an IAM policy. API keys only identify clients for usage plans and are not authentication. Resource policies allow or deny access by account, IP range, VPC endpoint, or organization, and they are required for private APIs.

Question 4: Explain how stages, throttling, usage plans, and caching help you run an API in production.

Maps to: Objective 3 (Application).

Stages give separate environments, such as dev and prod, each with its own settings and stage variables, and canary releases test a new deployment on part of the traffic. API Gateway throttles at 10,000 requests per second per account per Region by default and returns 429 errors above the limit. Usage plans with API keys give each client its own limits and quotas. A REST API stage cache returns stored responses, with a default TTL of 300 seconds and up to 3,600, to reduce latency and backend load.

Question 5: Compare Cognito user pools and identity pools, and explain how to give each user access to only their own data in DynamoDB.

Maps to: Objective 5 (Analysis).

A user pool is a user directory for sign-up and sign-in, with MFA and federation, and it returns JWT tokens that API Gateway or an ALB can validate. An identity pool exchanges a token for temporary AWS credentials through IAM roles for authenticated or guest users. For per-user data, the IAM policy of the identity pool uses the dynamodb:LeadingKeys condition with the Cognito identity ID, so each user can access only the items whose partition key is their own ID.

Question 6: Explain when you would choose AWS AppSync instead of API Gateway.

Maps to: Objective 6 (Evaluation).

Choose AppSync when a web or mobile app needs a GraphQL API that returns exactly the fields it asks for from several data sources in one request, such as DynamoDB, Aurora, Lambda, and HTTP endpoints, with real-time subscriptions or Event API channels, offline sync through Amplify, and several authorization modes. Choose API Gateway for REST, HTTP, or WebSocket APIs, API management features such as usage plans and API keys, or proxies to existing services.

Question 7: Design the API and identity layer for FlashCart: global customers, partner quotas, mobile sign-in with Google, direct photo uploads to S3, and live stock updates.

Maps to: Objective 7 (Synthesis).

Use an edge-optimized API Gateway REST API with a custom domain and an ACM certificate in us-east-1, Lambda integrations, and AWS WAF. Give partners API keys in usage plans with their own quotas, and use stages and canary releases for new versions. Sign customers in with a Cognito user pool federated with Google, and protect the API with a Cognito authorizer. Use a Cognito identity pool so users upload photos directly to their own S3 prefix with temporary credentials. Use AppSync subscriptions or Events for live stock updates on the app screens.

Question 8: A user reports 504 errors on a report API, and another user cannot upload a 50 MB video through the same API. Explain the causes and how you would redesign the API.

Maps to: Objective 3 (Application).

A 504 Gateway Timeout means the backend took longer than the integration timeout, 29 seconds by default for a REST API. The report should run asynchronously: the API puts the job in SQS or starts Step Functions, returns a job ID with 202 Accepted, and the client polls a status endpoint or gets a WebSocket or AppSync notification. The upload fails because API Gateway accepts at most 10 MB per request. The API should return an S3 presigned URL from a Lambda function, and the client uploads the video straight to S3, where an event can trigger the processing.
