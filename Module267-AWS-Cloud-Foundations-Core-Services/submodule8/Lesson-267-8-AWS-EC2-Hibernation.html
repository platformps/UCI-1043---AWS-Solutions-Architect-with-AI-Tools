1. How EC2 Hibernation Works

Problem Statement

You work as a junior AWS solutions architect at RetailCloud, a fast-growing e-commerce platform, under the guidance of a lead architect. To save costs, developers turn off the non-production testing environments every night. However, reloading heavy software dependencies each morning takes over 20 minutes.

Your lead architect assigns you to preserve the state of these environments and reduce their startup times, without paying for compute while the instances are paused. Before you change anything, you need answers to the questions below. This lesson explains how Amazon EC2 Hibernation answers them.

Your challenge:

  • How can an instance save the contents of its memory so that it resumes where it left off?
  • What must be true of an instance and its root volume before hibernation works?
  • What happens to the private, public, and Elastic IP addresses of an instance that is hibernated and started?
  • What does RetailCloud pay for while an instance is hibernated?

1.1 Overview of Amazon EC2 Hibernation

EC2 Hibernation is an instance management feature that saves the in-memory state (RAM) of a running virtual server to its persistent EBS root volume before the instance powers down.

  • Initiating hibernation: when you issue a hibernate request, EC2 signals the operating system to freeze the application processes and write the current contents of the system RAM to the root Amazon Elastic Block Store (EBS) volume.
  • Instance state: the instance moves from running to stopping to stopped.

1.2 What Happens When You Hibernate an Instance?

The diagram shows a basic overview of the hibernation process for EC2 instances.

When you hibernate an instance, the following happens:

  • The instance moves to the stopping state. Amazon EC2 signals the operating system to perform hibernation (suspend-to-disk). The hibernation freezes all of the processes, saves the contents of the RAM to the EBS root volume, and then performs a regular shutdown.
  • After the shutdown is complete, the instance moves to the stopped state.
  • Any EBS volumes remain attached to the instance, and their data persists, including the saved contents of the RAM.
  • Any Amazon EC2 instance store volumes remain attached to the instance, but the data on the instance store volumes is lost.
  • In most cases, AWS migrates the instance to a new underlying host computer when it starts. The same happens when you stop and start an instance.
  • When you start the instance, it boots, and the operating system reads in the contents of the RAM from the EBS root volume before it unfreezes the processes to resume their state.
  • The instance keeps its private IPv4 addresses and any IPv6 addresses, and it keeps them when it starts again.
  • Amazon EC2 releases the public IPv4 address. When the instance starts, Amazon EC2 assigns a new public IPv4 address.
  • The instance keeps its associated Elastic IP addresses. You are charged for any Elastic IP addresses that are associated with a hibernated instance.

For how hibernation differs from reboot, stop, and terminate, see Differences between instance states.

Advantage: hibernation preserves the running process state and the in-memory datasets. The application resumes from its previous state when it starts, without repeating long initialization steps.

1.3 Hibernation Requirements: Good to Know

You must enable hibernation when you launch the instance. You cannot enable it later on an existing instance, whether the instance is running or stopped. The instance must also have:

  • A supported AMI: a hardware virtual machine (HVM) AMI that supports hibernation. Supported AMIs include Amazon Linux, Ubuntu, and Windows images. Check the AWS documentation for the current list.
  • A supported instance type: an instance family that supports hibernation. Bare metal instances are not supported.
  • A root volume that is an EBS volume, not an instance store volume. It must be encrypted, and it must be large enough to hold the contents of the RAM and your expected usage. AWS allocates space on the root volume at launch to store the RAM.
  • A purchase option: On-Demand Instances and Spot Instances support hibernation.
  • An instance RAM size of less than 150 GiB for a Linux instance, and 16 GiB or less for a Windows instance.
  • A hibernation period of no more than 60 days. AWS does not support keeping an instance hibernated for longer. To keep the instance longer, start the hibernated instance, stop it, and start it again.

For the current rules, see Prerequisites for EC2 instance hibernation.

1.4 Limitations

These limitations also apply. They come from the AWS documentation on how hibernation works:

  • While an instance is hibernated, you cannot modify it. For example, you cannot change its instance type, which you can do for a stopped instance that is not hibernated.
  • You cannot hibernate an instance that is in an Auto Scaling group or that Amazon ECS uses.
  • You cannot hibernate an instance that boots in UEFI mode with UEFI Secure Boot enabled.
  • Data on instance store volumes is lost when the instance hibernates.
  • AWS regularly updates its platform with upgrades and security patches. These can conflict with hibernated instances, and AWS notifies you about critical updates that require a start.

For more information, see How Amazon EC2 instance hibernation works.

2. Billing, IP Addresses, and the Lab

Problem Statement

RetailCloud’s finance team asks what the company pays for while a test instance is hibernated. The developers ask whether the instance keeps its addresses when they start it each morning.

The architect explains the billing rules and the behavior of each kind of IP address, and then has the developers practice in a lab.

Your challenge:

  • Explain what AWS charges while an instance is hibernated.
  • Describe what happens to private, public, and Elastic IP addresses.
  • Match hibernation to the right use case.

2.1 Billing While an Instance Is Hibernated

While the instance is in the stopped state, compute charges (vCPU and RAM) are paused ($0 per hour). You pay only for the EBS volume storage that the OS and the saved RAM contents occupy. You also pay for the public IPv4 charge on any Elastic IP addresses that stay associated with the instance. AWS does not charge for the data transfer when the contents of the RAM move to the EBS root volume.

2.2 Use Cases of Hibernation

  • Long-running processing.
  • Saving the RAM state.
  • Services that take time to initialize.

2.3 Real-World Hibernation Scenario

A data analyst uses a memory-intensive application that takes 20 minutes to load datasets and prepare its working environment. At the end of the day, the analyst hibernates the EC2 instance instead of stopping it. AWS saves the contents of the RAM to the encrypted root EBS volume.

The next morning, the analyst starts the instance. The application and the datasets resume from their previous state, which reduces the startup time. The company does not pay EC2 compute charges while the instance is hibernated, but it continues to pay for the EBS storage.

For more information, see the EC2 hibernation documentation.

A company runs an application server with a private IP address of 10.0.1.25, an automatic public IP address of 3.95.15.155, and an optional Elastic IP address of 18.210.40.50. If the instance is stopped or hibernated and then restarted:

2.6 Exam Tips

  • Internal VPC communication: private IP.
  • Temporary internet connectivity: automatic public IP.
  • Persistent public IPv4 address: Elastic IP.
  • Move a public IP to a replacement instance: Elastic IP.
  • Preserve RAM and running processes: hibernate.
  • Preserve disk data but not RAM: stop.
  • Hibernated instance: no compute charge while stopped, but EBS storage charges continue.
  • Private IP after stop and start: remains the same.
  • Automatic public IP after stop and start: usually changes.
  • Elastic IP after stop and start: remains the same.
  • Public IPv4 addresses: incur charges, including Elastic IP addresses.

Memory aid: a private IP stays with the instance, an automatic public IP can change, an Elastic IP remains static, and hibernation preserves RAM on EBS.

2.8 Lesson Summary

In this lesson, you learned the following:

  • EC2 Hibernation saves the contents of an instance’s memory (RAM) to its encrypted Amazon EBS root volume before the instance shuts down, so the instance can resume where it left off.
  • When you hibernate an instance, it moves from running to stopping to stopped. When you start it, the operating system reads the saved RAM back from the root volume and resumes the processes.
  • Hibernation must be enabled when the instance is launched. You cannot enable it later on an existing instance.
  • The instance needs a supported Amazon Machine Image (AMI), an encrypted EBS root volume that is large enough to hold the saved RAM, and a RAM size and hibernation period within the supported limits.
  • A hibernated instance keeps its private IPv4 address and its Elastic IP addresses. AWS releases an automatically assigned public IPv4 address and assigns a new one when the instance starts.
  • While an instance is hibernated and stopped, compute charges are paused. You continue to pay for EBS storage, including the saved RAM, and for public IPv4 addresses, including Elastic IP addresses that remain associated.
  • Hibernation suits long-running processes and applications that take a long time to initialize.

3. Knowledge Check

Answer each question in your own words before you open the model answer. The questions were written for this course.

Question 1: What happens to the system RAM when an Amazon EC2 instance is hibernated?

Maps to: Objective 2 (Comprehension).

The operating system writes the current contents of the system RAM to the encrypted EBS root volume before the instance moves to the stopped state. When you start the instance, the operating system reads the contents back and resumes the processes.

Question 2: Can you enable hibernation on an existing EC2 instance after it has been launched?

Maps to: Objective 1 (Knowledge).

No. You must enable hibernation when you launch the instance. You cannot enable it later on an existing instance, whether it is running or stopped.

Question 3: What are the billing impacts while an EC2 instance remains hibernated?

Maps to: Objective 4 (Analysis).

EC2 compute charges (vCPU and RAM) are paused ($0 per hour). Standard EBS storage charges continue for the root volume and the saved RAM contents, and the public IPv4 charge continues for any Elastic IP address that stays associated.

Question 4: How do private IPs, automatic public IPs, and Elastic IPs behave after a hibernated instance is restarted?

Maps to: Objective 3 (Comparison).

The private IP and the Elastic IP stay the same, as long as the Elastic IP stays associated. AWS releases an automatically assigned public IP address when the instance stops, and it usually assigns a different one when the instance starts.

Question 5: What is the main advantage of EC2 Hibernation for an application that takes a long time to boot or initialize?

Maps to: Objective 2 (Comprehension).

Hibernation preserves the running process state and the in-memory datasets. The application resumes from its previous state when the instance starts, without repeating the long initialization steps.

Question 6: List the main prerequisites and limitations of EC2 hibernation.

Maps to: Objective 1 (Knowledge and Comprehension).

Hibernation must be enabled at launch. The instance needs a supported AMI and instance type, an encrypted EBS root volume that is large enough for the RAM, and a RAM size of less than 150 GiB on Linux or 16 GiB or less on Windows. It works with On-Demand and Spot Instances, and AWS does not support keeping an instance hibernated for more than 60 days. You cannot modify a hibernated instance, you cannot hibernate an instance in an Auto Scaling group, and instance store data is lost.

Question 7: A company wants to avoid paying for compute overnight, and wants an application with a 20-minute startup to resume in its loaded state. What would you recommend, and what will the company still pay for?

Maps to: Objectives 2 and 4 (Application).

Launch the instance with hibernation enabled and an encrypted EBS root volume, hibernate it each night, and start it each morning. The company does not pay compute charges while the instance is stopped. It still pays for the EBS storage, including the saved RAM, and for any Elastic IP address that stays associated.
