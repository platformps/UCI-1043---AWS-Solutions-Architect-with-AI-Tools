1. On-Premises vs. Cloud

Problem Statement

RetailCloud, the e-commerce company from the Module 267 kick-off, runs its storefront in its own small data center. When a promotion goes viral, the servers crash, and buying new ones takes weeks. When traffic is low, the hardware sits idle and loses value.

The CEO asks the new junior solutions architect to explain what cloud computing is, why it fits RetailCloud, and what the company would give up and gain by moving.

Your challenge:

  • Compare running RetailCloud on premises with running it in the cloud.
  • Define cloud computing, and name the six advantages that AWS describes.
  • Name the three components that make cloud services possible.

1.1 Traditional In-House Data Centers

  • On-premises infrastructure means resources that are hosted locally, in an organization’s own data center or facility.
  • Full physical ownership: the organization manages the hardware, racks, power, cooling, and physical security.
  • CapEx heavy: servers and network equipment need significant upfront capital expenditure.
  • Manual maintenance: IT teams handle hardware upgrades, patching, and repairs.
  • Fixed capacity: scaling means a long procurement cycle and a physical installation.

1.2 What Is Cloud Computing?

  • Cloud computing is the on-demand delivery of IT resources, such as compute, storage, and databases, over the internet with pay-as-you-go pricing.
  • Instead of buying, owning, and maintaining physical data centers and servers, you use technology services as you need them from a cloud provider such as Amazon Web Services (AWS).
  • The services include servers, storage, databases, networking, software, analytics, and intelligence. The word “cloud” is a metaphor for a large shared pool of computing resources that you reach through the internet.
  • No server management: the provider maintains the data centers and the hardware.
  • OpEx flexibility: fixed capital costs become variable operational costs.
  • Global scale: you can deploy an application in several Regions in minutes.
  • API driven: you can provision and orchestrate infrastructure with code.

1.3 Strategic Benefits of Cloud Adoption

  • On demand: customers sign up, pay for, and start using resources on their own, without help from a sales agent.
  • Elastic: you grow or shrink your active servers as demand changes.
  • Measured service: customers pay for the amount of resources that they use in a given period, not for hardware or software upfront. In a private cloud, measured service usually means chargebacks, where IT tracks how much each department uses.
  • Serverless: developers write and deploy code without worrying about the underlying infrastructure.

AWS summarizes the value of the cloud as six advantages. These are exam vocabulary, so learn the names.

1.4 Characteristics of Cloud Computing

CharacteristicWhat it meansExample
Network accessResources are reached over the network, from any location.A developer in one country manages servers in another through the AWS Management Console.
Shared pool of resourcesResources are pooled and abstracted for the user, instead of the “silo-based” infrastructure of a traditional data center.Many customers run on the same physical hardware, each isolated from the others.
On-demand self-serviceUsers provision resources themselves, without a sales agent.Launching a server in minutes.
Rapid elasticityCapacity grows and shrinks quickly with demand.Adding servers for a flash sale and removing them afterward.
Measured serviceUsage is metered, and customers pay for what they use.A monthly bill based on compute hours and storage.
Business agility and speedProvision complex environments in minutes instead of weeks or months. This supports rapid experimentation and CI/CD pipelines.A team builds a test environment for each new release.

The U.S. National Institute of Standards and Technology (NIST) defines on-demand self-service, broad network access, resource pooling, rapid elasticity, and measured service as the essential characteristics of cloud computing.

1.5 Cloud Computing Components

  • Data centers: physical facilities house servers, storage, and supporting hardware. AWS runs its data centers in Regions and Availability Zones (lesson 267.2).
  • Networking capabilities: high-speed connections move data between users and cloud resources.
  • Virtualization: software abstracts physical hardware into flexible resource pools, such as virtual machines (VMs).
  • Working together: facilities supply capacity, networks connect it, and virtualization allocates it.

2. Cloud Service Models and Shared Responsibility

Problem Statement

RetailCloud’s developers want to deploy code without patching servers. The operations team wants full control of the operating system for a legacy payment component. The security team asks a simple question about each option: who is responsible for securing what?

The architects need a shared vocabulary for the choices, so that every team knows what it manages and what the provider manages.

Your challenge:

  • Differentiate IaaS, PaaS, SaaS, FaaS, and NaaS.
  • Explain how the shared responsibility model changes with each model.
  • List the cloud security best practices that apply to every model.

2.1 Core Cloud Service Models

ModelWhat it deliversExamples
IaaS, infrastructure as a serviceThe fundamental computing resources: virtual servers, storage, and networking.Amazon EC2, Azure Virtual Machines, Google Compute Engine
PaaS, platform as a serviceA managed execution environment for your code. The provider manages the operating system and middleware layers.AWS Elastic Beanstalk (lesson 270.5), Heroku, Google App Engine
SaaS, software as a serviceA fully managed, ready-to-use application that you reach through a web browser.Microsoft 365, Salesforce, Google Workspace

2.2 Specialized Service Models

ModelWhat it isKey points
FaaS, function as a serviceServerless, event-driven compute. Developers run code in response to events without building or maintaining complex infrastructure.The code runs only when triggered and is stateless. There is no cost when it is idle, and it scales automatically for each request. It fits microservices, API backends, and data processing. On AWS, this is AWS Lambda (lesson 273.1).
NaaS, network as a serviceCloud-based virtual networking: connectivity services, software-defined WAN (SD-WAN), and routing on demand.It replaces physical routers, MPLS lines, and switches. Bandwidth allocation and security rules are customizable, and cross-region and multi-cloud connectivity is simpler. NaaS is mainly an industry term, and this course uses it to compare service abstractions.

2.3 Comparing Service Abstractions

ModelCustomer managesProvider managesPrimary benefit
IaaSOperating system, applications, data, middlewarePhysical hardware, virtualizationMaximum control and customization
PaaSApplication code, dataOperating system, runtime, hardware, virtualizationRapid application deployment
SaaSUser access, basic configuration, dataThe entire stack: application, runtime, serversZero maintenance and instant use
FaaSIndividual function logicServer management, automatic scalingEvent-driven cost efficiency

2.4 The Shared Responsibility Model

  • The cloud provider is responsible for the security of the cloud: the physical infrastructure, hosts, network, and data centers.
  • The customer is responsible for security in the cloud: data, user identities, applications, and access control.
  • The division depends on the service. With IaaS, the customer manages most responsibilities, including virtual machines, storage, and networking. With PaaS, the customer manages fewer tasks, mainly application settings and data. With SaaS, the provider handles most responsibilities, and the customer is responsible for data and user access.
AWS exampleAWS is responsible forThe customer is responsible for
Amazon EC2 (IaaS)The physical data center, hardware, and virtualization layerThe guest operating system and its patches, the applications, security group rules, data, and access
AWS Lambda (FaaS)The servers, the operating system, and the runtime environmentThe function code, its permissions, and the data that it handles
A SaaS applicationThe application and the infrastructure under itThe data that users put in, and who has access

2.5 Cloud Security Best Practices

  • Shared responsibility for security: the provider generally secures the cloud infrastructure, and the customer protects its data in the cloud. Define data ownership clearly between private and public third parties.
  • Data encryption: encrypt data at rest, in transit, and in use. Customers need to keep complete control of their security keys and hardware security modules (lesson 268.7).
  • Collaborative management: clear processes and communication between IT, operations, and security teams keep cloud integrations secure and sustainable.
  • Security and compliance monitoring: know the regulatory standards that apply to your industry, and actively monitor all connected systems and cloud services. This gives you visibility of data exchanges across on-premises, private cloud, hybrid cloud, and edge environments.

3. Cloud Deployment Models, CapEx, and OpEx

Problem Statement

RetailCloud must keep its customer records in a private environment for compliance, but its storefront needs elastic capacity for sales events. The CFO also asks how a move to the cloud changes the way the company budgets for IT.

The architects need to choose a deployment model and explain the difference between capital and operational spending.

Your challenge:

  • Compare private, public, and hybrid cloud.
  • Name the AWS services that connect an on-premises environment to AWS.
  • Explain CapEx and OpEx, and say how cloud computing shifts spending.

3.1 Cloud Deployment Models

ModelWhere resources are hosted and managedFocus
Private cloudInfrastructure operated solely for one organization, in its own data center or hosted by a dedicated provider. It is usually managed with internal resources, with selective access.High control and strict compliance
Public cloudServices owned and operated by third-party providers, and delivered over the public internet to many customers (tenants). Examples are AWS, Microsoft Azure, and Google Cloud Platform. Customers share the provider’s infrastructure but manage their own data and configurations.Elastic scale and low overhead
Hybrid cloudA mix of private and public environments, joined by technology that lets data and applications move between them. Sensitive data can stay on premises while the public cloud adds capacity and speeds up innovation.Flexibility and phased migration
  • Hybrid models are growing, especially in heavily regulated industries that move from private systems to less costly cloud infrastructure.
  • A hybrid cloud helps meet regulatory and data residency requirements by keeping sensitive workloads in private infrastructure, and it improves scalability by using the public cloud for the rest.

3.3 Overview of CapEx and OpEx

CapEx (capital expenditure)OpEx (operational expenditure)
DefinitionUpfront investment in physical assets or infrastructure. This is the traditional model for on-premises IT.Ongoing, day-to-day costs to run services and resources. This is the model that cloud environments such as AWS and Azure mainly use.
ExamplesBuying servers and networking equipment, setting up data centers, and buying perpetual software licenses.Monthly payments for virtual machines or storage, subscription fees for SaaS tools, billing by usage (compute hours, bandwidth), and support and monitoring costs.
CharacteristicsLarge upfront cost, and hardware loses value over time.Pay as you go or pay per use, with a low upfront cost. It is scalable, flexible, and easy to adjust as business needs change.

3.4 CapEx vs. OpEx in the Cloud

  • Capital expenditure (CapEx) is a large, upfront cost for physical infrastructure or long-term assets, such as servers or data centers.
  • Operational expenditure (OpEx) is an ongoing cost for services and subscriptions, such as leasing hardware or using cloud resources.
  • Cloud computing shifts IT spending from CapEx to OpEx. Organizations scale usage up or down and pay only for what they consume. With AWS, most services fall under OpEx.
  • Some AWS pricing options, such as Savings Plans, trade a commitment for a lower rate. Cost optimization is covered later in this course.

4. Application Migration

Problem Statement

RetailCloud decides to move its legacy order-management application to the cloud. Some leaders want to move it unchanged this quarter. Others want to rebuild it with cloud-native services first.

The architects need a structured plan, so that the move starts with facts and ends with an optimized, governed environment.

Your challenge:

  • Outline the phases of an application migration.
  • Name the seven migration strategies (the 7 Rs).
  • Match a strategy to a workload.

4.1 The Four Phases of Application Migration

PhaseWhat happens
1. Discovery and AssessmentInventory the legacy workloads, map their dependencies, and calculate the total cost of ownership (TCO).
2. Strategy and DesignSelect a migration strategy (the 7 Rs, in the next section) and design the landing zone.
3. Migration and ExecutionMigrate the data, execute the cutover, integrate security policies, and validate workload performance.
4. Optimize and GovernFine-tune cloud cost efficiency (FinOps), establish automated governance, and keep monitoring.

4.2 The 7 Rs Migration Strategies

  • AWS describes seven migration strategies for moving applications to the AWS Cloud. They are known as the 7 Rs: retire, retain, rehost, relocate, repurchase, replatform, and refactor or re-architect.
StrategyWhat it meansExample
RetireDecommission or archive applications that you no longer need.Shut down an application that almost nobody uses.
RetainKeep the application in the source environment, and revisit later.Keep a system on premises because of data residency rules or a dependency.
Rehost (lift and shift)Move the application to the cloud without changes.Move servers to Amazon EC2 as they are.
RelocateMove instances or objects to a different VPC, AWS Region, or AWS account, or move at the hypervisor level.Move VMware workloads to VMware Cloud on AWS.
Repurchase (drop and shop)Replace the application with a different product, often a SaaS product.Replace a self-hosted tool with a SaaS subscription.
Replatform (lift and reshape)Move to the cloud and add some optimization, without changing the core architecture.Move an on-premises Oracle database to Amazon RDS for Oracle.
Refactor or re-architectChange the architecture to use cloud-native features for agility, performance, and scalability.Rebuild a monolith as serverless microservices.

Source: AWS Prescriptive Guidance, About the migration strategies.

4.3 Choosing a Strategy

  • For large migrations, AWS lists rehost, replatform, relocate, and retire as common strategies. Refactor is not recommended for large migrations, because it changes the application during the move and is the most complex strategy to manage at scale.
  • Match the strategy to the driver: speed points to rehost or relocate, lower operating effort points to replatform or repurchase, and long-term agility points to refactor.
  • Phase 1 supplies the facts for this decision: the inventory, the dependencies, and the TCO.

4.4 Exam-Style Question

Written for this course.

  • A. Rehost.
  • B. Replatform.
  • C. Repurchase.
  • D. Refactor.

Correct answer: B. The company keeps the application and its architecture, and adds a managed database service. That small optimization is replatforming.

5. Knowledge Check

Answer each question in your own words before you open the model answer. The questions were written for this course.

Question 1: Define cloud computing, and name the six advantages that AWS describes.

Maps to: Objective 1 (Knowledge and Comprehension).

Cloud computing is the on-demand delivery of IT resources, such as compute, storage, and databases, over the internet with pay-as-you-go pricing. The six advantages are: trade fixed expense for variable expense, benefit from massive economies of scale, stop guessing capacity, increase speed and agility, stop spending money running and maintaining data centers, and go global in minutes.

Question 2: How does cloud computing differ from on-premises infrastructure in terms of hardware ownership, maintenance, and capacity?

Maps to: Objective 2 (Comprehension).

On premises, the organization owns the hardware, handles upgrades, patching, and repairs, and has fixed capacity that needs procurement to expand. In the cloud, the provider owns and maintains the infrastructure, the customer manages only what its service model assigns, and capacity scales up and down on demand with pay-as-you-go pricing.

Question 3: What roles do data centers, networking, and virtualization each play in delivering cloud services?

Maps to: Objective 3 (Comprehension).

Data centers house the servers, storage, and supporting hardware that supply capacity. Networking provides the high-speed connections between users and cloud resources. Virtualization abstracts the physical hardware into flexible resource pools that can be allocated on demand.

Question 4: A team wants to manage its own operating system and applications but does not want to buy physical servers. Which cloud service model fits, and why?

Maps to: Objective 4 (Application).

IaaS fits. The provider supplies the virtual servers, storage, and networking, so the team buys no hardware, and the team still manages the operating system, middleware, applications, and data. Amazon EC2 is an example.

Question 5: How does the customer’s security responsibility change when moving from IaaS to PaaS to SaaS?

Maps to: Objective 4 (Analysis).

With IaaS, the customer manages most things, including the guest operating system, applications, and data. With PaaS, the provider takes the operating system and runtime, and the customer focuses on application settings and data. With SaaS, the provider handles almost everything, and the customer remains responsible for its data and user access.

Question 6: A healthcare organization must keep patient records in its private environment but needs public cloud capacity for its appointment website during busy periods. Which deployment model would you recommend, and why?

Maps to: Objective 5 (Application).

A hybrid cloud. Patient records stay on premises, which meets data residency and regulatory requirements, and the public cloud absorbs the traffic spikes of the website. A private connection such as AWS Direct Connect or a Site-to-Site VPN links the two environments.

Question 7: What is the difference between CapEx and OpEx? Give one IT spending example of each.

Maps to: Objective 5 (Comprehension).

CapEx is a large, upfront investment in physical assets, for example buying servers for a data center. OpEx is an ongoing cost of running services, for example a monthly bill for cloud compute and storage. The cloud shifts spending from CapEx to OpEx.

Question 8: What information should an organization gather during the discovery and assessment phase of an application migration?

Maps to: Objective 6 (Application).

An inventory of the legacy workloads, a map of their dependencies, and a calculation of the total cost of ownership. This information supports the choice of a migration strategy, one of the 7 Rs, in the strategy and design phase.

Question 9: RetailCloud needs elastic capacity for its storefront, keeps customer records private, wants less upfront spending, and must move a legacy order system quickly. Design a recommendation, and justify each decision.

Maps to: Objective 7 (Synthesis).

Use a hybrid cloud: customer records stay on premises, and the storefront runs in the public cloud, where capacity scales on demand. Pay as you go moves spending from CapEx to OpEx. Choose IaaS for any component that needs operating system control and FaaS for short event-driven jobs. Rehost the legacy order system first for speed, then replatform its database to a managed service to reduce operating effort. Start with discovery and assessment so that the inventory, dependencies, and TCO support the plan.
