1. What EFA Is and How It Works

Problem Statement

You work as a junior AWS solutions architect at RetailCloud, a fast-growing e-commerce platform, under the guidance of a lead architect. RetailCloud’s data science team runs a demand-forecasting simulation across 20 EC2 instances. The instances must constantly exchange large amounts of data, and the simulation takes longer than the team expected.

Your lead architect asks whether a special network device can lower the latency between the instances. Before you recommend it, you need answers to the questions below. This lesson explains how Elastic Fabric Adapter (EFA) answers them.

Your challenge:

  • What is an Elastic Fabric Adapter, and what does it do?
  • How is an EFA attached to an instance?
  • Does an EFA add a charge?
  • How does EFA differ from the standard Elastic Network Adapter (ENA)?

1.1 Overview of Elastic Fabric Adapter (EFA)

  • An Elastic Fabric Adapter (EFA) is a network device that you attach to Amazon EC2 instances to accelerate High Performance Computing (HPC) and Machine Learning (ML) applications.
  • It enables applications that need inter-node communication to run at scale, with the low latency and high throughput that you find in custom on-premises HPC clusters.
  • It is designed mainly for workloads in which several EC2 instances communicate rapidly and frequently.
  • It reduces networking overhead by communicating directly with the network device, which bypasses much of the operating system TCP/IP stack (OS-bypass).

Reference: Elastic Fabric Adapter for AI/ML and HPC workloads on Amazon EC2.

1.2 How to Attach the EFA Device to the EC2 Instance

You can add an EFA to an instance through one of two interface types:

  1. EFA with ENA (the traditional EFA interface): one interface that gives the instance both an EFA device and an ENA device.
  2. EFA-only: an interface that has just the EFA device and no ENA device, so you cannot assign an IP address to it.

Reference: EFA basics.

1.3 EFA Pricing

EFA is an optional feature of supported EC2 instances. AWS does not charge extra for it, so you pay only for the instances and the other resources that you use.

1.4 Key Capabilities

EFA enhances traditional cloud networking by bypassing the operating system kernel and communicating directly with the network interface hardware.

  • OS Bypass (kernel bypass): EFA provides an application-level interface that lets user-space applications bypass the Linux kernel driver and talk directly to the network interface. This reduces the latency of inter-node communication significantly.
  • Scalable Reliable Datagram (SRD): TCP guarantees the ordered delivery of packets, and it can suffer from head-of-line blocking when packets are lost. EFA uses SRD instead. SRD load-balances traffic dynamically across multiple network paths, and it handles out-of-order packet delivery efficiently at the receiving end.
  • EFA supports AI and ML communication libraries such as NCCL.
  • EFA works only with supported EC2 instance types and operating systems.
  • EFA works best with a cluster placement group, which places instances close together to minimize latency.

2. Use Cases, Instance Types, and Setup

Problem Statement

The data science team asks which kinds of work benefit from EFA, which instance types support it, and how to set it up. The lead architect also asks whether EFA appears on the AWS Certified Solutions Architect – Associate (SAA-C03) exam that you are preparing for.

Your challenge:

  • Which workloads benefit from EFA?
  • Which EC2 instances support it?
  • In what order do you set up an EFA-enabled cluster?
  • How much do you need to know about EFA for the SAA-C03 exam?

2.1 Target Workloads and Primary Use Cases

2.1.1 High Performance Computing (HPC)

  • Computational Fluid Dynamics (CFD): solvers such as OpenFOAM and ANSYS Fluent benefit from low latency during the synchronization of the domain decomposition.
  • Weather and climate modeling: WRF (Weather Research and Forecasting) can run at scale across hundreds of compute nodes.
  • Molecular dynamics: EFA accelerates codes such as NAMD and GROMACS, which need frequent node-to-node communication in under a millisecond.

2.1.2 Distributed Machine Learning and Deep Learning

  • Large Language Model (LLM) training: EFA accelerates multi-node training with frameworks such as PyTorch and TensorFlow through aws-ofi-nccl.
  • Parameter server architecture: EFA speeds up the heavy GPU-to-GPU communication (for example, AllReduce algorithms) across distributed clusters.

2.2 Real-World Scenario

A research organization runs a weather simulation across 20 EC2 instances. Each instance calculates one portion of the simulation, but the instances must continually exchange large quantities of data.

With traditional TCP networking, operating system processing can add latency and reduce the overall performance of the cluster. The organization uses the following:

  • Supported compute-optimized EC2 instances.
  • An Elastic Fabric Adapter.
  • A cluster placement group.
  • MPI-based simulation software.

EFA allows the instances to exchange data with lower latency and higher throughput, which helps the simulation finish more quickly.

2.3 Supported Instance Types

EFA is supported on select high-performance Amazon EC2 compute, memory, and GPU instances. The supported types vary by Region, so the following groups are examples:

  • HPC optimized: Hpc6a, Hpc6id, Hpc7g, and Hpc7a.
  • GPU and accelerated: P4d, P5, G5, Trn1, and Trn2.
  • Compute, memory, and general purpose: C5n, C6i, C7g, M6i, and R6i, on select large sizes or metal.

To list the instance types that support EFA in a Region, run the following AWS CLI command:

aws ec2 describe-instance-types \
    --region us-east-1 \
    --filters Name=network-info.efa-supported,Values=true \
    --query "InstanceTypes[*].[InstanceType]" \
    --output text | sort

Reference: Supported instance types.

2.4 Implementation and Configuration Flow

Setting up EFA follows a fixed order. AWS publishes a full tutorial, so for the exam you only need to know the order and the purpose of each step.

2.4.1 Prerequisites

  1. Supported instance and operating system: choose a supported instance type and an image for a supported operating system.
  2. Subnet: select a subnet when you launch the instance. Without a subnet, you cannot enable EFA on it.
  3. Placement group (recommended): launch the instances in a cluster placement group, so that they sit close together and communicate with low latency. AWS ParallelCluster recommends one to minimize latency, and AWS Batch requires one for jobs that use EFA.
  4. Security group configuration: the security group that is associated with the EFA interface must contain a self-referencing rule that allows all inbound and outbound traffic to itself. This rule enables OS-bypass.

2.4.2 Configuration Flow

Follow these steps to launch a cluster of EFA-enabled instances for an HPC workload.

  1. Create an EFA-enabled security group. Allow all inbound and outbound traffic to and from the group itself, and allow SSH so that you can connect.
  2. Launch a temporary instance. Choose a supported operating system image, a supported instance type, a subnet, and the EFA-enabled security group. Under Advanced network configuration, enable the EFA interface, using the interface type EFA with ENA or EFA-only.
  3. Install the EFA software. Install the EFA-enabled kernel, the EFA drivers, Libfabric, and Open MPI on the temporary instance.
  4. Finish the setup and test it. Complete the steps that apply to your case, such as installing Intel MPI or disabling ptrace (process trace) protection, then confirm the installation and install your HPC application.
  5. Create an EFA-enabled AMI. Create an image from the configured temporary instance, so that every new instance starts with the EFA software already installed.
  6. Launch the cluster. Launch the EFA-enabled instances from that AMI into a cluster placement group.
  7. Clean up and connect the instances. Terminate the temporary instance, and enable passwordless SSH between the instances, so that an application can run across the whole cluster.

Note: you can add an EFA when you launch an instance, or attach one to a supported instance that is stopped. You cannot attach or detach an EFA while the instance is running.

Reference: Get started with EFA and MPI for HPC workloads on Amazon EC2.

2.6 Is EFA Part of the SAA-C03 Exam?

EFA is not named as a separate service in the current official SAA-C03 in-scope service list. However, Amazon EC2 is in scope, and AWS states that the list is non-exhaustive and subject to change. Therefore, EFA can appear as an EC2 networking feature in a high-performance architecture scenario.

For the SAA-C03 exam, you should know EFA at a high level, but you do not need deep configuration knowledge. Focus on recognizing this requirement: choose EFA when multiple EC2 instances that run an HPC or distributed machine learning workload require extremely low-latency, high-throughput communication.

2.8 Summary

In this lesson, you learned what EFA does:

  • Tightly coupled workloads: EFA helps large groups of virtual servers talk to each other very quickly and frequently.
  • High-scale operations: EFA helps machine learning training and simulations, such as weather models, keep scaling as more instances join the cluster.
  • No extra cost: EFA is available as an optional networking feature on supported EC2 instances, with no added pricing.
  • OS-bypass: EFA lets applications talk directly to the network hardware without going through the operating system kernel, which cuts down delay and CPU usage.
  • SRD protocol: EFA uses the custom Scalable Reliable Datagram protocol, which spreads data across multiple network paths and avoids overloaded ones.

3. Knowledge Check

Answer each question in your own words before you open the model answer. The questions were written for this course.

Question 1: What is an Elastic Fabric Adapter (EFA)?

Maps to: Objective 1 (Knowledge).

An EFA is a network device that you attach to Amazon EC2 instances to accelerate High Performance Computing (HPC) and machine learning (ML) applications. It lets applications that exchange data between many instances run at scale, with low latency and high throughput.

Question 2: In what two ways can you add an EFA to an instance, and which way cannot have an IP address?

Maps to: Objective 1 (Knowledge and Comprehension).

You can use an EFA with ENA, which gives the instance both an EFA device and an ENA device, or an EFA-only interface, which has just the EFA device. You cannot assign an IP address to an EFA-only interface. You can add an EFA when you launch an instance, or attach one to a supported instance that is stopped, but not to a running instance.

Question 3: Name two HPC use cases and two distributed machine learning use cases for EFA.

Maps to: Objective 2 (Knowledge and Comprehension).

HPC: computational fluid dynamics, weather and climate modeling, and molecular dynamics. Distributed machine learning: large language model training across several nodes, and GPU-to-GPU communication in a parameter server architecture, for example with AllReduce.

Question 4: Explain OS-bypass and the Scalable Reliable Datagram (SRD) protocol, and say how they differ from the standard ENA path.

Maps to: Objective 3 (Comprehension and Analysis).

With ENA, data passes through the TCP/IP stack in the operating system kernel. With OS-bypass, the application talks to the EFA device through Libfabric, without the kernel TCP/IP stack, which lowers latency and CPU work. TCP delivers packets in order and can suffer head-of-line blocking. SRD delivers packets reliably but not in order, and it spreads traffic across many network paths, so one delayed packet does not hold back the others.

Question 5: A company runs a public website and a tightly coupled weather simulation. Which one needs EFA, which one needs ENA, and why?

Maps to: Objective 4 (Analysis).

The weather simulation needs EFA, because its instances constantly exchange data and need very low latency and high throughput. The website needs only ENA, the standard device for general networking, because it does not depend on constant low-latency communication between instances.

Question 6: An engineering team runs a computational fluid dynamics solver on 40 EC2 instances. Which networking design do you recommend, and what do you need to set up?

Maps to: Objective 4 (Evaluation).

Recommend EFA on supported instance types, in a cluster placement group in one Availability Zone. The security group needs a self-referencing rule that allows all inbound and outbound traffic to itself. The setup order is: create the security group, launch a temporary instance with EFA, install the EFA software, finish and test the setup, create an EFA-enabled AMI, launch the cluster, and then clean up and connect the instances.

Question 7: Does EFA cost extra, and how much do you need to know about it for the SAA-C03 exam?

Maps to: Objectives 1 and 4 (Comprehension).

AWS does not charge extra for EFA. You pay only for the instances and the other resources that you use. EFA is not named separately in the SAA-C03 in-scope list, but Amazon EC2 is in scope and the list is non-exhaustive, so know EFA at a high level: choose it when instances in an HPC or distributed machine learning workload need extremely low-latency, high-throughput communication.
