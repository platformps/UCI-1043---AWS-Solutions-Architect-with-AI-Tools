1.1 Introduction to Amazon Q

Amazon Q is a family of generative AI assistants. It is designed to support both business operations and technical software engineering across AWS environments. It provides specialized assistance for work that employees, developers, and users of selected AWS services perform.

Amazon Q can answer questions about best practices for building solutions, troubleshooting issues, and identifying next steps. Amazon Q is the product family name, and each offering targets a different type of work:

Role-based variantType of assistantWhat it supports
Amazon Q BusinessEnterprise knowledge assistantAnswers questions and completes tasks by using authorized company content.
Amazon Q DeveloperSoftware and AWS assistantSupports coding, testing, troubleshooting, security scanning, and modernization.
Amazon Q in AWS servicesEmbedded assistanceAdds natural-language capabilities to services such as QuickSight, Connect, and Supply Chain.

Current Status

AWS has changed the availability of several Amazon Q offerings. Amazon Q Business is no longer open to new customers, and AWS points to Amazon Quick for similar capabilities. Amazon Q Developer IDE plugins and paid subscriptions reach end of support on April 30, 2027, and Amazon Q Developer in the AWS Management Console is not affected. Check the AWS documentation for the status of the Amazon Q experiences that are built into other AWS services. See Amazon Q Business availability change and Amazon Q Developer end-of-support announcement.

1.2 Amazon Q AI Chat Assistant

The phrase “AI Chat Assistant” describes the conversational experience, not a separate AWS service name.

1.2.1 How a Chat Answers a Question

A user asks a question in natural language. Then:

  • The assistant interprets the request and uses the context available to it.
  • It may retrieve authorized enterprise information or AWS guidance.
  • It generates an answer, summary, recommendation, or requested artifact.
  • The user must verify important output before acting on it.

The Amazon Q AI Chat Assistant is tailored for enterprise knowledge workers, operations teams, and business analysts. It enables users to search internal corporate data, synthesize complex information, ask questions, and run multi-step business tasks.

Chat is the interface. The product and connected data determine what the assistant can do.

1.2.2 Key Capabilities and Features

  • Conversational intelligence: answers complex queries, synthesizes data across multiple documents, and creates summaries of long reports or company policies.
  • Content generation and automation: drafts communications, memos, executive summaries, and reports that follow organization guidelines.
  • Enterprise security and ACL respect: strictly enforces existing user permissions and Access Control Lists (ACLs), so that users receive only the data that they are authorized to view.
  • Custom actions and plugins: supports custom plugins that connect to enterprise REST APIs and third-party software for automated workflows.
  • AWS Console and operations assistance: recommends EC2 instances based on workloads, troubleshoots AWS Console errors across EC2, S3, and Lambda, assists with network connectivity troubleshooting, and conducts cost analysis in AWS Cost Explorer.

1.2.3 Chatting About Your Network Security

Amazon Q can help you analyze your network security configurations, identify missing or misconfigured AWS network security services, and give recommendations for a stronger network security posture. This helps you understand network security findings, apply remediation steps, and follow security best practices without interrupting your workflow.

When you ask Amazon Q about your network security, its responses include specific information about your resources, related security findings, and detailed remediation instructions, together with links to learn more in the AWS Management Console.

Example questions that you can ask Amazon Q about network security:

  • Identify my top network security findings.
  • Summarize the network security of my environment.
  • Are my systems at risk of DDoS attacks?
  • How can I improve my network security?
  • Do I have any resources without WAF protection?
  • Which resources are not protected from common web vulnerabilities?
  • What are the common network security issues on my EC2 instances?
  • Do I have any WAF WebACLs that are not protecting anything?

2.1 Amazon Q Developer

Amazon Q Developer is a generative AI assistant that is purpose-built to help software developers, DevOps engineers, solutions architects, and AWS cloud environments. It can:

  • Generate and explain code.
  • Write tests and documentation.
  • Debug and refactor applications.
  • Scan code and recommend security fixes.
  • Troubleshoot AWS resources and operational issues.
  • Transform and modernize applications.

What Is Changing

Amazon Q Developer IDE plugins and paid subscriptions reach end of support on April 30, 2027, and AWS directs developers to Kiro. New Amazon Q Developer accounts and subscriptions have been blocked since May 15, 2026. Amazon Q Developer in the AWS Management Console and the other first-party AWS experiences are not affected.

2.1.1 Key Capabilities and Features

  • Domain-expert AI agent: answers architectural questions and explains AWS service configurations. Operational investigation helps investigate AWS resource health and resolve cloud operational issues.
  • IDE and CLI, code generation and explanation: generates inline code suggestions, explains unfamiliar codebases, and writes tests. Vulnerability scanning and debugging scans applications for security vulnerabilities and assists in debugging runtime errors. Application modernization assists in upgrading runtime environments and updating legacy applications.
  • Multi-functional team collaboration: enables the sharing of code insights, architectural designs, and automated solution workflows across development, security, and operations teams.

2.2 How to Use Amazon Q Developer

Amazon Q Developer is directly integrated into the following:

  • The AWS Management Console.
  • Integrated Development Environments (IDEs), such as Visual Studio Code.
  • The Command Line Interface (CLI) and chat environments.

Reference: Setup Kiro and Amazon Q Developer Authentication with IAM Identity Center SSO.

2.2.1 Example 1: Troubleshooting an AccessDenied Error

A software application throws an AccessDenied error when it tries to read an S3 object. The developer asks Amazon Q Developer to analyze the error trace. Amazon Q identifies the missing IAM permission and generates a least-privilege IAM policy snippet for the developer to review and apply.

Example prompt for Amazon Q:

I'm getting an AccessDenied error when trying to read an S3 object from my application. Here is the error trace: [paste error trace]. Can you help me fix this?

2.2.2 Example 2: Legacy Code Modernization

An enterprise needs to upgrade a legacy Java 8 microservice to Java 17 to meet security compliance standards. The developer uses Amazon Q Developer in VS Code to analyze the codebase, identify deprecated dependencies, automatically refactor syntax, and generate updated unit tests.

Example prompt for Amazon Q:

/transform Upgrade this Java 8 project to Java 17, update deprecated library calls, and ensure all existing unit tests pass.

Availability of Code Transformation

Java upgrades and .NET porting are delivered through the Amazon Q Developer IDE plugins. They require a paid Amazon Q Developer subscription, and they will no longer be accessible after April 30, 2027. AWS recommends AWS Transform custom for Java upgrades. See the end-of-support announcement.

3.1 Kiro

Kiro is an agentic software-engineering environment and automation tool for developers and technical teams that work in IDEs and CLI (terminal) environments. Unlike traditional chat tools, Kiro provides structured, spec-driven development workflows.

Kiro also includes the capabilities that developers used in Amazon Q Developer: agentic coding, inline chat, terminal integration, and MCP support. See the end-of-support announcement.

3.1.1 Key Architecture and Concepts

  • Specs: transform raw functional requirements into structured technical designs and actionable implementation tasks.
  • Steering: maintains persistent project standards, architecture rules, and continuous development instructions.
  • Hooks: trigger automatic agent actions when specific development events take place.
  • MCP integration: connects the agent directly to external tools, APIs, and systems.
  • Custom agents: allow the creation of specialized agents that are tailored to specific repository workflows.
  • Checkpoints: enable developers to review, restore, or branch from earlier development states.

Kiro focuses on structured delivery from concept to production code.

The Kiro documentation describes checkpoints as snapshots of your files that you restore when you go back to an earlier point in a session. It marks checkpoints as experimental in the IDE, and says that they are not available in Kiro CLI 3.0. See Checkpoints and rewind.

3.1.2 Multi-Surface Availability

Kiro is available in IDEs and Command Line Interfaces (CLI). Web and Mobile versions are in Preview, and Kiro also supports automated background agent workflows. See the Kiro documentation for the current list of surfaces.

3.2 Kiro Specs Formalize the Development Process

A spec moves a feature through four stages. Specs make assumptions visible before the agent writes large amounts of code.

StageNameWhat it holds
01RequirementsUser stories, acceptance criteria, constraints, and expected behavior.
02DesignArchitecture, interfaces, data models, dependencies, and technical decisions.
03TasksSequenced implementation work that is linked to the requirements and the design.
04ImplementationAgent-assisted coding, with reviewable progress and changes.

4.2 Additional Prompt Examples

The templates below are prompts for interacting with Amazon Q in the AWS Management Console across four operational domains. Each prompt states a role, a context, a task, and requirements.

4.2.1 AWS Console Diagnostic and Troubleshooting Prompt

Role: AWS Operations & Troubleshooting Expert

Context: I am receiving an error in the AWS Console while attempting to launch or configure resources.

Task: Analyze the following AWS Management Console error message and provide a step-by-step resolution.

Error Message: "Client.UnauthorizedOperation: You are not authorized to perform this operation. Encrypted message: [Paste Encrypted Error Message or Error Code Here]"

Requirements:
1. Decode/explain the root cause of this error.
2. Identify the exact IAM permissions (Action, Resource, Condition) required to resolve it.
3. Provide an example JSON IAM Policy snippet to grant the minimum necessary permissions under the principle of least privilege.

4.2.2 Infrastructure Architecture and Service Guidance Prompt

Role: AWS Certified Solutions Architect

Context: I am designing a web application in the AWS Management Console and need architecture guidance based on AWS Well-Architected Framework best practices.

Scenario: A high-traffic REST API backed by a database needs high availability, sub-second latency, and automatic cross-region disaster recovery.

Task:
1. Recommend the optimal AWS managed services to build this architecture using the console.
2. Provide a step-by-step console setup workflow (e.g., API Gateway -> AWS Lambda -> Amazon Aurora Global Database).
3. Highlight key configuration parameters in the console (e.g., Multi-AZ, Auto Scaling triggers, backup windows) to ensure high availability and compliance.

4.2.3 Cost Analysis and Resource Optimization Prompt

Role: AWS FinOps & Cost Optimization Specialist

Context: I am reviewing current usage and spending trends in the AWS Management Console / Cost Explorer.

Task: Help me audit and reduce monthly costs for my AWS account.

Prompt Input:
"Analyze my current running EC2 instances, EBS volumes, and S3 storage classes to identify potential cost savings."

Requirements:
1. List specific console dashboards or Cost Explorer filters to pinpoint idle resources (e.g., unattached EBS volumes, unassociated Elastic IPs).
2. Outline recommended actions (e.g., migrating to S3 Glacier, rightsizing EC2 instances, leveraging Savings Plans vs. Reserved Instances).
3. Provide step-by-step instructions for implementing these savings directly through the AWS Console.

4.2.4 Security and Compliance Enforcement Prompt (SCP and IAM)

Role: AWS Cloud Security Engineer

Context: I need to enforce governance across multiple member accounts using AWS Organizations in the console.

Task: Generate a Service Control Policy (SCP) and step-by-step console instructions to enforce data residency and restrict unauthorized regions.

Requirements:
1. Write a valid JSON SCP that denies all AWS API operations outside of region 'us-east-1', excluding necessary global services (IAM, Route 53, CloudFront).
2. Explain where and how to attach this policy in the AWS Organizations console (Root vs. OU level).
3. Explain how to verify that the policy is active using IAM Evaluation Logic.

4.2.5 Prompting Tips for Amazon Q in the AWS Console

  • Reference console context: Amazon Q can analyze resources in your current active Region and account. Include specific resource names or ARNs in your prompt, for example, “Why is EC2 instance i-0123456789abcdef0 failing its health check?”
  • Use action keywords: use verbs such as Troubleshoot, Generate JSON policy, Step-by-step console guide, or Audit to tell Amazon Q the exact output format that you need.

4.3 Hands-On Lab

Hands-On Lab

Lab Overview:

In this guided lab, you use the Amazon Q chat panel in the AWS Management Console to explore the Amazon AI chat assistant. You ask Amazon Q to explain IAM concepts, an IAM policy, an IAM role, and an access denied error, and then you check each answer against the AWS documentation, because you decide what access to grant, not the AI assistant. Estimated time: 30 minutes. Format: instructor demonstration with learners following along.

The goal of the lab is to show you how to work with Amazon Q chat, not to teach you IAM. Some steps use services that you have not learned yet, such as IAM Access Analyzer, trust policies, and AWS Lambda, so they might feel advanced. Follow your instructor’s demonstration, and focus on the prompts that you write and on how you verify each answer.

Lab purpose:

  • Describe the tool: describe what the Amazon Q chat panel can do in the console, and its limit on questions about account identity and security.
  • Use the tool: use the chat panel to explain IAM concepts, an IAM policy, a role trust policy, and an access denied error.
  • Compare: compare a least-privilege policy from Amazon Q with a reference policy, and identify the differences.
  • Assess: assess each answer from Amazon Q against the AWS documentation, and decide whether it is correct, partly correct, or wrong.
  • Justify: justify which suggestions from Amazon Q to accept, change, or reject.

4.5 Lesson Summary

In this lesson, you learned the following:

  • Amazon Q is the family name of a set of generative AI assistants, and each offering targets a different type of work: enterprise knowledge work, software and AWS work, and embedded assistance in AWS services.
  • An Amazon Q chat interprets a request, uses the context and permissions available to it, may retrieve authorized information or AWS guidance, and generates an answer. The user must verify important output before acting on it.
  • Amazon Q Developer helps with code generation, debugging, security scanning, modernization, and AWS troubleshooting. Its IDE plugins and paid subscriptions reach end of support on April 30, 2027, and Amazon Q Developer in the AWS Management Console is not affected.
  • Amazon Q Business is no longer open to new customers, and AWS points to Amazon Quick for similar capabilities.
  • Kiro is an agentic, spec-driven environment. It uses specs, steering, hooks, MCP integration, custom agents, and checkpoints, and it is available in IDEs and the CLI, with Web and Mobile in Preview.
  • A good prompt states a role, a context, a task, and requirements.

5. Knowledge Check

Answer each question in your own words before you open the model answer. The questions were written for this course.

Question 1: Describe the Amazon Q family of AI assistants and the type of work that each one supports.

Maps to: Objective 1 (Comprehension).

Amazon Q is the product family name, and each offering targets a different type of work. Amazon Q Business is an enterprise knowledge assistant that answers questions and completes tasks by using authorized company content. Amazon Q Developer is a software and AWS assistant that supports coding, testing, troubleshooting, security scanning, and modernization. Amazon Q in AWS services adds natural-language help inside other AWS services. AWS has since closed Amazon Q Business to new customers, and it points to Amazon Quick for similar capabilities.

Question 2: Explain how an Amazon Q chat answers a question, and why the user must verify important output.

Maps to: Objective 2 (Comprehension and Evaluation).

The user asks a question in natural language. The assistant interprets the request and uses the context and permissions that are available to it, and it may retrieve authorized enterprise information or AWS guidance. It then generates an answer, a summary, a recommendation, or a requested draft. The assistant can be wrong, and it can explain and suggest but it does not decide, so the user must verify important output, for example against the AWS documentation, before acting on it.

Question 3: Identify the main capabilities of Amazon Q Developer, and say what is changing for it.

Maps to: Objective 3 (Knowledge).

Amazon Q Developer generates and explains code, writes tests and documentation, debugs and refactors applications, scans code and recommends security fixes, troubleshoots AWS resources and operational issues, and helps modernize applications. Its IDE plugins and paid subscriptions reach end of support on April 30, 2027, and AWS directs developers to Kiro. Amazon Q Developer in the AWS Management Console is not affected.

Question 4: Describe how Kiro uses specs, steering, hooks, and checkpoints.

Maps to: Objective 4 (Comprehension).

Specs turn requirements into a design and implementation tasks, so that assumptions are visible before code is written. Steering keeps persistent project standards and rules across sessions. Hooks trigger automatic agent actions when development events, such as a file save, take place. Checkpoints let developers review and restore earlier states.

Question 5: Compare the Amazon Q AI Chat Assistant, Amazon Q Developer, and Kiro by audience, environment, and capabilities.

Maps to: Objective 5 (Analysis).

The chat assistant serves enterprise knowledge workers and business operations, in the console, web chat, and enterprise apps, for search, synthesis, and drafting with permission-bound access. Amazon Q Developer serves developers and cloud architects, in IDEs, the console, and the terminal, for code suggestions, scans, and troubleshooting. Kiro serves software engineers and automation architects, in IDEs, the CLI, and Web and Mobile previews, for spec-driven, agentic development with hooks, checkpoints, and custom agents.

Question 6: RetailCloud has three requests: an HR question about parental leave, an AccessDenied error in an application, and a new authentication feature that needs requirements, a design, and tests. Which assistant do you choose for each, and why?

Maps to: Objective 5 (Application and Evaluation).

Use the enterprise Amazon Q chat assistant for the HR question, because it searches authorized company documents and respects permissions. Use Amazon Q Developer for the AccessDenied error, because it can analyze the error trace and suggest a least-privilege policy to review. Use Kiro for the authentication feature, because its specs turn requirements into a design and tasks, and it verifies the code against the specification. In each case the user verifies the output before acting on it.
