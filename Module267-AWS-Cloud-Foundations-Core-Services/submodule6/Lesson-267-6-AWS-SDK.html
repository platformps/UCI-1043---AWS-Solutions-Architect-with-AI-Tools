1. AWS SDK Basics

Problem Statement

You have joined RetailCloud, an online retail company, as a cloud developer. The company has a web application that receives customer orders. Today, someone enters each order by hand in the AWS Management Console, which is slow and does not scale.

The lead architect asks you to find out how the application can talk to AWS services directly from its own code.

Your challenge:

  • Explain what an AWS SDK is.
  • Compare the SDK with the console, the CLI, and the API.
  • Describe how an SDK request flows from the application to the AWS service.

1.1 Introduction to the AWS Software Development Kit (SDK)

An AWS Software Development Kit (AWS SDK) is a collection of programming libraries and tools that lets developers interact with AWS services directly from application code. Instead of managing AWS resources manually through the Management Console, or entering AWS CLI commands, a developer can use an AWS SDK to program AWS services in a familiar programming language.

AWS provides SDKs for languages such as Python, Java, JavaScript and TypeScript, .NET, PHP, Ruby, and more. For example, the AWS SDK for Python is commonly called Boto3.

1.2 What Can an AWS SDK Do?

Applications can use AWS SDKs to:

  • Upload and download objects from Amazon S3.
  • Read and write items in DynamoDB.
  • Send messages to Amazon SQS.
  • Publish notifications through Amazon SNS.
  • Invoke Lambda functions.
  • Start or stop EC2 instances.
  • Retrieve secrets from AWS Secrets Manager.
  • Access AWS service APIs.
  • Handle AWS authentication, requests, responses, retries, and errors.

1.3 How an AWS SDK Works

When an application uses an AWS SDK:

  1. The application obtains AWS credentials.
  2. The SDK creates a request to an AWS service API.
  3. IAM evaluates whether the identity has permission.
  4. The AWS service processes an authorized request.
  5. The SDK returns the result to the application.

The SDK does not provide permissions by itself. The application receives permissions from the IAM user or role whose credentials it uses.

2. Boto3 and Credentials

Problem Statement

RetailCloud’s web application must save every customer order in a DynamoDB table named CustomerOrders. The application runs on Amazon EC2, and the security team does not allow access keys in source code.

The architect shows a Boto3 example, and explains how the application gets its permissions safely.

Your challenge:

  • Read a Boto3 example that calls an AWS service.
  • Explain how an application on EC2 gets credentials without stored keys.
  • Apply the credential best practices.

2.1 AWS SDK for Python Example

The following Python code uses Boto3 to upload a file to Amazon S3:

import boto3
s3 = boto3.client("s3")
s3.upload_file(
    "daily-sales.csv",
    "company-report-backups",
    "daily/daily-sales.csv"
)
print("Report uploaded successfully.")

This example:

  • Imports the Boto3 library.
  • Creates an S3 service client.
  • Uploads the local file to an S3 bucket.
  • Stores the object inside the daily prefix.

The application’s IAM role must allow the s3:PutObject action for the destination.

The SDK also needs an AWS Region. You can set it with the region_name parameter in code, with the AWS_DEFAULT_REGION environment variable, or in the AWS config file. For example:

s3 = boto3.client("s3", region_name="us-east-1")

2.2 Real-World Scenario: Processing Customer Orders

2.2.1 Business Situation

You have joined an online retail company as a cloud developer. The company has a web application that receives customer orders. Each order must be saved in a DynamoDB table named CustomerOrders.

2.2.2 AWS SDK Solution

The application uses Boto3 to send the order directly to DynamoDB:

import boto3
dynamodb = boto3.resource("dynamodb")
table = dynamodb.Table("CustomerOrders")
table.put_item(
    Item={
        "OrderId": "ORD-1001",
        "CustomerId": "CUST-205",
        "Product": "Laptop",
        "Quantity": 1,
        "Status": "Received"
    }
)
print("Order saved successfully.")

2.2.3 Authentication Solution

If the application runs on Amazon EC2, the architect attaches an IAM role to the instance. The role allows the required DynamoDB action. For example, this permission lets the application save items in the table:

{
  "Effect": "Allow",
  "Action": "dynamodb:PutItem",
  "Resource": "arn:aws:dynamodb:us-east-1:123456789012:table/CustomerOrders"
}

The SDK automatically obtains temporary credentials from the EC2 role. The developer does not need to place access keys in the program.

2.2.4 Expected Outcome

Each customer order is stored as an item in the DynamoDB table. The application can process orders automatically, without an employee manually entering data through the AWS Management Console.

2.3 Credential Best Practices

  • Use IAM roles and temporary credentials.
  • Do not hard-code access keys in source code.
  • Do not upload credentials to GitHub or other repositories.
  • Assign only the permissions that the application requires.
  • Use separate roles for separate workloads.
  • Use AWS Secrets Manager for application secrets, such as database passwords.
  • Rotate credentials when long-term credentials cannot be avoided.
  • Monitor API activity with AWS CloudTrail.

2.5 Lesson Summary

In this lesson, you learned the following:

  • An AWS SDK is a collection of programming libraries and tools that lets application code interact with AWS services, in languages such as Python, Java, JavaScript and TypeScript, .NET, PHP, and Ruby.
  • Boto3 is the AWS SDK for Python.
  • Applications use AWS SDKs to work with services such as Amazon S3, Amazon DynamoDB, Amazon SQS, Amazon SNS, AWS Lambda, Amazon EC2, and AWS Secrets Manager.
  • An SDK request has five steps: the application obtains credentials, the SDK creates a request to a service API, IAM evaluates permission, the service processes an authorized request, and the SDK returns the result.
  • The SDK does not provide permissions by itself. The application receives permissions from the IAM user or role whose credentials it uses.
  • The AWS Management Console, AWS CLI, AWS SDK, and AWS API are all subject to IAM authorization. The console suits manual work, the AWS CLI suits scripts, the SDK integrates services into application code, and the API holds the underlying operations.
  • The credential best practices are to use IAM roles and temporary credentials, not to hard-code or upload access keys, to assign only the permissions that the application requires, to use separate roles for separate workloads, to use AWS Secrets Manager for application secrets, and to monitor API activity with AWS CloudTrail.

Question 2: Compare the AWS Management Console, the AWS CLI, the AWS SDK, and the AWS API. What do all four have in common?

For example, upload and download objects in Amazon S3, read and write items in DynamoDB, send messages to Amazon SQS, publish notifications through Amazon SNS, invoke Lambda functions, start or stop EC2 instances, and retrieve secrets from AWS Secrets Manager.

Question 4: Walk through the five steps of an SDK request, and say where IAM is involved.

Maps to: Objective 4 (Comprehension).

First, the application obtains AWS credentials. Second, the SDK creates a request to an AWS service API. Third, IAM evaluates whether the identity has permission. Fourth, the AWS service processes the authorized request. Fifth, the SDK returns the result to the application. IAM is involved in the third step.

Question 5: Explain what this Boto3 code does, and which IAM permission the application needs: s3 = boto3.client("s3"), then s3.upload_file("daily-sales.csv", "company-report-backups", "daily/daily-sales.csv").

Maps to: Objective 5 (Application).

The code imports Boto3, creates an S3 client, and uploads the local file daily-sales.csv to the company-report-backups bucket, where it is stored under the daily prefix. The application’s IAM role must allow the s3:PutObject action for that destination, and the SDK also needs a Region.

Question 6: A web application on EC2 must save orders in a DynamoDB table. How should it get its credentials, and which best practices apply?

Maps to: Objective 5 (Application).

Attach an IAM role to the EC2 instance that allows dynamodb:PutItem on the table, and let the SDK obtain temporary credentials from the role. Do not hard-code access keys or upload them to a repository. Assign only the permissions that the application requires, use separate roles for separate workloads, use AWS Secrets Manager for application secrets, and monitor API activity with AWS CloudTrail.

Question 7: Why does the SDK not provide permissions by itself, and what happens if the role lacks a permission?

Maps to: Objective 4 (Analysis).

The SDK only creates and sends requests. The permissions come from the IAM user or role whose credentials the application uses. If the role does not allow the action, IAM denies the request, and the application receives an access denied error.
