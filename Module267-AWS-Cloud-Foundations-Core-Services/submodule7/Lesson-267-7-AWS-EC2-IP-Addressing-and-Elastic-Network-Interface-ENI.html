1. EC2 IP Addressing

Problem Statement

RetailCloud runs a three-tier application: a public load balancer, private EC2 application servers, and a private RDS database. A developer also launches temporary test servers, and a partner company allows traffic only from one fixed IP address. Finance has noticed a new line for public IPv4 addresses on the AWS bill.

The architect must choose the right kind of IP address for each need, explain what happens to each address when an instance stops or restarts, and keep the cost under control.

Your challenge:

  • Compare private, public, and Elastic IP addresses.
  • Explain how each kind of address behaves when an instance changes state.
  • Allocate and associate an Elastic IP address, and say what public IPv4 addresses cost.

1.1 Amazon EC2 IP Addressing Overview

Instances in an Amazon Virtual Private Cloud (VPC) rely on specific IPv4 address types to communicate inside the network, to connect to the internet, and to keep an address mapping that does not change. In the diagram, Amazon EC2 instances in public subnets automatically receive public IPv4 addresses, because the auto-assign public IP setting is enabled.

1.2 Amazon EC2 Private IP Addresses

  • A private IP address is an internal IPv4 address that AWS assigns to an EC2 instance within the VPC network boundary. It comes from the RFC 1918 address space, for example 10.0.0.0/16, 172.31.0.0/16, or 192.168.0.0/16, and AWS assigns it from the IP address range of the instance’s subnet.
  • It is normally released when the instance is terminated.
  • Scope: private IPv4 addresses are reachable only within the VPC, peered VPCs, or connected on-premises networks, through AWS Site-to-Site VPN or AWS Direct Connect. They are not directly reachable from the public internet.
  • Lifecycle persistence: the primary private IP address stays associated with the instance when it is stopped, started, or hibernated. Secondary private IP addresses can be reassigned between compatible network interfaces.
  • Cost: free of charge.

1.2.1 Primary Use Cases

  • Communication between EC2 instances, for example between a web server and an internal database server, or between application and database servers.
  • Microservice API routing behind internal Application Load Balancers (ALBs).
  • Internal load balancing.
  • Communication with other private VPC resources.
  • Hybrid communication through VPN or Direct Connect.

1.2.2 Scenario

A three-tier application uses a public load balancer to receive customer requests, private EC2 application servers, and a private RDS database. The application servers communicate with the database through private IP addresses, which keeps internal traffic inside the VPC.

1.3 Amazon EC2 Public IP Addresses

  • A public IP address is a dynamically assigned IPv4 address from the AWS public IP pool. It lets an instance communicate directly with the public internet through an internet gateway (IGW). The address is not permanently owned by your AWS account.
  • The public IP address is mapped to the instance’s primary private IP address through network address translation.
  • For internet connectivity, the instance also needs a route to an internet gateway, appropriate security group rules, appropriate network ACL rules, and a public subnet configuration.
  • Lifecycle behavior: public IP addresses are ephemeral. When an EC2 instance is stopped or terminated, AWS releases its public IP address back to the general AWS public pool. When you start the instance again, AWS assigns a new public IP address. A reboot does not change the public IP address.
  • DNS resolution: AWS automatically generates a public DNS hostname. It resolves to the instance’s public IP address outside the VPC and to its private IP address inside the VPC.
  • Cost: standard AWS public IPv4 charges apply for each hour that the address is allocated.

1.3.1 Base Pricing Model

  • Rate: $0.005 per IP per hour, which is about $3.65 per month for one IP address. For example, 100 EC2 public IPs at $0.005 per IP per hour for 730 hours a month cost $365 a month.
  • Billing unit: AWS bills in hourly increments for each allocated or assigned public IPv4 address.
  • Free Tier: the AWS Free Tier for EC2 includes 750 hours of public IPv4 address usage per month for the first 12 months.

For more information, see View public IP insights.

1.3.2 Primary Use Cases and Scenario

  • Temporary access to instances during development or testing.
  • Direct public access for standalone web servers where static IP addresses are not strictly required.

A developer launches a temporary web server for testing. The instance receives a public IP address, so the developer can open the website from the internet. Because the server is temporary, it does not need a permanent IP address.

Note on SSH: from the internet, you can connect to an EC2 instance with SSH only through its public IP address or an Elastic IP address, because a private IP address is not reachable from the internet. From inside the VPC, or over a VPN or AWS Direct Connect, you can use the private IP address.

1.4 Amazon EC2 Elastic IP Addresses (EIPs)

  • An Elastic IP address (EIP) is a static, persistent public IPv4 address that is designed for dynamic cloud computing. AWS allocates it to your account at the Region level, and it stays bound to your account until you explicitly release it.
  • Lifecycle persistence: unlike an automatically assigned public IP address, an Elastic IP address does not change when you stop and restart an EC2 instance. It remains allocated to your account until you explicitly release it.

1.4.1 Elastic IP Address Pricing

AWS charges for every public IPv4 address, including Elastic IP addresses:

  • Rate: $0.005 per IP per hour, or about $3.65 per month at 730 hours.
  • In use or idle: the same rate applies whether the address is associated with a running instance or is not associated with any resource in your account.
  • When you no longer need an Elastic IP address, disassociate it from your instance and then release it, so that you do not keep paying for it. If you try to release an Elastic IP address that is still associated, AWS does not release it.

For more information, see New: AWS Public IPv4 Address Charge and Public IP Insights. These rates can vary by Region and change over time, so check the AWS pricing page for current information.

1.4.2 Primary Use Cases

  • A consistent public IP address for your EC2 instances, so that your applications stay reachable during instance failures or replacements.
  • Fixed public endpoints for domain names, such as DNS A records that point directly to an instance.
  • Allow-listed outgoing IP addresses for third-party firewall rules.

1.4.3 Scenario: Remapping and High Availability

You can quickly re-associate an Elastic IP address with another EC2 instance or Elastic Network Interface in the same AWS Region. If an instance fails, you can redirect traffic to a standby instance by remapping the Elastic IP address.

1.4.4 Capabilities of Elastic IP Addresses

Elastic IP addresses play a pivotal role in masking instance or software failures. You can quickly remap the address to another instance in your account, which keeps disruption to a minimum and maintains service continuity. You can also link the address to DNS records, so your domain points directly to your instance. This is useful for hosting websites or running domain-based services.

Because Elastic IP addresses are public IPv4 addresses, they let instances reach the internet and support tasks such as SSH or RDP access from your local machine. Their static nature makes them useful for internet-facing applications such as web servers, email servers, or VPNs. Their main capabilities are:

  • Static nature: a consistent public IP address for services that need a stable connection.
  • Failure masking: remap the address quickly to another instance in the account for resilience during instance or software failures.
  • DNS integration: link the address to DNS records so that domains point directly to instances.
  • Internet communication: a public address through which an instance can interact with the internet and allow remote access.
  • Operational flexibility: associate or re-associate the address with different EC2 instances for failover.
  • Control and security: keep control of the IP address even when it is not associated with any instance.

For more information, see Amazon EC2 instance IP addressing.

1.5 Allocating an Elastic IP Address

To allocate an Elastic IP address, follow these steps:

  1. Open the EC2 dashboard.
  2. Select the Elastic IPs section.
  3. Choose Allocate Elastic IP address, and choose Amazon’s pool of IPv4 addresses.

After a successful allocation, you might receive an IP address such as 35.173.92.86. The Elastic IP addresses page confirms the allocation:

1.5.1 Associating the Elastic IP Address With an Instance

After you allocate the address, associate it with your instance:

  1. In the EC2 console, select the allocated Elastic IP address.
  2. Choose Actions, and then choose Associate Elastic IP address.
  3. Choose to associate it with an instance (or a network interface), and select your instance. If the instance has several private IP addresses, specify the correct one. In this example, the instance has only one.

After you associate it, the instance’s public IP address shows as 35.173.92.86.

1.5.2 Verifying Connectivity

To verify that the Elastic IP address is associated and reachable, you can use the ping command. Use your own Elastic IP address in the command. The ping works only if the instance’s security group allows inbound ICMP echo requests.

1.6 IP Addresses and Instance State Changes

An Elastic IP address stays associated with an instance when you reboot it and when you stop and start it. To verify this, stop and start the instance, and confirm that the public IP address still shows as 35.173.92.86. An automatically assigned public IP address changes after a stop and start, so an application that needs a fixed address requires an Elastic IP address.

For an instance with a single network interface, each action affects the IP addresses as follows:

  • Reboot: the instance keeps its private IPv4 address, its public IPv4 address, and any associated Elastic IP address.
  • Stop and start: the instance keeps its private IPv4 address and any associated Elastic IP address. AWS releases an automatically assigned public IPv4 address when the instance stops and assigns a new one when the instance starts.
  • Terminate: AWS releases the private IPv4 address and any automatically assigned public IPv4 address. An associated Elastic IP address is disassociated, but it stays allocated to your account until you release it.

For more information, see Amazon EC2 instance IP addressing, Manage the IPv4 addresses for your EC2 instances, and Elastic IP addresses.

2. Elastic Network Interfaces

Problem Statement

RetailCloud’s public web server must accept customer traffic on port 80, but the security team does not want SSH open to the internet. Administrators connect from the company network over a VPN.

The architect must explain how a second network interface lets the instance keep public web traffic and private management traffic apart.

Your challenge:

  • Describe primary and secondary ENIs and their attributes.
  • Explain how separate ENIs separate web traffic from administrative access.
  • Use security group rules to control traffic on each ENI.

2.1 Introduction to the Elastic Network Interface (ENI)

In traditional IT infrastructure, each server had a network interface card installed in it. In AWS, the virtual equivalent is the Elastic Network Interface (ENI).

  • An ENI is a virtual network card that resources inside an Amazon VPC use. Every EC2 instance needs at least one ENI to communicate with other resources.
  • An ENI plays a role like a physical network interface card in a computer.
  • Each EC2 instance has one primary ENI, and you can attach secondary ENIs as well, depending on the instance type.
  • eth0, the primary interface: AWS creates it automatically when an EC2 instance launches. You cannot detach it from the instance.
  • eth1 and later, the secondary interfaces: you can create them independently. You can detach a secondary ENI and attach it to another EC2 instance in the same Availability Zone. Each ENI stays in the subnet where you created it, and the destination instance’s primary ENI can be in a different subnet, as long as it is in the same Availability Zone. See Create a network interface for your EC2 instance.
  • An ENI is bound to a single Availability Zone, and it cannot move across Availability Zones.

2.2 What Does an ENI Contain?

An ENI can have the following networking attributes:

  • A primary private IPv4 address.
  • One or more secondary private IPv4 addresses.
  • One Elastic IP address (IPv4) for each private IPv4 address.
  • One public IPv4 address.
  • IPv6 addresses.
  • One or more security groups.
  • A MAC address.
  • A source and destination check flag, which is a configurable setting.
  • A description.

These attributes stay associated with the ENI when you move a detachable ENI between EC2 instances. Route tables are not an ENI attribute. They belong to the subnet in which the ENI sits. For more information, see Elastic network interfaces.

2.3 Multiple ENI Scenarios

An EC2 network appliance may use two ENIs: ENI 1 connects to a public-facing subnet, and ENI 2 connects to a private application subnet. This configuration lets the appliance inspect or route traffic between different network segments. Multiple ENIs are useful for:

  • Virtual firewalls.
  • Network appliances.
  • Management networks.
  • Dual-homed instances.
  • Workload separation.
  • Network failover.

2.4 Example: Using Separate ENIs for Web and Management Traffic

Imagine a public-facing web server on an EC2 instance that uses separate network paths and access rules for application traffic and for administrative traffic. Both interfaces connect to the same EC2 instance. The architecture looks roughly like this:

The instance’s primary ENI, eth0, is in the public subnet. Its security group allows inbound HTTP traffic on TCP port 80 from the internet. For direct IPv4 access from the internet, the primary ENI needs an associated public IPv4 address or Elastic IP address, and the public subnet needs a route to an internet gateway. None of the security groups on this ENI allow inbound SSH.

Next, create a secondary ENI, eth1, in a private management subnet in the same Availability Zone as the EC2 instance. Associate the secondary ENI with a management security group that allows inbound SSH on TCP port 22 only from an approved source, such as the organization’s internal network connected through a VPN. Then attach the secondary ENI to the existing EC2 instance.

Make sure that the VPN and the subnet routes let administrators reach the management IP address and allow return traffic. Depending on the operating system, you may also need to configure the secondary interface’s private IP address and routing. Interface names such as eth0 and eth1 are examples, and the actual names can vary by operating system.

When you finish, the EC2 instance has two network interfaces:

  1. eth0, in the public subnet: the primary interface serves public HTTP traffic on TCP port 80.
  2. eth1, in the private subnet: the secondary interface receives administrative SSH traffic on port 22 from the approved internal network over the VPN. Administrators connect to its private management IP address. With the required routes configured, and no security group on the public-facing ENI that allows inbound SSH, this gives a separate management path without exposing SSH directly to the internet.

For more detailed examples, see Multiple network interfaces for your Amazon EC2 instances: creating a management network.

SAA-C03 exam note: if the requirement only says, “Manage EC2 securely without opening inbound SSH,” AWS Systems Manager Session Manager is usually the simpler and more secure answer. It can provide administrative access without a bastion host, a public IP address, or inbound port 22. A secondary ENI is appropriate when the requirement explicitly calls for network-level separation of management and application traffic.

2.5 Security Groups and ENI Permissions

Security groups control the network traffic that is allowed to enter and leave an Elastic Network Interface. They act as virtual firewalls for the resources that connect to the ENI.

2.5.1 Assigning Security Groups

When you create an ENI, you can assign one or more security groups to it, and you can change them after you create the ENI. This gives you flexibility when network access requirements change. For example, an EC2 instance can have a public ENI with a security group that allows web traffic, and a private ENI with a different security group that allows administrative traffic.

2.5.2 Inbound and Outbound Rules

Security groups use two types of rules: inbound rules control traffic that enters the ENI, and outbound rules control traffic that leaves it. A rule can identify permitted traffic by:

  • Protocol, such as TCP or UDP.
  • Port number, such as 22, 80, 443, or 3306.
  • Source or destination IP address.
  • Another security group.

Security groups contain only allow rules, and they do not support explicit deny rules. AWS blocks traffic when no rule allows it.

2.5.3 Modifying Security Groups

You can add, remove, or update security group rules at any time. AWS applies the changes automatically to all ENIs that use that security group. For example, to let an application server talk to a MySQL database, add an inbound rule to the database ENI’s security group that allows TCP port 3306 and uses the application server’s security group as the source. This is more secure than allowing database traffic from every IP address.

2.8 Conclusion

Understanding Amazon EC2 IP addressing and Elastic Network Interfaces is essential for designing secure, reliable, and highly available cloud architectures. When you use private IPs for internal communication, public IPs for temporary connectivity, and Elastic IPs for persistent public endpoints, you get smooth network routing and uninterrupted service access.

Elastic Network Interfaces add advanced networking designs, such as dual-homed instances and network-level separation of application and management traffic. When you combine these interfaces with tailored security group rules, organizations keep a strong security posture, good traffic flow, and operational efficiency across their AWS infrastructure.

3. Knowledge Check

Answer each question in your own words before you open the model answer. The questions were written for this course.

Question 1: What is the primary function of a private IPv4 address on an EC2 instance, and how does its lifecycle behave when the instance is stopped and started?

Maps to: Objective 1 (Comprehension).

A private IPv4 address is an internal address that AWS assigns from the subnet’s range. It lets the instance communicate with other resources inside the VPC, peered VPCs, and connected on-premises networks, and it is not reachable from the internet. The primary private IP address stays with the instance when it is stopped and started, and AWS releases it when the instance is terminated.

Question 2: Why is an automatically assigned public IPv4 address considered ephemeral?

Maps to: Objective 3 (Comprehension).

AWS takes it from the public pool, and your account does not own it. AWS releases it when the instance is stopped or terminated, and assigns a new address when the instance starts again. A reboot does not change it.

Question 3: How does an Elastic IP address differ from an automatically assigned public IP address in account ownership and persistence?

Maps to: Objective 2 (Analysis).

An Elastic IP address is allocated to your AWS account at the Region level and stays bound to the account until you release it, so it does not change when you stop and start the instance and you can move it to another instance. An automatically assigned public IP address does not belong to the account, and it changes after a stop and start.

Question 4: What does an EC2 instance with a public IP address need to communicate in both directions with the public internet?

Maps to: Objective 4 (Application).

The instance needs a public IP address, a route to an internet gateway, a public subnet configuration, appropriate security group rules, and appropriate network ACL rules.

Question 5: Describe the pricing model that AWS applies to public IPv4 addresses, including Elastic IP addresses.

Maps to: Objective 4 (Comprehension).

AWS charges $0.005 per public IPv4 address per hour, about $3.65 a month at 730 hours. The same rate applies to an in-use address and an idle Elastic IP address, and AWS bills in hourly increments. The EC2 Free Tier includes 750 hours of public IPv4 usage a month for the first 12 months, and rates can change, so check the pricing page.

Question 6: Why should you disassociate an Elastic IP address from an instance before you release it?

Maps to: Objective 5 (Application).

AWS does not release an Elastic IP address while it is associated with an instance. You disassociate it first and then release it. If you do not release it, the account keeps paying the hourly public IPv4 charge for the address.

Question 7: In a multi-tier application, which IP address type should the application servers use to talk to the database servers, and why?

Maps to: Objective 2 (Application).

Private IP addresses. They are free, they keep the traffic inside the VPC, and the database does not need to be reachable from the internet.

Question 8: Explain what an Elastic Network Interface is.

Maps to: Objective 6 (Comprehension).

An ENI is a virtual network card that resources in a VPC use, like a physical network interface card in a computer. Every EC2 instance has at least one ENI, the primary interface, and you can attach more, depending on the instance type. An ENI is bound to one Availability Zone, and a secondary ENI can be detached and attached to another instance in the same Availability Zone.

Question 9: List the networking attributes of an ENI.

Maps to: Objective 6 (Knowledge).

A primary private IPv4 address, secondary private IPv4 addresses, one Elastic IP address per private IPv4 address, one public IPv4 address, IPv6 addresses, one or more security groups, a MAC address, a source and destination check flag, and a description. These stay with the ENI when you move it to another instance.

Question 10: How do the primary interface (eth0) and secondary interfaces (eth1 and later) differ in creation, detachment, and lifecycle?

Maps to: Objective 6 (Analysis).

AWS creates eth0 automatically when the instance launches, and you cannot detach it. You can create secondary interfaces independently, detach them, and attach them to another instance in the same Availability Zone, and each one stays in the subnet where it was created.

Question 11: Can you detach an ENI from an instance in one Availability Zone and attach it to an instance in a different Availability Zone of the same Region? Explain.

Maps to: Objective 6 (Application).

No. An ENI is bound to a single Availability Zone, so it can only move between instances in that Availability Zone.

Question 12: Explain how two ENIs on one EC2 instance separate public web traffic from administrative SSH traffic, and give the security group rules for each interface.

Maps to: Objectives 7 and 8 (Synthesis).

Put eth0 in the public subnet, with a security group that allows inbound HTTP on TCP port 80 from the internet and no inbound SSH. Create eth1 in a private management subnet in the same Availability Zone, with a management security group that allows inbound SSH on TCP port 22 only from an approved source, such as the internal network over a VPN. Make sure that the VPN and routes work, and that the public-facing ENI allows no inbound SSH. If the requirement only asks for secure management without inbound SSH, Session Manager is usually simpler.
