Introduction

An EBS volume belongs to one instance in one Availability Zone, and an S3 bucket is accessed through an API, not through a drive letter or a path. Many applications need something else: a shared folder that several servers open at the same time, with the same files visible to all of them. That is file storage. AWS offers it as Amazon EFS for Linux workloads and as Amazon FSx for Windows, high performance computing, NetApp ONTAP, and OpenZFS workloads. An architect who passes SAA-C03 questions on storage needs to know which one fits which requirement.

This lesson assumes that you know the basics of Amazon EC2, Amazon EBS, and Amazon S3. It follows FlashCart Inc., an online store, through the Problem Statement of each tab.

Three terms appear often in this lesson:

  • File system: storage that organizes data as files in folders, which clients open through a path.
  • Mount: to attach a shared file system to a server so that it appears as a folder.
  • Throughput: the amount of data that a file system reads or writes each second.

1. Amazon EFS Basics

Problem Statement

FlashCart runs its web application on Linux EC2 instances in three Availability Zones behind a load balancer. The instances serve the same product images and the same content-management files, and editors upload new files every day. With EBS, each instance has its own copy, so a file that an editor uploads is missing on the other servers. Copying files between servers is slow and error-prone, and the team does not want to plan storage capacity. FlashCart needs one shared place that every server can open at the same time.

1.1 What File Storage Is

  • File storage keeps data as files in folders. A client opens a file through a path, and many clients can use the same folder at the same time.
  • Block storage (Amazon EBS) is a raw drive that is attached to one instance. Object storage (Amazon S3) keeps objects in a bucket that you reach through an API.
  • File storage fits applications that expect a shared folder: web servers, content management systems, home directories, and shared data sets.

1.2 What Amazon EFS Is

  • Amazon Elastic File System (Amazon EFS) is a managed Network File System (NFS) that you can mount on many EC2 instances at the same time.
  • EFS works with EC2 instances in several Availability Zones, so it is highly available.
  • EFS uses the NFS version 4.1 protocol, and it is a POSIX file system, which means that it follows the standard Linux file API.
  • EFS is for Linux instances. It is not for Windows instances. Use Amazon FSx for Windows File Server for Windows (tab 5).
  • EFS is serverless and elastic. The file system grows and shrinks as you add and remove files, so you do not plan capacity, and you pay for the storage that you use.
  • EFS works with most AWS compute services: Amazon EC2, Amazon ECS, Amazon EKS, AWS Fargate, AWS Lambda, and Amazon SageMaker.

1.4 Basic Amazon EFS Workflow

The basic workflow is:

  1. Create an EFS file system.
  2. Select Regional or One Zone availability.
  3. Create mount targets in the required VPC subnets.
  4. Associate security groups with the mount targets.
  5. Install an NFS client or the EFS mount helper.
  6. Mount the file system on the compute resource.
  7. Read and write files using normal file-system operations.

1.5 How Amazon EFS Works

Amazon EFS works by exposing a network file system endpoint, which uses the NFS protocol, that multiple compute services can mount at the same time. Once you create an EFS file system, you can attach it in real time to Amazon EC2 instances, to containers that run on Amazon ECS or Amazon EKS, and even to AWS Lambda functions through EFS access points. This allows many instances and services to read and write to a centralized, shared file system as if it were a local drive. EFS adjusts its capacity automatically as files are added or removed, so it needs no manual scaling. This elasticity keeps performance consistent as your storage needs grow.

Because of its broad integration with other AWS services and its ability to support hybrid cloud setups, EFS is a foundational component in many modern cloud architectures. In practice, you can mount EFS file systems on multiple EC2 instances, even across Availability Zones, to provide a common data source. The service is scalable and managed, so you do not have to worry about provisioning storage or planning capacity — Amazon EFS handles growth automatically behind the scenes.

1.6 EFS Use Cases

  • Content management systems (CMS), web servers, and web applications, for example a WordPress site whose servers share the same files.
  • Data sharing between many instances.
  • Containerized and serverless applications that need a persistent shared folder.
  • Machine learning training that reads shared data sets.
  • User home directories.
  • Data science and analytics workflows.
  • Media processing pipelines.
  • Lift-and-shift enterprise applications.

1.7 What Mount Targets Are

A mount target provides network access from a VPC to an EFS file system.

1.7.1 Mount-Target Components

Each mount target has:

  • A subnet.
  • An Availability Zone.
  • An elastic network interface.
  • A private IP address.
  • One or more security groups.
  • A DNS-access path.

For a Regional EFS file system, you can create a mount target in each Availability Zone that contains application clients.

1.7.2 Mounting an EFS File System

EFS can be mounted by using:

  • Amazon EFS mount helper.
  • Standard Linux NFS client.
  • EFS CSI driver for Kubernetes.
  • Container task definitions.
  • Lambda file-system configuration.

Mount-helper example

sudo mount -t efs -o tls fs-12345678:/ /mnt/efs

The command is an example. The file system ID in it is not a real file system.

1.8 How Clients Reach EFS

A client reaches an EFS file system over the network. The path depends on where the client runs: in the same VPC, in another VPC, or on premises.

1.8.1 Clients in the Same VPC: Mount Targets

  • To access an EFS file system in a VPC, you create one or more mount targets in the VPC. A mount target provides an IP address for an NFSv4 endpoint where you mount the file system.
  • You can create one mount target in each Availability Zone of the Region. If an Availability Zone has several subnets, you create the mount target in one of them, and all EC2 instances in that zone share it.
  • You mount the file system with its DNS name. The name resolves to the IP address of the mount target in the same Availability Zone as the instance.
  • For performance and cost, access the file system through the mount target in the same Availability Zone as the instance.
  • Mount targets are designed to be highly available. Their IP addresses and DNS names are static.
  • A file system can have mount targets in only one VPC at a time.
  • AWS recommends a current Linux NFSv4.1 client together with the EFS mount helper. After you mount the file system, you use it like any other file system.
  • A One Zone file system has only one mount target. An instance in another Availability Zone can still use it, but it pays EC2 data access charges for the traffic that crosses zones.

1.8.2 Clients in Another VPC and On-Premises Clients

  • Another VPC: instances in a different VPC, in the same Region or in another Region, can reach the file system over a VPC peering connection.
  • On premises: servers in your data center can mount the file system when they are connected to your VPC with AWS Direct Connect or AWS Site-to-Site VPN.
  • On-premises access is used to migrate data sets to EFS, to burst work to a fleet of EC2 instances in the cloud, and to back up on-premises data to EFS.
  • The on-premises server must run a Linux-based operating system. Linux kernel version 4.0 or later is recommended.
  • AWS recommends that you mount the file system from an on-premises server with the IP address of a mount target, not its DNS name.
  • Add a rule to the mount target security group that allows inbound NFS traffic on TCP port 2049 from the on-premises server (tab 4).
  • There is no additional cost for on-premises access to EFS. You pay for the Direct Connect connection.

2. EFS Storage Classes and Lifecycle

Problem Statement

FlashCart’s shared media folder holds 40 TB of product photos and campaign files. Editors open the files of the current month all day, but files that are older than a quarter are almost never opened. The development team also needs a cheap shared folder for tests, where losing the data in a failure would not matter. The finance team asks how to stop paying the full price for files that nobody opens.

2.1 File System Types: Regional and One Zone

Amazon EFS offers two types of file systems, so that you can balance durability and cost requirements:

TypeWhere the data is storedUse it for
Regional (Standard), recommendedRedundantly across multiple Availability Zones in the Region. It offers the highest durability and availability. If one Availability Zone goes down, the file system stays accessible from the other zones. It is designed for 11 nines (99.999999999 percent) of durability.Use Regional EFS when the workload requires:
  • Multi-AZ resilience.
  • Highly available shared storage.
  • Production application data.
  • Access from compute resources in multiple AZs.
  • Protection from a single-AZ failure.
One ZoneWithin a single Availability Zone. If that zone has an outage, the file system is unavailable, and the data may be lost if a disaster affects all copies of the data in the zone or destroys the zone.Non-critical or reproducible data, and development and test workloads that do not need multi-zone resilience. It lowers the storage cost by about 47 percent compared with the Regional Standard class (AWS figure, so check the pricing page).

Use One Zone when:
  • The application runs in one AZ.
  • The data is reproducible.
  • The workload does not require Multi-AZ resilience.
  • Lower storage cost is more important than AZ-level resilience.
  • Backups provide sufficient protection.
  • A One Zone file system has only one mount target, in its Availability Zone.
  • One Zone file systems always use the General Purpose performance mode (tab 3).

2.2 EFS Storage Classes

EFS storage classes match the cost of storage to how often you open a file:

  • EFS Standard: SSD storage that is designed for sub-millisecond latency. It holds active, frequently accessed data.
  • EFS Infrequent Access (EFS IA): cost-optimized for files that you open only a few times a quarter. It costs less to store a file, and you pay to read it.
  • EFS Archive: cost-optimized for long-lived data that you open a few times a year or less. It has performance similar to EFS IA, and it costs less to store than EFS IA.
  • Each class is available for Regional file systems. One Zone file systems also work with the infrequent access class, called EFS One Zone-IA.

2.3 Lifecycle Management: EFS Storage Classes

  • A lifecycle policy moves a file to a colder storage class when nobody has accessed it for a number of days.
  • For example, a policy can move files from Standard to Infrequent Access after 30 days without access, and from Infrequent Access to Archive after 90 days without access.
  • The EFS lifecycle policy setting Transition into IA automatically moves files from EFS Standard to EFS Standard-IA, the Infrequent Access class, if the files are not accessed for 30 days.
  • The EFS lifecycle policy setting TransitionToArchive automatically moves files to EFS Archive storage if the files are not accessed for 90 days.
  • The EFS lifecycle policy setting Transition to Standard is set to None by default.
  • You can also set a policy that moves a file back to Standard when somebody opens it.
  • Lifecycle management lowers the storage cost without a change to the application. The file stays in the same folder, and the path does not change.

2.4 Real-World Scenario: FlashCart’s Shared Media Library

This scenario follows the engineers as they choose the file system type, the storage classes, and the throughput mode for a shared media library. Use the Previous and Next buttons to move through the slides.

The Situation

  • FlashCart runs its web application on Linux EC2 instances in three Availability Zones.
  • All of the servers share 40 TB of product photos and campaign files on one Regional EFS file system, in the EFS Standard storage class.
  • Editors open the files of the current month all day.
  • Files that are older than a quarter are almost never opened.
  • A separate test environment needs its own shared folder, and losing its data would not matter.
  • The finance team asks the engineers to cut the storage bill without breaking the applications.

What the Team Finds

The team reviews when each file was last accessed. These figures are invented for this scenario.

Time since last accessShare of the dataBest storage class
Up to 30 days15 percentEFS Standard
30 to 90 days25 percentEFS Infrequent Access
More than 90 days60 percentEFS Archive
  • The production data must stay available if an Availability Zone fails.
  • The test data can be rebuilt, so it does not need that protection.

Decision 1: Which File System Type?

EnvironmentChoiceWhy
ProductionRegional file systemAWS recommends it for production. It stores data in several Availability Zones, so the file system stays accessible if one zone goes down.
TestOne Zone file systemIt lowers the storage cost. The risk is acceptable, because the team can rebuild the data if the zone has an outage.

Decision 2: Which Storage Classes?

  • Turn on lifecycle management for the production file system.
  • Move files to Infrequent Access after 30 days without access.
  • Move files to Archive after 90 days without access.
  • Set the policy so that a file returns to Standard when somebody opens it, if the team wants that.
  • The files stay in the same folders, so the applications and the paths do not change.
  • Reads from Infrequent Access and Archive carry an access charge, so the team keeps the files that people open often in Standard.

Decision 3: Performance and Throughput

  • Use the General Purpose performance mode. The web servers need low latency for small file reads.
  • Use Elastic throughput. The nightly media-processing job reads and writes a different amount of data every night, and the team does not want to guess a value.
  • Max I/O is not needed, and it does not work with Elastic throughput.

Result and Watch-Outs

  • Files move to colder classes by themselves as they age, so the storage cost falls as the share of cold data grows.
  • The web application keeps working, and the editors notice no change.
  • The test environment costs less on One Zone.

What the team keeps an eye on:

  • If people open old files often, the read charges can cancel the savings, so the team reviews the lifecycle policy.
  • The production file system needs backups and replication for protection (tab 4).
  • The team estimates the new cost with the AWS Pricing Calculator before it commits.

Exam Takeaways

  • Regional file systems are for production. One Zone file systems are for non-critical, reproducible, and development data.
  • Lifecycle management lowers the cost of files that nobody opens, without a change to the application.
  • Elastic throughput fits an unpredictable workload, and General Purpose fits latency-sensitive web serving.
  • Infrequent Access and Archive lower the storage price, but you pay per read.

3. EFS Performance and Throughput

Problem Statement

FlashCart’s web servers need fast responses for small file reads. Separately, the media team runs a nightly job that processes thousands of video files in parallel, and its load changes from night to night. The team asks which EFS performance mode and throughput mode to choose, because it cannot change some of these settings later.

3.1 EFS Scale

  • EFS supports thousands of concurrent NFS clients.
  • The file system grows to petabyte scale automatically, with no capacity planning.
  • You choose two settings: a performance mode and a throughput mode.

3.2 Performance Modes

You set the performance mode when you create the file system:

ModeWhat it givesUse it for
General Purpose (default)The lowest latency per operation. AWS recommends it for nearly every workload.Latency-sensitive use cases: web servers, content management systems, and home directories.
Max I/OHigher latency per operation, with higher aggregate throughput and a highly parallel design.Highly parallel workloads such as big data and media processing.
  • Max I/O is not supported for One Zone file systems or for file systems that use Elastic throughput.

3.3 Throughput Modes

The throughput mode decides how much data per second the file system can read and write:

ModeHow throughput is setUse it for
ElasticScales up and down automatically with the workload. You do not set it.Unpredictable or spiky workloads.
ProvisionedYou set the throughput, regardless of how much data is stored. You pay for the throughput that you provision.Workloads that need more throughput than the amount of stored data would give.
BurstingThroughput scales with the amount of data that you store, with bursts above the baseline.Workloads with steady needs that fit the size of the file system.
  • Elastic throughput is available only for file systems that use the General Purpose performance mode.

Exam-Style Question

Scenario: A company runs a data processing job on EFS. The amount of data that the job reads and writes changes a lot from day to day, and the company does not want to guess a throughput setting. Which throughput mode should the company use?

  • A. Elastic throughput.
  • B. Provisioned throughput set to the peak value.
  • C. Bursting throughput on a small file system.
  • D. Max I/O performance mode.
Show Answer and Explanation

Correct answer: A. Elastic throughput scales automatically up and down with the workload, so it fits unpredictable demand. Max I/O is a performance mode, not a throughput mode.

OptionResultReason
ACorrectElastic throughput follows the load without any setting.
BIncorrectProvisioned throughput set to the peak value would be paid for all the time, even when the job uses less.
CIncorrectBursting throughput scales with the size of the data, so a small file system gives low throughput.
DIncorrectMax I/O is a performance mode. It does not set throughput, and it does not work with Elastic throughput.

Exam Trap

Remember these three points:

  • Performance mode (General Purpose or Max I/O) and throughput mode (Elastic, Provisioned, or Bursting) are two different settings.
  • General Purpose is the default and is for latency-sensitive workloads. Max I/O trades latency for parallel throughput.
  • Elastic is for unpredictable workloads, and Provisioned is for a fixed throughput that is higher than the size of the data would give.

Memory Hook

Two settings: performance mode = latency or parallel. Throughput mode = elastic, provisioned, or bursting.

→ Elastic throughput

4. EFS Security, Access, and Data Protection

Problem Statement

FlashCart’s security team reviews the shared file system before it goes live. Only the web servers may reach it. Each of two applications must see only its own folder and must not run as root. All data must be encrypted, including data that moves across the network. The team also needs backups and a copy of the data in a second Region for disaster recovery.

4.1 Network Access

  • Clients reach EFS through mount targets. You create one mount target in each Availability Zone where clients run.
  • A security group on the mount targets controls the traffic. It must allow inbound NFS traffic on TCP port 2049 from the security group of the client instances.
  • Network ACLs and VPC routing also apply to the traffic.

4.2 Access Control: IAM and Access Points

  • IAM policies control which identities can mount and write to the file system.
  • Amazon EFS is POSIX-compliant, and it supports concurrent read and write access from multiple EC2 instances.
  • POSIX file permissions (owner, group, and mode) control access to individual files and folders.
  • An EFS access point is an application entry point into the file system. It enforces an operating system user and group, and a root directory, for every request that comes through it.
  • Access points let several applications share one file system, while each application sees only its own folder.

4.3 Encryption

  • Encryption at rest uses keys that are managed by AWS Key Management Service (AWS KMS).
  • Encryption in transit uses Transport Layer Security (TLS). You turn it on with the EFS mount helper, without a change to the application.
sudo mount -t efs -o tls fs-0123456789abcdef0:/ /mnt/efs

The command is an example. The file system ID in it is not a real file system.

4.4 Backup and Replication

  • AWS Backup backs up EFS file systems (tab 6). You set the schedule and the retention in a backup plan, and you can keep backups in another Region.
  • EFS Replication copies the data of a file system into another file system in a Region that you choose. Use it for disaster recovery.
  • A Regional file system stores data in several Availability Zones, so a zone failure does not stop access. Replication and backups protect against a Region problem and against deletion.

5. Amazon FSx

Problem Statement

FlashCart acquires a company whose finance team uses Windows servers and a Windows shared drive that is integrated with Active Directory. FlashCart’s data science team also needs a very fast file system to train machine learning models on data that sits in S3, and an engineering team wants to move a NetApp storage system to AWS. EFS does not fit any of these. The team needs to know what else AWS offers for file storage.

5.1 What Amazon FSx Is

  • Amazon FSx lets you launch third-party, high-performance file systems on AWS. It is a fully managed service.
  • You choose from four file systems: FSx for Windows File Server, FSx for Lustre, FSx for NetApp ONTAP, and FSx for OpenZFS.
  • Unlike EFS, which is for Linux, FSx works with Windows and other operating systems.

5.2 Amazon FSx for Windows File Server

  • A fully managed, reliable, and scalable Windows shared file system that uses Windows File Server. It supports the SMB protocol and the Windows NTFS file system.
  • It integrates with Microsoft Active Directory, and it supports ACLs and user quotas.
  • You can mount it on Linux EC2 instances too.
  • It supports Microsoft Distributed File System (DFS) Namespaces, which group files across several file systems.
  • Storage options: SSD for latency-sensitive workloads such as databases, media processing, and data analytics, and HDD for a broad range of workloads such as home directories and content management.
  • It is accessible across VPCs, across AWS Regions, and across accounts.
  • You can reach it from on premises over a VPN or AWS Direct Connect. You can configure it as Multi-AZ for high availability, and AWS backs up its data daily to Amazon S3.

5.3 Amazon FSx for Lustre

  • Lustre is a parallel distributed file system for large-scale computing. The name comes from “Linux” and “cluster”.
  • Use cases: machine learning, high performance computing (HPC), video processing, financial modeling, and electronic design automation.
  • It scales to hundreds of GB per second and millions of IOPS, with sub-millisecond latencies.
  • Storage options: SSD for low-latency, IOPS-intensive workloads with small, random file operations, and HDD for throughput-intensive workloads with large, sequential file operations.
  • It integrates with Amazon S3. The file system can read S3 data as files, and it can write the results of the computation back to S3.
  • You can use it from on-premises servers over a VPN or AWS Direct Connect.

5.3.1 Lustre Deployment Options

OptionWhat it meansUse it for
Scratch file systemTemporary storage. The data is not replicated, so it does not persist if the file server fails. It has high burst throughput.Short-term processing, and to optimize cost.
Persistent file systemLong-term storage. The data is replicated within the same Availability Zone, and failed files are replaced within minutes.Long-term processing and sensitive data.

5.4 Amazon FSx for NetApp ONTAP

  • A managed NetApp ONTAP file system on AWS. It is compatible with NFS, SMB, and iSCSI.
  • Use it to move workloads that run on ONTAP or on a NAS to AWS.
  • It works with Linux, Windows, macOS, VMware Cloud on AWS, Amazon WorkSpaces, Amazon AppStream 2.0, and Amazon EC2, ECS, and EKS.
  • Storage shrinks or grows automatically.
  • Features: snapshots, replication, low cost, compression, data de-duplication, and point-in-time instantaneous cloning, which helps when you test new workloads.

5.5 Amazon FSx for OpenZFS

  • A managed OpenZFS file system on AWS. It is compatible with NFS (versions 3, 4, 4.1, and 4.2).
  • Use it to move workloads that run on ZFS to AWS.
  • It works with Linux, Windows, macOS, VMware Cloud on AWS, Amazon WorkSpaces, Amazon AppStream 2.0, and Amazon EC2, ECS, and EKS.
  • It offers up to 1,000,000 IOPS with latency below 0.5 ms.
  • Features: snapshots, compression, low cost, and point-in-time instantaneous cloning.

6. AWS Backup

Problem Statement

FlashCart protects its data in many different ways. One team runs scripts that copy files from the shared EFS file system, another relies on EBS snapshots that it takes by hand, and the Windows file server and the S3 buckets have no regular backup at all. Auditors ask for proof of a daily backup that is kept for 35 days and copied to a second Region. The security team also worries that a ransomware attack could delete the backups. FlashCart needs one policy that protects all of these resources and that nobody can quietly turn off.

6.1 What Problem AWS Backup Resolves

  • Decentralized management: each AWS service has its own backup mechanism.
  • Manual orchestration: teams use custom scripts or manual processes to manage the backups.
  • Compliance and audit issues: it is difficult to enforce consistent backup policies.
  • Solution: AWS Backup provides a centralized, policy-based approach.

6.2 What AWS Backup Is

  • AWS Backup is a fully managed, centralized, policy-based backup service. It automates and standardizes data protection across AWS services.
  • It supports many resources, including Amazon EBS volumes, Amazon EC2 instances, Amazon EFS file systems, Amazon FSx file systems, Amazon S3 buckets, Amazon RDS and Amazon Aurora databases, Amazon DynamoDB tables, and AWS Storage Gateway volumes.
  • You manage the backups of all of these services from one place, and you do not write backup scripts.
  • The backups have storage and encryption that are independent from the source data.
  • For services that have their own backup features, such as EBS snapshots and RDS snapshots, AWS Backup works with those features.

6.3 AWS Backup Features

6.4.1 What Services Can Be Backed Up via AWS Backup

6.4.2 AWS Backup for File Storage

  • For Amazon EFS, AWS Backup creates the backups of the file system (tab 4). EFS recovery points can use cold storage.
  • For Amazon FSx, AWS Backup protects the file systems, and you can copy the backups to another Region or account.
  • For Amazon S3 and Amazon EBS, AWS Backup protects buckets and volumes with the same plan, so that one policy covers block, file, and object data.

6.5 Core Concepts

ConceptWhat it is
Backup planThe policy that defines your backup requirements. A plan has one or more backup rules.
Backup ruleA schedule and backup window, a lifecycle, the vault that stores the backups, optional copy destinations, and tags to add to the backups.
Resource assignmentThe resources that a plan protects. You choose them by resource ID, by resource type, or by tag.

6.6 AWS Backup Vault

  • A backup vault is an encrypted storage location in your AWS account that stores and organizes your backups, which are called recovery points.
  • You can create vaults in each Region where AWS Backup is available.
  • Each backup rule names the vault that receives its recovery points.
  • A recovery point in a vault carries metadata: information about the resource, the restore parameters, and the tags.
  • You can protect a vault with AWS Backup Vault Lock, which stops anyone from deleting the backups or changing their retention.
  • A rule can copy recovery points to a vault in another Region or another account.

6.6.1 AWS Backup Vault Use Cases

  • Compliance and auditing: ensuring consistent, auditable backup policies across an entire organization.
  • Operational efficiency: automating backup schedules and lifecycle management to free up IT staff.
  • Cross-Region disaster recovery: automating the replication of recovery points to secondary AWS Regions as part of a disaster recovery strategy.
  • Ransomware protection: using Vault Lock to make backups immutable and safe from deletion by malicious actors.

6.7 How It Works

  1. Create a backup vault in the Region where the resources are.
  2. Create a backup plan with a rule that sets the schedule, the lifecycle, and the vault.
  3. Assign the resources to the plan, for example every resource that has the tag Backup=daily.
  4. AWS Backup runs the rule on the schedule and stores a recovery point in the vault.
  5. To restore, choose a recovery point. AWS Backup creates a new resource from it.
  • Backups stay in the Region that you select unless you set up a cross-Region copy.

6.8 Protecting the Backups

  • Encryption: a backup vault is encrypted, and the encryption is independent from the encryption of the source data.
  • Cross-Region copy: a rule can copy recovery points to a vault in another Region, for example for disaster recovery.
  • Cross-account copy: a rule can copy recovery points to a vault in another account, so that a problem in one account does not destroy the backups.
  • AWS Backup Vault Lock: delete protection for a vault. When it is on, no user, including an administrator or an attacker, can delete the backups or change their retention settings.
  • Logically air-gapped vault: a vault that holds immutable copies of the backups.

6.9 Lifecycle and Retention

  • A lifecycle setting in a rule moves recovery points from a warm storage tier to a lower-cost cold storage tier, and then expires them.
  • Cold storage is available only for backups of Amazon EBS, Amazon EFS, Amazon DynamoDB, Amazon Timestream, and VMware virtual machines. It is not available for Amazon S3, Amazon FSx, or Amazon RDS backups.
  • The retention period decides when AWS Backup deletes a recovery point.
  • Amazon Data Lifecycle Manager policies and AWS Backup plans work independently from each other. They are two ways to manage EBS snapshots.

6.10 Monitoring and Compliance

  • The AWS Backup dashboard shows the health of your backups across several accounts and Regions.
  • Amazon CloudWatch alarms can notify a team when backup jobs fail.
  • AWS Backup Audit Manager checks your backups against rules that you define and creates compliance reports.
  • Restore testing restores recovery points automatically, so that you know a restore works before you need it.

6.11 AWS Backup Use Cases

  • Central backup policy: protect many services with one plan, instead of a script for each service.
  • Disaster recovery: copy the recovery points to another Region.
  • Ransomware protection: keep the backups in a locked vault, in a logically air-gapped vault, or in another account.
  • Compliance and audit: keep the backups for the required period, and show evidence with Audit Manager reports.
  • Lower cost for long retention: move old recovery points to cold storage where it is available.
  • Confidence in restores: test the restores before an incident.
  • Protection of file, block, and object data: back up EFS, FSx, EBS, and S3 under the same policy.

6.12 AWS Backup Pricing

Prices change often and differ by Region. Always check the current rates on the AWS Backup pricing page, and estimate your own cost with the AWS Pricing Calculator.

  • Backup storage: a price per GB-month. It depends on the resource type, on whether the backup is in warm or cold storage, and on whether it is in a logically air-gapped vault.
  • Restores: restore charges apply, and cold storage restores cost more than warm storage restores.
  • Cross-Region copies: data transfer charges apply when you copy backups to another Region.
  • Extra features: restore testing and AWS Backup Audit Manager have their own charges.
  • Keep only the recovery points that you need, and move old ones to cold storage where it is available.

7. File Storage Pricing and Cost Optimization

Problem Statement

The FlashCart finance team asks how file storage is billed and how it compares with EBS and S3. It also wants to know what to turn on to keep the EFS bill down as the shared media folder grows. The engineers must explain the cost model, not guess a monthly figure.

7.1 The Cost Models Compared

ServiceHow you payWhat it means
Amazon S3Pay as you go. No capacity to provision.You pay per GB-month for the data that you store, plus requests.
Amazon EBSYou pay for the provisioned capacity.You pay even if you do not use the whole volume.
Amazon EFSPay as you go. No capacity to provision.You pay per GB-month for the data that you store, and the price differs by storage class.
  • EFS costs more per GB than EBS, and much more than S3. The extra cost buys a shared file system that grows and shrinks on its own.

7.2 What You Pay for With EFS

Prices change often and differ by Region. Always check the current rates on the Amazon EFS pricing page, and estimate your own cost with the AWS Pricing Calculator.

  • Storage: a price per GB-month for each storage class. The price is highest for Standard, lower for Infrequent Access, and lowest for Archive. One Zone classes cost less than Regional classes.
  • Data access: charges apply when you read data from the Infrequent Access and Archive classes, and when files move between classes.
  • Throughput: Provisioned throughput is billed for the throughput that you provision, and Elastic throughput is billed for the data that you read and write.
  • Replication and backup: EFS Replication and AWS Backup have their own charges.

7.3 What You Pay for With Amazon FSx

  • The price depends on the file system type, the storage capacity, the storage type (SSD or HDD), the throughput, and the backups.
  • Check the pricing page of each FSx file system for the current rates.

7.4 Ways to Lower the Cost

  • Turn on lifecycle management so that files that nobody opens move to Infrequent Access and Archive.
  • Use One Zone file systems for development, test, and reproducible data.
  • Choose the throughput mode that fits the workload. Elastic avoids paying for peak throughput all the time, and Provisioned avoids paying for extra storage only to get throughput.
  • Keep data that is rarely changed and not shared in S3, which costs less per GB.
  • Delete test file systems, and review replication and backup retention.

Question 1: Explain how Amazon EFS differs from Amazon EBS and Amazon S3, and give a workload for each.

Maps to: Objectives 1 and 7 (Comprehension).

EFS is a managed NFS file system that many Linux instances in several Availability Zones mount at the same time, for example web servers that share content files. EBS is block storage that is attached to one instance in one Availability Zone, for example a database volume. S3 is object storage that you reach through an API, for example a static website or backups. EFS and S3 are billed for the data that you store, and EBS is billed for the provisioned capacity.

Question 2: Describe the EFS file system types and storage classes, and explain how lifecycle management lowers the cost.

Maps to: Objective 3 (Comprehension).

A Regional file system stores data in several Availability Zones, and a One Zone file system stores data in one zone and suits non-critical data. EFS Standard holds frequently accessed files, EFS Infrequent Access holds files that are opened a few times a quarter, and EFS Archive holds files that are opened a few times a year or less. A lifecycle policy moves files that nobody has accessed for a set number of days to a colder class, so the storage cost falls and the path of the file does not change. You pay for reads from the colder classes.

Question 3: Compare the EFS performance modes and throughput modes, and recommend settings for an unpredictable media job.

Maps to: Objective 4 (Analysis).

General Purpose is the default and has the lowest latency, and Max I/O has higher latency and suits highly parallel workloads. The throughput modes are Elastic, which scales automatically, Provisioned, which you set regardless of the data size, and Bursting, which scales with the data size. For an unpredictable job, use Elastic throughput with General Purpose, because Elastic needs General Purpose and removes the need to guess a throughput value.

Question 4: Explain how to secure an EFS file system so that only web servers reach it and each application sees only its own folder.

Maps to: Objective 2 (Application).

Create mount targets in the Availability Zones that the clients use, and attach a security group that allows NFS traffic on TCP port 2049 only from the security group of the web servers. Create an EFS access point for each application that enforces a POSIX user and group and a root directory. Turn on encryption at rest with AWS KMS and encryption in transit with TLS through the mount helper, and use AWS Backup and EFS Replication for protection.

Question 5: Name the four Amazon FSx file systems and choose one for a Windows shared drive and one for machine learning on data in S3.

Maps to: Objective 5 (Comprehension).

The four file systems are FSx for Windows File Server, FSx for Lustre, FSx for NetApp ONTAP, and FSx for OpenZFS. For a Windows shared drive that uses SMB and Active Directory, choose FSx for Windows File Server. For machine learning on data in S3, choose FSx for Lustre, which reads the data from S3 and writes the results back to S3.

Question 6: Design a file storage solution for a multi-AZ web application with shared media, a Windows reporting team, and a cost target.

Maps to: Objective 9 (Synthesis).

Use a Regional EFS file system with a mount target in each Availability Zone for the shared media of the Linux web servers, with General Purpose mode and Elastic throughput. Turn on lifecycle management so that old files move to Infrequent Access and Archive, and protect the data with AWS Backup. Use Amazon FSx for Windows File Server with Active Directory for the Windows reporting team. Keep rarely changed data in Amazon S3 to lower the cost, and use AWS DataSync to move existing data into the new storage.

Question 7: Explain how AWS Backup protects file storage and other data, and how you would stop an attacker from deleting the backups.

Maps to: Objective 6 (Comprehension).

AWS Backup is a managed, centralized, policy-based service. A backup plan has rules that set the schedule, the lifecycle, and the backup vault, and you assign resources such as EFS file systems, FSx file systems, EBS volumes, and S3 buckets to the plan by tag or by resource ID. The recovery points are stored in an encrypted backup vault, and you restore one to a new resource. To stop an attacker or an administrator from deleting the backups, turn on AWS Backup Vault Lock on the vault, and add a cross-account or cross-Region copy so that another copy exists elsewhere.
