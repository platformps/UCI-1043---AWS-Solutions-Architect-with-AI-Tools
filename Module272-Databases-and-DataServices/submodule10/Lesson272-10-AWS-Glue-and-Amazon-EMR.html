AWS Glue and Amazon EMR

Discover, transform, and process data for analytics with AWS Glue and Amazon EMR: what each service does, how it works, and how to choose between them.

Overview and Objectives

Lesson Overview

AWS Analytics Services

AWS offers a service for each stage of an analytics pipeline: ingest, store, catalog and process, query, and visualize. This lesson starts the analytics part of the module with the two services that transform data at scale, AWS Glue and Amazon EMR.

AWS Glue is a serverless data integration service that discovers, catalogs, and transforms data. Amazon EMR is a managed big data platform that runs frameworks such as Apache Spark and Apache Hive on clusters or on serverless capacity. 1. Data Analytics on AWS

Problem Statement

FlashCart’s checkout runs on Amazon RDS. Last week an analyst ran a report that added up a full year of orders, and the checkout slowed down for every shopper. The company also keeps customer events in Amazon DynamoDB and daily sales files in Amazon S3, and nobody can ask a question that uses all three sources.

Your challenge:

  • Explain why analytics queries should not run on the production database.
  • Decide where the combined data should live.
  • Name the stages that data passes through before an analyst can use it.

1.1 What Data Analytics Is

  • Data analytics is the process of examining data to find patterns, answer questions, and support decisions, such as total sales by month or the products that customers buy together.
  • Analytics queries scan large amounts of data. They usually read a few columns from many rows, and they are different from the small reads and writes that an application makes.
  • On AWS, analytics follows a pipeline of stages: ingest, store, catalog and transform, query, and visualize (1.4).

1.2 OLTP and OLAP

Two kinds of workloads use data in different ways. OLTP stands for online transaction processing, and OLAP stands for online analytical processing.

FeatureOLTPOLAP
PurposeRuns the application and processes transactions.Analyzes data for reports, trends, and dashboards.
Typical queriesRead or change a few rows.Scan and aggregate many rows.
DataCurrent and detailed.Historical, and often combined from many sources.
Storage layoutRow based.Column based.
AWS examplesAmazon RDS, Amazon Aurora, and Amazon DynamoDB.Amazon Redshift, and Amazon Athena (lesson 272.11) over Amazon S3.
  • Because the two workloads are so different, run analytics on a copy of the data in an OLAP system, not on the OLTP database that serves the application.

1.3 Row-Based and Column-Based Storage

  • Row-based storage keeps all the values of one record together. It is fast to read or write one whole record, so OLTP databases use it.
  • Column-based storage keeps all the values of one column together. A query that needs one column reads only that column, and similar values compress well, so analytics systems use it.
  • Apache Parquet is a column-based file format that data lakes on Amazon S3 use (2.7).

1.4 Data Lakes and the Analytics Pipeline

  • A data lake is a central store, usually Amazon S3, that holds raw and processed data from many sources at low cost.
  • Data passes through stages on its way to an analyst. The services in the table below fit each stage.
StageWhat happensAWS services
1. IngestData arrives from applications, devices, and databases, in batches or as streams.Amazon Kinesis (lesson 273.6) and Amazon MSK (lesson 272.13) for streams, plus files and database exports for batches.
2. StoreRaw data lands in a central, low-cost store.Amazon S3.
3. Catalog and transformThe data is described, cleaned, and converted to a fast format.AWS Glue and Amazon EMR (this lesson).
4. QueryAnalysts run SQL on the prepared data.Amazon Athena for SQL on Amazon S3, and Amazon Redshift for a data warehouse.
5. VisualizeDashboards and reports show the results.AWS Quick (lesson 272.15).
  • Later lessons in this module cover the query, search, governance, and visualization services in this pipeline.

Exam Trap

Remember these points:

  • OLTP databases (Amazon RDS, Amazon Aurora, and Amazon DynamoDB) run applications. OLAP systems (Amazon Redshift, and Amazon Athena over Amazon S3) run analytics.
  • A data lake lives in Amazon S3. AWS Glue and Amazon EMR transform the data, but they are not the long-term store.
  • Do not run heavy reports on the production database. Copy the data to an analytics store.

Memory Hook

OLTP runs the shop. OLAP studies the shop. The lake holds the data.

2. AWS Glue

Problem Statement

FlashCart receives a CSV file of sales every night in an Amazon S3 bucket, and its customer data lives in Amazon RDS. The analytics team queries the CSV files with SQL, and the queries are slow and expensive because each query reads every column of every file. Nobody keeps a list of the tables and columns, so each analyst guesses the schema.

The team has no data engineers to run servers. It wants a service that finds the data, records its schema, converts the files to a faster format, and processes only the new files each night.

Your challenge:

  • Choose a service that finds and catalogs the data automatically.
  • Choose a way to convert the CSV files to a column-based format without managing servers.
  • Avoid reading the same files again on every run.

2.1 Introduction to AWS Glue

  • AWS Glue is a serverless data integration service that makes it easier to discover, prepare, move, and combine data for analytics, machine learning, and application development.
  • It is built around ETL: extract data from a source, transform it, and load it into a target.
  • Serverless means that you do not provision or manage servers. AWS Glue runs your jobs on resources that it manages, and you pay for the time that the jobs use.
  • It connects to many sources and targets, such as Amazon S3, Amazon RDS, Amazon DynamoDB, Amazon Redshift, other JDBC databases, and Amazon DocumentDB.
  • It has five main parts, shown in the table below.
ComponentWhat it does
Data CatalogA central metadata repository. It records the location and schema of your data (2.2).
CrawlerScans a data store, infers the schema, and creates or updates tables in the Data Catalog (2.2).
JobRuns the ETL code that extracts, transforms, and loads data (2.3).
Trigger and workflowStart jobs and crawlers on demand, on a schedule, or after another job. A workflow chains several jobs and crawlers.
Glue Studio and DataBrewVisual tools. Glue Studio builds ETL jobs, and DataBrew cleans and normalizes data without code (2.5).

2.2 Glue Data Catalog and Crawlers

  • The Glue Data Catalog is a central metadata repository. It acts as an index to the location and schema of your data, but it does not store the data itself.
  • Other AWS analytics services use the Data Catalog, including Amazon Athena, AWS Lake Formation (lesson 272.12), Amazon EMR, and Amazon Redshift Spectrum.
  • A crawler connects to a data store, tries a prioritized list of classifiers to find the schema, and creates or updates tables in the Data Catalog.
  • You can run a crawler on demand, on a schedule, or when an event happens.
  • A crawler uses an IAM role. For Amazon S3, the role must have permission to read the bucket or the prefix.
  • A crawler is optional. You can also add tables to the Data Catalog with the console or the API.

2.3 Glue Jobs

  • A Glue job is a script that extracts data from sources, transforms it, and loads it into targets. You write the script in Python or Scala, or Glue Studio generates it for you.
  • The job type decides the engine that runs the script.
Job typeWhat it runsUse it for
Spark ETL jobApache Spark on serverless resources.Large-scale batch ETL.
Spark Streaming jobApache Spark Structured Streaming.Continuous ETL on streams (2.6).
Python shell jobA Python script without Spark.Small tasks that do not need a Spark environment.
Ray jobPython code on the Ray framework.AWS Glue for Ray has been closed to new customers since April 30, 2026. Existing customers can keep using it.
  • A data processing unit (DPU) is the unit of compute that Glue jobs use. One DPU provides 4 vCPUs and 16 GB of memory. You choose the worker type and the number of workers.
  • You start a job on demand, on a schedule, or with a trigger.
  • You monitor job runs in the AWS Glue console and in Amazon CloudWatch (lesson 274.1).

2.4 Job Bookmarks

  • A job bookmark remembers which data a Glue ETL job has already processed, so the next run processes only new or changed data.
  • Glue keeps this state for each job, as data that is specific to the source, the transforms, and the target. If you delete the job, its bookmark is deleted.
  • Without bookmarks, every run reads all the data again. This costs more time and money, and it can create duplicates.
  • With bookmarks, Glue processes only the new files or records. The ETL is faster and cheaper.
  • You can enable, disable, or pause the bookmark. Disable is the default. Pause reads the saved state but does not update it.
  • To reprocess all the data with the same job, reset the bookmark.

2.5 Glue Studio and DataBrew

  • AWS Glue Studio has a visual interface to create, run, and monitor ETL jobs. You choose a source, add transform steps, and choose a target, and Glue Studio generates the Spark code.
  • Use Glue Studio for low-code ETL. Write the script yourself when the job needs custom logic.
  • AWS Glue DataBrew is a visual data preparation tool. It cleans and normalizes data with prebuilt transformations, and it needs no code.

2.6 Streaming ETL

  • Glue streaming ETL runs continuous ETL jobs on streaming data. It is built on Apache Spark Structured Streaming.
  • The sources are Amazon Kinesis Data Streams, Apache Kafka, and Amazon MSK. The targets are Amazon S3 and JDBC data stores.
  • Use it to cleanse and transform event data, such as IoT streams, clickstreams, and network logs, while the data is in flight.

2.7 Converting CSV to Parquet

  • Apache Parquet is a column-based file format for analytics. It stores data column by column, so the files are smaller because they compress well, and a query reads only the columns that it needs.
  • Amazon Athena and Amazon Redshift Spectrum query Parquet faster and at lower cost than CSV.
  • A common Glue job converts CSV files in one Amazon S3 bucket to Parquet files in another bucket.

The steps of this example follow the demonstration in the course slides:

  1. Create a source bucket and a target bucket in Amazon S3, and load the CSV files into the source bucket.
  2. Create an IAM role for Glue. Attach the AWSGlueServiceRole managed policy, and add a policy that allows reading the source bucket and writing to the target bucket.
  3. Create a job in Glue Studio.
  4. Set the source to the bucket or prefix, with the data format CSV.
  5. Add a Change Schema step to choose the columns to keep.
  6. Set the target to the target bucket, with the data format Parquet.
  7. Save and run the job, and check the Parquet files in the target bucket.
  • To run the job when a file arrives, an Amazon S3 event notification can invoke an AWS Lambda function (lesson 273.1) that starts the Glue job. Amazon EventBridge (lesson 273.3) works as an alternative.

2.8 Security and Encryption

  • Data in transit: Glue supports TLS endpoints. You can also require that Glue connects to JDBC data stores only through a TLS connection.
  • Data at rest: you can use AWS KMS keys to encrypt the metadata in the Data Catalog, the job bookmarks, and the logs that crawlers and jobs write to Amazon CloudWatch.
  • For the data that a job writes to Amazon S3, create a security configuration and attach it to the ETL job to turn on SSE-S3 or SSE-KMS encryption. A security configuration can also encrypt the job bookmarks and the CloudWatch Logs (lesson 274.2).
  • Give crawlers and jobs IAM roles with only the permissions that they need.

2.9 AWS Glue Pricing

Prices change often and differ by Region. Always check the current rates on the AWS Glue pricing page.

  • ETL jobs and crawlers are billed per DPU-hour, by the second. A minimum charge applies to each run, so check the pricing page for the current minimums.
  • The Data Catalog has a free tier. The first million objects stored and the first million requests each month are free, and charges apply above that.
  • The Flex execution class can reduce the cost of non-urgent Spark jobs by up to 35 percent, because their start and finish times may vary.
  • To lower the cost, use job bookmarks, convert to Parquet, and do not run a crawler more often than the data changes.

3. Amazon EMR

Problem Statement

FlashCart’s data science team has years of Apache Spark and Apache Hive jobs that run on an on-premises Hadoop cluster. The jobs process terabytes of clickstream logs in batches overnight. The cluster sits idle during the day, but the team must keep it sized for the peak load.

The team wants to move to AWS without rewriting the jobs. It wants to keep control of the frameworks and the instance types, and it wants to lower the cost of the nightly runs.

Your challenge:

  • Choose a service that runs Spark and Hive with few code changes.
  • Decide how to keep the data after the compute is turned off.
  • Reduce the cost of the nightly batch jobs.

3.1 Introduction to Amazon EMR

  • Amazon EMR, formerly Elastic MapReduce, is a managed big data platform for processing and analyzing very large amounts of data.
  • It runs open source frameworks such as Apache Hadoop, Apache Spark, Apache Hive, Presto, Trino, Apache HBase, and Apache Flink.
  • EMR provisions and configures the cluster. You choose the EMR release, the applications, and the instance types.
  • It supports auto scaling, and it works with Amazon EC2 Spot Instances.
  • Typical use cases are log analysis, web indexing, processing data for machine learning, and analysis of financial data, market trends, and customer preferences.
  • Compared with AWS Glue, EMR gives you more control and more frameworks, and it asks you to manage more (tab 4).

3.2 Deployment Options

OptionWhere it runsUse it when
EMR on EC2A cluster of Amazon EC2 instances that you configure.You need full control of the cluster, the instance types, and the frameworks.
EMR on EKS (lesson 273.5)Amazon EKS, the managed Kubernetes service.You already run Kubernetes, and you want to share that infrastructure for Spark jobs.
EMR ServerlessCapacity that EMR manages for each application.You want to run Spark or Hive jobs without configuring or managing clusters.
  • EMR also runs on AWS Outposts. Its pricing is the same as for EMR in the cloud.

3.3 Cluster Architecture and Node Types

  • An EMR cluster is a group of Amazon EC2 instances. Each instance has a role, called a node type.
  • The primary node manages the cluster, coordinates the other nodes, and runs the main components of the distributed applications. Older material calls it the master node.
  • The core nodes run tasks and store data in HDFS. They are long running, and removing a core node can lose data.
  • The task nodes are optional. They run tasks only and do not store data in HDFS. Because they hold no data, they are usually Spot Instances.
  • For high availability, a cluster can run three primary nodes. If one fails, EMR fails over to a standby primary node.
  • A long-running cluster stays up for continuous work. A transient cluster is temporary: it starts, runs the jobs, and ends.

3.4 Storage: HDFS and EMRFS

  • HDFS is the Hadoop Distributed File System. It stores data on the core nodes, on EBS volumes or instance store. It is fast, but the data is lost when the cluster ends.
  • EMRFS lets EMR read and write Amazon S3 as a file system. The data in Amazon S3 stays after the cluster ends.
  • A common design keeps the input and output data in Amazon S3 and runs transient clusters to process it. The sources can be Amazon RDS, Amazon S3, and Amazon DynamoDB, and the targets can be Amazon S3 and Amazon Redshift.

3.5 Purchasing Options and Cost

OptionHow it worksUse it for
On-DemandReliable and predictable. AWS does not terminate the instances.Primary nodes and core nodes.
ReservedSaves cost with a commitment of one year or three years. Savings Plans are another commitment option.Clusters that run for a long time.
SpotCheaper, but AWS can terminate the instances, so it is less reliable.Task nodes and fault-tolerant batch jobs.
  • Be careful with Spot Instances on core nodes. If a core node ends, you can lose HDFS data.
  • Use a transient cluster for a nightly batch job. It exists only while the job runs, so you pay only for that time.
  • EMR can add or remove instances automatically to match the workload.
  • EMR on EC2: the EMR price is added to the Amazon EC2 price and, if you attach volumes, the Amazon EBS price. All of them are billed per second, with a one-minute minimum.
  • EMR on EKS: you pay an EMR charge for the vCPU and memory that the job uses, plus the cost of the Amazon EKS cluster and its compute.
  • EMR Serverless: you pay for the vCPU, memory, and storage that your workers use, with no upfront cost.
  • Prices change often. Check the Amazon EMR pricing page for the current rates.

3.6 Security Basics

  • An EMR cluster uses IAM roles: a service role for EMR, and an instance profile for the Amazon EC2 instances.
  • Place the cluster in private subnets, and control access with security groups.
  • Use a security configuration to encrypt data at rest and data in transit.
  • EMR also supports Kerberos authentication for the cluster services.

Exam Trap

Remember these points:

  • Hadoop, Hive, Presto, HBase, or Spark migration points to Amazon EMR.
  • HDFS data ends with the cluster. Keep data that must last in Amazon S3, and read it through EMRFS.
  • Use task nodes on Spot Instances to lower cost. Spot on core nodes risks data loss.
  • EMR on EC2 gives full control. EMR Serverless removes cluster management.

Memory Hook

Primary leads, core stores, task helps. Keep the data on S3.

4.2 When to Use Each Service

4.2.1 Use AWS Glue When

  • You want visual, low-code ETL tools.
  • You need built-in connectors, transformations, incremental loads, job monitoring, and orchestration.
  • You need a central data catalog and governance.
  • You do not want to manage infrastructure.

4.2.2 Use Amazon EMR When

  • You are migrating Hadoop from on premises.
  • Your team has expertise beyond Spark, such as Hive and Presto.
  • The team can build its own connectors and manage its own jobs.
  • You need large-scale distributed processing with consistent usage, and control of the instance types.

4.4 Lesson Summary

This lesson covered the following points:

  • Analytics is an OLAP workload that should run on a copy of the data. A data lake on Amazon S3 holds the data, and AWS Glue and Amazon EMR transform it.
  • AWS Glue is a serverless ETL service. Its Data Catalog stores metadata, crawlers fill the catalog, jobs transform the data, bookmarks avoid reprocessing, and Glue Studio builds jobs visually.
  • Glue streaming ETL handles Kinesis, Kafka, and Amazon MSK streams. Parquet makes later queries faster and cheaper.
  • Amazon EMR is a managed big data platform for Hadoop, Spark, Hive, Presto, HBase, and Flink. It runs on EC2, EKS, or as EMR Serverless.
  • An EMR cluster has a primary node, core nodes that store HDFS data, and optional task nodes. Keep lasting data in Amazon S3, and use Spot task nodes to lower the cost.
  • Choose Glue for low-code, serverless ETL, and choose EMR for Hadoop migration, other frameworks, and large-scale processing with control.

Memory Hook

Glue is the serverless ETL service, and EMR is the big data toolbox.

5. Knowledge Check

Answer each question in your own words before you open the model answer. The questions were written for this course.

Question 1: Explain the difference between OLTP and OLAP, and say why FlashCart should not run its yearly sales report on its checkout database.

Maps to: Objective 1 (Comprehension).

OLTP workloads run applications. They read or change a few rows at a time, and they use row-based storage. OLAP workloads analyze data. They scan and aggregate many rows, and they use column-based storage. A report over a full year of orders is an OLAP query. If it runs on the checkout database, it competes with the shoppers for the same resources and slows the checkout. FlashCart should copy the data to an Amazon S3 data lake and analyze it there.

Question 2: Describe what AWS Glue is, and explain the roles of the Glue Data Catalog and crawlers.

Maps to: Objective 2 (Comprehension).

AWS Glue is a serverless data integration service that discovers, prepares, and moves data, and it is built around ETL. The Glue Data Catalog is a central metadata repository. It records the location and schema of the data, but it does not hold the data. A crawler connects to a data store, finds the schema with a list of classifiers, and creates or updates the tables in the catalog. It runs on demand, on a schedule, or when an event happens, and it uses an IAM role to read the data. Amazon Athena, AWS Lake Formation, Amazon EMR, and Amazon Redshift Spectrum can use the catalog.

Question 3: Explain how a Glue ETL job, job bookmarks, and Glue Studio work together to convert nightly CSV files to Parquet.

Maps to: Objective 3 (Application).

In Glue Studio, the team sets the source to the Amazon S3 bucket with the format CSV, adds a Change Schema step, and sets the target to another bucket with the format Parquet. Glue Studio generates the Spark code, and an IAM role lets the job read the source and write the target. The team runs the job every night with a trigger. With job bookmarks enabled, Glue remembers which files it already processed, so each run reads only the new files. The Parquet output is smaller and faster for Amazon Athena to query.

Question 4: Describe Amazon EMR, its three node types, and its three deployment options.

Maps to: Objective 4 (Comprehension).

Amazon EMR is a managed big data platform that runs frameworks such as Hadoop, Spark, Hive, Presto, HBase, and Flink. The primary node manages the cluster. The core nodes run tasks and store data in HDFS. The optional task nodes run tasks only, and they are often Spot Instances. EMR runs on Amazon EC2, where you control the cluster, on Amazon EKS, where Spark jobs run on Kubernetes, and as EMR Serverless, where you run jobs without managing clusters.

Question 5: Differentiate AWS Glue and Amazon EMR, and name one requirement that points to each service.

Maps to: Objectives 5 and 6 (Analysis).

AWS Glue is serverless and low code. It is built for ETL, schema discovery, and a data catalog, and it suits ad hoc and small batch jobs and incremental loads. Amazon EMR is a managed platform for many big data frameworks, and it suits large-scale distributed processing with steady use. It needs some infrastructure management, and it gives control of the frameworks and the instance types. A requirement for visual, serverless ETL with no infrastructure points to Glue. A requirement to migrate Hadoop, Hive, or Presto jobs from on premises points to EMR.

Question 6: Design a solution for FlashCart that converts the nightly CSV files and the customer data in Amazon RDS into a fast, queryable format, and that moves the existing Spark and Hive jobs to AWS at a lower cost.

Maps to: Objective 7 (Synthesis).

Keep a data lake in Amazon S3. Use a Glue crawler to catalog the CSV files and the Amazon RDS tables in the Glue Data Catalog. Use a Glue ETL job with job bookmarks to convert the nightly files to Parquet in a curated bucket, and give the job an IAM role with access only to those buckets. Turn on encryption with a security configuration. For the existing Spark and Hive jobs, use Amazon EMR on EC2 with transient clusters that start each night, read and write Amazon S3 through EMRFS, and use Spot Instances for the task nodes. Use the Glue Data Catalog from EMR so that both services share the same table definitions. Check the pricing pages for current costs.
