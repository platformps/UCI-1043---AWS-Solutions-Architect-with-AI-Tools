AWS Data Exchange and AWS Data Pipeline

Bring in third-party data with AWS Data Exchange, and understand AWS Data Pipeline, the legacy scheduler that AWS has closed to new customers.

Overview and Objectives

Lesson Overview

AWS Analytics Services

The services in this module so far work on data that you already have. This lesson covers two services at the edges of that work. AWS Data Exchange brings in data that belongs to someone else, such as a market data feed or a weather history. AWS Data Pipeline is an older service that schedules the movement and processing of data between your own systems. Data Exchange is a service to learn for new designs. Data Pipeline is a service to recognize, because it appears in older architectures and in exam questions, and AWS no longer offers it to new customers.

This lesson explains what Data Exchange is and how subscribers and providers use it, what Data Pipeline does and why AWS moved it to maintenance mode, which services replace it, and how to choose between them. The last two tabs prepare you for the AWS Certified Solutions Architect – Associate (SAA-C03) exam and check what you learned.

1. AWS Data Exchange

Problem Statement

FlashCart’s forecasting model improves when it uses outside data, such as weather history and holiday calendars. Vendors sell this data, and an analyst currently receives files by email, checks the licence terms, and uploads each file to Amazon S3 by hand.

The vendor files change every week, so the manual work repeats. FlashCart also wants to send a daily sales extract to one supplier’s AWS account, without building its own delivery system.

Your challenge:

  • Choose a service to find, buy, and receive third-party data.
  • Automate the delivery of each new version of the data.
  • Share FlashCart’s own data with one supplier.

1.1 Introduction to AWS Data Exchange

  • AWS Data Exchange is a service that helps AWS customers share and manage data entitlements from other organizations at scale.
  • A data receiver can track and manage all of its data grants and AWS Marketplace data subscriptions in one place.
  • After you have access to a data set, you can use compatible AWS or partner analytics and machine learning services to find insights in it.
  • A data sender does not need to build and maintain any data delivery or entitlement infrastructure. AWS Data Exchange provides it.
  • Anyone, with or without an AWS account, can find and use the public data sets of the Open Data on AWS program.
  • Data grants, subscriptions, data sets, revisions, and assets are Region resources, and they are managed in supported Regions.

1.2 The Three Building Blocks

Data is organized in AWS Data Exchange using three building blocks:

  • Assets: A piece of data.
  • Revisions: A container for one or more assets.
  • Data sets: A series of one or more revisions.

These three building blocks form the foundation of the product that you manage using the AWS Data Exchange console or the AWS Data Exchange API.

To create, view, update, or delete data sets, you can use the AWS Data Exchange console, the AWS Command Line Interface (AWS CLI), your own REST (Representational State Transfer) client, or one of the AWS SDKs. For more information about programmatically managing AWS Data Exchange data sets, see the AWS Data Exchange API Reference.

1.3 Key Terms

Data setA resource that the sender or provider curates. It holds the data assets that a receiver can use after getting access.
RevisionA new version or an incremental change of a data set. Providers update a data set with revisions.
AssetOne piece of data in a revision. An asset can be an Amazon S3 object, an Amazon Redshift datashare, an Amazon API Gateway (lesson 273.2) API, an AWS Lake Formation data permission, or Amazon S3 data access.
Data grantThe unit of exchange for sharing data directly. A sender creates it to give a receiver access to a data set.
Data productThe unit of exchange in AWS Marketplace. It includes one or more data sets, and subscribers buy it.
EntitlementThe right to use a data set, which a subscriber or receiver gets through a subscription or an accepted data grant.
JobAn asynchronous operation that imports assets into a revision or exports assets out of one.

1.6 The Subscriber Workflow

  1. Find a data product in the AWS Marketplace catalog, or accept a data grant that a sender made.
  2. Review the offer, which has the price, the duration, and the data subscription agreement, and subscribe.
  3. The data sets that you are entitled to appear in the AWS Data Exchange console.
  4. Export the assets of a revision to Amazon S3, in the console, with an API call, or with a job.
  5. Analyze the data with services such as Amazon Athena, Amazon Redshift, Amazon EMR, AWS Glue, AWS Lake Formation, and Amazon SageMaker.

1.7 Automating New Revisions

  • Providers publish new revisions on a schedule, such as a new file every day.
  • AWS Data Exchange is integrated with Amazon EventBridge (lesson 273.3). A subscriber with an active subscription receives an event each time the provider publishes a new revision or adds a data set to the product.
  • An EventBridge rule can start an AWS Lambda function (lesson 273.1) that creates an export job. The new revision then lands in your Amazon S3 bucket without any manual step.
  • AWS delivers these events on a best effort basis.

1.8 The Provider Workflow

  1. Create a data set, and import assets into a revision, for example from your Amazon S3 buckets.
  2. Share it with a data grant to a receiver’s AWS account, or publish it as a data product in AWS Marketplace with a public offer.
  3. Add a new revision each time the data changes. Subscribers receive an event.
  • You can also work programmatically with the AWS Data Exchange API, and with the AWS Marketplace Catalog API for products.

Exam Trap

Remember these points:

  • AWS Data Exchange is the answer for finding, subscribing to, and receiving third-party data in AWS.
  • A data grant shares data with a specific AWS account. A data product is sold in AWS Marketplace.
  • New data arrives as revisions. Use EventBridge to export each one to Amazon S3 automatically.
  • Data Exchange delivers the data. It does not analyze it. Use Athena, Redshift, or EMR for that.

Memory Hook

Subscribe once, and every revision arrives.

1.9 Exam-Style Question

Written for this course.

Scenario: A company subscribes to a vendor’s daily market data. The vendor publishes a new set of files every day. The company wants the new files in its Amazon S3 bucket every day with no manual work. Which solution meets the requirements?

  • A. Create an Amazon Kinesis (lesson 273.6) data stream, and ask the vendor to write to it.
  • B. Run AWS DataSync on a schedule against the vendor’s file server.
  • C. Subscribe to the product in AWS Data Exchange, and use an Amazon EventBridge rule to start an export of each new revision to Amazon S3.
  • D. Subscribe to the product in AWS Data Exchange, and download each file by hand.
Show Answer and Explanation

Correct answer: C. AWS Data Exchange sends an event when the vendor publishes a new revision. An EventBridge rule can start an export job that copies the revision to Amazon S3, with no manual work.

OptionResultReason
AIncorrectA Kinesis stream would need the vendor to change how it delivers data, and the data is not in AWS Data Exchange.
BIncorrectDataSync copies from storage that you can reach, and the data would not come through the subscription.
CCorrectThe event and the export job deliver every new revision automatically.
DIncorrectDownloading by hand does not meet the requirement of no manual work.

2. AWS Data Pipeline

Problem Statement

FlashCart’s acquired company left a job that copies a DynamoDB table to Amazon S3 every night and starts a weekly Amazon EMR cluster to build a report. It runs on AWS Data Pipeline, and nobody on the team has used the service.

A new project needs a similar scheduled workflow. The team wants to know whether to build it on Data Pipeline, and what to do about the old job.

Your challenge:

  • Explain what the old job does and which parts of Data Pipeline run it.
  • Decide whether a new project should use Data Pipeline.
  • Choose a replacement for the old job.

2.1 Introduction to AWS Data Pipeline

  • AWS Data Pipeline is a web service that automates the movement and transformation of data.
  • You define data-driven workflows, so that a task depends on the successful completion of the tasks before it. Data Pipeline enforces the logic that you set up.
  • It was launched in 2012. AWS now says that it is in maintenance mode, with no new features or Region expansions planned.
  • It is no longer available to new customers. Existing customers can continue to use it as normal.
  • You can use the AWS Management Console, the AWS CLI, the AWS SDKs, or the Query API to manage pipelines.

2.2 Components

ComponentWhat it does
Pipeline definitionStates the business logic: the data sources, the activities, the schedule, the resources, the preconditions, and the alerts.
Data nodeThe location of the input data for a task, or the location where the output goes.
ActivityThe work to do on a schedule, with a computing resource, usually between input and output data nodes.
ScheduleWhen the activities run, and how often.
PreconditionA condition that must be true before an activity can start, such as the final day’s data being in Amazon S3.
ResourceThe computing resource that does the work, such as an Amazon EC2 instance or an Amazon EMR cluster that the pipeline creates.
Task RunnerThe application that polls Data Pipeline for tasks, performs them, and reports the status back.

2.3 How It Works

  1. Write a pipeline definition, in the console, in a definition file, or with the API.
  2. Create a pipeline, upload the definition, and activate the pipeline.
  3. Data Pipeline works out the tasks from the definition, schedules them, and creates the resources that run them.
  4. Task Runner polls for tasks and performs them, for example copying log files to Amazon S3 or launching an Amazon EMR cluster.
  5. If a task fails, Data Pipeline retries it according to your instructions, and it can reassign it to another task runner. If the task keeps failing, the pipeline can notify you.
  • AWS gives this example: archive the web server logs to Amazon S3 each day, then run a weekly Amazon EMR cluster over them. Data Pipeline makes the cluster wait for the last day’s data, even if the upload is late.

2.4 Pricing

Prices change often and differ by Region. Check the current rates on the AWS Data Pipeline pricing page.

  • You pay for a pipeline based on how often its activities and preconditions are scheduled to run, and where they run.
  • Accounts that are less than 12 months old have a free tier of three low-frequency preconditions and five low-frequency activities each month.

2.5 Migrating From Data Pipeline

AWS says that other services now give customers a better experience, and it describes three targets for migration.

AWS Step Functions (lesson 273.4)You orchestrate tasks across several AWS services, such as Amazon EMR, AWS Lambda, AWS Glue, and DynamoDB. You want a serverless, low-code, visual design with the workflow written in JSON.

Exam Trap

Remember these points:

  • AWS Data Pipeline is in maintenance mode and is closed to new customers. For a new design, choose AWS Glue, AWS Step Functions, or Amazon MWAA.
  • If a question describes scheduled data movement with preconditions, Task Runner, and EC2 or EMR resources, the service is Data Pipeline.
  • A precondition must be true before an activity runs. A schedule decides when it runs.
  • A serverless, low-code orchestration across many AWS services points to Step Functions.

Memory Hook

Data Pipeline moves, but the future flows through Glue, Step Functions, and MWAA.

4.5 Lesson Summary

This lesson covered the following points:

  • AWS Data Exchange helps you share and receive data entitlements. A data set holds assets, and providers update it with revisions.
  • A data grant shares data with a specific AWS account. A data product is sold in AWS Marketplace with an offer that sets the price and the terms.
  • There are five data set types: files, API, Amazon Redshift, Amazon S3, and AWS Lake Formation (Preview).
  • EventBridge events announce each new revision, so a subscriber can export it to Amazon S3 automatically and analyze it with Athena, Redshift, EMR, Glue, or SageMaker.
  • AWS Data Pipeline automates scheduled data movement with a pipeline definition, preconditions, and Task Runner. It is in maintenance mode and closed to new customers.
  • AWS recommends AWS Glue, AWS Step Functions, or Amazon MWAA instead, depending on the workload.

5. Knowledge Check

Answer each question in your own words before you open the model answer.

Question 1: Explain what AWS Data Exchange is, and describe the difference between a data grant and a data product.

Maps to: Objectives 1 and 2 (Comprehension).

AWS Data Exchange helps customers share and manage data entitlements from other organizations at scale. A data grant is created by a sender to give one receiver’s AWS account access to a data set, and the receiver accepts it. A data product is the unit of exchange in AWS Marketplace. A registered seller publishes it after AWS reviews it, and subscribers buy it under an offer that sets the price, the duration, the data subscription agreement, and the refund policy.

Question 2: Describe a data set, a revision, and an asset, and name the five types of data sets.

Maps to: Objective 2 (Comprehension).

A data set is a resource that the provider curates and that holds the data a receiver gets. A revision is a new version or an incremental change of the data set. An asset is one piece of data in a revision. The five data set types are files, API, Amazon Redshift, Amazon S3, and AWS Lake Formation, which is in preview.

Question 3: FlashCart subscribes to a daily weather product. Describe how the new files reach the data lake automatically.

Maps to: Objective 3 (Application).

The provider publishes a new revision each day. AWS Data Exchange sends an Amazon EventBridge event to the subscriber. An EventBridge rule starts an AWS Lambda function that creates an export job, which copies the revision’s assets to the FlashCart Amazon S3 bucket. The team then queries them with Amazon Athena or loads them into Amazon Redshift. Events are delivered on a best effort basis.

Question 4: Describe the main components of AWS Data Pipeline and what each one does.

Maps to: Objective 4 (Comprehension).

The pipeline definition states the business logic. Data nodes are the input and output locations. Activities are the work, run on a schedule. Preconditions must be true before an activity can start. Resources, such as Amazon EC2 instances or Amazon EMR clusters, do the work. Task Runner polls Data Pipeline for tasks, performs them, and reports the status back. Data Pipeline retries failed tasks and can notify you.

Question 5: Explain the status of AWS Data Pipeline today, and what a team should do about an existing pipeline.

Maps to: Objective 5 (Comprehension).

AWS Data Pipeline is in maintenance mode, with no new features or Region expansions planned, and it is no longer available to new customers. Existing customers can keep using it as normal. A team with an existing pipeline should plan to migrate it, because AWS describes migration paths to AWS Glue, AWS Step Functions, and Amazon MWAA.

Question 6: FlashCart’s old job exports a DynamoDB table to Amazon S3 each night and runs a weekly Amazon EMR report. Compare the three migration options and choose one.

Maps to: Objective 6 (Analysis).

AWS Glue suits a workload that was built from a console template, such as exporting DynamoDB to Amazon S3, and it is serverless, but it is a weaker fit when the work depends on Apache Hive or needs on-premises servers. AWS Step Functions suits orchestrating several AWS services, such as DynamoDB and EMR, with a low-code visual designer. Amazon MWAA suits teams that want managed Apache Airflow in Python. For this job, a Step Functions workflow on an EventBridge schedule is a good choice, because it can combine the DynamoDB export and the EMR step in one workflow.

Question 7: Design a solution for FlashCart that brings in third-party weather data and orchestrates its processing each day.

Maps to: Objective 8 (Synthesis).

Subscribe to the weather product in AWS Data Exchange. Use an EventBridge rule to export each new revision to an Amazon S3 bucket in the data lake. Let an AWS Glue crawler catalog the files, and query them with Amazon Athena. Use AWS Step Functions on an EventBridge schedule to run the Glue job and any follow-up steps, with retries and error handling. Feed the results to the forecasting model and to AWS Quick Sight. Do not build the orchestration on AWS Data Pipeline, because it is closed to new customers.
