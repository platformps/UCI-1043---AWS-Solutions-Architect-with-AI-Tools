Introduction

Some questions are about connections, not about rows: who is connected to whom, how a payment links to a suspicious account, or what is the shortest route between two points. A relational database can answer them with many self-joins, but the queries get slow as the number of hops grows. A graph database stores the connections directly. An architect has to recognize these keywords and choose Neptune instead of a relational or key-value database.

This lesson assumes that you know the Aurora cluster design from Lesson 272.2, because Neptune uses a similar shared-volume design. It follows FlashCart Inc. through the Problem Statement of each tab. It was numbered 272.7 because Lesson 272.6 covers Amazon ElastiCache.

1. What Amazon Neptune Is

Problem Statement

FlashCart wants product recommendations of the type "customers who bought this also bought", a fraud check that follows chains of shared cards and addresses, and a friends feature in its app. In the relational database each question needs many self-joins, and the queries take minutes. The team needs a database that stores the connections themselves.

1.1 What a Graph Database Is

  • A graph database stores data as a network of entities and relationships.
  • A graph has nodes (also called vertices), which are the objects such as a person, a post, or a product, and edges, which are the relationships between the nodes, such as "is friend of" or "bought".
  • Nodes and edges can have properties, such as a name or a date.
  • A graph database is built for highly connected data and for queries that follow many relationships, where a relational database needs many joins.

1.2 What Amazon Neptune Is

  • Amazon Neptune is a fully managed graph database. It handles provisioning, patching, backups, and recovery, and it supports high availability and replication.
  • It lets you build applications on highly connected datasets and query billions of relationships with millisecond latency.
  • It supports both the property graph model and the RDF model.
  • It is highly available across three Availability Zones, with up to 15 read replicas.
  • Neptune can analyze graph datasets with tens of billions of relationships within seconds by using built-in algorithms, and it can run similarity searches on vectors stored with the graph for generative AI applications (course slide).

1.3 Use Cases

Use caseThe question that a graph answers
Social networkingWho are the friends of my friends, and what do they like?
Fraud detectionWhich accounts share a card, a device, or an address through a chain of links?
RecommendationsWhat did the people who bought this product also buy?
Knowledge graphs, such as WikipediaHow are these entities related?
Network and security analysisWhich systems are reachable from this compromised host?
RoutingWhat is the shortest path between a driver and a rider on a road network?

2. Cluster Architecture and Global Database

Problem Statement

The FlashCart recommendation service must keep answering when a zone fails, and the reads grow as more screens use the graph. The engineers ask how Neptune stores the graph, how many replicas it allows, and how a second Region can serve users in Asia.

2.1 The Cluster

  • A Neptune DB cluster has one primary instance that takes the writes, and up to 15 read replicas.
  • All the instances use one shared cluster volume. A replica reads the same storage as the primary.
  • The volume is replicated six ways across three Availability Zones, and it grows automatically, up to 128 TiB in most Regions.
  • The storage handles the loss of up to two copies without losing write availability, and up to three copies without losing read availability.

2.2 Failover and Endpoints

  • If the primary fails, Neptune uses Multi-AZ to fail over automatically to one of up to 15 replicas that you created in any of the three zones.
  • The cluster endpoint points to the primary, and the reader endpoint balances the connections across the replicas.
  • Replication to the replicas is asynchronous, so a replica can lag a little.
  • Add replicas to scale reads. A larger instance class scales the writes.

2.3 Neptune Global Database

  • Neptune Global Database spans several Regions: a primary cluster in one Region, and up to five secondary read-only clusters in other Regions, each with up to 16 read replicas.
  • Use it for low-latency reads for users in other Regions, and for disaster recovery from a Regional outage.

3. Query Languages and Related Features

Problem Statement

The FlashCart analysts use three different tools. One team already knows Apache TinkerPop traversals, another knows the Cypher language from another graph database, and a data team works with linked data in RDF. The company also wants a notification when the graph changes, and a bulk load from files in S3.

3.1 Query Languages

LanguageGraph modelNotes
Apache TinkerPop GremlinProperty graphA traversal language: you walk from node to node along the edges.
openCypherProperty graphA declarative language that describes the pattern to match.
SPARQLRDF graphThe W3C standard query language for RDF data.
  • Neptune supports all three, and it supports both graph models. You can query property graph data with either Gremlin or openCypher.
  • Neptune does not support every step or feature of these languages. Check the supported features.

3.2 Related Features

  • Neptune Streams give a real-time, strictly ordered sequence of every change to the graph. They are available through an HTTP REST API, and you can use them to send notifications or to keep another store, such as S3 or OpenSearch (lesson 272.14), in sync.
  • A change is available in the stream immediately after it is written. The stream has no duplicates and keeps a strict order.
  • Uses of Neptune Streams: send notifications when certain changes are made, keep the graph data synchronized in another data store such as Amazon S3, Amazon OpenSearch Service, or Amazon ElastiCache, and replicate data across Regions.
  • Bulk load imports large datasets into Neptune from files in Amazon S3.
  • Neptune Analytics is a separate analytics engine for fast, in-memory analysis of large graph datasets, including graph algorithms and similarity search on vectors that are stored with the graph for generative AI applications.
  • Neptune ML adds machine learning on graph data, with Amazon SageMaker.

3.3 Exam-Style Question

Written for this course.

Scenario: A team wants to keep a search index in Amazon OpenSearch Service in sync with every change that is made to its Neptune graph, in the same order. Which Neptune feature meets the requirement?

  • A. Neptune Streams.
  • B. Neptune bulk load.
  • C. A Neptune snapshot.
  • D. The reader endpoint.
Show Answer and Explanation

Correct answer: A. Neptune Streams record each change to the graph in order, and a reader application can apply them to another store.

CIncorrectA snapshot is a point-in-time copy, not a change feed.

Remember these points:

  • Gremlin and openCypher query property graphs. SPARQL queries RDF.
  • Neptune Streams are the change feed. Bulk load imports from S3.
  • Neptune Analytics is a separate engine for analysis.

Gremlin walks. Cypher matches patterns. SPARQL queries RDF.

4. Serverless, Security, and Backup

Problem Statement

FlashCart traffic to the recommendation graph is only high during the day. The security team asks who can query the graph and how it is encrypted, and the operations team asks how to recover from a bad bulk load.

4.1 Neptune Serverless

  • Neptune Serverless scales the compute capacity of an instance up and down automatically with the workload, in Neptune capacity units (NCUs). One NCU is about 2 GiB of memory.
  • You pay per second for the capacity that you use.
  • It supports Gremlin, openCypher, and SPARQL, and the same high availability as a provisioned cluster.

4.2 Security

  • The cluster runs in your VPC, and security groups control access.
  • IAM database authentication controls who can connect, and applications use HTTPS connections.
  • Encryption at rest uses AWS KMS.

4.3 Backup and Restore

  • Neptune takes automated backups that allow point-in-time recovery, and you can take manual snapshots.
  • A restore creates a new cluster.

5. Neptune Pricing

Problem Statement

The FlashCart finance team asks what Neptune costs and what the levers are.

5.1 What You Pay For

Prices change often and differ by Region. Check the current rates on the Amazon Neptune pricing page, and estimate your own cost with the AWS Pricing Calculator.

  • Instances: instance hours for the primary and each replica, or NCU-seconds for Neptune Serverless.
  • Storage: a price per GB-month for the storage that the cluster uses.
  • I/O: requests to the storage, depending on the configuration that you choose.
  • Backups: backup storage beyond the included amount, and snapshots.
  • Data transfer: for example, replication in a global database.

5.2 Lowering the Cost

  • Use Serverless for a variable workload.
  • Use only the replicas that you need for reads and availability.
  • Delete old snapshots.

Exam Trap

Remember these points:

  • Each read replica adds an instance cost.
  • Serverless capacity is billed per second in NCUs.

Memory Hook

Replicas cost instance hours. Serverless costs NCU-seconds.

SAA-C03 Keyword Triggers

Trigger 1: “Variable graph workload that should not pay for idle capacity”
→ Amazon Neptune Serverless

Trigger 2: “Lower the cost of a cluster with replicas that nobody reads”
→ Keep only the read replicas that you need

Trigger 3: “Old Neptune backups that you no longer need”
→ Delete the old snapshots

6.4 Lesson Summary

This lesson covered the following points:

  • A graph database stores nodes and the edges between them. Amazon Neptune is the managed graph database for highly connected data, such as social networks, recommendations, and fraud detection.
  • A Neptune cluster has one primary and up to 15 read replicas on a shared volume that keeps six copies in three zones and grows up to 128 TiB. Global Database adds up to five secondary Regions.
  • Neptune supports Gremlin and openCypher for property graphs, and SPARQL for RDF. Streams give an ordered change feed, and Neptune Analytics analyzes large graphs.
  • Neptune Serverless follows the load in NCUs. IAM authentication, KMS encryption, and point-in-time recovery protect the data.

Nodes and edges. Many hops mean Neptune. Gremlin walks, Cypher matches, SPARQL speaks RDF.

7. Knowledge Check

Answer each question in your own words before you open the model answer. The questions were written for this course.

Question 1: Explain what a graph database is, and give two use cases for Amazon Neptune.

Maps to: Objectives 1 and 2 (Comprehension).

A graph database stores data as nodes, which are the entities, and edges, which are the relationships between them, and both can have properties. It is built for queries that follow many relationships. Amazon Neptune is the managed graph database. Typical uses are social networks, recommendations, fraud detection, knowledge graphs, and shortest-path routing.

Question 2: Describe how a Neptune cluster stores data and handles a failure.

Maps to: Objective 3 (Comprehension).

A cluster has one primary and up to 15 read replicas on a shared cluster volume. The volume keeps six copies of the data across three Availability Zones and grows automatically up to 128 TiB. If the primary fails, Neptune promotes one of the replicas in any of the three zones. The cluster endpoint then points to the new primary, and the reader endpoint balances the reads.

Question 3: Compare Gremlin, openCypher, and SPARQL.

Maps to: Objective 4 (Analysis).

Gremlin, from Apache TinkerPop, is a traversal language for property graphs. openCypher is a declarative pattern-matching language for property graphs. SPARQL is the W3C standard language for RDF graphs. Neptune supports all three, but not every feature of each language.

Question 4: Explain the purpose of Neptune Streams, the bulk loader, Neptune Analytics, and Neptune Serverless.

Maps to: Objective 5 (Comprehension).

Streams give an ordered change feed of the graph, for notifications or for keeping another store in sync. The bulk loader imports large datasets from Amazon S3. Neptune Analytics is a separate in-memory engine for graph algorithms and vector similarity search. Neptune Serverless adjusts compute capacity in NCUs to the workload.

Question 5: Choose the right database for four scenarios: a friends-of-friends feature, a shopping cart, an order system with joins, and a MongoDB catalog.

Maps to: Objective 6 (Evaluation).

Use Neptune for friends of friends, because it follows relationships over many hops. Use DynamoDB for a shopping cart, which is a key lookup at scale. Use RDS or Aurora for orders that need joins and transactions. Use DocumentDB for the MongoDB catalog, because it keeps the MongoDB drivers.
