AWS Lake Formation

Govern, secure, and share the data in an Amazon S3 data lake: how AWS Lake Formation sets up a data lake, controls access to tables, columns, and rows, and shares data across accounts.

Overview and Objectives

Lesson Overview

AWS Analytics Services

A data lake in Amazon S3 can hold data from every team in a company. The more data it holds, the more important it becomes to control who can see which table, column, and row. This lesson covers the AWS service that centralizes that control: AWS Lake Formation.

AWS Lake Formation helps you centrally govern, secure, and share the data in a data lake. It builds on the AWS Glue Data Catalog, and it adds fine-grained permissions that engines such as Amazon Athena, Amazon EMR, and Amazon Redshift Spectrum enforce. This lesson explains what Lake Formation is, how to set up a data lake with it, how its permissions work, and how it handles sharing, auditing, and pricing. The last two tabs prepare you for the AWS Certified Solutions Architect – Associate (SAA-C03) exam and check what you learned.

1. Introduction to AWS Lake Formation

Problem Statement

FlashCart’s data lake in Amazon S3 now holds orders, customer profiles with names and email addresses, and finance reports. Analysts, the marketing team, and the finance team all query it with Amazon Athena. Today the company controls access with IAM policies and S3 bucket policies, one prefix at a time.

The security team cannot answer a simple question: who can see the customer email column? A new company rule also says that the marketing team must never see email addresses.

Your challenge:

  • Explain why object-level S3 permissions are not enough.
  • Name the service that manages permissions on tables, columns, and rows.
  • Describe where that service keeps the metadata.

1.1 Introduction to AWS Lake Formation

  • AWS Lake Formation helps you centrally govern, secure, and share data for analytics and machine learning.
  • It manages fine-grained access control for the data in your data lake in Amazon S3, and for its metadata in the AWS Glue Data Catalog.
  • It gives you one place to define who can see which database, table, column, row, and cell.
  • It also helps you build the data lake: it can import data from databases, crawl and catalog the data, and prepare it for analytics (tab 2).
  • The permissions that you define are enforced by the analytics services that read the data, such as Amazon Athena, AWS Quick (lesson 272.15), Amazon Redshift Spectrum, Amazon EMR, and AWS Glue.

1.2 Why IAM Alone Is Not Enough

  • An IAM policy or an S3 bucket policy controls access to Amazon S3 objects and prefixes. It cannot say “this user may read the Region and Spend columns but not the Email column.”
  • Without Lake Formation, a user who queries a table with Athena needs three kinds of permissions: read access to the S3 objects, permission to run Athena queries, and permission to read the table definitions in the Glue Data Catalog. All of them are IAM permissions, and they are set per object.
  • With Lake Formation, the user needs Lake Formation permissions on the database, table, column, or row. Direct access to the S3 objects is not needed to query the data.

1.3 Lake Formation Components

ComponentWhat it does
Data lake locationAn Amazon S3 path that you register with Lake Formation. Lake Formation then governs the data under that path.
AWS Glue Data CatalogThe central metadata repository. Lake Formation uses it to store the databases and tables, and it enforces permissions on them.
Lake Formation permissionsA permissions model that is similar to a relational database. You grant or revoke access to databases, tables, columns, and rows.
Data lake administratorA user or role that manages the data lake and its permissions.
Workflows and blueprintsTemplates that automate the steps to ingest data into the data lake (2.3).
  • The Lake Formation permissions model augments the IAM permissions model. IAM still decides who can call the AWS APIs, and Lake Formation decides who can see which data.

1.4 Services That Use Lake Formation

  • Lake Formation permissions are enforced across Amazon Athena, AWS Quick, Amazon Redshift Spectrum, Amazon EMR, and AWS Glue.
  • The engine asks Lake Formation whether the user may read the data. If the user may, Lake Formation gives the engine temporary credentials and the list of allowed columns, and the engine applies the row and cell filters (3.5).
  • You define the permissions once, and every integrated engine follows them.

Exam Trap

Remember these points:

  • Lake Formation is the answer for fine-grained access control at table, column, row, and cell level on an Amazon S3 data lake.
  • IAM policies and S3 bucket policies control access to objects. They cannot hide a column or filter rows.
  • Lake Formation builds on the AWS Glue Data Catalog. It does not replace it, and it does not store the data.
  • Lake Formation permissions augment IAM. They do not replace it.

Memory Hook

2. Setting Up a Data Lake

Problem Statement

FlashCart wants to bring its order database in Amazon RDS and its log files in Amazon S3 into the data lake. It wants to catalog the data and secure it with one set of tools. The data team is small, and it wants to avoid writing a custom script for each data source.

Your challenge:

  • Decide how to bring the Amazon S3 data under Lake Formation control.
  • Choose how to import and catalog the database and the log files.
  • Decide who is allowed to manage the data lake.

2.1 Introduction to Data Lake Setup

  • Lake Formation helps you break down data silos. You combine structured and unstructured data from several sources in one central repository.
  • The steps are: identify the data sources, move the data into the data lake, crawl and catalog the data, and give users secure access through their choice of analytics services.
  • The data stays in Amazon S3. The metadata goes to the AWS Glue Data Catalog.

2.2 Registering a Data Lake Location

  • A data lake location is an Amazon S3 bucket or path that you register with Lake Formation.
  • After you register a location, Lake Formation can govern the data under that path and give analytics engines temporary access to it.
  • When you register a location, you also give Lake Formation an IAM role that it can assume to read the data. The role needs access to the Amazon S3 location and to any AWS KMS keys that encrypt it.
  • A data lake administrator manages the data lake. This person registers the locations and grants the permissions.

2.3 Importing and Cataloging Data

  • Databases in AWS: Lake Formation can import data from MySQL, PostgreSQL, SQL Server, MariaDB, and Oracle databases that run in Amazon RDS or on Amazon EC2. It reads the data and its schema, imports the data into the data lake, and records the metadata in the catalog. Both bulk and incremental loading are supported.
  • On-premises databases: use a JDBC connection. For other databases, create custom ETL jobs with AWS Glue.
  • Files in Amazon S3: use AWS Glue crawlers to read the files, find the database and table schemas, and store them in the Data Catalog (Lesson 272.10).
  • After the tables are in the catalog, label them and set permissions (tab 3).

2.4 Workflows and Blueprints

  • A workflow encapsulates a complex ETL activity that has several steps. It generates AWS Glue crawlers, jobs, and triggers that orchestrate the loading and updating of data.
  • Lake Formation runs and tracks a workflow as a single unit. You can run it on demand or on a schedule.
  • A blueprint is a template that you use to create a workflow. You give it the import source, the import target (a database, an Amazon S3 location, and a data format), and an import frequency.
  • When a workflow finishes, the user who ran it gets the Lake Formation SELECT permission on the tables that it created.
  • Workflows that you create in Lake Formation are visible in the AWS Glue console as a graph of jobs, crawlers, and triggers.
Blueprint typeWhat it does
Database snapshotLoads or reloads the data of all tables from a JDBC source. You can exclude some data with an exclude pattern.
Incremental databaseLoads only new data from a JDBC source, based on bookmarks that it sets. You choose the tables to include.
Log fileBulk loads data from log files, including AWS CloudTrail (lesson 274.3) logs, Elastic Load Balancing logs, and Application Load Balancer logs.

2.5 Bringing Other Data Into the Catalog

  • Lake Formation can also manage permissions on data that stays in other sources. You create a federated catalog in the Data Catalog, and you do not copy the data.
  • Examples include data in Amazon Redshift data warehouses, in Amazon DynamoDB, and in third-party sources such as Google BigQuery and MySQL.
  • Lake Formation also supports licensing access to data through AWS Data Exchange (a later lesson).

Exam Trap

Remember these points:

  • To put data under Lake Formation control, register the Amazon S3 location and catalog the data in the AWS Glue Data Catalog.
  • A Glue crawler discovers the schema of files in Amazon S3. Lake Formation can also import data from databases in Amazon RDS and on Amazon EC2.
  • A blueprint configures a workflow that automates data ingestion.

3. Permissions and Access Control

Problem Statement

FlashCart now has 300 tables in the Data Catalog. The marketing, finance, and analytics teams each need different tables, and different columns of the customer table. Writing one grant for each table for each team does not scale.

The marketing team must not see the email column, and each finance analyst must see only the rows of their own Region.

Your challenge:

  • Manage permissions for hundreds of tables without one grant for each table.
  • Hide the email column from the marketing team.
  • Limit the rows that each finance analyst can see.

3.1 The Lake Formation Permissions Model

  • Lake Formation uses its own permissions model, which augments the IAM permissions model.
  • You grant and revoke permissions much as you do in a relational database. A user or role can get SELECT on a table, for example.
  • The permissions apply to IAM users and roles, and to users and groups that sign in through an external identity provider.
  • The data lake administrator manages the permissions in one place.

3.2 Named Resource Permissions

  • A named resource grant gives a permission on a specific database or table by name. An example is a grant of SELECT on the table company.finance.
  • You can limit a grant to specific columns of the table.
  • Named grants are simple and clear, but with hundreds of tables they become hard to manage.

3.3 Tag-Based Access Control With LF-Tags

  • An LF-Tag is a custom label, a key and a value, such as department=finance.
  • You attach LF-Tags to databases, tables, or columns, and you grant users permissions on the tags. A user who has a permission on department=finance can then read every resource that carries that tag.
  • LF-Tags replace the policy definitions of thousands of resources with a few logical tags, so governance scales.
  • Lake Formation also supports attribute-based access control (ABAC), which grants access by matching tags on the IAM principal with tags on the resource.

3.4 Row, Column, and Cell-Level Security

  • Column-level permissions let a user see some columns of a table and not others.
  • Data filters restrict access to a combination of rows and columns. A filter that limits rows is row-level security. A filter that limits both rows and columns is cell-level security.
  • Use row-level and cell-level security to protect sensitive data, such as personally identifiable information.
  • FlashCart uses a filter for the marketing team: it hides the Email column. For a finance analyst, it keeps only the rows of one Region.

3.5 How a Query Is Authorized

This sequence follows the course slides. An analyst runs a query in Amazon Athena, or in another engine, on a table that Lake Formation governs:

  1. The data user submits the query to Athena, or to another engine.
  2. The engine gets the table metadata from the AWS Glue Data Catalog.
  3. Lake Formation checks the permissions of the user.
  4. If the user is allowed, Lake Formation gives the engine temporary credentials.
  5. The engine uses the credentials to read the data in Amazon S3, applies the column, row, or cell filtering, and returns only the data that the user may see.
  • Because Lake Formation gives the credentials, the data user does not need direct access to Amazon S3, and you do not need to change the S3 bucket policies or IAM policies when you grant permissions.
  • If the user is not authorized, Lake Formation denies access and the query fails.

Exam Trap

Remember these points:

  • Use LF-Tags to manage permissions for many tables with a few tag grants. A grant for each table does not scale.
  • Column-level permissions hide columns. Data filters limit rows, and rows and columns together give cell-level security.
  • With Lake Formation, users need Lake Formation permissions, and direct Amazon S3 access is not needed for querying.
  • The data lake administrator, not the data user, manages the permissions.

4. Sharing, Auditing, and Pricing

Problem Statement

A FlashCart partner runs its analytics in a different AWS account. The partner needs the product sales tables, but FlashCart does not want to copy the data. FlashCart already uses IAM-based access for several teams, and it cannot switch them all to Lake Formation at once.

The auditors also ask who accessed the customer data last quarter, and the finance team wants to know what Lake Formation costs.

Your challenge:

  • Share the tables with another account without copying the data.
  • Adopt Lake Formation step by step, without breaking existing access.
  • Show the access history, and estimate the cost.

4.1 Cross-Account Sharing

  • Lake Formation can share data with other AWS accounts, with an entire AWS organization, or directly with an IAM principal in another account.
  • You share the Data Catalog metadata and the underlying data, with the same fine-grained permissions. The data is not copied.
  • The administration stays central, in the account that owns the data.

4.2 Hybrid Access Mode

  • Hybrid access mode lets you secure the same cataloged data with both Lake Formation permissions and IAM policies.
  • You can enable Lake Formation permissions for selected databases and tables and for a selected set of users, without interrupting the policies of other users and workloads.
  • This gives an incremental path: onboard one data lake use case at a time.

4.3 Audit Logging

  • Lake Formation records audit logs in AWS CloudTrail.
  • The logs show which users or roles tried to access what data, with which services, and when. They cover the analytics and machine learning services that read the data through Lake Formation.
  • You read the logs in the same way as other CloudTrail logs. You can also query them with Athena (Lesson 272.11).

4.4 Lake Formation Pricing

Prices change often and differ by Region. Check the current details on the AWS Lake Formation pricing page.

  • According to the AWS pricing page, the Lake Formation permissions (database, table, column, row, and cell level, by tag or by name) and cross-account sharing have no additional charge.
  • Standard rates for the integrated services still apply, such as Amazon S3 and the AWS Glue Data Catalog.
  • Some separate Lake Formation features are charged, such as the Storage API, Governed Tables, and the storage optimizer. Check the pricing page before you use them.
  • Services that you use with Lake Formation, such as Athena, EMR, and Glue jobs, are billed by their own pricing models.

Exam Trap

Remember these points:

  • Cross-account sharing with Lake Formation shares the catalog tables and the data without copying them.
  • Hybrid access mode allows Lake Formation permissions and IAM policies together, so teams can move step by step.
  • Audit logs for Lake Formation are in AWS CloudTrail.
  • The Lake Formation permissions have no extra charge. You pay for the integrated services.

5.2 When to Use Lake Formation

5.2.1 Use AWS Lake Formation When

  • Different teams need different tables, columns, or rows of the same data lake.
  • You need one central place to define and audit access.
  • You want to share data lake tables with other accounts without copying the data.
  • You want to set up a data lake quickly, with ingestion, cataloging, and security together.

5.2.2 Use Another Control When

  • IAM and bucket policies: you only need to allow or deny access to whole buckets, prefixes, or API calls.
  • AWS Glue: you need to transform the data, or to catalog files with a crawler.
  • Amazon Athena: you need to run SQL queries. Lake Formation decides what the query may see.

5.4 Lesson Summary

This lesson covered the following points:

  • AWS Lake Formation helps you centrally govern, secure, and share data in an Amazon S3 data lake, and it manages the metadata in the AWS Glue Data Catalog.
  • IAM and S3 bucket policies work at the object level. Lake Formation adds permissions at the database, table, column, row, and cell level, and its permissions augment IAM.
  • You register an Amazon S3 location, import and catalog the data, and optionally automate ingestion with workflows and blueprints.
  • You manage permissions with named grants, LF-Tags, column-level permissions, and data filters. Athena, AWS Quick, Redshift Spectrum, EMR, and AWS Glue enforce them.
  • In a query, the engine gets the metadata, Lake Formation checks the permissions and gives temporary credentials, and the engine reads Amazon S3.
  • Lake Formation shares data across accounts without copying it, supports hybrid access mode, logs access in AWS CloudTrail, and has no additional charge for its permissions.

Use a data filter with a row condition on the Region for each finance analyst, which gives row-level security, and combine rows and columns for cell-level security. To manage 300 tables, attach LF-Tags such as department=finance to databases, tables, and columns, and grant the teams permissions on the tags. Question 5: Describe what happens when an analyst runs an Athena query on a table that Lake Formation governs.

Maps to: Objective 5 (Comprehension).

Athena gets the table metadata from the AWS Glue Data Catalog. Lake Formation checks the permissions of the user. If the user is allowed, Lake Formation gives Athena temporary credentials. Athena reads the data in Amazon S3 with those credentials, and it returns only the columns and rows that the user may see. The user needs Lake Formation permissions, and no direct Amazon S3 access.

Question 6: Explain cross-account sharing, hybrid access mode, and audit logging in Lake Formation, and say how Lake Formation is priced.

Maps to: Objective 6 (Comprehension).

Cross-account sharing lets you share catalog tables and their data with other accounts, an organization, or an IAM principal in another account, with fine-grained permissions and without copying the data. Hybrid access mode lets Lake Formation permissions and IAM policies secure the same data, so you can adopt Lake Formation for one use case at a time. Audit logs go to AWS CloudTrail and show who tried to access which data, with which service, and when. According to the AWS pricing page, the Lake Formation permissions and cross-account sharing have no additional charge, and you pay for the integrated services, such as Amazon S3 and the Glue Data Catalog.

Question 7: Differentiate Lake Formation from IAM policies and the AWS Glue Data Catalog, and name one requirement that points to Lake Formation.

Maps to: Objectives 7 and 8 (Analysis).

IAM and S3 bucket policies control access to objects and API calls. The Glue Data Catalog stores metadata and is not a permissions service on its own. Lake Formation uses the catalog and adds central, fine-grained permissions at the table, column, row, and cell level, and it augments IAM. A requirement that different teams see different columns and rows of the same S3 data lake, managed in one place, points to Lake Formation.

Question 8: Design a governed data lake for FlashCart that serves marketing, finance, and a partner in another AWS account.

Hide the email column from marketing with column-level permissions, and use data filters to limit finance analysts to their own Region.
