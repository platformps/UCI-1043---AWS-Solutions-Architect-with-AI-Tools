1. AWS Database Migration Service

Problem Statement

FlashCart buys a small marketplace company. The seller and inventory data of the marketplace sits in an Oracle database in an office data center. FlashCart wants this data in Amazon Aurora (lesson 272.2), which its engineers already run, and the marketplace cannot stop taking orders for hours.

The team needs a way to copy the data and keep it up to date until the day that the marketplace switches over.

Your challenge:

  • Choose a service to move the database with minimal downtime.
  • Explain how the service copies the existing data and the new changes.
  • Choose between the deployment options of the service.

1.1 Introduction to AWS DMS

  • AWS Database Migration Service (AWS DMS) is a managed migration and replication service. It moves databases and analytics workloads to AWS.
  • The source database stays fully operational during the migration, so the applications that use it have minimal downtime.
  • AWS DMS can also replicate data continuously with low latency, for example from several sources into an Amazon S3 data lake, or into Amazon Redshift (lesson 272.8).

1.2 Homogeneous and Heterogeneous Migrations

TypeMeaningExamplesBefore the data moves
HomogeneousThe source and target engines are the same or compatible.Oracle to Oracle; MySQL to Amazon AuroraCopy the schema with the tools of the engine, or with the AWS SCT.
HeterogeneousThe source and target engines are different.Oracle or Microsoft SQL Server to Amazon AuroraConvert the schema and the code first (tab 2).

1.3 How a Migration Runs

A typical migration has five steps:

  1. Create the target database.
  2. Migrate the schema (tab 2).
  3. Create a task. Specify the source endpoint and the target endpoint, choose a replication instance, and accept the default schema mapping rules or define your own.
  4. Run the task. AWS DMS does a full load of the existing data, and then applies the changes with change data capture (CDC).
  5. Perform the cutover: switch the application to the new database when the target has caught up with the source.

For continuous replication, the only difference is that there is no cutover. The task runs until you change or stop it.

1.4 Deployment Options

OptionHow it runsBest for
Replication instanceYou choose the size of the instance. A Multi-AZ option adds a redundant instance.Predictable, stable data transfers that you can size for performance and cost.
AWS DMS ServerlessIt provisions, monitors, and scales the resources automatically. It supports Single-AZ and Multi-AZ.Heterogeneous migrations, and continuous replication where the amount of data changes.
Homogeneous data migrationsBuilt-in native tooling that is serverless and does not use a replication instance.Homogeneous migrations between supported engines.

1.5 Limits to Know

  • Either the source or the target, or both, must be in Amazon RDS or on Amazon EC2.
  • Replication from an on-premises database to another on-premises database is not supported.

Exam Trap

Remember these points:

  • AWS DMS is the answer for moving a database with minimal downtime. It is not the answer for files or servers.
  • A heterogeneous migration needs the schema and code converted first. AWS DMS moves the data.
  • On-premises to on-premises replication is not supported. One side must be in RDS or on EC2.
  • Use full load plus CDC to keep the source online. A full load alone does not copy the changes that happen during the copy.

Memory Hook

Full load first, then the changes, then the cutover.

1.6 Exam-Style Question

Written for this course.

Scenario: A company must move a 2 TB MySQL database from its data center to Amazon RDS for MySQL. The application can stop for only a few minutes at the cutover. Which solution meets the requirements?

  • A. Use AWS DMS with a full load and change data capture, and switch the application to the target when the target has caught up.
  • B. Use AWS DataSync (lesson 271.3) to copy the database files to Amazon S3, and restore them in Amazon RDS.
  • C. Stop the database, take a backup, and restore the backup in Amazon RDS.
  • D. Use AWS Storage Gateway (lesson 271.3) to present the database files to Amazon RDS.
Show Answer and Explanation

Correct answer: A. AWS DMS keeps the source database online, copies the existing data, and applies the changes until the cutover, so the downtime is only the switch.

OptionResultReason
ACorrectThe full load and CDC keep the source online, and the cutover is short.
BIncorrectDataSync copies files. It does not apply the changes that happen after the copy, so the database would stop or lose changes.

2. Schema Conversion, Security, and Pricing

Problem Statement

The marketplace database holds more than tables. It also holds stored procedures that are written in Oracle PL/SQL, and the target, Amazon Aurora PostgreSQL-Compatible Edition, uses a different procedural language called PL/pgSQL.

The security team asks how the migration traffic is protected, and the CFO asks what the migration costs.

Your challenge:

  • Choose how to convert the schema and the stored procedures.
  • Explain what the conversion tools do and do not do.
  • Explain how a migration is made reliable and secure, and what you pay for.

2.1 Why Schema Conversion Matters

  • A database holds code, such as stored procedures, in the dialect of one engine.
  • When the engines differ, the schema and the code must be converted before the new engine can use them. A heterogeneous migration is therefore a two-step process.
  • Two tools convert them: DMS Schema Conversion, which is part of AWS DMS, and the downloadable AWS Schema Conversion Tool (AWS SCT).

2.2 DMS Schema Conversion and the AWS SCT

FeatureDMS Schema ConversionAWS SCT
What it isA feature of AWS DMS.A downloadable application.
What it convertsOracle PL/SQL and SQL Server T-SQL code to the Amazon RDS for MySQL dialect, or to PL/pgSQL in PostgreSQL.Database conversions, such as Oracle to PostgreSQL, and data warehouse conversions, such as Netezza to Amazon Redshift.
Ongoing replicationNot its job. AWS DMS does the replication.Not supported.
Typical workloadRelational databases.AWS SCT is primarily used for large data warehouse workloads.

2.3 What the Conversion Does Not Do

  • Some code cannot be converted automatically. DMS Schema Conversion documents the locations that need manual input from the application developer.
  • Neither tool replaces the data migration. AWS DMS moves the data and keeps the target in sync.

2.4 Reliability and Security

  • A Multi-AZ option uses redundant replication instances for high availability of the migration.
  • AWS DMS secures the connections to the endpoints with SSL/TLS.
  • It creates the replication instances in an Amazon VPC, which isolates them and gives you control of the networking.
  • Data validation compares the source and the target data to find differences.
  • AWS DMS integrates with AWS CloudTrail and Amazon CloudWatch Logs.

2.5 Pricing

  • You pay for the replication instances and for any additional log storage. The AWS DMS FAQ states that data transfer is free.
  • DMS Schema Conversion is free. You pay only for the storage that it uses.
  • A Database Savings Plan can reduce the AWS DMS cost by up to 20 percent with a one-year commitment.
  • Check the AWS DMS pricing page for current prices.

Exam Trap

Remember these points:

  • Schema conversion is not data migration. Converting the code does not copy the data.
  • The AWS SCT does not support ongoing replication. AWS DMS does.
  • Use DMS Schema Conversion or the AWS SCT when the engines differ, for example Oracle to Aurora PostgreSQL.

Memory Hook

Convert first, then move.

SAA-C03 Keyword Triggers

Trigger 1: “Convert Oracle PL/SQL or SQL Server T-SQL code to PostgreSQL”
→ DMS Schema Conversion or the AWS SCT

Trigger 2: “Convert the schema of a data warehouse such as Netezza to Amazon Redshift”
→ AWS SCT

Trigger 3: “High availability for the migration itself”
→ A Multi-AZ replication instance or AWS DMS Serverless with Multi-AZ

Trigger 4: “Check that the source and the target data match”
→ AWS DMS data validation

3.3 Lesson Summary

This lesson covered the following points:

  • AWS DMS is a managed service that migrates and replicates databases. The source stays online during the migration.
  • A migration runs as a full load, then CDC, then a cutover. A continuous replication task has no cutover.
  • Homogeneous migrations use the same or compatible engines. Heterogeneous migrations need the schema and code converted first.
  • AWS DMS runs on a replication instance or as DMS Serverless, and homogeneous data migrations use serverless native tooling.
  • DMS Schema Conversion and the AWS SCT convert schemas and code. The AWS SCT does not replicate, and AWS DMS does.

Memory Hook

Convert the shape with SCT, move the data with DMS.

4. Knowledge Check

Answer each question in your own words before you open the model answer. The questions were written for this course.

Question 1: Explain what AWS DMS is, and describe the stages of a migration with minimal downtime.

Maps to: Objectives 1 and 2 (Comprehension).

AWS DMS is a managed migration and replication service. You create endpoints and a task. The task does a full load of the existing data, and then applies the changes with change data capture while the source stays online. When the target has caught up, you switch the application to it. That switch is the cutover, and it is the only downtime.

Question 2: Differentiate homogeneous from heterogeneous migrations, and say what each needs before the data moves.

Maps to: Objective 2 (Comprehension).

A homogeneous migration moves between the same or compatible engines, such as MySQL to Amazon Aurora. The schema can be copied with the tools of the engine or with the AWS SCT. A heterogeneous migration moves between different engines, such as Oracle to Amazon Aurora. The schema and the code must be converted first, so it is a two-step process.

Question 3: Compare the three AWS DMS deployment options.

Maps to: Objective 3 (Comprehension).

A replication instance is sized by you, and it fits predictable, stable transfers. AWS DMS Serverless provisions, monitors, and scales the resources automatically, and it fits heterogeneous migrations and continuous replication where the data volume changes. Homogeneous data migrations use built-in serverless native tooling with no replication instance, for supported engines.

Question 4: Explain what DMS Schema Conversion and the AWS SCT do, and what they cannot do.

Maps to: Objective 4 (Comprehension).

They convert the schema and the code of the source to the dialect of the target, for example Oracle PL/SQL to PL/pgSQL. They mark the code that cannot be converted automatically so that a developer can finish it. They do not move the data, and the AWS SCT does not support ongoing replication.

Question 5: A team must move an NFS file share, a database, and a group of servers to AWS. Choose a service for each, and say why.

Maps to: Objective 5 (Application).

Use AWS DataSync for the NFS files, because it copies on a schedule and verifies the data. Use AWS DMS for the database, because it migrates the data with minimal downtime. Use AWS Application Migration Service for the servers, because it is the server migration service.

Question 6: Design a low-downtime migration of an on-premises SQL Server database to Amazon Aurora PostgreSQL.

Maps to: Objective 6 (Synthesis).

Create the Aurora PostgreSQL cluster. Convert the schema and the T-SQL code with DMS Schema Conversion or the AWS SCT, and finish the code that is marked for manual work. Create the endpoints and a task in AWS DMS, with a replication instance or DMS Serverless, and run a full load followed by CDC. Use data validation to compare the data, and switch the application at the cutover. The target is in AWS, which meets the rule that one side must be in RDS or on EC2.
