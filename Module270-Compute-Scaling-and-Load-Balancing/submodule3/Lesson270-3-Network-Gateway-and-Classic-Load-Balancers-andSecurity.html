Lesson 270.3 - Network, Gateway and Classic Load Balancers, and Security

The Network Load Balancer, the Gateway Load Balancer, and the Classic Load Balancer, how the four types compare, which client IP address a target sees, and how to secure a load balancer with security groups, SSL/TLS certificates, and Server Name Indication.

Lesson Overview

This lesson covers the following topics:

  • Network Load Balancer — layer 4 performance, static and Elastic IP addresses, and when to put it in front of an Application Load Balancer (ALB).
  • Gateway Load Balancer — a transparent gateway and load balancer for third-party security appliances.
  • Classic Load Balancer — the legacy type, its limits, and how to move away from it.
  • Client IP Preservation — which address a target sees behind an Application Load Balancer and a Network Load Balancer, and how to get the real client IP address.
  • Securing Load Balancers — security groups, Secure Sockets Layer and Transport Layer Security (SSL/TLS) basics, load balancer certificates, Server Name Indication (SNI), and SSL termination.
  • Load Balancer Certificates — what an SSL certificate does, how SSL and TLS differ, and who issues public certificates.
  • Server Name Indication — how one load balancer holds several certificates, and which services support it.
  • Comparison and Scenarios — a comparison of the four types, scenarios, a cheat sheet, and two exam-style questions.

Learning Objectives

By the end of this lesson, you will be able to:

  1. Describe the Network Load Balancer, the Gateway Load Balancer, and the Classic Load Balancer.
  2. Compare the four load balancer types.
  3. Explain which client IP address a target sees behind an Application Load Balancer and behind a Network Load Balancer, and how Proxy Protocol v2 passes the address on.
  4. Describe the security groups that a load balancer and its targets need.
  5. Explain SSL/TLS, load balancer certificates, Server Name Indication (SNI), and SSL termination.
  6. Apply security groups to a load balancer and its targets so that only the load balancer can reach the instances.
  7. Choose the load balancer type, the certificate, and the SNI settings for a stated requirement.
  8. Design a secure front end that gives a partner a static IP address, keeps layer 7 routing, and serves several domains over HTTPS.

1. Network Load Balancer

Problem Statement

Northwind's live auction uses User Datagram Protocol (UDP) and must handle millions of connections with very low delay. A bank partner will allow-list only fixed IP addresses, and the website's Application Load Balancer cannot give them.

You need a load balancer that works at layer 4, is very fast, and has static IP addresses.

1.1 What Is a Network Load Balancer?

  • Works at layer 4: it forwards Transmission Control Protocol (TCP), TLS, and UDP connections without reading the content.
  • Very high performance: it can handle millions of requests per second with very low latency.
  • Has one static IP address for each Availability Zone and supports Elastic IP addresses. This is the choice when a partner must allow-list a fixed IP address.
  • Can preserve the client's source IP address.
  • Targets: EC2 instances, IP addresses, and an Application Load Balancer.
  • Use cases: gaming, Internet of Things (IoT), real-time and streaming traffic, any non-HTTP protocol, and the front of an AWS PrivateLink endpoint service.
  • Trick: put a Network Load Balancer (NLB) in front of an Application Load Balancer (ALB) to get a static IP address and still use layer 7 routing.
  • A Network Load Balancer can be used with AWS PrivateLink to expose services privately.

1.2 Network Load Balancer: Target Groups

  • Targets: EC2 instances, IP addresses, and an Application Load Balancer.

1.3 Network Load Balancer vs. Application Load Balancer

Layer4 (transport)7 (application)
ProtocolsTCP, UDP, TLSHTTP, HTTPS, WebSocket

1.4 Static IP Addresses and Elastic IPs

  • For each Availability Zone (subnet) you enable, the NLB gets one IP address.
  • For an internet-facing NLB, you can assign an Elastic IP address to each one, so the addresses never change.
  • For an internal NLB, the address is a private IP address from the subnet.
  • Example: a partner allow-lists the two Elastic IP addresses. If you add targets or replace instances, the partner changes nothing.

1.5 Listeners, Targets, and Health Checks

  • Listeners accept TCP, UDP, TLS, or TCP_UDP (both) on the port you choose.
  • Targets are EC2 instances, IP addresses, or an Application Load Balancer.
  • Health checks can use TCP, HTTP, or HTTPS. A target that fails them gets no traffic.
  • The NLB does not read the content, so it has no path or host rules. It forwards each connection to a target in the target group.

1.6 Security, TLS, and Stickiness

  • An NLB can have security groups. For a design with one, treat it like the ALB: allow clients on the listener port, and allow only the load balancer on the targets (tab 5).
  • A TLS listener uses certificates from AWS Certificate Manager (ACM), with Server Name Indication (SNI) for several domains (tab 5).
  • Stickiness uses the client's source IP address, not a cookie (lesson 270.2, tab 2).
  • Cross-zone load balancing is off by default, and turning it on is charged for the data between Availability Zones.

1.7 NLB Proxy Protocol

  • Proxy Protocol is an Internet protocol used to carry information from the source (the client requesting the connection) to the destination (where the connection was requested).
  • Client IP preservation is a target group setting. It is on by default for instance targets, so the target sees the client's source IP address. For IP targets that use TCP or TLS, it is off by default, so the target sees the load balancer's private IP address.
  • Enable Proxy Protocol v2 (off by default) to pass the connection information, including the client address, to the backend.
  • When Proxy Protocol v2 is enabled, the NLB adds a small binary header to the TCP packet. The header contains:
    • The original source IP address and port (client).
    • The destination IP address and port (load balancer).
    • The protocol type (TCP, UDP, or TLS).
    • Optional fields for Secure Sockets Layer and Transport Layer Security (SSL/TLS) information.

2. Gateway Load Balancer

Problem Statement

The security team wants all traffic to Northwind's VPC to pass through a fleet of third-party firewall appliances that check it for attacks. The fleet must scale and survive the failure of one appliance, and the applications must not need to change.

You need a transparent gateway in front of the appliances that also load balances across them.

2.1 What Is a Gateway Load Balancer?

  • Works at layer 3 as a gateway, and balances load at layer 4: it handles IP packets, using the Generic Network Virtualization Encapsulation (GENEVE) protocol on port 6081.
  • Combines two jobs: a transparent network gateway, a single entry and exit point for all traffic, and a load balancer that spreads traffic across appliances.
  • Used to deploy, scale, and manage third-party virtual appliances: firewalls, intrusion detection and prevention systems, deep packet inspection, and payload manipulation.
  • You send traffic to it through Gateway Load Balancer endpoints and route tables.
  • Traffic is sent to Gateway Load Balancer (GWLB) endpoints (GWLBe) created in each VPC using AWS PrivateLink.
  • It integrates with partners such as Aviatrix, Cisco Systems, Fortinet, and Palo Alto Networks.
  • It is for inspection appliances, not for serving a website.

2.2 How the Traffic Flows

StepWhat happens
1Route tables send the traffic to a Gateway Load Balancer endpoint in your VPC
2The endpoint passes the packets to the Gateway Load Balancer
3The load balancer chooses an appliance and sends it the packets using GENEVE on port 6081. All packets of one flow go to the same appliance
4The appliance inspects the traffic and returns it to the load balancer
5The load balancer sends it back through the endpoint, and it continues to the application

2.3 Components

ComponentWhat it is
Gateway Load BalancerThe layer 3 gateway and load balancer that spreads the traffic across appliances
Gateway Load Balancer endpointThe entry and exit point in your VPC. Route tables point to it
Target groupThe group of virtual appliances, with health checks
Virtual appliancesThird-party firewalls, IDS or IPS, or deep packet inspection tools, for example from AWS Marketplace

2.4 Use Cases

  • Firewalls and intrusion detection and prevention for all traffic in or out of a VPC.
  • Deep packet inspection and payload manipulation.
  • Scale and update the appliance fleet without changing the applications.
  • One central inspection VPC shared by many VPCs, often together with a Transit Gateway (lesson 269.3).
  • It is not for serving a website: it passes traffic through appliances.
Exam trap: GWLB is for appliances, not for web traffic

Third-party firewall or IDS/IPS appliances and inspect all traffic mean the Gateway Load Balancer. It works at layer 3 with GENEVE on port 6081. It does not route HTTP by content (ALB) and does not give you a static IP for your application (NLB). AWS-native filtering uses AWS Network Firewall (lesson 268.9).

Memory hook

GWLB = a gateway and a load balancer for firewalls. Layer 3, GENEVE, 6081.

  • Trigger 2: "Inspect all VPC traffic with IDS/IPS appliances..."
    → Gateway Load Balancer
  • Trigger 3: "A transparent network gateway plus load balancing..."

3. Classic Load Balancer

Problem Statement

Northwind found an old application behind a Classic Load Balancer. It has only one certificate, cannot route by path, and the team wants to know whether to keep it.

You need to know what the Classic Load Balancer can do, why it is legacy, and what to use instead.

3.1 What Is a Classic Load Balancer?

  • The previous generation (2009), working at layer 4 and layer 7: HTTP, HTTPS, TCP, and Secure Sockets Layer (SSL).
  • Supports only one SSL certificate and has no path or host routing.
  • It is legacy and may still be found in older environments, such as applications that were built for the EC2-Classic network, which AWS retired on August 15, 2022. AWS recommends the ALB or NLB for new applications.
  • Health checks can use TCP, SSL, HTTP, or HTTPS, and it has a fixed hostname.

3.2 Limits Compared With the Newer Types

FeatureClassic Load BalancerALB and NLB
GenerationPrevious (2009)Newer (2016 and 2017)
Certificates on one load balancerOneSeveral, with SNI
Path, host, and header routingNoALB: yes
Lambda and IP targets, ECS dynamic portsNoYes
Static or Elastic IPNoNLB: yes
Recommended for new applicationsNoYes

3.3 Moving Away From a Classic Load Balancer

  • AWS recommends the newer generation load balancers, which provide more features.
  • Choose the ALB for HTTP and HTTPS applications, and the NLB for TCP, UDP, or a static IP.
  • Typical steps: create the new load balancer and a target group, register the same instances, test it, then move the DNS record from the old load balancer to the new one.
  • Keep the old load balancer until the new one has been checked, so you can go back.
Exam trap: the Classic Load Balancer is the legacy answer

CLB appears as the answer only for legacy applications, for example older ones built for EC2-Classic, which AWS retired in 2022. It supports one certificate and has no SNI. For several certificates, content routing, Lambda or IP targets, or a static IP, the answer is the ALB or NLB.

Memory hook

CLB = the old one: one certificate, no content routing.

4. Client IP Preservation

Problem Statement

The web servers of Northwind Shop log the same IP address for every request, so the team cannot tell which customer sent which request.

You need to know which address the target sees behind an Application Load Balancer and behind a Network Load Balancer, and how the target gets the real client IP address.

4.1 Client IP With an Application Load Balancer

  • With an ALB, the target (EC2 instance) sees the ALB's private IP address as the source.
  • To get the real client IP address, use the X-Forwarded-For header in the HTTP request.

4.2 Client IP With a Network Load Balancer

  • An NLB is a pass-through load balancer, but what the target sees depends on the client IP preservation setting of the target group.
  • For instance targets, client IP preservation is on by default, so the target sees the client's original IP address.
  • For IP targets that use TCP or TLS, it is off by default, so the target sees the load balancer's private IP address. For UDP target groups, it is always on.
  • When the target does not see the client IP address, turn on client IP preservation if the target group allows it, or enable Proxy Protocol v2 (off by default) to pass the address in a header (section 1.7).
Exam trap: the address depends on the load balancer and the target type

Behind an ALB, the target sees the ALB's private IP address, so it reads the client address from the X-Forwarded-For header. Behind an NLB, instance targets see the client IP address, and IP targets that use TCP or TLS see the load balancer unless the setting is on. Proxy Protocol v2 passes the details in a header.

Memory hook

ALB = look in the header (X-Forwarded-For). NLB = instance targets see the client, IP targets need the setting or Proxy Protocol v2.

SAA-C03 Keyword Triggers
  • Trigger 1: "Web servers behind an ALB log the load balancer's address instead of the client's..."
    → Read the X-Forwarded-For header
  • Trigger 2: "The target must see the client's source IP behind an NLB, and the targets are registered by IP address..."
    → Turn on client IP preservation, or enable Proxy Protocol v2
  • Trigger 3: "Pass the original client address and connection details to the backend in a header..."
    → NLB Proxy Protocol v2

5. Securing Load Balancers

Problem Statement

Northwind's customers log in and pay on the website, so the traffic must be encrypted. The company also runs shop.example.com and partners.example.com on the same load balancer. And the team found that someone could still reach an instance directly, skipping the load balancer.

You need security groups that force traffic through the load balancer, and certificates for HTTPS.

5.1 Load Balancer Security Groups

Security groupDirectionRuleWhy
Load balancer (SG-alb)InboundHTTP 80 and HTTPS 443 from 0.0.0.0/0 (for an internet-facing load balancer)Customers can reach the load balancer
Load balancer (SG-alb)OutboundThe application port to the targetsThe load balancer can reach the targets and run health checks
Instances (SG-app)InboundThe application port from SG-alb (the source is the load balancer's security group, not an IP range)Only the load balancer can reach the instances, so nobody can skip it
  • A security group as the source keeps working when the load balancer's IP addresses change, and when the load balancer scales.
  • The Application Load Balancer, the Network Load Balancer, and the Classic Load Balancer can have security groups. The Gateway Load Balancer does not use them.
  • For an NLB without a security group, the targets see the client's IP address and must allow the clients directly, so a security group on the NLB is the simpler design.
  • Keep instances in private subnets, so that they have no public address at all.

5.2 SSL/TLS Basics

  • An SSL/TLS certificate lets the traffic between the client and the load balancer be encrypted in transit (in-flight encryption). Only the two ends can read it.
  • This protects against eavesdropping and man-in-the-middle attacks, for example on a login or a payment.
  • SSL means Secure Sockets Layer. TLS means Transport Layer Security and is the newer version. Today, TLS certificates are what is used, but people still say "SSL".
  • HTTPS is HTTP carried over TLS.
  • Public certificates are issued by a Certificate Authority (CA), such as DigiCert, GlobalSign, Let's Encrypt, or Amazon.
  • A certificate names the domain, holds the public key, and has an expiration date. It must be renewed before it expires.
StepWhat happens
1The client connects and lists the TLS versions it supports
2The server sends its certificate
3The client checks the certificate against the Certificate Authorities it trusts, and checks the domain name and expiry
4Both sides agree on session keys
5The traffic is encrypted with those keys

5.3 Load Balancer SSL Certificates

  • The load balancer uses an X.509 certificate (an SSL/TLS server certificate).
  • Manage certificates with AWS Certificate Manager (ACM), or upload your own certificate.
  • An HTTPS listener (ALB) or TLS listener (NLB) must have a default certificate.
  • You can add an optional list of certificates to support several domains.
  • Clients use Server Name Indication (SNI) to tell the load balancer which hostname they want.
  • You choose a security policy that sets the TLS versions and ciphers, for example to support older clients.
  • The ACM certificate must be in the same Region as the load balancer.

5.3.1 Server Name Indication (SNI)

  • SNI solves the problem of loading several certificates onto one server.
  • It is a newer protocol feature: the client names the target hostname in the first step of the TLS handshake. The server then finds the right certificate, or returns the default one.
  • It works with the ALB, the NLB, and CloudFront. It does not work with the Classic Load Balancer.
Classic Load BalancerApplication Load BalancerNetwork Load Balancer
Certificates on one load balancerOneSeveral, with SNISeveral, with SNI
Several domainsUse one CLB for each domainOne load balancer for allOne load balancer for all

Exam trap: one certificate, SNI, and Regions

The Classic Load Balancer supports only one certificate. SNI needs the ALB or NLB. A certificate for a load balancer must be in the load balancer's Region (a certificate for CloudFront must be in us-east-1). The target's security group should allow the load balancer's security group, not the internet.

Memory hook

Security group chain: internet, then SG-alb, then SG-app. Certificate on the load balancer, SNI for many domains, and termination at the load balancer.

6. Load Balancer Certificates

Problem Statement

Northwind Shop customers enter their payment details on the website. The team wants the traffic between the customers and the load balancer to be encrypted. The security team also asks where the certificate comes from and what happens when it expires.

You need to know what an SSL certificate does, how SSL and TLS differ, and who issues a public certificate.

6.1 SSL/TLS Basics

This section repeats the basics from section 5.2, and it adds the mandatory video. Section 5.3 explains certificates on the load balancer in more detail.

  • An SSL certificate allows traffic between your clients and your load balancer to be encrypted in transit (in-flight encryption).
  • SSL refers to Secure Sockets Layer, which is used to encrypt connections.
  • TLS refers to Transport Layer Security, which is a newer version.
  • Nowadays, TLS certificates are mainly used, but people still refer to them as SSL.
  • Public SSL certificates are issued by Certificate Authorities (CA), such as DigiCert, GlobalSign, GoDaddy, Sectigo, Let's Encrypt, and Amazon.
  • SSL certificates have an expiration date, which the issuer sets, and must be renewed before it passes.

Mandatory Video

This video is part of the lesson. Watch it for more detailed information on SSL/TLS certificates.

  • Watch the SSL/TLS certificates video on YouTube

6.2 Overview of Load Balancer Certificates

  • The load balancer uses an X.509 certificate (SSL/TLS server certificate).
  • You can manage certificates using AWS Certificate Manager (ACM).
  • Alternatively, you can create and upload your own certificates.
  • HTTPS listener:
    • You must specify a default certificate.
    • You can add an optional list of certificates to support multiple domains.
    • Clients can use Server Name Indication (SNI) to specify the hostname they reach.
    • You can specify a security policy to support older versions of SSL/TLS (legacy clients).
Exam trap: a certificate expires, and it must be in the right Region

TLS is the newer version of SSL, but people still say SSL. A public certificate comes from a Certificate Authority and has an expiration date, so it must be renewed. An ACM certificate must be in the same Region as the load balancer.

Memory hook

Certificate = proof of identity with an expiry date. TLS = the new SSL. The load balancer needs a default certificate.

SAA-C03 Keyword Triggers

    → An HTTPS listener with a certificate from ACM
  • Trigger 2: "Clients see a certificate warning because the certificate expired..."
    → Renew or replace the certificate on the listener
  • Trigger 3: "Clients that use older SSL or TLS versions must still connect..."
    → A load balancer security policy that allows them

7. Server Name Indication

Problem Statement

Northwind Shop wants to run its shop website and its admin website behind one load balancer. Each website has its own domain name and its own SSL certificate.

You need to know how one load balancer can hold several certificates and still return the correct one to each client.

7.1 What Is SNI?

Section 5.3.1 also explains SNI. This tab adds the diagram and the list of services that support it.

  • Server Name Indication (SNI) solves the problem of loading multiple SSL certificates onto one web server or load balancer, so that it can serve multiple websites or web applications.
  • It is a newer protocol, and it requires the client to indicate the hostname of the target server in the initial SSL handshake.
  • The server then finds the correct certificate for that hostname, or returns the default certificate.

7.2 Where SNI Works

ServiceSNI support
Application Load Balancer (ALB), newer generationYes — supported.
Network Load Balancer (NLB), newer generationYes — supported.
Amazon CloudFrontYes — supported.
Classic Load Balancer (CLB), older generationNo — does not work.
Exam trap: SNI is how one load balancer holds several certificates

The ALB, the NLB (with a TLS listener), and CloudFront support SNI. The Classic Load Balancer does not, so it has one certificate. The client names the hostname in the first step of the handshake.

Memory hook

SNI = the client says the name, and the load balancer picks the matching certificate.

SAA-C03 Keyword Triggers
  • Trigger 1: "Several domains, each with its own certificate, on one load balancer..."
    → ALB or NLB with SNI
  • Trigger 2: "The client sends the hostname in the handshake so the server can pick the certificate..."
    → Server Name Indication
  • Trigger 3: "Only one certificate can be used on the load balancer..."
    → Classic Load Balancer (no SNI)

A company runs a real-time multiplayer game on EC2 instances in two Availability Zones. Players connect with UDP. The company expects millions of connections and needs very low latency. A partner also needs a fixed IP address for each Availability Zone to put in a firewall.

Which load balancer should the solutions architect use?

  1. Application Load Balancer.
  2. Network Load Balancer.
  3. Gateway Load Balancer.
  4. Classic Load Balancer.

8.4.2 Question 2: Two Domains and Private Instances (Select Two)

Scenario

A company hosts shop.example.com and partners.example.com on EC2 instances in private subnets. Each domain has its own TLS certificate. The company wants one load balancer, and the instances must be reachable only through the load balancer.

Which combination of steps meets the requirements? (Select TWO.)

  1. Use an Application Load Balancer with both certificates and SNI.
  2. Use a Classic Load Balancer with both certificates.
  3. In the instances' security group, allow the application port from the load balancer's security group.
  4. In the instances' security group, allow the application port from 0.0.0.0/0.
Show answer and explanation

Answer: A and C. The ALB supports several certificates with SNI, and using the load balancer's security group as the source makes it the only way in.

Speed, UDP, static IP = NLB. Firewall appliances = GWLB. Legacy = CLB. Client IP = header on the ALB, setting or Proxy Protocol on the NLB. Many domains = SNI on an ALB or NLB. Only the load balancer reaches the instances = the source is the load balancer's security group.

9. Knowledge Check

Answer each question in your own words first, then expand the model answer to compare.

  1. Describe the Network Load Balancer, the Gateway Load Balancer, and the Classic Load Balancer.

    Show model answer

    The Network Load Balancer works at layer 4 with TCP, UDP, and TLS. It handles very high performance, gives one static or Elastic IP address for each Availability Zone, and can preserve the client IP address. The Gateway Load Balancer works at layer 3 as a gateway and balances load at layer 4. It sends IP packets, wrapped with GENEVE on port 6081, to third-party appliances such as firewalls and intrusion detection systems. The Classic Load Balancer is the legacy type. It works at layers 4 and 7, supports one certificate and no SNI, and is replaced by an ALB or NLB in new designs.

  2. Compare the four load balancer types.

    Show model answer

    The ALB works at layer 7 with HTTP, HTTPS, and WebSocket and routes by path, host, and headers. The NLB works at layer 4 with TCP, TLS, and UDP, has very high performance and a static IP per Availability Zone. The GWLB works at layer 3 and balances traffic to third-party appliances using GENEVE. The CLB is the legacy type with layer 4 and 7 features and one certificate.

  3. Which client IP address does a target see behind an ALB and behind an NLB, and how does it get the real one?

    Show model answer

    Behind an ALB, the target sees the private IP address of the load balancer, and it reads the client address from the X-Forwarded-For header. Behind an NLB, it depends on client IP preservation, a target group setting. For instance targets it is on by default, so the target sees the client IP address. For IP targets that use TCP or TLS it is off by default, so the target sees the private IP address of the load balancer. When the target needs the client address, turn the setting on, or enable Proxy Protocol v2, which passes the address in a header.

  4. Recommend a load balancer for each case: a game that uses UDP with millions of connections, all VPC traffic that must pass through third-party firewalls, an HTTP service that needs path-based routing, and an old application that still uses a Classic Load Balancer.

    Show model answer

    Use a Network Load Balancer for the UDP game, because it works at layer 4 with very high performance. Use a Gateway Load Balancer for the firewall fleet, because it is a transparent gateway for appliances. Use an Application Load Balancer for path-based routing at layer 7. For the old application, keep the Classic Load Balancer only until you can move it to an ALB or NLB.

  5. How do you make sure instances are reachable only through the load balancer?

    Show model answer

    Put the instances in private subnets, and in their security group allow the application port with the load balancer's security group as the source, not an IP range. The load balancer's own security group allows the client traffic, such as HTTPS from the internet.

  6. What is SSL/TLS, and how does a load balancer use certificates?

    Show model answer

    TLS, the newer version of SSL, encrypts traffic in transit. A certificate issued by a Certificate Authority proves the server's identity. The load balancer's HTTPS or TLS listener uses a certificate, often from ACM in the same Region, can decrypt the traffic (SSL termination), and forwards it to the targets, optionally re-encrypting it.

  7. What is SNI, and which load balancers support it?

    Show model answer

    Server Name Indication lets a client name the hostname in the first step of the TLS handshake, so one load balancer can hold several certificates and pick the right one. The ALB and NLB support it, and so does CloudFront. The Classic Load Balancer does not, and supports only one certificate.

  8. A partner will allow-list only one fixed IP address for each Availability Zone, but the application needs path-based routing. Design the front end.

    Show model answer

    Put a Network Load Balancer in front of an Application Load Balancer. The NLB gives one static or Elastic IP address for each Availability Zone, and the partner allows those addresses in its firewall. The NLB forwards the traffic to the ALB as its target, and the ALB keeps layer 7 routing, with path-based rules that send each path to its target group.

  9. Design a scalable, highly available, and secure web tier.

    Show model answer

    Place the application in an Auto Scaling group across two or more Availability Zones, in private subnets, behind an ALB in public subnets. Use scaling policies for elasticity, health checks to remove failing instances, an HTTPS listener with an ACM certificate, security groups that allow only the load balancer to reach the instances, and a shared session store so the instances stay stateless.
