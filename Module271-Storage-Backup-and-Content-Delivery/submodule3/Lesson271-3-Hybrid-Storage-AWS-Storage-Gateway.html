Introduction

Many companies cannot move all of their data to the cloud at once. Their applications run on premises and speak file and block protocols, such as NFS, SMB, and iSCSI, and they cannot call the Amazon S3 API. AWS Storage Gateway lets these applications keep their protocols while the data is stored in AWS. An architect who passes SAA-C03 questions on hybrid storage needs to know which gateway type fits which requirement. Some companies also exchange files with partners who use SFTP or FTP, which AWS Transfer Family handles, and large amounts of data must be copied into AWS, which AWS DataSync does.

This lesson assumes that you know the basics of Amazon S3, which Lesson 271.2 covers. It follows FlashCart Inc., an online store, through the Problem Statement of each tab.

Two terms appear often in this lesson:

  • Hybrid storage: storage that is partly on premises and partly in the cloud, where the applications see one storage system.
  • Local cache: a copy of recently used data that the gateway keeps on premises for low-latency access.

1. Hybrid Storage and AWS Storage Gateway

Problem Statement

The FlashCart warehouse offices keep invoices and scanned documents on an on-premises file server that is almost full. The applications there can only use NFS and SMB file shares, and they cannot call the S3 API. The team also keeps backups on physical tapes. FlashCart wants to move this data to Amazon S3 without rewriting the applications, and the users still need fast access to the files they open every day. The team must choose how to connect the on-premises systems to AWS storage.

1.1 Overview of AWS Storage Gateway

  • AWS Storage Gateway is a hybrid cloud storage service. It gives on-premises applications access to virtually unlimited cloud storage.
  • Applications talk to the gateway with standard storage protocols: NFS and SMB for file shares, iSCSI for block volumes, and an iSCSI virtual tape library for tape backup software. The applications do not need to be changed.
  • The gateway is a bridge between your on-premises environment and AWS storage services, such as Amazon S3, S3 Glacier, and Amazon EBS snapshots.
  • The gateway keeps a local cache of recently used data, so that users get low-latency access to frequently used data while the full data set lives in AWS.
  • You deploy the gateway as a virtual machine (VMware ESXi, Microsoft Hyper-V, or Linux KVM), as a hardware appliance, or as an Amazon EC2 instance.
  • The gateway connects to AWS over the internet, over AWS Direct Connect, or through a VPC endpoint. The data is encrypted in transit and is encrypted at rest in AWS.
  • Common use cases: extend an on-premises file share to the cloud, back up and archive data, disaster recovery, cloud migration, and replace physical tape libraries.
  • Hybrid storage means that part of the storage is on premises and part is in the cloud, and the applications see one storage system.

Exam Trap

Remember these two points:

  • The S3 gateway VPC endpoint (Lesson 271.2, tab 7) and AWS Storage Gateway are different services. The endpoint gives private network access from a VPC to S3. Storage Gateway connects on-premises storage to AWS.
  • AWS Storage Gateway is a hybrid service. If all of the applications already run in AWS, you do not need a gateway.

Memory Hook

Gateway = a bridge. Protocols stay the same. Local cache = fast. AWS = the storage behind it.

SAA-C03 Keyword Triggers

Trigger 1: "Hybrid cloud storage with low-latency local access to frequently used data"
→ AWS Storage Gateway with a local cache.

Trigger 2: "On-premises applications must keep using NFS, SMB, or iSCSI, but the data must live in AWS"
→ AWS Storage Gateway.

Trigger 3: "Extend an on-premises file share to the cloud"
→ AWS Storage Gateway.

2. Types of AWS Storage Gateway

Problem Statement

FlashCart has three storage needs on premises: file shares for the warehouse offices, an iSCSI volume for a database server, and a backup application that writes to physical tapes. The team wants to use AWS storage for all three, and it must pick the right gateway type for each one.

2.1 S3 File Gateway

  • It gives NFS and SMB file shares that are backed by an Amazon S3 bucket.
  • Each file is stored as an object in S3, and recently used files stay in the local cache.
  • It suits file shares, backups, and moving files from on premises to S3.

2.2 FSx File Gateway

  • It gives SMB access with a local cache to Amazon FSx for Windows File Server.
  • Amazon FSx File Gateway has not been available to new customers since October 28, 2024. Existing customers can continue to use it.

2.3 Volume Gateway

  • It gives block storage to on-premises applications over iSCSI.
  • Cached volumes: the primary data is stored in AWS, and the frequently accessed data is cached on premises.
  • Stored volumes: the entire data set is stored on premises, and the gateway backs it up to AWS asynchronously as point-in-time EBS snapshots.

2.4 Tape Gateway

  • Some companies have backup processes that use physical tapes.
  • With Tape Gateway, companies use the same processes, but in the cloud.
  • It gives a virtual tape library (VTL) over iSCSI, backed by Amazon S3 and S3 Glacier.
  • You back up data with your existing tape-based processes, through the iSCSI interface.
  • It works with leading backup software vendors.
  • The virtual tapes are stored in Amazon S3 and can be archived to S3 Glacier Flexible Retrieval or S3 Glacier Deep Archive.
  • Use it to replace physical tapes without changing the backup process.

2.5 Summary of the Gateway Types

  • S3 File Gateway: NFS and SMB file shares on S3.
  • FSx File Gateway: SMB access to FSx for Windows File Server.
  • Volume Gateway: iSCSI block volumes.
  • Tape Gateway: virtual tapes.

Exam-Style Question

Scenario: A company backs up its servers to physical tapes with backup software, and it wants to store the backups in AWS without changing the backup process. Which solution meets the requirement?

  • A. A Tape Gateway.
  • B. An S3 File Gateway.
  • C. A Volume Gateway with stored volumes.
  • D. An S3 gateway VPC endpoint.
Show Answer and Explanation

Correct answer: A. A Tape Gateway gives a virtual tape library over iSCSI that works with the existing backup software. It stores the virtual tapes in Amazon S3 and can archive them to S3 Glacier.

OptionResultReason
ACorrectA Tape Gateway replaces the physical tapes and keeps the backup process.
BIncorrectAn S3 File Gateway gives file shares. The backup software writes to tapes, not to file shares.
CIncorrectA Volume Gateway gives iSCSI block volumes, not a virtual tape library.
DIncorrectA gateway VPC endpoint gives private network access from a VPC to S3. It does not connect on-premises backup software.

Exam Trap

Remember these three points:

  • S3 File Gateway is for NFS and SMB files on S3, Volume Gateway is for iSCSI block volumes, and Tape Gateway is for virtual tapes.
  • Volume Gateway has cached volumes (primary data in AWS) and stored volumes (primary data on premises).
  • Amazon FSx File Gateway has not been available to new customers since October 28, 2024.

Memory Hook

File = S3 File Gateway. Block = Volume Gateway. Tape = Tape Gateway.

SAA-C03 Keyword Triggers

Trigger 1: "On-premises applications need NFS or SMB access to files stored in S3"
→ S3 File Gateway.

Trigger 2: "Replace physical tape backups with cloud storage, keeping the backup software"
→ Tape Gateway.

Trigger 3: "iSCSI block storage on premises with backups in AWS"
→ Volume Gateway.

Trigger 4: "The primary data stays on premises and the gateway backs it up to AWS"
→ Volume Gateway with stored volumes.

3. How Storage Gateway Works With Amazon S3

Problem Statement

The FlashCart architects ask what happens to the data after the gateway receives it. They want to know which components make up the architecture, where the data is stored, and which Amazon S3 features still apply to files that are written through a gateway.

3.1 How Storage Gateway Works With S3

The architecture of AWS Storage Gateway revolves around three main components:

  1. On-premises Gateway: the gateway is a virtual appliance deployed on premises that connects your local applications with AWS cloud storage. It runs in your environment as a VMware ESXi, Microsoft Hyper-V, or Amazon EC2 instance.
  2. AWS Storage Gateway Service: this service, hosted in the AWS Cloud, manages the storage volumes and their associated snapshots. It also provides a management interface for configuring and monitoring your storage gateway.
  3. AWS Cloud Storage: the gateway integrates with AWS cloud storage services such as Amazon S3, S3 Glacier, and Amazon EBS, providing scalable and durable storage options for your data.

3.2 Amazon S3 and AWS Storage Gateway

  • Amazon S3 is the storage. AWS Storage Gateway is the access layer that lets on-premises applications reach it with protocols that they already use.
  • S3 does not speak NFS, SMB, or iSCSI. The gateway translates between those protocols and AWS storage.
  • With S3 File Gateway, each file becomes an object in your S3 bucket. You can also read that object with the S3 API.
  • With Volume Gateway, the backups are stored as EBS snapshots, which are kept in Amazon S3.
  • With Tape Gateway, the virtual tapes are stored in Amazon S3 and archived to the S3 Glacier classes.
  • Because the data is in S3, S3 features apply to it: lifecycle rules, versioning, replication, encryption, and event notifications.

Exam Trap

Remember these two points:

  • Amazon S3 is the storage, and AWS Storage Gateway is the access layer. S3 does not speak NFS, SMB, or iSCSI.
  • Volume Gateway backups are EBS snapshots kept in S3, and Tape Gateway tapes are archived to the S3 Glacier classes.

Memory Hook

S3 stores. The gateway translates. The local cache speeds up.

SAA-C03 Keyword Triggers

Trigger 1: "Files written through a gateway must follow S3 lifecycle, versioning, and encryption rules"
→ The data is stored in S3, so the S3 features apply.

Trigger 2: "Virtual tapes must be archived at low cost"
→ Tape Gateway with S3 Glacier Flexible Retrieval or S3 Glacier Deep Archive.

Trigger 3: "Volume Gateway backups"
→ EBS snapshots stored in S3.

4. S3 File Gateway

Problem Statement

The FlashCart warehouse offices open the same invoices every day, and they open older scanned documents only once in a while. The applications use NFS file shares. The team wants the invoices to open quickly, the older documents to cost less, and the files to live in Amazon S3. The team must understand how S3 File Gateway reads, writes, and stores files.

4.1 S3 File Gateway

  • S3 File Gateway presents a file share over NFS or SMB, and it maps the share to an S3 bucket.
  • Each file is stored as an object. The file metadata, such as owner, permissions, and timestamps, is stored as object metadata.
  • When an application writes a file, the gateway stores it in the local cache and uploads it to S3 asynchronously.
  • When an application reads a file, the gateway returns it from the local cache if it is there, and otherwise gets it from S3.
  • The gateway can store objects in S3 Standard, S3 Intelligent-Tiering, S3 Standard-IA, or S3 One Zone-IA.
  • You can use S3 lifecycle rules to move objects to colder classes. Objects in the S3 Glacier classes must be restored before the file share can read them.
  • The gateway needs an IAM role that allows it to use the bucket.
  • S3 File Gateway uses the same deployment options and connection options as every gateway type (section 1.1).

With S3 File Gateway storage, you can do such tasks as ingesting cloud workloads to Amazon S3, performing backups and archiving, tiering, and migrating storage data to the AWS Cloud. The following diagram provides an overview of file storage deployment for Storage Gateway.

S3 File Gateway converts files to S3 objects when uploading files to Amazon S3. The interaction between file operations performed against file shares on S3 File Gateway and S3 objects requires certain operations to be carefully considered when converting between files and objects.

Visit this official AWS document for more detail: S3 File Gateway concepts.

4.1.1 When to Use S3 File Gateway

  • Applications on premises need a file share, but the data must live in S3.
  • You want to move files to S3 gradually, with low-latency access for the users.
  • You use S3 as a backup target for file-based backups, or as a data lake that on-premises systems also write to.

Exam-Style Question

Scenario: A company has on-premises applications that can only use NFS file shares. The company wants the files to be stored as objects in Amazon S3, and the users need low-latency access to the files they use every day. Which solution meets the requirements?

  • A. Amazon S3 Transfer Acceleration.
  • B. A Tape Gateway with virtual tapes.
  • C. An S3 gateway VPC endpoint.
  • D. An S3 File Gateway with a local cache.
Show Answer and Explanation

Correct answer: D. S3 File Gateway presents NFS and SMB file shares that store each file as an S3 object, and its local cache gives low-latency access to frequently used files.

OptionResultReason
AIncorrectTransfer Acceleration speeds up uploads to S3. It does not provide an NFS file share.
BIncorrectTape Gateway gives a virtual tape library for backup software, not a file share.
CIncorrectA gateway VPC endpoint gives private access from a VPC to S3. It does not provide NFS file shares.
DCorrectS3 File Gateway gives an NFS share backed by S3, with a local cache.

Exam Trap

Remember these three points:

  • S3 File Gateway uploads written files to S3 asynchronously, and it serves reads from the local cache when it can.
  • Objects that a lifecycle rule moves to the S3 Glacier classes must be restored before the file share can read them.
  • The gateway needs an IAM role that allows it to use the S3 bucket.

Memory Hook

Write to the cache, upload to S3. Read from the cache, or fetch from S3. Glacier needs a restore.

SAA-C03 Keyword Triggers

Trigger 1: "On-premises applications need NFS or SMB access to files stored in S3"
→ S3 File Gateway.

Trigger 2: "Files must open quickly on premises, and older files can move to cheaper S3 classes"
→ S3 File Gateway with a local cache and lifecycle rules.

Trigger 3: "Files that were archived to S3 Glacier must be read through the file share"
→ Restore the objects first.

5. AWS Storage Gateway Pricing

Problem Statement

The FlashCart finance team asks what an AWS Storage Gateway design costs, and whether the cost is only the storage in Amazon S3. The engineers must name the parts of the cost and find ways to lower it before they approve the design.

5.1 AWS Storage Gateway Pricing

Prices change often and differ by Region. Always check the current rates on the AWS Storage Gateway pricing page, and estimate your own cost with the AWS Pricing Calculator.

The cost of a gateway design has these parts:

  • The AWS storage behind the gateway: Amazon S3, S3 Glacier, or EBS snapshots, billed at their own storage rates (Lesson 271.2 covers S3 pricing).
  • Data written to AWS through the gateway is charged per GB, up to a monthly maximum for each gateway, and the first 100 GB written to AWS per account is free. A File Gateway also pays for the S3 requests that it makes.
  • Data transfer out of AWS, for example when users read data that is not in the local cache. Transfer from the Storage Gateway service to an EC2-based gateway in the same Region has no charge.
  • The gateway itself: the host for the virtual machine costs money on premises, and a hardware appliance has an additional purchase cost. A gateway on an EC2 instance costs the EC2 price, so check the Amazon EC2 pricing page.
  • Amazon CloudWatch: standard CloudWatch rates apply for logs, events, and metrics if you configure health notifications or audit logs.
  • The network: an AWS Direct Connect connection, if you use one.

5.1.1 Ways to Lower the Cost

  • Size the local cache so that the files that users open often are served from the cache and do not need a transfer from AWS.
  • Use lifecycle rules to move older objects to colder S3 classes (Lesson 271.2, tab 4).
  • Choose the gateway type that fits the workload, so that you do not pay for features that you do not use.
  • Monitor the gateway with Amazon CloudWatch, and review the data that it uploads.

Exam Trap

Remember these two points:

  • The cost of a gateway design is more than the S3 storage. It also includes data written to AWS, data transfer out, the gateway host, and the network.
  • A larger local cache can lower the data transfer out, because more reads are served on premises.

Memory Hook

Storage + transfer + gateway host + network. A bigger cache means fewer reads from AWS.

SAA-C03 Keyword Triggers

Trigger 1: "Lower the cost of repeated reads of the same files from on premises"
→ Size the local cache so that frequently used files are served from it.

Trigger 2: "Lower the storage cost of older files behind a file gateway"
→ S3 lifecycle rules to colder classes.

Trigger 3: "Check the current gateway prices"
→ The AWS Storage Gateway pricing page and the AWS Pricing Calculator.

6. AWS Transfer Family

Problem Statement

FlashCart’s suppliers send invoices and stock files every night to an old FTP server in the warehouse office. Each supplier uses its own SFTP software, and none of them will change it. The server is hard to patch, and the security team wants the files in Amazon S3 without servers to run. FlashCart must keep the same protocol, the same host name, and the same user logins, so that the suppliers notice nothing.

6.1 What AWS Transfer Family Is

  • AWS Transfer Family is a fully managed service that transfers files into and out of Amazon S3 or Amazon EFS over the SFTP, FTPS, FTP, and AS2 protocols. AS2 transfers work with Amazon S3 only.
  • Users and partners keep their existing clients and workflows. The files that they upload are stored in your S3 bucket or EFS file system.
  • AWS runs and manages the servers. The service is scalable, reliable, and highly available across Availability Zones.
  • It replaces traditional FTP and SFTP servers that you would patch and operate yourself.
  • Use cases: sharing files with partners, public data sets, business-to-business exchange, and CRM and ERP data.

6.2 Protocols

ProtocolNameWhat to know
SFTPSecure Shell (SSH) File Transfer ProtocolEncrypted. Use it for transfers over the public network.
FTPSFile Transfer Protocol over SSLEncrypted. Use it for transfers over the public network.
FTPFile Transfer ProtocolNot encrypted. The endpoint is reachable only from resources inside your VPC, so use FTP only on a private network.
AS2Applicability Statement 2For business-to-business exchange with trading partners. It transfers files into and out of Amazon S3 only.
  • You can enable several protocols on one server.
  • Your users must use one of these protocols. They cannot use a web browser for file transfer unless you set up a Transfer Family web app (6.6).

6.3 Endpoints and DNS

  • You can host a server endpoint in a VPC, and you can make it reachable from the internet or only from inside the network. A security group controls the access to a VPC endpoint.
  • Only SFTP and FTPS are supported for the internet-facing VPC endpoint. AWS does not allow FTP over public networks.
  • You can use Amazon Route 53 for DNS routing, or a custom host name, so that your partners keep using the same host name after the move.

6.4 Authentication and Access

  • Service managed: you store and manage the users in Transfer Family, for example with SSH public keys.
  • AWS Directory Service for Microsoft Active Directory: users authenticate with their Active Directory credentials.
  • Custom identity provider: you connect your own directory through AWS Lambda or Amazon API Gateway, for example Okta or Amazon Cognito.
  • Each user has an IAM role and a home directory. The role controls what the user can reach in the S3 bucket or the EFS file system.
  • You can use AWS KMS to control encryption at rest, and Amazon CloudWatch to monitor the server.

6.5 Processing Files After Upload

  • Managed workflows run steps on a file after it arrives, for example copy, tag, or decrypt, so that you do not write code for the usual steps.
  • Because the files are in Amazon S3, you can also use S3 event notifications to start AWS Lambda functions or other targets (Lesson 271.2, tab 10).

6.6 Connectors and Web Apps

  • SFTP connectors and AS2 connectors let Transfer Family send files to, and get files from, external servers that other companies host.
  • Web apps give users a browser-based way to transfer files with Amazon S3. You can make a web app public or host it inside a VPC.

6.7 AWS Transfer Family Pricing

Prices change often and differ by Region. Always check the current rates on the AWS Transfer Family pricing page, and estimate your own cost with the AWS Pricing Calculator.

  • You pay per hour for each protocol that you enable on a server, from the time that you create the server until you delete it.
  • You also pay for the amount of data that you transfer, in GB.
  • A web app is billed per hour for each active web app endpoint.
  • Enable only the protocols that you need, and delete servers that nobody uses.

6.8.1 DataSync Between AWS Storage Services

Exam-Style Question

Scenario: A company’s partners upload files every night to an on-premises SFTP server. The company wants to store the files in Amazon S3 and stop managing servers, and the partners must keep using their SFTP clients and the same host name. Which solution meets the requirements?

  • A. Use AWS DataSync to copy the files every night to an S3 bucket.
  • B. Create an S3 File Gateway and give the partners an NFS share.
  • C. Use AWS Transfer Family with SFTP, and keep the host name in Amazon Route 53.
  • D. Ask the partners to change their software to call the S3 API.
Show Answer and Explanation

Correct answer: C. Transfer Family provides a managed SFTP endpoint that stores files in Amazon S3. Route 53 keeps the same host name, so the partners change nothing.

OptionResultReason
AIncorrectDataSync moves data on a schedule between storage systems. It does not give partners an SFTP endpoint.
BIncorrectA file gateway gives NFS and SMB shares to on-premises applications, not SFTP access for external partners.
CCorrectA managed SFTP server backed by S3, with the same host name through Route 53.
DIncorrectThe partners would have to change their software.

Exam Trap

Remember these three points:

  • FTP is not allowed over the public network. It works only inside a VPC. For the internet, use SFTP or FTPS.
  • Transfer Family is for interactive transfers by users and partners. DataSync is for bulk, scheduled migration. Storage Gateway is for on-premises applications that need NFS, SMB, or iSCSI.
  • AS2 works with Amazon S3 only. SFTP, FTPS, and FTP work with S3 and EFS.

Memory Hook

Partners with SFTP = Transfer Family. Bulk migration = DataSync. On-premises apps with a cache = Storage Gateway.

7. AWS DataSync

Problem Statement

FlashCart is moving 200 TB of archived order files from an on-premises NFS storage system to Amazon S3, and the files of its Windows file server to Amazon FSx. The copy must keep running until the day of the cut-over, so that only changed files move at the end. File permissions and time stamps must survive, the copy must not use all of the office network during business hours, and the team needs proof that every file arrived intact. Nobody wants to write copy scripts.

7.1 What AWS DataSync Is

  • AWS DataSync is an online data transfer service. It simplifies, automates, and accelerates moving data between on-premises storage systems, other clouds, and AWS storage services.
  • It is built for bulk transfers and synchronization, for example a large migration, a recurring copy, or an archive to the cloud.
  • DataSync is not for end users. An administrator sets up the transfer, so nobody has to worry about user access.
  • It handles the details for you: network optimization, encryption, retries, and integrity checks.
  • DataSync copies data incrementally and handles failure during the transmission.
  • It can run multiple tasks in parallel.

7.2 Sources and Destinations

Supported locations
SourcesNetwork File System (NFS) and Server Message Block (SMB) file servers, Hadoop Distributed File System (HDFS), self-managed object storage, and storage at other cloud providers.
DestinationsAmazon S3 in any storage class, including S3 Glacier, Amazon EFS, and Amazon FSx (Windows File Server, Lustre, NetApp ONTAP, and OpenZFS).
Between AWS servicesAmazon S3, Amazon EFS, and Amazon FSx can be both the source and the destination.
  • The direction is not limited to the cloud. DataSync can also copy data from AWS back to an on-premises system.

7.3 How DataSync Works

  • An agent is a virtual machine that you run next to your on-premises storage. It reads from your NFS server or SMB share, or writes to it. You activate the agent in the same AWS Region as the S3 bucket or EFS file system that you use.
  • A location is any source or destination, such as an NFS server, an S3 bucket, or an EFS file system.
  • A task connects a source location to a destination location, with options such as a schedule and a bandwidth limit.
  • A task execution is one run of a task. You can start it by hand or on a schedule, and you can monitor its progress.
  • No agent is needed to transfer data between AWS storage services in the same AWS account. You need an agent when the source or the destination is outside AWS.

7.4 Scheduling, Performance, and Data Integrity

  • Scheduling: you can run a task hourly, daily, or weekly. DataSync is not a continuous replication service. Each run detects and copies the changes since the last run.
  • Metadata: file permissions and metadata are preserved, including NFS POSIX permissions and SMB permissions.
  • Speed: one agent can use up to 10 Gbps of network capacity, and you can run several tasks in parallel.
  • Bandwidth limit: you can set a limit, so that a transfer does not use all of the network that your applications need.
  • Integrity: DataSync verifies the data during the transfer and again at the end of the transfer.
  • Security: data is encrypted in transit with Transport Layer Security (TLS), and default encryption of the destination S3 bucket or EFS file system protects the data at rest.

8. AWS Data Transfer Terminal

Problem Statement

FlashCart’s data science team records video on delivery trucks and stores it on drives at depots that have a slow internet link. Together the drives hold about 400 TB. The transfer-time table in 7.5 shows that even 500 TB needs 58 days on a 1 Gbps link, so a slow depot link would need even longer for 400 TB, and shipping drives by courier takes weeks and puts the data out of the team’s hands. The team wants to get the data into Amazon S3 quickly, and to keep control of the drives while it does.

8.1 What AWS Data Transfer Terminal Is

  • AWS Data Transfer Terminal is a secure, network-ready physical location where you bring your own storage devices and upload large data sets to AWS over a high-bandwidth connection.
  • You upload to AWS public endpoints, such as Amazon S3 and Amazon EFS.
  • You reserve a time slot for a location, visit it, and upload the data. You keep custody of your devices the whole time, and you do not ship them.
  • It suits data that is stored on devices in a place where the network is slow or unreliable.
  • You can also bring an AWS Snowball Edge device that you already have to a terminal, and upload from it, without shipping it.
  • Availability: AWS Data Transfer Terminal is available only to AWS Enterprise Support customers at this time. Check the AWS documentation for current availability.

8.2 How It Works

  1. Load your data onto the storage devices that you will bring. You prepare the devices yourself.
  2. Reserve a time slot. In the AWS Management Console, find a location, choose Create Reservation, and pick the date and time.
  3. Visit the location. Confirm your access with the building reception. Building staff escort you to the reserved room.
  4. Connect and upload. The room has a patch panel with fiber optic cables, and a PC to monitor the transfer. Connect your storage device to the network, link to your S3 bucket, and start the transfer. AWS recommends the AWS Command Line Interface commands aws s3 cp and aws s3 sync for the upload.
  5. Validate the transfer and leave with your devices.
  • The data moves at the speed of the connection and of your storage devices. A fast connection does not help if the devices read slowly, so plan the devices as well as the reservation.

8.3 When to Use It

  • Large data sets that sit on storage devices, and an internet link that is slow, limited, or unreliable.
  • Data that was collected at remote sites, for example vehicle or sensor data.
  • Migrating legacy data to the cloud, or ingesting data quickly so that processing can start soon.
  • A one-time or occasional bulk upload, where you do not want to ship devices.

Do not use it when:

  • The data is already in AWS, or an online transfer over your existing link is fast enough. Use AWS DataSync (tab 7).
  • Partners must send files all the time over SFTP. Use AWS Transfer Family (tab 6).

8.4 Security and Custody

  • The terminal is a private, time-limited room that you reserve. It is in a colocation facility, and building staff escort you to the room.
  • You keep control of your storage devices throughout the transfer. They do not travel with a courier, and nobody else holds them.
  • The data goes directly from your device to the AWS endpoint that you choose.

8.5 AWS Data Transfer Terminal Pricing

Prices change often and differ by location. Always check the current rates on the AWS Data Transfer Terminal pricing page.

  • You pay per port-hour for each port that you use during the reservation. There is a minimum of one port-hour for each reservation.
  • You pay for the reserved port-hours even when no data is moving, so use the time well.
  • The rate depends on the terminal location and on the Region of the AWS endpoint. There is no per-GB data transfer charge when you upload to a Region on the same continent as the location.
  • Charges of the AWS services that receive the data, such as Amazon S3 storage and requests, still apply.

8.6 Where It Fits With AWS Snowball

AWS Snow devices were the usual way to move data offline. Their availability has changed:

  • AWS Snowcone and AWS Snowmobile have been discontinued and can no longer be ordered.
  • AWS Snowball Edge has been available only to existing customers since November 7, 2025. Existing customers can continue to use it.
  • For new customers, AWS recommends AWS DataSync for online transfers, AWS Data Transfer Terminal for secure physical transfers, and AWS Partner solutions. For edge computing, it recommends AWS Outposts.
  • Exam questions and older course material may still describe Snowball. Know what it was for, and know the current status.

9.5 Lesson Summary

This lesson covered the following points:

  • AWS Storage Gateway is a hybrid cloud storage service that gives on-premises applications NFS, SMB, iSCSI, and virtual tape access to AWS storage, with a local cache for low-latency access.
  • The four gateway types are S3 File Gateway, FSx File Gateway, Volume Gateway, and Tape Gateway.
  • The architecture has three components: the on-premises gateway, the AWS Storage Gateway service, and AWS cloud storage.
  • Amazon S3 is the storage and the gateway is the access layer, so S3 features such as lifecycle rules and encryption apply to the data.
  • S3 File Gateway stores each file as an S3 object, writes to S3 asynchronously, and reads from the local cache when it can.
  • The cost of a gateway design includes the AWS storage, data written to AWS, data transfer out, the gateway host, and the network.
  • AWS Transfer Family gives partners and users managed SFTP, FTPS, FTP, and AS2 access to Amazon S3 and Amazon EFS. It is billed per hour for each enabled protocol, plus the data transferred.
  • AWS DataSync copies data on a schedule between on-premises storage, other clouds, and AWS storage, with permissions preserved, a bandwidth limit, and integrity checks. It is billed per GB copied, and it needs an agent only when a location is outside AWS. Storage Gateway is for on-premises applications that need a cache.
  • AWS Data Transfer Terminal is a reserved physical location where you bring your own storage devices and upload at high speed, which suits large data sets on devices at sites with a slow link. It is billed per port-hour. AWS Snowball Edge is limited to existing customers, and Snowcone and Snowmobile are discontinued.

Memory Hook

The gateway is the bridge. File, block, or tape picks the type. The cache keeps it fast. S3 keeps the data.

10. Knowledge Check

Answer each question in your own words before you open the model answer.

Question 1: Explain what AWS Storage Gateway does, name its gateway types, and say which one you use to give on-premises applications an NFS file share on S3.

Maps to: Objectives 1, 2, and 9 (Application).

AWS Storage Gateway is a hybrid cloud storage service. It gives on-premises applications access to AWS storage through standard protocols, and it keeps a local cache for low-latency access. Its types are S3 File Gateway (NFS and SMB file shares on S3), FSx File Gateway (SMB access to Amazon FSx for Windows File Server), Volume Gateway (iSCSI block volumes with cached or stored volumes), and Tape Gateway (virtual tapes archived to S3 Glacier). Use S3 File Gateway to give on-premises applications an NFS file share that stores each file as an S3 object.

Question 2: Describe the three components of the AWS Storage Gateway architecture.

Maps to: Objective 3 (Comprehension).

The first component is the on-premises gateway, a virtual appliance that connects local applications with AWS storage. The second is the AWS Storage Gateway service in the AWS Cloud, which manages the storage volumes and their snapshots and provides a management interface. The third is AWS cloud storage, such as Amazon S3, S3 Glacier, and Amazon EBS.

Question 3: Differentiate cached volumes from stored volumes in a Volume Gateway.

Maps to: Objective 10 (Analysis).

With cached volumes, the primary data is stored in AWS and the frequently accessed data is cached on premises. With stored volumes, the entire data set is stored on premises, and the gateway backs it up to AWS asynchronously as point-in-time EBS snapshots. Use cached volumes when the full data set should live in AWS, and stored volumes when the data must stay on premises.

Question 4: Explain how Amazon S3 and AWS Storage Gateway relate, and which S3 features apply to data written through a gateway.

Maps to: Objectives 7 and 8 (Comprehension).

Amazon S3 is the storage, and AWS Storage Gateway is the access layer that translates NFS, SMB, and iSCSI to AWS storage. With S3 File Gateway each file becomes an S3 object. Because the data is in S3, lifecycle rules, versioning, replication, encryption, and event notifications apply. Objects that move to the S3 Glacier classes must be restored before the file share can read them.

Question 5: Name the parts of the cost of a gateway design and recommend ways to lower it.

Maps to: Objective 12 (Application).

The cost has these parts: the AWS storage behind the gateway, data written to AWS and the requests to S3, data transfer out, the gateway host or EC2 instance, and the network such as AWS Direct Connect. To lower the cost, size the local cache so that frequently used files are served on premises, use lifecycle rules to move older objects to colder S3 classes, choose the gateway type that fits the workload, and monitor the gateway with Amazon CloudWatch. Check the pricing page for the current rates.

Question 6: Explain how AWS Transfer Family lets partners keep using SFTP while the files are stored in Amazon S3, and how it differs from AWS DataSync and AWS Storage Gateway.

Maps to: Objectives 4 and 11 (Comprehension).

Transfer Family is a fully managed service that gives partners an SFTP, FTPS, FTP, or AS2 endpoint, and it stores the files that they upload in an Amazon S3 bucket or an Amazon EFS file system (AS2 works with S3 only). The partners keep their clients, and Amazon Route 53 keeps the same host name. Users authenticate through service-managed credentials, Active Directory, or a custom identity provider, and an IAM role controls what each user can reach. DataSync is for bulk, scheduled transfers between storage systems, and Storage Gateway gives on-premises applications NFS, SMB, or iSCSI access with a local cache.

Question 7: Explain how AWS DataSync migrates data from an on-premises NFS server to Amazon S3, and name three features that help with a large migration.

Maps to: Objective 5 (Comprehension).

You run a DataSync agent as a virtual machine next to the NFS server and activate it in the same Region as the S3 bucket. You create a location for the NFS server and a location for the bucket, and a task that connects them. Each task execution copies the data, and a schedule of hourly, daily, or weekly runs copies only the changes since the last run. Helpful features are the preservation of file permissions and metadata, a bandwidth limit that protects the production network, and integrity verification during and at the end of the transfer. DataSync needs no agent between AWS storage services, and it is billed per GB copied.

Question 8: Explain how AWS Data Transfer Terminal works, when to choose it, and how it relates to AWS Snowball and AWS DataSync.

Maps to: Objective 6 (Comprehension).

Data Transfer Terminal is a secure physical location that you reserve in the AWS console. You bring your own storage devices, connect them to the high-bandwidth network, upload to endpoints such as Amazon S3 or Amazon EFS, and leave with your devices. You pay per port-hour. Choose it for large data sets on devices at a site where the link is slow or unreliable. AWS DataSync is for online transfers over a network that is fast enough. AWS Snowball Edge, where AWS ships you a device, has been limited to existing customers since November 7, 2025, and Snowcone and Snowmobile are discontinued, so new customers use DataSync or Data Transfer Terminal.
