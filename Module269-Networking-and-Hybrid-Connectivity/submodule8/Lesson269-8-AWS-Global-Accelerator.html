1. AWS Global Accelerator Basics

Problem Statement

A gaming company runs servers in us-east-1 and eu-west-1. Players around the world connect over the public internet and see high latency. Partners must allow-list fixed IP addresses, and if a Region fails, players must reach the other Region quickly.

1.1 Unicast IP vs. Anycast IP

Before we start AWS Global Accelerator, let us quickly understand Unicast IP and Anycast IP.

Unicast IP vs. Anycast IP.
AspectUnicast IPAnycast IP
Servers and addressesOne server holds one IP addressAll servers hold the same IP address
Where the client connectsTo that one serverTo the nearest server
ExampleAn EC2 instance with its own public IP addressThe static IP addresses of AWS Global Accelerator

1.2 What Is AWS Global Accelerator?

  • Similar to Amazon CloudFront, AWS Global Accelerator also uses AWS edge locations.
  • Global Accelerator’s two static IP addresses are anycast: the same addresses are announced from many AWS edge locations, so every user is routed to the nearest edge location.
  • The anycast IP sends traffic directly to the edge locations.
  • The edge locations send the traffic to your application.
  • A networking service that improves the performance and availability of applications with a global audience.
  • Gives you two static anycast IP addresses as a fixed entry point (four with dual-stack IPv4 and IPv6).
  • Users enter the AWS network at the nearest edge location, then travel over the AWS global network, not the public internet.
  • Works with TCP and UDP, so it is not limited to web traffic.
  • Endpoints: Application Load Balancer, Network Load Balancer, EC2 instance, or Elastic IP address.
  • Health checks and automatic failover to healthy endpoints, usually in under a minute.
  • No caching: it speeds up the path, but does not store content.
  • Protected by AWS Shield Standard against DDoS attacks.

1.3 Key Components

Key Components.
ComponentWhat it is
AcceleratorThe Global Accelerator resource. It has a type: standard or custom routing.
Static IP addressesTwo anycast addresses (in different network zones) that never change while the accelerator exists.
ListenerChecks for connection requests on a port or port range and a protocol (TCP, UDP, or both).
Endpoint groupOne group per AWS Region. It has a traffic dial and health check settings.
EndpointThe resource that receives the traffic: ALB, NLB, EC2 instance, or Elastic IP.

1.4 How It Works

  • Clients connect to the static IP addresses of the accelerator.
  • The IP addresses are anycast from AWS edge locations, so each user reaches the nearest one.
  • Traffic goes over the AWS global network to the closest healthy endpoint group (Region).
  • If an endpoint becomes unhealthy, traffic goes to other healthy endpoints.

1.5 Global Accelerator Pricing

  • Fixed charge: per accelerator, about $0.025 per hour.
  • Data transfer charge: per GB of traffic processed.
  • Free tier: no free tier.
  • Cost vs. benefit: justified when latency and availability have real business impact.
  • Check the Global Accelerator pricing page for current rates.

Exam Trap

Static IPs, no caching.

Global Accelerator gives static IP addresses and uses the AWS network, but it does not cache content. If the question says cache, the answer is CloudFront. If it says static IPs, UDP, or fast Regional failover, the answer is Global Accelerator.

Memory Hook

Two static anycast IPs + AWS edge + AWS backbone + health-based failover = Global Accelerator.

2.1 CloudFront vs. Global Accelerator

CloudFront vs. Global Accelerator.
AspectAmazon CloudFrontAWS Global Accelerator
What it doesContent delivery network: caches content at edge locationsNetwork acceleration: routes traffic over the AWS backbone
CachingYesNo
ProtocolsHTTP, HTTPS, and WebSocketTCP and UDP
Entry pointA domain name (the distribution)Two static anycast IP addresses
Origins or endpointsS3, ALB, EC2, API Gateway, or any HTTP serverALB, NLB, EC2, or Elastic IP
Edge computeYes: CloudFront Functions and Lambda@EdgeNo
FailoverOrigin groups, per requestHealth-based failover between Regions

2.4 Exam-Style Questions

2.4.1 Question 1: Multiplayer Game With Fixed IPs

Exam-Style Question 1

A company runs a multiplayer game on Network Load Balancers in two AWS Regions. Players use UDP. Partners need fixed IP addresses to allow-list, and traffic must fail over quickly if a Region becomes unhealthy.

Which solution meets these requirements?

  1. Amazon CloudFront with the NLBs as origins
  2. Route 53 latency routing with the NLB DNS names
  3. AWS Global Accelerator with an endpoint group in each Region
  4. S3 Transfer Acceleration
Show the answer and explanation

Answer: C. Global Accelerator supports UDP, gives two static IP addresses, and fails over to healthy endpoints quickly.

OptionWhy
A. CloudFrontServes HTTP and HTTPS content and caches it. It does not support UDP game traffic or give static IPs.
B. Route 53 latency routingReturns DNS answers, so there are no static IPs, and failover is slowed by the DNS TTL.
C. Global AcceleratorUDP, two static IPs, and fast health-based failover between Regions. Correct.
D. S3 Transfer AccelerationSpeeds up uploads to S3. It is unrelated to game servers.

2.4.2 Question 2: Real-Time Multiplayer Gaming

Exam-Style Question 2

A company runs a real-time multiplayer gaming platform hosted on EC2 instances in us-east-1. Players in Asia and Europe experience high latency and packet loss during gameplay. The game uses both TCP and UDP. Which AWS service should the solutions architect recommend to improve the experience for global players?

  1. Amazon CloudFront with an EC2 origin
  2. AWS Global Accelerator with EC2 endpoints
  3. Amazon Route 53 with latency-based routing
  4. AWS Direct Connect with BGP routing
Show the answer and explanation

Answer: B. Global Accelerator supports TCP and UDP and routes traffic over the AWS private backbone.

OptionWhy
A. CloudFront with an EC2 originOnly supports HTTP and HTTPS. Gaming uses UDP.
B. Global Accelerator with EC2 endpointsSupports TCP and UDP and routes through the AWS private backbone. Perfect for gaming. Correct.
C. Route 53 latency-based routingImproves DNS routing, but still sends traffic over the public internet.
D. Direct Connect with BGP routingFor dedicated private connections from on premises to AWS, not for players around the world.

2.4.4 Question 4: Gradual Release to a New Region

Exam-Style Question 4

A solutions architect is deploying a new version of a web application to a second AWS Region using AWS Global Accelerator. They want to send only 15% of traffic to the new Region initially and gradually increase it while monitoring for errors. Which Global Accelerator feature should the solutions architect use?

  1. Traffic dial on the new Region’s endpoint group
  2. Client affinity set to SOURCE_IP
  3. Endpoint weight adjustment
  4. Health check threshold configuration
Show the answer and explanation

Answer: A. The traffic dial sets the percentage of traffic (0 to 100%) for each endpoint group, and an endpoint group is a Region.

OptionWhy
A. Traffic dial on the new Region’s endpoint groupSets the traffic percentage per endpoint group (per Region). Correct.
B. Client affinity (SOURCE_IP)Controls session stickiness, not traffic distribution.
C. Endpoint weight adjustmentDistributes traffic within a Region (between endpoints), not across Regions.
D. Health check thresholdDecides when endpoints are considered unhealthy, not routing percentages.

3. Knowledge Check

Answer each question in your own words first, then expand the model answer to compare.

Question 1. What is AWS Global Accelerator, and what does it give you?

Show the model answer

It is a networking service that improves the performance and availability of global applications. It gives you two static anycast IP addresses, brings users onto the AWS network at the nearest edge location, and sends traffic over the AWS global network to healthy endpoints such as ALBs, NLBs, EC2 instances, or Elastic IPs. It supports TCP and UDP and does not cache content.

Question 2. What are listeners, endpoint groups, and endpoints?

Show the model answer

A listener checks for connections on a port or port range and a protocol. An endpoint group exists for each AWS Region and has a traffic dial and health check settings. An endpoint is the resource that receives the traffic: an ALB, NLB, EC2 instance, or Elastic IP.

Question 3. How do the traffic dial and endpoint weights differ?

Show the model answer

The traffic dial, from 0 to 100%, controls how much traffic goes to an endpoint group, which is a Region, so it suits canary and blue/green releases. Endpoint weights, from 0 to 255, split traffic between endpoints inside one endpoint group.

Question 4. How does Global Accelerator handle a failed endpoint, and why is it faster than DNS failover?

Show the model answer

It checks endpoints with TCP, HTTP, or HTTPS health checks and sends traffic only to healthy endpoints, usually failing over in under a minute. Clients keep the same static IP addresses, so there is no DNS caching or TTL delay as with Route 53.

Question 5. When do you use a custom routing accelerator?

Show the model answer

When the application must send a user to a specific EC2 instance and port in a VPC subnet, for example game matchmaking or VoIP. Routing is deterministic, and there are no health checks or failover.

Question 6. Compare CloudFront and Global Accelerator.

Show the model answer

CloudFront is a CDN that caches HTTP and HTTPS content at edge locations, is reached by a domain name, and supports edge compute. Global Accelerator does not cache, supports TCP and UDP, gives two static anycast IPs, and routes traffic over the AWS network to ALB, NLB, EC2, or Elastic IP endpoints with fast failover. Both use the edge network and the AWS backbone.

Question 7. A game uses UDP on NLBs in two Regions and needs static IPs and fast failover. What do you use, and why not CloudFront or Route 53?

Show the model answer

Use AWS Global Accelerator. CloudFront serves HTTP and HTTPS content and does not support UDP game traffic or give static IPs. Route 53 gives DNS answers, so there are no static IPs, and failover is slowed by the DNS TTL.
