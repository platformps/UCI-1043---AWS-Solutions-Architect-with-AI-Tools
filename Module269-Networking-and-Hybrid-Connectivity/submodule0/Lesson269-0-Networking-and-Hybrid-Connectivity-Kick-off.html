Overview of Module 269: Networking and Hybrid Connectivity

In this module, you will learn and demonstrate:

  • How to design a VPC with subnets, CIDR blocks, an internet gateway, route tables, network ACLs, and security groups (269.1)
  • How NAT gateways and NAT instances let private subnets reach the internet without being reachable from it (269.2)
  • How VPC peering, Transit Gateway, VPC endpoints, and AWS PrivateLink connect VPCs and services privately (269.3)
  • How VPC Flow Logs and Traffic Mirroring monitor and troubleshoot network traffic (269.4)
  • How a bastion host and Session Manager give secure remote access to private servers (269.5)
  • How Site-to-Site VPN and AWS Direct Connect connect on-premises networks to AWS (269.6)
  • How edge locations and Amazon CloudFront deliver content faster to users worldwide (269.7)
  • How AWS Global Accelerator provides static IP addresses and faster, more available global access (269.8)
  • How Amazon Route 53 routes users with DNS, routing policies, health checks, and hybrid DNS (269.9)

1. Workplace Simulation: How It Works

1.1 Modules as Working Group Projects: How It Works

  • Each module in this course is treated as a working group project within our simulated workplace.
  • Working Groups (teams) are expected to collaborate daily, support one another, and manage shared accountability for module success.
  • Every Working Group member has specific responsibilities: complete all assigned quizzes, labs, reflections, and checkpoints (your KPIs), and actively participate in team stand-ups and collaborative work sessions.
  • Working Group Leaders rotate with each new module and serve as the point of coordination, tracking, and reporting.
  • This model aims to simulate a realistic IT team environment, where communication, initiative, and reliability are just as important as technical skills.

1.2 Group Leader Responsibilities

There is one Working Group Leader per group (rotating per module).

  • Initiate daily morning stand-ups.
  • Maintain a shared Stand-up Notes Document (provided).
  • Monitor the group’s completion of quizzes, labs, and reflections.
  • Coordinate with the Training Manager (instructor) as needed.
  • Participate in the Working Group leaders’ check-in meetings with the Training Manager (instructor).
  • Keep everyone to one minute each (politely cut off if needed).
  • Capture blockers for later discussion (not solved during the stand-up).
  • Ensure the meeting ends on time (20 min hard stop).

1.3 Working Group and Learner Responsibilities

Each Working Group will:

  • Treat each module as a real-world project with clear deliverables and deadlines.
  • Support all Working Group members in completing KPIs, ensuring that no one falls behind.
  • Use daily stand-ups to track progress, identify blockers, and coordinate efforts.
  • Ensure the meeting ends on time (20 min firm stop).

Each learner is responsible for:

  • Submitting and passing all required module assignments, including quizzes, labs, reflections, and checkpoint reviews.
  • Participating in daily Working Group stand-ups and contributing to team collaboration.
  • Asking for help when needed and offering help when able.
  • Tracking their progress and sharing updates with the Working Group.
  • Arriving prepared with yesterday’s, today’s, and blocker notes.

3. Workplace Scenario Simulation

3.1 The Situation

Scenario

Northwind Shop is a fictional online retailer. Its next stage is to build the network for the shop: new VPCs on AWS, six servers and three branch offices that must connect to them, and customers around the world who expect a fast, always-on site.

You are the cloud network engineer. Over nine phases, the people around you bring real problems. For each one, write your own solution first, then open Show solution to compare.

3.3 Phase 1: Design the Network Foundation (Lesson 269.1)

Problem

Northwind is moving the shop into a new VPC. The web servers must be reachable from the internet, but the database must never be. The company’s data center already uses 10.0.0.0/16.

Your tasks

  1. Choose a VPC CIDR block and a public and private subnet layout across two Availability Zones.
  2. Explain what makes a subnet public.
  3. Decide where to use security groups and where network ACLs.
Show solution
  • Pick a CIDR block that does not overlap the data center, such as 10.10.0.0/16, and split it into subnets in two Availability Zones: public subnets for the load balancer and private subnets for the application and the database.
  • A subnet is public when its route table has a route to an internet gateway (0.0.0.0/0) and its instances have public IP addresses. Private subnets have no route to the internet gateway.
  • Security groups are stateful, have allow rules only, and work at the instance level. Network ACLs are stateless, can allow and deny, and work at the subnet level.
  • Overlapping CIDR blocks block later connections such as VPN, peering, and Transit Gateway, so plan them first.

3.4 Phase 2: Let Private Servers Reach the Internet (Lesson 269.2)

Problem

Servers in the private subnets must download patches and call a payment API on the internet, but nobody on the internet may start a connection to them.

Your tasks

  1. Choose the outbound gateway.
  2. Explain where it lives and how the route table points to it.
  3. Plan for high availability and cost.
Show solution
  • Use a NAT gateway in a public subnet with an Elastic IP address. In the private route table, send 0.0.0.0/0 to the NAT gateway.
  • A NAT gateway is managed and scales. A NAT instance is the older choice: you run, patch, and size it, and you must turn off the source/destination check.
  • For high availability, use one NAT gateway in each Availability Zone, or consider a Regional NAT Gateway (covered in lesson 269.2).
  • You pay for each gateway hour and for each GB processed, so send S3 and DynamoDB traffic through gateway endpoints instead (next phase).

3.5 Phase 3: Connect VPCs and Reach AWS Services Privately (Lesson 269.3)

Problem

The shop now has eight VPCs. Some must talk to each other, a partner needs to call one internal API, and the app sends a lot of traffic to S3 through the NAT gateway, which is expensive.

Your tasks

  1. Choose how to connect a few VPCs and how to connect many VPCs.
  2. Choose how to reach S3 and DynamoDB privately and cheaply.
  3. Choose how to expose one service to the partner without opening the whole VPC.
Show solution
  • VPC peering for a few one-to-one links: no overlapping CIDRs, and it is not transitive. Transit Gateway as a hub for many VPCs and on-premises networks.
  • Gateway endpoints for S3 and DynamoDB: a route table entry, no hourly fee, and the traffic skips the NAT gateway. Interface endpoints (AWS PrivateLink) reach other services.
  • AWS PrivateLink: put the service behind a Network Load Balancer and publish it as an endpoint service. The partner creates an interface endpoint in their VPC, reaches only that service, and the CIDR blocks may overlap.

3.6 Phase 4: Find Out Why Traffic Fails (Lesson 269.4)

Problem

After a change, the app cannot reach the database. Separately, the security team wants to inspect the actual packets of suspicious traffic to the web tier.

Your tasks

  1. Find which rule rejected the traffic.
  2. Choose where to create the flow log and where to send it.
  3. Choose how to capture packet contents.
Show solution
  • VPC Flow Logs can be created for a VPC, a subnet, or a network interface. Each record shows the source, destination, ports, protocol, and ACCEPT or REJECT. Send the logs to CloudWatch Logs, S3, or Amazon Data Firehose, and analyze them with Logs Insights or Athena.
  • Security groups are stateful and network ACLs are stateless. A request that is accepted while its response is rejected points to the network ACL.
  • Flow logs do not capture packet contents. Use VPC Traffic Mirroring to copy the packets from a network interface to a monitoring target, such as a Network Load Balancer or another network interface running an inspection tool.

3.7 Phase 5: Secure Admin Access to Private Servers (Lesson 269.5)

Problem

Admins reach the private servers through a bastion host in a public subnet with SSH open to the world and shared key files. Auditors ask who connected, and when.

Your tasks

  1. Reduce the risk of the bastion host.
  2. Choose an option with no open inbound ports.
  3. Choose how to record the sessions.
Show solution
  • If you keep a bastion host: put it in a public subnet, limit its security group to the office IP range, protect the key pair, patch it, and send its SSH logs to CloudWatch Logs.
  • Better: Systems Manager Session Manager. It needs no inbound ports, no bastion host, and no SSH keys, and access is controlled with IAM. It needs the SSM Agent and an IAM role (lesson 268.8).
  • Session Manager sessions can be logged to CloudWatch Logs or S3, which answers the auditors’ question.

3.8 Phase 6: Connect the Data Center and Branches (Lesson 269.6)

Problem

Six data center servers and three branch offices need private connectivity to AWS. The CFO wants to start next week at low cost. The CTO wants consistent performance later for a database sync, and a backup if the main link fails.

Your tasks

  1. Choose the quick, low-cost option.
  2. Choose the option for consistent performance.
  3. Design a backup.
Show solution
  • Site-to-Site VPN: IPsec tunnels over the internet, two tunnels for each connection, fast to set up, and attached to a virtual private gateway or a Transit Gateway.
  • AWS Direct Connect: a dedicated private connection with consistent latency and bandwidth. It takes longer to provision. Use virtual interfaces, and a Direct Connect gateway to reach many Regions.
  • Backup: Direct Connect as the primary and Site-to-Site VPN as the backup, or two Direct Connect locations for maximum resiliency.
  • Keep the on-premises CIDR blocks different from the VPC CIDR blocks (phase 1).

3.9 Phase 7: Make the Shop Fast Worldwide (Lesson 269.7)

Problem

Customers in Europe and Asia say that product pages and images load slowly. The images live in an S3 bucket, and premium downloads must go only to paying customers.

Your tasks

  1. Choose a service that caches content near users.
  2. Keep the S3 bucket private.
  3. Restrict the premium downloads.
  4. Remove an updated file from the cache.
Show solution
  • Amazon CloudFront caches content at edge locations, so users get it from a nearby location.
  • Use S3 as the origin with origin access control (OAC) and a bucket policy for the distribution, so the bucket stays private.
  • Signed URLs for one file, or signed cookies for many files, serve premium content only to authorized users.
  • Use an invalidation (for example /images/*) or versioned file names to replace updated files. For HTTPS on your own domain, use an ACM certificate in us-east-1.

3.10 Phase 8: Static IPs and Fast Failover (Lesson 269.8)

Problem

A partner will allow-list only fixed IP addresses. The live-auction feature uses UDP and runs in two Regions, and traffic must move to the healthy Region quickly.

Your tasks

  1. Choose a service that gives static IPs for a multi-Region application.
  2. Explain why CloudFront or Route 53 alone does not fit.
  3. Plan a gradual release to the new Region.
Show solution
  • AWS Global Accelerator gives two static anycast IP addresses, supports TCP and UDP, and sends traffic over the AWS network to ALB, NLB, EC2, or Elastic IP endpoints, with health checks and automatic failover.
  • CloudFront caches HTTP and HTTPS content and gives no static IPs or UDP. Route 53 returns DNS answers, so there are no static IPs, and failover is slowed by the DNS TTL.
  • For the gradual release, use the traffic dial on the new Region’s endpoint group, for example 15%, and raise it as the release looks healthy.

3.11 Phase 9: Names, Routing, and Failover (Lesson 269.9)

Problem

Customers must reach example.com and www.example.com. About 10% of users should try version 2 first, and a maintenance page must appear if the main site fails. Internally, servers need names like db.internal.example.com, and on-premises servers must resolve AWS private names.

Your tasks

  1. Choose the record type for the root domain and for www.
  2. Choose the routing policies for the canary release and the maintenance page.
  3. Choose a design for internal names and hybrid DNS.
Show solution
  • Alias records for both names, pointing to the ALB or CloudFront. They work at the zone apex, and queries to AWS resources are free.
  • Weighted routing with weights 90 and 10 for the canary. Failover routing with a health check on the primary and an S3 maintenance page as the secondary.
  • A private hosted zone for the internal names, associated with the VPCs.
  • Route 53 Resolver: an inbound endpoint so on-premises servers can resolve AWS names, and an outbound endpoint with a rule so the VPC can resolve on-premises names, over the VPN or Direct Connect.

4. Debrief Questions

Answer each question in your own words first, then expand the model answer to compare.

Question 1. How do security groups and network ACLs differ, and where does each apply?

Show the model answer

Security groups are stateful, have allow rules only, and apply to instances or network interfaces. Network ACLs are stateless, can allow and deny, and apply to subnets, so return traffic needs its own rule.

Question 2. Why use a NAT gateway for private subnets, and how do you make it highly available?

Show the model answer

A NAT gateway lets instances in private subnets start outbound connections to the internet while staying unreachable from it. It sits in a public subnet with an Elastic IP address, and the private route table sends 0.0.0.0/0 to it. For high availability, use one in each Availability Zone, or consider a Regional NAT Gateway.

Question 3. When do you choose VPC peering, Transit Gateway, and PrivateLink?

Show the model answer

VPC peering suits a few one-to-one connections, needs non-overlapping CIDR blocks, and is not transitive. Transit Gateway is a hub for many VPCs and on-premises networks. PrivateLink exposes one service privately to other VPCs, even with overlapping CIDR blocks, without opening the whole network.

Question 4. How do gateway endpoints and interface endpoints differ?

Show the model answer

Gateway endpoints are for S3 and DynamoDB, work through a route table entry, and have no hourly fee. Interface endpoints use PrivateLink with network interfaces in your subnets and reach many other services.

Question 5. When do you use VPC Flow Logs, and when Traffic Mirroring?

Show the model answer

Flow Logs record metadata about traffic, such as addresses, ports, and accept or reject, and are used for troubleshooting and auditing. They do not capture packet contents. Traffic Mirroring copies the actual packets from a network interface to a monitoring target for deep inspection.

Question 6. Why is Session Manager preferred over a bastion host?

Show the model answer

Session Manager needs no inbound ports, no bastion host, and no SSH keys. Access is controlled with IAM and sessions can be logged, so there is less to patch and secure and a clear record of who connected.

Question 7. When do you choose Site-to-Site VPN, Direct Connect, or both?

Show the model answer

VPN is quick and low cost, using encrypted tunnels over the internet. Direct Connect is a dedicated private link with consistent performance but takes longer to provision. Using Direct Connect with a VPN as backup, or two Direct Connect locations, adds resilience.

Question 8. How do CloudFront, Global Accelerator, and Route 53 differ?

Show the model answer

CloudFront caches HTTP and HTTPS content at edge locations. Global Accelerator gives two static anycast IP addresses and routes TCP and UDP traffic over the AWS network with health-based failover, without caching. Route 53 answers DNS queries with records, routing policies, and health checks, and does not carry the traffic.
