Route users with DNS: hosted zones, records, routing policies, health checks, and hybrid DNS with Amazon Route 53.

1. Route 53 Basics

Problem Statement

Your company’s website runs on EC2 instances behind a load balancer. Customers type www.example.com, but computers connect with IP addresses. The load balancer’s address can change, and one day an endpoint will fail.

You need a reliable service that translates names to addresses, can send users to the best endpoint, and can react when an endpoint fails.

1.1 What Is DNS?

  • DNS (Domain Name System) translates human-friendly domain names into IP addresses, such as www.example.com to 192.0.2.10.
  • DNS is hierarchical: the root, then top-level domains (TLDs), then your domain.
  • Answers are cached by resolvers for a time set in each record, the TTL.

1.2 How DNS Resolution Works

  • The browser asks the recursive resolver for www.example.com.
  • The resolver asks a root server, which points it to the .com TLD servers.
  • The TLD servers point to the authoritative name servers for example.com. If you use Route 53, those are your Route 53 name servers.
  • Route 53 returns the IP address. The resolver caches it for the TTL and answers the browser.
  • The browser then connects directly to the IP address. DNS never carries the user’s traffic.

1.3 What Is Amazon Route 53?

  • Amazon Route 53 is a highly available and scalable cloud DNS service provided by AWS.
  • Route 53 is also a domain registrar.
  • Why 53 in Route 53? 53 is a traditional DNS port.
  • A global service: you do not choose a Region.
  • Does three jobs: domain registration, DNS routing (authoritative DNS), and health checking.
  • AWS offers a 100 percent availability SLA for the Route 53 authoritative DNS service (check the Route 53 SLA for the exact terms).
  • Works with public names on the internet and private names inside your VPCs.
  • Integrates with ELB, CloudFront, API Gateway, S3, Elastic Beanstalk, Global Accelerator, and other AWS services through alias records.

1.4 Security, Logging, and Pricing

  • DNSSEC signing for public hosted zones protects against forged DNS answers. It uses an asymmetric KMS key that must be in us-east-1.
  • IAM controls who can change hosted zones and records.
  • Query logging for public hosted zones goes to CloudWatch Logs (in us-east-1). Resolver query logging covers your VPCs.
  • Pricing: a monthly fee for each hosted zone, a charge for each million standard queries, a fee for each health check, and a yearly fee for each registered domain.
  • Alias queries to AWS resources are free.
  • Check the Route 53 pricing page for current rates.

Exam Trap

Route 53 does not carry your traffic.

Route 53 only answers DNS queries. The user’s connection goes straight to the IP address that Route 53 returned. Route 53 is not a load balancer, a proxy, or a CDN.

Memory Hook

DNS = the phone book for the internet. Route 53 = AWS’s phone book: it registers domains, answers queries, and checks health.

2. Hosted Zones and Records

Problem Statement

You own example.com. The public website needs records on the internet, and the application servers need internal names such as db.internal.example.com that only your VPCs can resolve.

You need to know where records live, which record types to use, and how TTL affects changes.

2.1 Hosted Zones

  • A hosted zone is a container for the records of one domain, such as example.com, and its subdomains.
  • Route 53 creates two records for you in every zone: NS (the zone’s name servers) and SOA (zone information).
  • A public hosted zone gets four name servers. To use Route 53 for a domain registered elsewhere, copy these four NS values to the registrar. This is called delegation.
  • A hosted zone costs a monthly fee. Domain registration and hosted zones are separate things.
  • You pay $0.50 per month per hosted zone. Check the Route 53 pricing page for current rates.
Hosted Zones.
AspectPublic hosted zonePrivate hosted zone
Answers queries fromThe internetAssociated VPCs only

NeedsName servers set at the registrarOne or more associated VPCs

2.1.1 Private Hosted Zone Requirements

  • Associate the zone with each VPC that should resolve its names. VPCs can be in other Regions and accounts.
  • The VPC must have DNS support (enableDnsSupport) and DNS hostnames (enableDnsHostnames) turned on (lesson 269.1).
  • Split-view DNS: you can create a public and a private zone with the same name. Inside the VPC, the private zone answers. On the internet, the public zone answers.

2.3 Record Fields and TTL

  • Each record has a name, a type, a value, a TTL, and a routing policy (tab 4).
  • TTL (time to live) is how many seconds resolvers may cache the answer.
  • High TTL (for example 86400 seconds): fewer queries and lower cost, but changes spread slowly.
  • Low TTL (for example 60 seconds): changes and failover take effect quickly, but there are more queries.
  • Tip: lower the TTL before a planned change, such as a migration, and raise it again afterwards.
  • Alias records do not have a TTL you can set (tab 3).

2.3.1 Example: A Public Hosted Zone

example.com.        NS    ns-1234.awsdns-12.org. ...   (four name servers)
example.com.        SOA   ns-1234.awsdns-12.org. awsdns-hostmaster.amazon.com. ...
example.com.        A     ALIAS  -> my-alb-123.us-east-1.elb.amazonaws.com
www.example.com.    A     192.0.2.10                    TTL 300
mail.example.com.   MX    10 mailserver.example.com.    TTL 3600
example.com.        TXT   "v=spf1 include:_spf.example.com ~all"

2.4 Example: Setting Up a Domain

  1. Register example.com — Route 53 domain registration (or another registrar)
  2. Create a public hosted zone — Route 53 gives you four name servers
  3. Point the domain to Route 53 — registrar uses the four NS values (skip if registered in Route 53)
  4. Create records — example.com A alias to the ALB, www CNAME or alias, MX, TXT
  5. Test with a lookup — dig www.example.com (or nslookup)

Exam Trap

No CNAME at the zone apex.

You cannot create a CNAME record for the zone apex (example.com). Use an alias record instead (tab 3). Also remember that registering a domain and creating a hosted zone are separate steps.

Memory Hook

Hosted zone = the folder of records for a domain. Public = the internet sees it. Private = only associated VPCs see it.

SAA-C03 Keyword Triggers

Trigger 1: “Internal DNS names that resolve only inside a VPC”→ Private hosted zone.

Trigger 2: “Use Route 53 for DNS while the domain is registered elsewhere”→ Create a public hosted zone and set the registrar’s name servers to its four NS values.

Trigger 3: “A private hosted zone does not resolve inside the VPC”→ Turn on enableDnsSupport and enableDnsHostnames, and associate the VPC.

Trigger 4: “Different answers inside and outside the VPC for the same name”→ Split-view DNS: a public and a private zone with the same name.

Trigger 5: “Make DNS changes take effect quickly”→ Lower the TTL.

3. Alias Records vs. CNAME Records

Problem Statement

Your site example.com must point to an Application Load Balancer. The ALB only has a DNS name, not a fixed IP address, and example.com is the zone apex, where a CNAME is not allowed.

You also want to avoid paying for DNS queries to your own AWS resources.

3.1 What Is an Alias Record?

  • An alias record is a Route 53 extension to DNS that points a name to selected AWS resources.
  • It works at the zone apex (example.com) and for subdomains.
  • The record type is A (IPv4) or AAAA (IPv6), and it must be the same type as the record or resource it points to.
  • Route 53 follows the alias and answers with the current IP addresses of the target, so changes at the target are picked up automatically.
  • Route 53 does not charge for alias queries to AWS resources.
  • Evaluate target health lets an alias record use the health of its target, such as a load balancer, without a separate health check.
  • You cannot set the TTL on an alias record. Route 53 uses the TTL of the target.

3.2 Alias vs. CNAME

Exam Trap

Apex plus AWS resource means alias.

When the question says example.com (no www) must point to an ELB or CloudFront, the answer is an alias record. A CNAME is wrong at the apex. Also, alias queries to AWS resources are free.

Memory Hook

Alias = AWS-only, apex allowed, free queries, A or AAAA. CNAME = any target, no apex, charged queries.

SAA-C03 Keyword Triggers

Trigger 1: “Point the root domain to a load balancer or CloudFront distribution”→ Alias record.

Trigger 2: “A CNAME record cannot be created for example.com”→ Use an alias record.

Trigger 3: “Reduce DNS query costs to AWS resources”→ Alias records (free to AWS resources).

Trigger 4: “Point a subdomain to a third-party service”→ CNAME record.

Trigger 5: “Route to a load balancer and use its health automatically”→ Alias with Evaluate target health.

4. Routing Policies

Problem Statement

Your application now runs in two Regions. You want to test a new version on 10 percent of users, send each user to the nearest Region, keep EU customers inside the EU, and switch to a backup if a site fails.

Route 53 has eight routing policies. You need to know which one fits which requirement.

4.1 What Is a Routing Policy?

  • A routing policy tells Route 53 how to answer a DNS query when a name has one or more records.
  • It decides which answer to return. It does not route the user’s packets.
  • You choose the policy when you create the record.
  • Records with the same name and type can share a policy, and health checks can remove unhealthy answers (tab 5).

4.2 The Eight Policies at a Glance

The Eight Policies at a Glance.
PolicyHow it chooses the answerHealth checksTypical use
SimpleOne record, or several values returned togetherNoOne resource, such as one web server
WeightedBy weights you assignYesCanary tests, gradual migration, A/B tests
LatencyThe AWS Region with the lowest latency to the userYesMulti-Region apps for the best speed
FailoverPrimary while healthy, otherwise secondaryRequired on the primaryActive-passive disaster recovery
GeolocationThe user’s location: continent, country, or US stateYesContent licensing, data residency, local language
GeoproximityDistance between users and resources, adjusted by a biasYesShift traffic toward or away from a location
IP-basedThe client’s IP address range (a CIDR collection)YesSend known networks or ISPs to specific endpoints
Multivalue answerUp to eight healthy records at randomYesSimple client-side spreading with health checks

4.3 The Policies in Detail

4.3.1 Simple

  • The default policy.
  • Typically used to route traffic to a single resource.
  • Can specify multiple values in the same record.
  • If multiple values are returned, a random one is chosen by the client.
  • Health checks are not supported, so all values are returned regardless of health.
  • Example: www.example.com A 192.0.2.10.

4.3.2 Weighted

  • You create multiple records with the same name and type, each assigned a weight.
  • Each record has a weight from 0 to 255. The share of traffic is the record’s weight divided by the total of all weights.
  • Route 53 routes traffic proportionally based on those weights (for example 70/30, 50/50, or 90/10).
  • Useful for load balancing, testing new versions, and gradual traffic shifting.
  • Supports health checks: unhealthy records are removed from responses.
  • A weight of 0 stops sending traffic to that record (it is excluded from routing).
  • Example (canary): the current version has weight 90 and the new version has weight 10, so about 10 percent of queries get the new version. Raise the weight as confidence grows.
Weighted.
RecordValueWeightShare
app.example.comVersion 1 (ALB 1)9090%
app.example.comVersion 2 (ALB 2)1010%

4.3.3 Latency

  • Routes users to the AWS Region that provides the lowest network latency for them.
  • You create records with the same name but in different AWS Regions, one for each Region where the app runs.
  • Uses latency measurements between AWS Regions and the user’s DNS resolver.
  • Supports health checks: Route 53 avoids unhealthy endpoints.
  • Ideal for latency-sensitive global applications.
  • Example: the app runs in us-east-1 and eu-west-1. A user in Paris is sent to eu-west-1.
  • Lowest latency is not always the closest location. It is the fastest measured path.

4.3.4 Failover

  • Achieves active-passive failover, generally across AWS Regions.
  • Uses health checks. The primary must have a health check.
  • You define Primary and Secondary (standby) records.
  • The Primary is returned only if its health check is healthy. If the Primary becomes unhealthy, Route 53 returns the Secondary.
  • The Secondary should point to a backup system: a DR site, another Region, a static maintenance page, and so on.
  • Example: primary is an ALB in us-east-1, and the secondary is a static maintenance page in S3.
  • More in tab 5.

4.3.5 Geolocation

  • Routes users based on their physical location (country, continent, or specific US state).
  • You explicitly assign which location goes to which endpoint.
  • Strict mapping: if a user is from India, they always go to the endpoint configured for India.
  • Useful for compliance, content localization, or region-restricted applications.
  • Must have a default record for unmatched locations. Without a default, users from unlisted locations get no answer.
  • Example (data residency): users in the EU go to eu-west-1, and everyone else goes to us-east-1.
  • Example (licensing): a streaming site serves only the catalog licensed for each country.

4.3.6 Geoproximity

  • Routes users based on geographic distance between the user and your AWS or on-premises endpoints.
  • You can add a bias to shift more or less traffic toward a specific endpoint.
  • Set a bias of 1 to 99 to expand the size of the geographic region.
  • Set a bias of -1 to -99 to shrink the size of the geographic region.
  • More flexible: traffic can shift dynamically as distances or biases change.
  • Requires Route 53 Traffic Flow (policy-based routing), section 4.5.
  • Example: a new Region has spare capacity, so you add a positive bias to move more users to it.

4.3.7 Routing Policies: IP-Based Routing

  • Routes traffic based on the client’s IP address range (CIDR blocks), using a CIDR collection that you define.
  • You create records mapped to specific IP ranges.
  • Gives fine-grained control, more precise than geolocation (country level).
  • Useful when you want certain networks, ISPs, or corporate ranges to reach specific endpoints.
  • Example: three records for example.com, each mapped to a client IP range.

4.3.8 Multivalue Answer

  • Allows multiple records with the same name and type.
  • Route 53 returns up to eight healthy IPs in each DNS response.
  • The client chooses one of those IPs to connect to.
  • Supports health checks: unhealthy endpoints are automatically removed.
  • Useful for distributing traffic across multiple servers or endpoints.
  • Provides basic DNS-level load balancing (not as advanced as an ELB).

Exam Trap

Latency, geolocation, and geoproximity.

Latency = fastest Region. Geolocation = the user’s country or continent, used for compliance and licensing. Geoproximity = distance with a bias. Also, failover needs a health check on the primary, and a geolocation record set needs a default record.

Weighted = percentages. Latency = speed. Failover = backup. Geolocation = where you are. Geoproximity = how far, plus bias. IP-based = who you are. Multivalue = several healthy answers.

5. Health Checks and DNS Failover

Problem Statement

The primary web site in us-east-1 becomes unavailable. Customers keep getting DNS answers that point to it.

You need Route 53 to notice the failure and automatically return a different answer.

5.1 What Are Route 53 Health Checks?

  • Route 53 uses health checkers in many locations around the world to test your endpoints.
  • If an endpoint is unhealthy, Route 53 stops returning it in DNS answers, when the record has a health check.
  • Health checks can also raise CloudWatch metrics and alarms for notifications.
What Are Route 53 Health Checks.
TypeWhat it monitorsTypical use
EndpointAn IP address or domain name over HTTP, HTTPS, or TCP, optionally checking for a string in the responsePublic web servers and load balancers
CalculatedThe results of other health checks, combined with AND, OR, or "at least N healthy"One status for a multi-part application
CloudWatch alarmThe state of a CloudWatch alarmPrivate resources that the health checkers cannot reach

5.2 Health Check Settings

  • Interval: every 30 seconds (standard) or every 10 seconds (fast, at extra cost).
  • Failure threshold: how many failed checks in a row make the endpoint unhealthy (the default is 3).
  • Path and string matching: for HTTP and HTTPS, the path to request, such as /health, and optional text that must appear in the response.
  • Firewalls: allow traffic from the Route 53 health checker IP ranges to the endpoint.

5.2.1 Health Checks for Private Resources

  • The health checkers are outside your VPC, so they cannot reach a private IP address.
  • Create a CloudWatch alarm on a metric of the private resource, such as an ALB’s unhealthy host count, then create a health check based on that alarm.

5.3 DNS Failover

  • Create a primary and a secondary failover record with the same name.
  • Attach a health check to the primary. For an alias record, you can instead turn on Evaluate target health.
  • While the primary is healthy, Route 53 answers with it. When it becomes unhealthy, Route 53 answers with the secondary.
  • When the primary recovers, Route 53 switches back.
DNS Failover.
RecordTypeValuePolicyHealth check
www.example.comA (alias)ALB in us-east-1Failover: PrimaryYes (or evaluate target health)

5.3.1 Demo: Failover Routing Policy

In the course demo, the Primary is in Mumbai and the Secondary is in N. Virginia, and Route 53 runs a health check against the Primary.

  1. Launch two EC2 instances (Primary and Secondary) in different Regions and configure them as web servers. Allow HTTP from anywhere in the security group.
  2. Create a Route 53 public hosted zone for your domain name. You must own the domain.
  3. Create a health check for the Primary web server in Route 53.
  4. Create an A record with the Failover routing policy that points to the Primary public IP. Create another A record with the Failover routing policy (Secondary) that points to the Secondary public IP.
  5. Access your domain name. It always points to the Primary.
  6. Stop the Primary EC2 instance to simulate a failure. Wait for the health check to fail.
  7. Access the domain name again. It should now point to the Secondary.

5.4 Active-Active Designs

  • With weighted, latency, geolocation, or multivalue records, attach a health check to every record.
  • Unhealthy records are removed from the answers, and traffic is spread across the healthy ones.
  • Without a health check, Route 53 keeps answering with a dead endpoint.

5.5 TTL and Failover Time

  • Resolvers cache answers for the TTL, so failover is not instant.
  • A low TTL (for example 60 seconds) on failover records makes clients switch sooner.
  • Total failover time is roughly the time to detect the failure (interval and threshold) plus the TTL.

6. Route 53 Resolver and Hybrid DNS

Problem Statement

Servers in your data center must resolve AWS private names, such as db.internal.example.com. EC2 instances in your VPC must resolve on-premises names, such as erp.corp.example.local.

The two environments are connected by a VPN or Direct Connect, but each has its own DNS.

6.1 What Is Route 53 Resolver?

  • The DNS resolver built into every VPC. It answers queries from your instances automatically.
  • It is reached at the VPC base address plus two (for example 10.0.0.2 in a 10.0.0.0/16 VPC) and is also known as AmazonProvidedDNS.
  • It resolves public names, VPC internal names (such as ip-10-0-0-5.ec2.internal), and names in private hosted zones.
  • It forwards other requests to public DNS (including Route 53 public hosted zones).
  • It is accessible only from within the VPC. It cannot be accessed from outside the VPC.
  • It cannot access other DNS servers, such as one on premises. Hybrid DNS (next section) fills that gap.
  • It needs the VPC’s DNS support setting on (lesson 269.1).

6.2 Hybrid DNS

  • Hybrid DNS is name resolution between your VPC and your corporate data center, connected by VPN or Direct Connect.
  • By default, the Route 53 Resolver cannot be reached from outside the VPC, and it cannot query on-premises DNS servers.
  • So on-premises servers cannot resolve AWS private names, and EC2 instances cannot resolve on-premises names, even though the VPN or Direct Connect link works. Network connectivity alone is not enough.
  • Resolver endpoints fix this: an inbound endpoint for queries from on premises, and an outbound endpoint for queries to on premises.

6.2.1 Route 53: Resolver Endpoints

  • Inbound resolver endpoint — allows your DNS resolvers to resolve domain names for AWS resources (for example EC2 instances) and records in private hosted zones.
  • Outbound resolver endpoint — the Route 53 Resolver forwards DNS queries to your DNS resolvers.
Route 53: Resolver Endpoints.

  • On premises, a DNS forwarder sends queries for AWS names to the inbound endpoint.
  • In the VPC, conditional forwarding (a resolver rule) sends queries for on-premises domains through the outbound endpoint to the corporate DNS server.
  • Each endpoint needs IP addresses in at least two Availability Zones for high availability.
  • The network must be connected by Site-to-Site VPN or Direct Connect (lesson 269.6).
  • Security groups on the endpoints must allow DNS (port 53) over UDP and TCP.

6.3 Resolver Rules

  • A forwarding rule says: for queries about domain X, send them to these DNS server IP addresses.
  • Example: a rule for corp.example.local forwards to the on-premises DNS servers 10.50.0.10 and 10.50.0.11.
  • A rule is associated with VPCs.
  • Rules can be shared with other accounts by using AWS Resource Access Manager (RAM).
  • System rules keep names such as internal VPC names resolving as usual.

6.4 DNS Firewall and Query Logging

  • Route 53 Resolver DNS Firewall filters outbound DNS queries from your VPCs. You allow or block domain lists, including AWS managed lists.
  • It helps stop DNS exfiltration and access to known bad domains.
  • Resolver query logging records the queries that your VPC resources make, and sends them to CloudWatch Logs, S3, or Kinesis Data Firehose.

7.5.1 Question 1: Data Residency

Exam-Style Question 1

A company runs its application in eu-west-1 and us-east-1. Because of data residency laws, customers in the European Union must always be served from eu-west-1. All other customers should be served from us-east-1. The company wants the least operational overhead.

Which Route 53 routing policy should the company use?

  1. Latency routing with a record for each Region.
  2. Geolocation routing with a record for the EU and a default record.
  3. Weighted routing with a weight of 100 for eu-west-1.
  4. Multivalue answer routing with both Regions.
Show the answer and explanation

Answer: B. Geolocation routes by the user’s location and can send EU users to eu-west-1 every time. The default record covers all other locations.

OptionWhy
A. Latency routingPicks the fastest Region. An EU user could be sent to us-east-1 if it measures faster, which breaks the residency rule.
B. Geolocation with a default recordRoutes by location. EU users always go to eu-west-1, and the default record sends everyone else to us-east-1. Correct.
C. Weighted routingSplits traffic by percentage, not by who the user is.
D. Multivalue answer routingReturns several healthy addresses at random, so EU users could reach either Region.

8. Knowledge Check

Answer each question in your own words first, then expand the model answer to compare.

Question 1. What are the three main functions of Amazon Route 53?

Show the model answer

Domain registration, DNS routing as an authoritative DNS service, and health checking. It is a global, highly available service, and AWS offers a 100 percent availability SLA for the authoritative DNS service.

Question 2. Describe how a DNS query for www.example.com is resolved when the domain uses Route 53.

Show the model answer

The browser asks a recursive resolver. The resolver asks a root server, which points to the .com TLD servers, which point to the authoritative name servers for example.com, which are Route 53’s. Route 53 returns the IP address, the resolver caches it for the TTL and returns it to the browser, and the browser connects directly to that address. DNS does not carry the user’s traffic.

Question 3. What is the difference between a public and a private hosted zone, and what does a private zone need?

Show the model answer

A public hosted zone answers queries from the internet. A private hosted zone answers only for the VPCs associated with it. The VPC needs DNS support and DNS hostnames turned on. You can create a public and a private zone with the same name for split-view DNS.

Question 4. Why cannot you use a CNAME for example.com, and what do you use instead?

Show the model answer

A CNAME is not allowed at the zone apex. Use a Route 53 alias record, an A or AAAA record that points to an AWS resource such as an ELB or a CloudFront distribution. Alias queries to AWS resources are free, and an alias can evaluate the target’s health.

Question 5. Compare alias records and CNAME records.

Show the model answer

An alias is a Route 53 extension for AWS resource targets or another record in the same zone. It works at the apex, is free for AWS targets, appears as A or AAAA, and takes its TTL from the target. A CNAME can point to any name, including outside AWS, but not at the apex, and it has standard query charges.

Question 6. A company wants to send 10 percent of traffic to a new version of an application. Which routing policy, and how?

Show the model answer

Weighted routing. Create two records with the same name: one with weight 90 for the current version and one with weight 10 for the new version, and raise the new version’s weight as confidence grows. A weight of 0 stops traffic to a record.

Question 7. How do latency, geolocation, and geoproximity routing differ?

Show the model answer

Latency routing sends users to the AWS Region with the lowest measured latency. Geolocation routes by the user’s country, continent, or US state, and needs a default record for other locations. Geoproximity routes by geographic distance and adds a bias to shift more or less traffic to a location.

Question 8. How does DNS failover work, and what must be in place?

Show the model answer

Create a primary and a secondary record with failover routing, and attach a health check to the primary, or turn on Evaluate target health for an alias record. While the primary is healthy, Route 53 answers with it. When it fails, Route 53 answers with the secondary. Failover is not instant because resolvers cache answers for the TTL, so use a low TTL.

Question 9. How do you health check a resource in a private subnet?

Show the model answer

The Route 53 health checkers are outside the VPC and cannot reach private IP addresses. Create a CloudWatch alarm on a metric of the resource, then create a Route 53 health check based on that alarm.

Question 10. On-premises servers must resolve names in a private hosted zone, and EC2 instances must resolve on-premises names. What do you configure?

Show the model answer

Use Route 53 Resolver. Create an inbound endpoint so the on-premises DNS server can forward AWS names to the VPC. Create an outbound endpoint and a forwarding rule so the VPC forwards the on-premises domain to the on-premises DNS servers. Both need a VPN or Direct Connect connection, and rules can be shared with AWS RAM.

Question 11. How can you protect against forged DNS answers, and what else can you do to control DNS in a VPC?

Show the model answer

Turn on DNSSEC signing for the public hosted zone, using an asymmetric KMS key in us-east-1. Inside the VPC, use Route 53 Resolver DNS Firewall to allow or block domain lists and Resolver query logging to record queries.
