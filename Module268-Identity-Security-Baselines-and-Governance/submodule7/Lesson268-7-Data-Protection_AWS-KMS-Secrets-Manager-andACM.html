Lesson 268.7 - Data Protection: AWS KMS, Secrets Manager, and ACM

Encrypt data at rest with KMS, rotate credentials with Secrets Manager, and secure data in transit with ACM.

Overview and Objectives

Lesson Overview

Three AWS services, three jobs: create and manage encryption keys, store and rotate secrets, and provision Transport Layer Security (TLS) certificates. The AWS Certified Solutions Architect – Associate (SAA-C03) exam often asks which service fits which scenario.

  • Tab 1 covers AWS Key Management Service (AWS KMS): how AWS creates, stores, and controls encryption keys, key types, envelope encryption, key policies, and Regional behavior.
  • Tab 2 covers AWS Secrets Manager: how to remove hard-coded credentials from applications and how automatic secret rotation works from start to finish.
  • Tab 3 covers AWS Certificate Manager (ACM): how to provision auto-renewing TLS certificates, where they can be deployed, and when to use AWS Private Certificate Authority (AWS Private CA).
  • Tab 4 compares the three services, shows a combined architecture, and lists scenario drills and decision rules.
  • Tab 5 checks your understanding with open-ended questions.

Learning Objectives

By the end of this lesson, you will be able to:

  1. Define the purpose of AWS KMS, Secrets Manager, and ACM, and list the three KMS key ownership types and the two ACM validation methods.
  2. Explain envelope encryption and why KMS never releases key material, and describe the automatic rotation workflow in Secrets Manager with the staging labels AWSCURRENT and AWSPENDING.
  3. Summarize how ACM automatic renewal works and why DNS validation is preferred over email validation.
  4. Apply the correct service to a requirement, for example by choosing a customer managed KMS key for cross-account snapshot sharing, or by placing an ACM certificate in us-east-1 for Amazon CloudFront.
  5. Differentiate Secrets Manager from AWS Systems Manager Parameter Store, and KMS from AWS CloudHSM, based on rotation, cost, tenancy, and compliance requirements.
  6. Evaluate the most appropriate encryption, secrets, and certificate design for exam-style scenarios, weighing cost, operational overhead, and security requirements.
  7. Design a layered architecture where ACM secures data in transit, Secrets Manager supplies rotating credentials, and KMS encrypts data at rest.

1. AWS Key Management Service (KMS)

Problem Statement

Your company stores customer data in Amazon S3, Amazon EBS volumes, and Amazon RDS databases. Compliance requires that everything is encrypted at rest. Where do you store the encryption keys? Keeping them on a developer’s laptop or hard-coded in an application is a breach waiting to happen.

How do you control who can use a key, and prove to an auditor exactly who used it and when? How do you rotate keys regularly without re-encrypting terabytes of data by hand? How do you get more than 50 AWS services to use these keys consistently, without writing your own cryptographic code?

You need a centralized, managed, auditable key service that is built into AWS itself.

1.1 What AWS KMS Is

AWS Key Management Service (AWS KMS) is a managed service for creating and controlling the cryptographic keys that encrypt your data. It integrates natively with almost every AWS service that stores data, such as Amazon S3, Amazon EBS, Amazon RDS, Amazon DynamoDB, AWS Lambda, and AWS Secrets Manager. Every use of a key is logged in AWS CloudTrail.

Think of it as a hardened vault. The keys never leave KMS unencrypted. Services and applications send data, or data keys, to KMS to be encrypted or decrypted, and they never hold the master key themselves.

1.2 Key Concepts

1.2.1 KMS Keys

A KMS key was formerly called a customer master key (CMK). It is the primary resource in KMS: a logical key that can encrypt and decrypt up to 4 KB of data directly. For anything larger, KMS uses envelope encryption. Three ownership types matter for the exam:

1.2.2 Envelope Encryption

KMS does not directly encrypt a 2 TB EBS volume. Instead:

  1. The service asks KMS to generate a data key (the GenerateDataKey API).
  2. KMS returns two things: a plaintext data key, which encrypts your data locally and is then discarded, and an encrypted data key, which is stored alongside your data.
  3. To decrypt later, the service sends the encrypted data key back to KMS. KMS decrypts it, the service uses the plaintext key, and then discards it again.

This is why KMS scales. The heavy encryption happens locally with the data key, and KMS handles only small amounts of key material. The exam expects you to recognize the term envelope encryption and the GenerateDataKey API.

1.2.3 Key Policies and Access Control

  • Every KMS key has a key policy. It is a resource-based policy and the primary way to control access to the key. Unlike most resources, a KMS key ignores IAM policies unless the key policy allows the account to use IAM.
  • Grants provide temporary, programmatic delegation of key usage. AWS services commonly use them on your behalf.
  • Cross-account access is allowed by combining the key policy in the key-owning account with an IAM policy in the user’s account. This is a common exam scenario for sharing encrypted snapshots and AMIs across accounts.

1.2.4 Region Behavior

  • KMS keys are Regional. A key in us-east-1 cannot be used in eu-west-1.
  • To copy an encrypted EBS snapshot to another Region, the copy is re-encrypted with a key in the destination Region.
  • Multi-Region keys exist. A primary key is replicated to other Regions with the same key ID and key material. They suit globally distributed applications and DynamoDB global tables, and each Region still manages its own copy independently.

1.2.5 Deletion Safety

You cannot delete a customer managed key instantly. You schedule deletion with a waiting period of 7 to 30 days (the default is 30). During that time the key is unusable but recoverable. This protects you from irreversibly losing access to every piece of data that the key encrypted.

1.3 Related but Different: AWS CloudHSM

If a question demands a dedicated, single-tenant hardware security module (HSM), full control of the HSM, or customer-only access to the keys, the answer is AWS CloudHSM, not KMS. KMS is multi-tenant and managed. CloudHSM gives you your own device. KMS can even use CloudHSM as a custom key store.

What Has Changed

Older study material says to choose CloudHSM when a question mentions “FIPS 140-2 Level 3.” AWS now states that both KMS and CloudHSM use hardware validated at Federal Information Processing Standard (FIPS) 140-3 Level 3. The deciding factor today is dedicated, single-tenant hardware that you control. Exam questions can still use the older FIPS wording, so match the trigger words. See AWS KMS or AWS CloudHSM: choose the right key management solution.

2. AWS Secrets Manager

Problem Statement

Encryption keys are handled, but your applications still need credentials: database passwords, API keys, and OAuth tokens. Where do they live today? They might be hard-coded in application code, where every developer and your Git history can read them. They might be in configuration files or environment variables, copied across environments, never rotated, and impossible to audit.

And when security says to rotate the production database password every 30 days, someone does it by hand at 2 AM, applications break because they still cache the old password, and everyone quietly agrees never to rotate again.

You need a place to store secrets encrypted, retrieve them at runtime through an API, and rotate them automatically, with the database updated and the application unaware of the change.

2.1 What AWS Secrets Manager Is

AWS Secrets Manager stores, encrypts, retrieves, and automatically rotates secrets such as database credentials, API keys, and tokens. Applications fetch secrets at runtime with an API call (GetSecretValue) instead of reading them from code or configuration files.

2.2 Real-World Architecture: A Serverless API

Follow the numbers in the diagram:

  1. Clients connect. A mobile app, website, or other service sends requests over the internet.
  2. API Gateway invokes Lambda. API Gateway receives the request and invokes a Lambda function that contains the business logic.
  3. Lambda fetches the secret. Instead of a hard-coded password, Lambda calls Secrets Manager (GetSecretValue) to retrieve the current database credentials at runtime.
  4. Lambda connects to RDS. With the credentials that it just retrieved, Lambda queries the database and returns the result through API Gateway to the client.

Meanwhile, automatic rotation every 30 days runs in the background. Because step 3 always fetches the current secret, the application keeps working through every rotation. Nothing needs to be redeployed or restarted.

2.3 Core Capabilities

  • Encrypted at rest with KMS: Every secret is encrypted with a KMS key. These services stack.
  • Automatic rotation: Built-in, managed rotation for Amazon RDS (MySQL, PostgreSQL, MariaDB, SQL Server, and Oracle), Amazon Aurora, Amazon Redshift, and Amazon DocumentDB. Secrets Manager rotates the credential and updates the database on your schedule, for example every 30 days. For anything else, it invokes a custom Lambda function that you provide.
  • Fine-grained access: IAM policies and resource policies control which identities can read which secret. Cross-account access is supported through resource policies.
  • Auditing: Every retrieval and rotation is logged in CloudTrail.
  • Multi-Region replication: Replicate a secret to other Regions for disaster recovery and low-latency access. Replicas stay in sync with the primary.
  • Versioning: Staging labels (AWSCURRENT, AWSPREVIOUS, and AWSPENDING) allow safe rotation without breaking clients in the middle of a rotation.

2.5 Basic Scenario With Typical Users

Typical users of Secrets Manager play one or more of these roles:

  • Secrets Manager administrator: Grants permissions to users who can then perform the other roles.
  • Database or service administrator: Determines and configures the rotation and expiration settings for database and service secrets.
  • Application developer: Configures the application to request the appropriate credentials from Secrets Manager.

A typical use case is to store credentials for a database in Secrets Manager, and then use the credentials in the application to access the database.

  1. The database admin creates the credentials on the Amazon Aurora database.
  2. The admin stores those credentials as a secret in Secrets Manager, encrypted with a KMS key.
  3. The web app requests the secret from Secrets Manager when it needs to connect.
  4. Secrets Manager returns the current credentials to the application.
  5. The app connects to the database with those credentials. Because it fetches them at runtime, rotation never breaks it.

3. AWS Certificate Manager (ACM)

Problem Statement

Keys are handled and secrets are handled. But your users connect to https://app.example.com, and data in transit needs TLS. Traditionally that means buying certificates from a certificate authority, per domain and per year. It means generating certificate signing requests, validating domain ownership, and installing the certificate on every load balancer and server.

The worst part is remembering to renew. One missed renewal and your site shows every customer a full-screen browser security warning.

You want certificates that are free, easy to request, automatically validated, deployed straight onto AWS services, and, above all, automatically renewed.

3.1 What ACM Is

AWS Certificate Manager (ACM) provisions, manages, and deploys public and private Secure Sockets Layer and TLS (SSL/TLS) certificates for use with AWS services. By default, public certificates are free and ACM renews them automatically. Those two facts make ACM the default answer for HTTPS on AWS.

3.2 Where ACM Certificates Can Be Used

  • Elastic Load Balancing (ALB and NLB): The most common use. Terminate HTTPS at the load balancer.
  • Amazon CloudFront: The certificate must be requested or imported in us-east-1 (N. Virginia), no matter where your origin lives. This is a favorite exam detail.
  • Amazon API Gateway: Custom domain names. To serve secure content over SSL/TLS, set up a custom domain name and provide an SSL/TLS certificate that ACM generates or imports.
  • Other integrated services: AWS App Runner, AWS Elastic Beanstalk, and others.

3.2.1 More Services Integrated With ACM

  • AWS Nitro Enclaves: EC2 instances that are connected to Nitro Enclaves support ACM certificates.
  • AWS CloudFormation: ACM certificates can be a template resource, so CloudFormation can request ACM certificates for your infrastructure as code.
  • AWS Amplify: When a custom domain is connected to an application, Amplify secures it by automatically issuing an ACM certificate.
  • Amazon OpenSearch Service: Integrates with ACM to enable secure capabilities such as log analytics, real-time application monitoring, and clickstream analysis.
  • AWS Network Firewall: Integrates with ACM for TLS inspection. You configure an ACM certificate to decrypt and re-encrypt SSL/TLS traffic that passes through the firewall.

3.3 What ACM Does Not Do by Default

What Has Changed

By default, you cannot export the private key of an ACM public certificate, so you cannot install it on an EC2 instance, an on-premises server, or anywhere outside integrated AWS services. Older study material states this as a permanent rule. Since June 2025, you can request an exportable public certificate for an additional charge, and then export the certificate and its private key for use on EC2 instances, containers, and on-premises hosts. You must choose export when you request the certificate, and you cannot export public certificates that already exist. See AWS Certificate Manager exportable public certificates.

For a workload that needs a certificate on EC2 or on premises, the options are:

  • Request an exportable public certificate in ACM, for an additional charge.
  • Import a third-party certificate into ACM. Renewal is then your job.
  • Use AWS Private CA to issue private certificates, which are exportable and are a paid service.

Using a standard, non-exportable ACM public certificate directly on an EC2 web server is still the wrong answer. The exam may use the older wording, so read the question carefully.

3.5 Public Versus Private Certificates

  • Public certificates: Trusted by browsers and renewed automatically. By default they are free and not exportable.
  • AWS Private CA: Run your own certificate authority for internal services, such as TLS between microservices and internal domains. Certificates can be exported. It has a monthly cost. The trigger is “internal applications need certificates that our browsers and services trust privately.”

Exam Trap

  • CloudFront accepts ACM certificates only from us-east-1. For a Regional ALB or API Gateway, the certificate lives in the same Region as the resource.
  • Email validation needs a person at every renewal. DNS validation renews automatically.
  • A standard ACM public certificate cannot be installed on an EC2 web server. Look for “exportable” in the question.

Memory Hook

ACM means certificates that renew. DNS validation is the one that renews by itself.

5. Knowledge Check

Answer each question in your own words, and then open the model answer to compare.

Question 1: Envelope Encryption. Explain envelope encryption in your own words. Why does KMS not simply encrypt a 2 TB EBS volume directly?

Show the model answer

A KMS key can encrypt only small payloads, up to 4 KB, and key material never leaves KMS. Sending terabytes of data to KMS would be slow and is impossible by design. Instead, KMS generates a data key. The plaintext copy encrypts the data locally and is then discarded, while the encrypted copy of the data key is stored alongside the data. To decrypt, the encrypted data key is sent back to KMS, which returns the plaintext data key for local decryption. Bulk cryptography stays local, and KMS handles only key material.

Question 2: Sharing an Encrypted Snapshot. A company needs to share an encrypted EBS snapshot with a partner’s AWS account. Which type of KMS key must be used, and what two things must be configured?

Show the model answer

A customer managed KMS key must be used, because AWS managed keys such as aws/ebs cannot be shared across accounts. First, the key policy in the owning account must grant the partner account permission to use the key, for example kms:Decrypt and kms:CreateGrant. Second, the snapshot itself must be shared with the partner’s account ID. The partner then typically copies the snapshot and re-encrypts it with its own key.

Question 3: Rotation and Staging Labels. What happens between the moment a Secrets Manager rotation Lambda function creates a new database password and the moment applications start using it? Mention the staging labels.

Show the model answer

The new credential is stored as a new secret version labeled AWSPENDING. The Lambda function updates the database with the new password and tests that it works. Only after a successful test does the new version become AWSCURRENT, and the old one becomes AWSPREVIOUS. Applications that call GetSecretValue always receive whatever is AWSCURRENT, so they pick up the new password automatically, with no redeployment and no breakage in the middle of a rotation.

Question 4: Secrets Manager or Parameter Store. Your team stores 300 plain configuration values and a handful of static API keys that never need rotation. Budget is tight. Should you use Secrets Manager or SSM Parameter Store, and why?

Show the model answer

Use SSM Parameter Store. The standard tier is free, it supports SecureString parameters that KMS encrypts for the API keys, and it handles plain configuration values natively. Secrets Manager costs about $0.40 per secret per month, and that cost pays for automatic rotation, which this scenario does not need. With no rotation requirement and a tight budget, the answer is Parameter Store.

Question 5: CloudFront Cannot See the Certificate. A solutions architect requests an ACM certificate in eu-west-1 for a CloudFront distribution, but CloudFront cannot see it. Diagnose the problem and state the fix.

Show the model answer

CloudFront is a global service and accepts ACM certificates only from us-east-1 (N. Virginia), no matter where the origin or the rest of the workload lives. The fix is to request or import the certificate in us-east-1 and attach it to the distribution. This rule is specific to CloudFront. For a Regional ALB or API Gateway, the certificate lives in the same Region as that resource.

Question 6: The Deletion Waiting Period. Why does AWS require a waiting period of 7 to 30 days before a customer managed KMS key is deleted?

Show the model answer

Key deletion is irreversible. Every piece of data that was ever encrypted under that key, directly or through data keys, becomes permanently unrecoverable. During the waiting period the key is unusable, so anything that still depends on it visibly fails. That gives you time to discover hidden dependencies and cancel the deletion before it is too late.

Question 7: TLS to the Instances. A web application runs on EC2 instances behind an ALB, and the security team wants TLS all the way to the instances. Explain what ACM can and cannot do here.

Show the model answer

ACM can provide the public certificate on the ALB, which terminates TLS at the load balancer and renews automatically. A standard ACM public certificate cannot be exported to the EC2 instances. For encryption from the ALB to the instances, install a certificate on the instance: an exportable public certificate from ACM (available since June 2025, for an additional charge), a third-party or self-managed certificate, or a certificate from AWS Private CA. The ALB does not validate the chain of the backend certificate, so a self-signed certificate also works for the backend connection.

Question 8: KMS and CloudHSM. Compare KMS and CloudHSM in one or two sentences each. Which wording should make you pick CloudHSM on the exam?

Show the model answer

KMS is a fully managed, multi-tenant key service that is deeply integrated with AWS services, and it is the default choice for encryption at rest. CloudHSM gives you a dedicated, single-tenant hardware security module that you control, and AWS cannot access your keys. Pick CloudHSM when the question says dedicated or single-tenant hardware. Older questions also use “FIPS 140-2 Level 3,” although AWS now describes both services as using FIPS 140-3 Level 3 validated hardware.

Question 9: Three Services in One Request. Describe how ACM, Secrets Manager, and KMS each appear in a single user request to a web application that is backed by RDS. Where does each service act?

Show the model answer

ACM acts first: the user’s HTTPS connection ends at the ALB, which uses an ACM certificate to protect data in transit. The application then calls Secrets Manager (GetSecretValue) to fetch the current RDS credentials, so there are no hard-coded passwords and rotation is automatic. Finally, KMS acts at the storage layer: the secret, the RDS storage, EBS volumes, and S3 objects are all encrypted at rest under KMS keys. That is three services in three layers, in transit, credentials, and at rest, for one request.

Question 10: DNS Validation. Why is DNS validation preferred over email validation for ACM certificates in an automated environment?

Show the model answer

DNS validation proves domain ownership through a CNAME record that stays in place, so ACM can validate again and renew the certificate automatically with no human involvement. The record takes one click to create if the zone is in Route 53. Email validation needs a person to receive and approve an email at every renewal, and that manual step brings back the expired-certificate risk that ACM is meant to remove.
