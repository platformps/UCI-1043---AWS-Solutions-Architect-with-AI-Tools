1. AWS WAF Basics

Problem Statement

A web application behind an Application Load Balancer is hit by SQL injection attempts, cross-site scripting, and a flood of requests from a few IP addresses.

Security groups and network ACLs only see IP addresses and ports. They cannot read the HTTP request. You need a filter that understands web requests.

1.1 Overview of AWS WAF

  • AWS WAF is a web application firewall that works at layer 7. It inspects HTTP and HTTPS requests before they reach your application.
  • Filters on IP address, country, headers, URI, query string, and body.
  • Blocks common exploits such as SQL injection and cross-site scripting (XSS), and limits request rates.
  • You create a web ACL with rules and attach it to a CloudFront distribution, an ALB, an API Gateway REST API, or another supported resource.
  • Each rule allows, blocks, or counts the requests it matches, and the default action handles the rest.
  • Can present a CAPTCHA or challenge to prevent bot attacks.
  • When it blocks malicious traffic, WAF returns an HTTP 403 status code (Forbidden).
  • A managed service: it scales automatically, and AWS keeps its managed rules up to date.

2. Web ACLs, Rules, and Actions

Problem Statement

You know WAF filters web requests. Now you must decide what to block, what to allow, and in what order the checks run, without breaking real users.

2.1 The Building Blocks

The building blocks of a web ACL.
Building blockWhat it is
Web ACLThe container of rules. You associate it with resources. It has a default action (Allow or Block) for requests that match no rule.
RuleA match condition plus an action.
Rule groupA reusable set of rules. Managed rule groups come from AWS or AWS Marketplace sellers.
IP setA list of IP addresses or CIDR ranges to match.
Regex pattern setA list of regular expressions to match.
  • One web ACL can protect many resources. A resource can have only one web ACL.

2.2 What a Rule Can Match

  • IP address (IP set) and country (geo match).
  • Strings and regular expressions in headers, URI, query string, or body.
  • Size of a request part.
  • SQL injection and cross-site scripting patterns.
  • Request rate (rate-based rule).

2.3 Actions

AWS WAF rule actions and what each one does.
ActionWhat happens
AllowThe request goes through. Stops evaluating.
BlockThe request is rejected. The default response is 403 Forbidden, and you can customize it. Stops evaluating.
CountCounts the match and keeps evaluating. Use it to test a rule before blocking.
CAPTCHAShows a puzzle to check that a human is sending the request.
ChallengeRuns a silent browser check without user interaction.

2.4 Rate-Based Rules

  • Count the requests from each IP address in a time window and act when a limit is exceeded.
  • Example: block an IP address that sends more than 2,000 requests in 5 minutes.
  • Use them for brute-force logins and request floods at the web layer.

2.5 How a Request Is Evaluated

  • Rules run in priority order, lowest number first.
  • Allow and Block end the evaluation. Count does not.
  • If no rule matches, the default action applies.

2.6 Managed Rule Groups

AWS managed rule groups and the threats they protect against.
Managed rule groupProtects against
Core rule setCommon web exploits (OWASP-style risks)
Known bad inputsRequest patterns known to be exploits
SQL databaseSQL injection
Amazon IP reputation listIP addresses known for bots and threats
Anonymous IP listVPNs, proxies, and hosting providers that hide the source
Bot ControlBots, with common and targeted levels
Account takeover preventionCredential stuffing on login pages
  • Each rule and rule group uses web ACL capacity units (WCUs), and a web ACL has a maximum capacity.

Exam Trap

Test first, order matters.

Set a new rule to Count first to see what it would block. Rule priority decides the result, so an early Allow can let a request skip later Block rules.

Memory Hook

Web ACL holds rules. Allow/Block decide. Count tests. Default action handles the rest.

SAA-C03 Keyword Triggers

Trigger 1: “Test a new rule without blocking real users”→ Set the rule action to Count

Trigger 2: “Block an IP address that sends too many requests”→ Rate-based rule

Trigger 3: “Allow only trusted IP addresses to an admin path”→ IP set rule with Allow, and a default Block

Trigger 4: “Block traffic from specific countries”→ Geo match rule with Block

Trigger 5: “Ready-made protection against common attacks”→ AWS Managed Rules rule groups

Trigger 6: “Confirm a visitor is human”→ CAPTCHA action

3. Integrations and Common Architectures

Problem Statement

The security team wants WAF protection for a public application, central rules for many accounts, and logs for audits.

You also need to know where WAF fits next to Shield, security groups, and Network Firewall.

3.1 Common Architectures

Common AWS WAF architectures and how each one works.
ArchitectureHow it works
CloudFront + WAFThe web ACL is attached to the distribution. Bad requests are blocked at the edge, before they reach your origin. (CloudFront is covered in lesson 269.7.)
ALB + WAFA regional web ACL on the load balancer protects EC2, ECS, and Lambda targets.
API Gateway + WAFProtects REST APIs from exploits and floods.
CloudFront + WAF + ALBPut WAF on CloudFront, and make the ALB accept traffic only from CloudFront.

3.2 Fixed IP Address While Using WAF With a Load Balancer

  • WAF does not support the Network Load Balancer (layer 4).
  • Use AWS Global Accelerator (introduced in lesson 269.7) for a fixed IP address, and put WAF on the ALB.
  • The web ACL must be in the same AWS Region as the ALB.

3.3 Logging and Monitoring

  • Full web ACL logs go to Kinesis Data Firehose, Amazon S3, or CloudWatch Logs.
  • The Firehose delivery stream name must start with aws-waf-logs-.
  • Sampled requests and CloudWatch metrics show what the rules match.
  • You can redact sensitive fields, such as headers, from the logs.

3.4 WAF With Other Security Services

  • You pay for each web ACL, each rule, and each million requests inspected.

4. AWS Shield

Problem Statement

During a big sale, your online store suddenly receives millions of requests from thousands of sources. Real customers cannot get through and the site goes down.

You need protection from DDoS attacks, and you need to know what AWS Shield gives you for free and what costs extra.

4.1 What Is a DDoS Attack?

  • DDoS = distributed denial of service. Many sources send a flood of traffic at the same time to make an application unavailable to real users.
  • Volumetric attacks (layer 3 and 4) use huge amounts of traffic, for example UDP floods and reflection or amplification attacks.
  • State-exhaustion attacks (layer 4) use up connection tables, for example SYN floods.
  • Application-layer attacks (layer 7) send many valid-looking requests, for example an HTTP flood.

4.1.1 Common DDoS Attacks

Common DDoS Attacks.
AttackWhat happensLayer
SYN floodToo many half-open TCP connectionsLayer 4
UDP floodToo many UDP requestsLayer 3 and 4
UDP reflectionThe attacker spoofs the victim server’s IP address as the source of UDP packets. The victim server receives the unexpected responses.Layer 3 and 4
DNS floodOverwhelms the DNS so legitimate users cannot find the siteLayer 7 (DNS)
Slow LorisA lot of HTTP connections are opened and kept openLayer 7
Cache bustingRequests un-cached data from the CDN, so every request reaches the originLayer 7
HTTP floodMany valid-looking HTTP requestsLayer 7

4.2 What Is AWS Shield?

  • A managed DDoS protection service for applications that run on AWS.
  • Always-on detection and automatic mitigation, so attacks are stopped with little or no downtime.
  • Two tiers: Shield Standard and Shield Advanced.
  • Shield protects against DDoS attacks. AWS WAF filters web request content.

4.3 Shield Standard vs. Shield Advanced

Shield Standard vs. Shield Advanced.
AspectShield StandardShield Advanced
CostFree, for all AWS customersOptional DDoS mitigation service: $3,000 per month per organization. It is a paid subscription with a 1-year commitment, plus data transfer out usage fees, so check the pricing page
SetupAutomatic, always onYou subscribe and choose the resources to protect
Protects againstCommon layer 3 and 4 attacksLarger and more complex attacks, plus layer 7 protection with AWS WAF
Resources protectedCommon attacks, with the best protection through CloudFront and Route 53More sophisticated attacks on Amazon EC2, Elastic Load Balancing (ELB), Amazon CloudFront, AWS Global Accelerator, and Route 53
Response teamNo24/7 Shield Response Team (SRT), which needs a Business or Enterprise Support plan
Cost protectionNoDDoS cost protection: credits for scaling charges caused by an attack

Automatic layer 7 mitigationNoYes, it can create and manage WAF rules during an attack

4.4 Resources Shield Advanced Protects

  • Amazon CloudFront distributions
  • Amazon Route 53 hosted zones
  • AWS Global Accelerator accelerators
  • Elastic Load Balancing load balancers (ALB, NLB, and Classic)
  • Elastic IP addresses, which protect EC2 instances

4.5 Building a DDoS-Resilient Architecture

  • Put CloudFront, Route 53, and Global Accelerator at the edge (CloudFront and Global Accelerator are covered in lesson 269.7, and Route 53 in lesson 269.9), so attack traffic is absorbed far from your application.
  • Add AWS WAF with rate-based rules for application-layer floods.
  • Use Elastic Load Balancing and Auto Scaling so the application can scale to absorb extra load.
  • Hide your origin: allow the ALB or EC2 to accept traffic only from CloudFront, and keep instances in private subnets.
  • Limit exposure with security groups and network ACLs, so only needed ports are open.

Exam Trap

Shield Standard is on by default and free. For the 24/7 response team, cost protection, or protection for EC2 and load balancers beyond the basics, the answer is Shield Advanced. Shield does not inspect web content: that is AWS WAF.

Memory Hook

Standard = free, automatic, layers 3 and 4. Advanced = paid, response team, cost protection, WAF included. Edge services plus Auto Scaling = a DDoS-resilient design.

5. AWS Network Firewall

Problem Statement

Workloads in your VPC must block outbound traffic to unapproved websites, detect and stop intrusions, and inspect traffic between VPCs and from on premises.

Security groups and network ACLs only filter by IP address and port. AWS WAF only inspects HTTP requests on certain resources. You need a firewall for the whole VPC.

5.1 What Is AWS Network Firewall?

  • A managed, stateful network firewall and intrusion detection and prevention (IDS/IPS) service for your VPCs.
  • Protects the entire VPC, with inspection from layer 3 to layer 7.
  • Scales automatically. You do not manage firewall appliances.
  • Uses Suricata-compatible rules for intrusion prevention.
  • Can inspect traffic to and from the internet gateway, between VPCs (for example through a transit gateway), and to and from on premises (VPN or Direct Connect).
  • Managed centrally across accounts with AWS Firewall Manager.

5.2 Key Components

Key components of AWS Network Firewall.
ComponentWhat it is
FirewallThe resource that protects a VPC. It uses a firewall policy.
Firewall policyA collection of rule groups and the default actions for traffic that no rule handles.
Rule groupA reusable set of rules, stateless or stateful.
Firewall endpointWhere the traffic is inspected. It lives in a dedicated firewall subnet, one in each Availability Zone you protect.
LoggingAlert and flow logs to S3, CloudWatch Logs, or Kinesis Data Firehose.

5.3 Stateless vs. Stateful Rules

Stateless vs. Stateful Rules.
AspectStateless rulesStateful rules
InspectsEach packet on its ownThe whole traffic flow, with context
Match onSource and destination IP address, port, and protocol (5-tuple)5-tuple, domain names, or Suricata signatures
ActionsPass, drop, or forward to the stateful enginePass, drop, or alert
Best forFast, simple filteringDomain filtering, intrusion prevention, deep inspection
  • Domain list rule groups allow or deny HTTP and HTTPS domains, using the host header and the TLS SNI. Example: allow outbound traffic only to *.amazonaws.com and updates.example.com.
  • TLS inspection can decrypt traffic so the stateful engine can inspect it.

5.4 How Traffic Reaches the Firewall

  • Create a firewall subnet in each Availability Zone, used only by Network Firewall.
  • Update the route tables so traffic goes through the firewall endpoint on its way in and out (lesson 269.1 covers route tables).
  • The firewall policy decides what to pass, drop, or alert on.

5.5 Common Use Cases

  • Outbound domain filtering: allow only approved websites.
  • Block traffic by IP address, port, or protocol at the VPC level.
  • Intrusion prevention with Suricata signatures.
  • Inspect traffic between VPCs and from on premises.
  • Central logging for compliance.

5.6 Network Firewall vs. Other Services

Network Firewall vs. Other Services.
ServiceWhere it worksKey point
Security groupInstance or network interfaceStateful. Allow rules only.
Network ACLSubnetStateless. Allow and deny by IP address and port.
AWS WAFCloudFront, ALB, API Gateway, and othersHTTP and HTTPS requests (layer 7).
AWS ShieldEdge and load balancersDDoS protection.
AWS Network FirewallThe whole VPCStateful inspection, domain filtering, and IDS/IPS.
AWS Firewall ManagerAcross accountsCentral management of WAF, Shield Advanced, Network Firewall, and more.

Exam Trap

Filtering by domain name.

Security groups and network ACLs cannot filter by domain name. To allow only certain websites for outbound traffic, or to run intrusion prevention for a whole VPC, use AWS Network Firewall. AWS WAF is only for HTTP requests to specific resources.

Memory Hook

Security group = the instance. NACL = the subnet. Network Firewall = the whole VPC, with domains and IPS. WAF = web requests. Shield = DDoS.

SAA-C03 Keyword Triggers

Trigger 3: “Stateful inspection of traffic between VPCs or from on premises”→ AWS Network Firewall

Trigger 4: “Managed network firewall for a VPC with no appliances to manage”→ AWS Network Firewall

6. AWS Firewall Manager

Problem Statement

Your company has 30 AWS accounts. Each team sets up WAF rules and security groups its own way, and new accounts often launch without any protection.

Auditors want the same rules everywhere. You need one place to define and enforce them.

6.1 What Is AWS Firewall Manager?

  • A central security management service to set up and manage firewall rules across accounts and applications.
  • Works with AWS Organizations: you define a policy once and it applies to many accounts.
  • New accounts and new resources are protected automatically.
  • Can flag or automatically fix resources that do not follow the policy (automatic remediation).
  • It manages other security services. It does not inspect traffic itself.

With AWS Firewall Manager, you can quickly configure AWS WAF rules for your Application Load Balancers, API Gateways, and Amazon CloudFront distributions.

You can safeguard your Application Load Balancers, Classic Load Balancers, Elastic IP addresses, and CloudFront distributions using AWS Shield Advanced.

6.2 Prerequisites

  • Your accounts are in AWS Organizations.
  • A Firewall Manager administrator account, which can be a delegated administrator.
  • AWS Config is turned on in the accounts and Regions that Firewall Manager covers.

6.3 Firewall Manager Policy Types

Firewall Manager policy types and what each one manages.
Policy typeWhat it manages
AWS WAFWeb ACLs and rule groups on CloudFront, ALBs, API Gateway, and others

AWS Network FirewallFirewalls and rule groups in your VPCs
Route 53 Resolver DNS FirewallDNS Firewall rule groups for your VPCs
  • Security group: security groups for EC2, Application Load Balancer, and ENI resources in a VPC.

6.4 How It Works

  • Choose the administrator account.
  • Create a policy: pick the type, and the scope (accounts or organizational units, resource types, tags, and Regions).
  • Firewall Manager applies the policy to existing resources, and to new resources and new accounts that match the scope.
  • With automatic remediation, non-compliant resources are fixed. Otherwise, they are reported.
  • Check results on the compliance dashboard, and get Amazon SNS notifications.

  • For CloudFront, create the WAF policy in us-east-1.

7.2 Exam-Style Question

Exam-Style Question 1

A company runs a web application on EC2 instances behind an Application Load Balancer. Logs show SQL injection attempts and a single IP address sending thousands of requests per minute. The company wants to block both with the least operational effort.

Which solution meets these requirements?

  1. Add deny rules for the attacker’s IP address to the instances’ security group
  2. Add network ACL rules that block SQL keywords
  3. Associate an AWS WAF web ACL with the ALB, using a managed SQL database rule group and a rate-based rule
  4. Turn on AWS Shield Standard for the ALB
Show the answer

Correct answer: C. WAF reads HTTP requests, and a managed rule group and a rate-based rule cover both problems.

Why each option is correct or incorrect.
OptionWhy
A. Security group deny rulesSecurity groups have only allow rules, and they cannot inspect the request for SQL injection.
B. Network ACL rulesNetwork ACLs work on IP addresses and ports. They cannot read request content.
C. AWS WAF with managed rules and a rate-based ruleBlocks SQL injection and limits requests per IP address. Correct.
D. Shield StandardProtects against network-level DDoS attacks, not SQL injection or a single noisy IP at layer 7.

Memory Hook

Web content = WAF. Flood of packets = Shield. IP and port = SG or NACL.

Question 2. Which AWS resources can you protect with AWS WAF, and which cannot you?

Show the model answer

You can protect CloudFront distributions, Application Load Balancers, API Gateway REST APIs, AppSync GraphQL APIs, and Cognito user pools, among others. You cannot protect a Network Load Balancer or EC2 instances directly.

Question 3. Where do you create a web ACL for CloudFront, and for an ALB?

Show the model answer

A CloudFront web ACL is global and must be created in us-east-1. A web ACL for an ALB or another regional resource is created in the same Region as the resource.

Question 4. Explain web ACLs, rules, and actions.

Show the model answer

A web ACL is a container of rules that you associate with resources, and it has a default action for requests that match no rule. A rule is a match condition plus an action: Allow, Block, Count, CAPTCHA, or Challenge. Rules run in priority order, and Allow and Block end the evaluation.

Question 5. How do you test a new WAF rule safely?

Show the model answer

Set its action to Count. WAF counts the requests the rule would match without blocking them, so you can review the results and then change the action to Block.

Question 6. A single IP address floods your site with requests. What WAF feature do you use?

Show the model answer

A rate-based rule, which counts requests per IP address in a time window and blocks the address when the limit is exceeded.

Question 7. How do WAF, Shield, security groups, and Firewall Manager differ?

Show the model answer

WAF filters HTTP content at layer 7. Shield protects against DDoS attacks at the network level, with Advanced adding more protection and cost protection. Security groups and network ACLs filter by IP address and port. Firewall Manager manages WAF, Shield Advanced, and other rules across accounts in AWS Organizations.

Question 8. What is a DDoS attack, and what does AWS Shield do about it?

Show the model answer

A DDoS attack sends a flood of traffic from many sources to make an application unavailable. AWS Shield is a managed DDoS protection service with always-on detection and automatic mitigation. Shield Standard is free and automatic for common layer 3 and 4 attacks, and Shield Advanced adds protection for larger attacks, a 24/7 response team, cost protection, and automatic layer 7 mitigation.

Question 9. Compare Shield Standard and Shield Advanced.

Show the model answer

Standard is free, automatic for all customers, and protects against common layer 3 and 4 attacks. Advanced is a paid subscription for chosen resources such as CloudFront, Route 53, Global Accelerator, load balancers, and Elastic IP addresses. It adds the Shield Response Team (with Business or Enterprise Support), DDoS cost protection, near real-time metrics, automatic layer 7 mitigation, and AWS WAF at no extra cost for protected resources.

Question 10. How do you design an application to resist DDoS attacks?

Show the model answer

Put CloudFront, Route 53, and Global Accelerator at the edge so attack traffic is absorbed far from the application, add AWS WAF with rate-based rules, use Elastic Load Balancing and Auto Scaling so the application can scale, hide the origin so it accepts traffic only from CloudFront, and limit open ports with security groups and network ACLs.

Question 11. What is AWS Network Firewall, and when do you use it?

Show the model answer

AWS Network Firewall is a managed, stateful network firewall and intrusion detection and prevention service for VPCs. Use it to protect the whole VPC, for example to filter outbound traffic by domain name, run intrusion prevention with Suricata-compatible rules, and inspect traffic between VPCs or from on premises. You deploy firewall endpoints in dedicated firewall subnets and route traffic through them.

Question 12. Compare stateless and stateful rule groups in Network Firewall.

Show the model answer

Stateless rules inspect each packet on its own using the 5-tuple and can pass, drop, or forward to the stateful engine. Stateful rules consider the whole traffic flow and support domain list filtering and Suricata signatures, with actions to pass, drop, or alert.

Question 13. How does Network Firewall differ from security groups, network ACLs, and AWS WAF?

Show the model answer

Security groups work at the instance level and only have allow rules. Network ACLs work at the subnet level and filter by IP address and port. AWS WAF inspects HTTP and HTTPS requests on resources such as CloudFront and an ALB. Network Firewall protects the whole VPC with stateful inspection, domain filtering, and intrusion prevention.

Question 14. What is AWS Firewall Manager, and what does it need?

Show the model answer

AWS Firewall Manager is a central security management service that defines and enforces firewall policies across accounts in AWS Organizations. It needs AWS Organizations, a Firewall Manager administrator account, and AWS Config turned on. It manages other services and does not filter traffic itself.

Question 15. Which policy types does Firewall Manager support?

Show the model answer

AWS WAF, AWS Shield Advanced, security group policies (common, audit, and usage audit), AWS Network Firewall, and Route 53 Resolver DNS Firewall.

Question 16. A company must make sure every ALB in 40 accounts has a web ACL, and that new accounts are covered. What do you use?

Show the model answer

Create an AWS Firewall Manager WAF policy scoped to the organization or its OUs and to ALBs. Firewall Manager applies it to existing resources and to new resources and accounts, and can automatically remediate non-compliant ones.

Question 17. Where can you send AWS WAF logs?

Show the model answer

To Kinesis Data Firehose (the stream name must start with aws-waf-logs-), Amazon S3, or CloudWatch Logs.
