1. AWS Directory Service Overview

Problem Statement

You are a cloud solutions architect at a multinational financial enterprise. The organization hosts its identity infrastructure on an on-premises Microsoft Active Directory. IT leadership has started a cloud migration plan to move several enterprise applications to AWS, including Windows Server workloads on Amazon EC2 and databases on Amazon RDS for SQL Server.

Three requirements apply. The applications need full Active Directory support, including Group Policy Objects (GPOs) and schema extensions. Users must authenticate with their existing credentials through a secure trust relationship with the on-premises directory. The EC2 Windows instances and the RDS for SQL Server databases must join the domain without extra work.

How will you meet these requirements?

1.1 What AWS Directory Service Is

AWS Directory Service is a managed service that lets you run Microsoft Active Directory, or something compatible with it, in AWS without building and patching domain controllers yourself. It is the foundation for centralized identity, authentication, and access management when your workloads need to work with Active Directory.

It offers several deployment models, depending on whether you need a fully managed Active Directory in the cloud, a gateway to an existing on-premises Active Directory, or a lightweight directory. It provides directory choices for accounts that use Microsoft Active Directory or Lightweight Directory Access Protocol (LDAP)-aware applications in the cloud.

1.2 What a Directory Stores

A directory stores information about:

  • Users.
  • Groups.
  • Computers and devices.
  • Domain memberships.
  • Password and authentication settings.
  • Group Policy configurations.
  • Access to applications and resources.

1.3 Why Use AWS Directory Service

Many organizations already use Microsoft Active Directory to manage their employees and computers. When they move workloads to AWS, they often want to keep using:

  • Existing user names and passwords.
  • Active Directory groups.
  • Windows domain authentication.
  • Group Policy.
  • Kerberos authentication.
  • LDAP-compatible applications.
  • Existing password and account-lockout policies.

AWS Directory Service provides managed and hybrid options, so the organization does not have to build and maintain every domain controller by hand. It can help an organization:

  • Run Microsoft Active Directory workloads in AWS.
  • Connect AWS applications to an existing on-premises Active Directory.
  • Join Windows or Linux EC2 instances to a domain.
  • Provide centralized user authentication.
  • Support single sign-on (SSO) to compatible applications.
  • Apply Group Policies to domain-joined computers.

Exam Trap

The service removes the work of building, patching, and replicating domain controllers. It does not remove the need to design the network path, such as a VPN or AWS Direct Connect, between AWS and an on-premises directory.

Memory Hook

Directory Service means Active Directory without building the domain controllers.

SAA-C03 Keyword Triggers

Trigger 1: “Use existing Microsoft Active Directory credentials for workloads in AWS”→ AWS Directory Service

Trigger 2: “Avoid building and patching domain controllers on Amazon EC2”→ AWS Directory Service

2. AWS Managed Microsoft AD

Problem Statement

A financial services company with an on-premises Active Directory is moving several Windows Server applications to AWS. The applications need Group Policy, schema extensions, and domain join for Amazon EC2 and Amazon RDS for SQL Server. The company also wants employees to keep signing in with their existing credentials.

2.1 What AWS Managed Microsoft AD Is

AWS Managed Microsoft AD is a full Microsoft Active Directory that runs on AWS-managed Windows Servers. AWS runs it on Windows Server 2019. It supports:

  • Active Directory-aware workloads.
  • Amazon RDS for Microsoft SQL Server.
  • AWS managed services such as Amazon WorkSpaces and Amazon QuickSight.
  • Linux applications that use an LDAP directory.
  • Trust relationships with your on-premises Active Directory, either one-way or two-way.

2.2 When to Use It

Use AWS Managed Microsoft AD when you need:

  • The full Active Directory feature set: Group Policy, schema extensions, LDAP, and Kerberos.
  • To extend your on-premises Active Directory into AWS for hybrid identity.
  • Windows workloads that need domain join: Amazon EC2, Amazon RDS for SQL Server, and Amazon FSx for Windows File Server.
  • AWS IAM Identity Center integration.

AWS deploys the directory across two Availability Zones automatically, with a domain controller in each, for high availability (HA).

2.3 Native Active Directory Administration

Administrators can use standard Active Directory management tools, such as Remote Server Administration Tools (RSAT). AWS Managed Microsoft AD supports native Active Directory features, including:

  • GPOs: Centralized governance and operational controls for joined instances.
  • SSO: Seamless user authentication across enterprise applications and services.
  • Trust relationships: The ability to establish forest or domain trusts with on-premises Active Directory environments.

2.4 Integration With AWS Services

AWS Directory Service integrates directly with a wide range of AWS services:

  • Compute and database instances: Join Amazon EC2 (Windows and Linux) and Amazon RDS for SQL Server instances directly to your domain.
  • Enterprise applications: Provide user identity management for desktop and enterprise apps, such as Amazon WorkSpaces, Amazon QuickSight, and AWS Client VPN.
  • AWS Management Console: Enable identity federation and SSO access to the AWS Management Console for domain users.

3. AD Connector and Simple AD

Problem Statement

Two other teams have different needs. One team already runs an on-premises Active Directory and only wants AWS applications to authenticate against it, without copying any directory data into AWS. Another team supports a small application that needs a basic directory with LDAP.

3.1 AD Connector

AD Connector is not a directory. It is a directory gateway that redirects directory requests to your existing on-premises Microsoft Active Directory without caching any credentials in the cloud.

  • It forwards authentication requests straight to your existing on-premises Active Directory.
  • No user data is stored or synced in AWS.

Use AD Connector when:

  • You already have an on-premises Active Directory and want AWS resources to authenticate against it.
  • You do not want to replicate or sync directory data into the cloud.
  • You need a lightweight way to connect, for example for AWS Management Console sign-in or Amazon WorkSpaces.

AD Connector needs network connectivity, such as a virtual private network (VPN) or AWS Direct Connect, to the on-premises directory. It does nothing on its own.

3.2 Simple AD

Current Service Note

AWS Directory Service Simple AD moves to maintenance mode and closes to new customers from July 30, 2026. Customers that already use Simple AD can continue to use it, and AWS continues to operate and support the service. AWS recommends that new customers evaluate AWS Managed Microsoft AD or AD Connector. For details, see AWS Service Availability Updates.

Simple AD is a standalone, basic directory that is compatible with Active Directory and powered by Samba 4. It is the cheapest and lowest-feature option.

  • It supports basic features: user accounts, groups, Group Policy, and domain join.
  • It does not support trust relationships, multi-factor authentication (MFA), Microsoft Active Directory-specific features such as schema extensions, or domain join for RDS.
  • It suits small, simple use cases: basic directory needs, a small number of users, and compatible applications that need only LDAP.

4. Deployment Example and Best Practices

Problem Statement

A team has to deploy a new solution in AWS from scratch. It has one account, one Region, and one Amazon Virtual Private Cloud (VPC). It needs a directory in minutes, and it has no extra requirement to isolate application tiers or administrators.

4.1 Example: A Single Account, AWS Region, and VPC

The simplest case is a new solution built in the cloud from scratch. You can deploy AWS Managed Microsoft AD in minutes and use it for most of the services and applications that require Active Directory. This design suits scenarios with no extra requirement for logical isolation between application tiers or administrators.

4.2 Administration and Best Practices

  • High availability: AWS Managed Microsoft AD deploys domain controllers across multiple Availability Zones automatically for built-in fault tolerance. By default, it creates two domain controllers in separate Availability Zones.
  • Security and auditing: Integrate with AWS CloudTrail to log directory administrative actions and operational changes for compliance monitoring.
  • Multi-account sharing: Share one AWS Managed Microsoft AD directory across multiple AWS accounts in an organization to simplify management and reduce operational overhead.

Exam Trap

The Availability Zone redundancy is automatic for AWS Managed Microsoft AD and Simple AD. You choose two subnets in two Availability Zones when you create the directory. You do not build the replication yourself.

Memory Hook

Two subnets, two Availability Zones, two domain controllers.

  • Domain join for RDS for SQL Server requires AWS Managed Microsoft AD. It does not work with Simple AD or AD Connector.

  • AD Connector needs network connectivity, such as a VPN or AWS Direct Connect, to the on-premises directory.

6. Knowledge Check

Answer each question in your own words, and then open the model answer to compare.

Question 1: Choosing for a Migration. A financial services company with an on-premises Active Directory is migrating Windows Server workloads to AWS. It needs Group Policy, schema extensions, domain join for Amazon EC2 and Amazon RDS for SQL Server, and a trust relationship with its on-premises domain so users keep their existing credentials. Which AWS Directory Service option should the company choose, and why?

Show the model answer

The company should choose AWS Managed Microsoft AD. It is a full Microsoft Active Directory that supports Group Policy and schema extensions, joins Amazon EC2 and Amazon RDS for SQL Server to the domain, and supports one-way or two-way trust relationships with an on-premises Active Directory. Users can then authenticate with their existing credentials without re-creating them.

Question 2: Self-Managing Versus Directory Service. Describe why an organization might use AWS Directory Service instead of self-managing Active Directory on Amazon EC2.

Show the model answer

With AWS Directory Service, AWS builds, monitors, patches, and replicates the domain controllers. AWS Managed Microsoft AD creates two domain controllers in separate Availability Zones for resilience, so the organization does not have to build and maintain every domain controller by hand. The organization keeps its users, groups, Group Policy, and Windows domain authentication.

Question 3: AD Connector Versus AWS Managed Microsoft AD. Explain the difference between AD Connector and AWS Managed Microsoft AD in terms of where directory data lives and which workloads each one supports.

Show the model answer

AD Connector is a gateway. It redirects authentication requests to the on-premises Active Directory and stores no directory data in AWS. It cannot join Amazon RDS for SQL Server to a domain. AWS Managed Microsoft AD is a full directory that runs in AWS and stores directory data there. It supports Group Policy, schema extensions, trust relationships, and domain join for EC2, RDS for SQL Server, and Amazon FSx for Windows File Server.

Question 4: Trust Relationships. Explain how a trust relationship between an on-premises Active Directory and AWS Managed Microsoft AD helps users and workloads.

Show the model answer

A trust relationship, one-way or two-way, lets users from the on-premises Active Directory authenticate to resources in AWS Managed Microsoft AD with their existing credentials. The organization does not need to re-create those users in AWS. Workloads such as EC2 Windows instances and RDS for SQL Server that join the AWS directory can then use those identities. The on-premises directory and AWS need a network path between them, such as a VPN or AWS Direct Connect.

Question 5: Simple AD for New Customers. Simple AD is the cheapest option. Why should a new customer not choose it, and what should the customer choose instead?

Show the model answer

AWS moves Simple AD to maintenance mode and closes it to new customers from July 30, 2026. Existing customers can keep using it. A new customer should choose AWS Managed Microsoft AD for a standalone or hybrid directory, or AD Connector to reuse an existing on-premises Active Directory.
