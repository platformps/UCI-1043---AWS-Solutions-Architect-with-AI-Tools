CloudWatch Logs, Logs Insights, Metric Filters, and Alarms

How Amazon CloudWatch collects, stores, exports, and analyzes logs, and how alarms watch metrics and run actions: log groups and retention, log sources and the agent, exports and subscription filters, Logs Insights queries, metric filters, Contributor Insights, alarm types and actions, and the destinations of service logs.

Lesson Overview

This lesson introduces CloudWatch Logs, the part of Amazon CloudWatch that collects, stores, and searches log data on Amazon Web Services (AWS), and CloudWatch alarms, which watch metrics and run actions. It builds on metrics (lesson 274.1). In this lesson, you will study:

  • Log Groups, Streams, and Retention: how logs are organized, how long they are kept, the log classes, and encryption with AWS Key Management Service (AWS KMS).
  • Getting Logs Into CloudWatch Logs: the three ways logs arrive, and why Amazon Elastic Compute Cloud (Amazon EC2) instances need the CloudWatch agent.
  • Exporting and Streaming Logs: exports to Amazon Simple Storage Service (Amazon S3), subscription filters, and collecting logs from several accounts and Regions.
  • Logs Insights: querying log data in place with a purpose-built query language.
  • Metric Filters and Contributor Insights: turning log patterns into metrics, and finding the top contributors in a log.
  • CloudWatch Alarms: alarm states, evaluation settings, missing data, and the metric, composite, and anomaly detection alarm types.
  • Alarm Actions and Automation: notifications, EC2 actions, Auto Scaling, Systems Manager, Amazon EventBridge, and billing alarms.
  • Where CloudWatch Logs and Alarms Fit: which AWS services send logs to CloudWatch Logs, where else they can send them, which features use the data, and which alarms suit common signals.
  • Comparison and Scenarios: comparison tables and a cheat sheet for the AWS Certified Solutions Architect – Associate (SAA-C03) exam.
  • Knowledge Check: open-ended questions with model answers.

1. Log Groups, Streams, and Retention

Problem Statement

FlashCart Inc. runs its checkout service on six Amazon EC2 instances on a normal day, and Auto Scaling grows the group to as many as 40 instances during a flash sale. In lesson 270.4, the team set the group to end instances when the load drops. Each instance writes its application log to its own disk.

During the last sale, Auto Scaling ended 25 instances in the evening. At 9 a.m. the next day, a customer disputed a double charge from 7:40 p.m. The engineers needed the checkout logs from that time, but the instance that handled the order no longer existed, and its logs were gone.

The compliance team adds requirements. Payment-related logs must be kept for about 13 months and then deleted, and FlashCart must own the encryption keys for them. A finance review also finds that a “temporary” debug log group has grown for two years. Nobody reads debug logs after the first day, and the group now costs more than the checkout database.

Your challenge:

  • Explain where the checkout logs should be stored so that they survive the end of an instance, and how the groups and streams should be organized.
  • Choose the retention period for the payment logs and for the debug logs, and explain what happens to events that are older.
  • Choose the log class for the debug logs, and say what you give up by choosing it.
  • Describe how FlashCart controls the encryption key for the payment logs, and what must be in place before it works.

1.1 What CloudWatch Logs Does

CloudWatch Logs collects log data from AWS services, applications, and servers, and stores it centrally. You can search it, count patterns in it, send it to other services, and keep it for as long as you need. This tab explains how CloudWatch Logs organizes data. Tab 2 covers how logs get in, tab 3 covers how they get out, and tabs 4 and 5 cover analysis. To follow one request across several services, use AWS X-Ray (lesson 274.6).

1.2 Log Events, Streams, and Groups

TermMeaningExample
Log eventA record of activity from the application or resource being monitored. It has a timestamp and the raw event message. Messages must be UTF-8 encoded.10:00:05 ERROR timeout
Log streamA sequence of log events that share the same source, such as one application instance or one log file on one host.The stream for instance i-0a12b3c4
Log groupA group of log streams that share the same retention, monitoring, and access control settings. There is no limit on the number of log streams in one log group./flashcart/checkout

1.2.1 Settings That Belong to the Log Group

You configure the following at the log group, and every stream in the group inherits it:

  • The retention setting (section 1.3).
  • The log class (section 1.4).
  • The AWS KMS key used for encryption (section 1.5).
  • Metric filters (tab 5) and subscription filters (tab 3).
  • Access control through AWS Identity and Access Management (IAM).

1.3 Retention

  • By default, log events are kept indefinitely. The default setting is “never expire,” so storage cost grows until you change it.
  • You can set retention for each log group, from 1 day up to 10 years, by choosing from a fixed list of values.
  • CloudWatch Logs deletes expired log events automatically.
  • Retention is assigned to the log group, and it applies to every stream in the group.
aws logs put-retention-policy --log-group-name /flashcart/checkout --retention-in-days 90

Deletion protection is an optional safeguard that blocks all deletion operations on a log group and its streams until you turn it off. It is off by default, and it suits log groups that hold audit or production data.

1.4 Log Classes

A log group has one of three classes. The class is set when you create the log group, and you cannot change it afterward.

FeatureStandard classInfrequent Access class
Intended useFull-featured option for logs that need real-time monitoring or frequent accessLower-cost option for logs that you access less often
Price differenceStandard ingestion priceLower ingestion price per gigabyte. Storage and Logs Insights charges are the same in both classes.
Logs Insights queriesYes — all query commandsYes — most commands. The pattern, diff, and unmask commands are not supported.
Metric filtersYes — supportedNo — not supported
Subscription filtersYes — supportedNo — not supported
Live TailYes — supportedNo — not supported
Embedded metric formatYes — supportedNo — not supported
Export to Amazon S3Yes — supportedYes — supported
Encryption with AWS KMSYes — supportedYes — supported

The Delivery class is a third option. Use it only to deliver Lambda logs to Amazon S3 or Amazon Data Firehose. It keeps events in CloudWatch Logs for two days, a fixed period that you cannot change, and it does not offer Logs Insights queries.

1.5 Encryption

  • Log group data is always encrypted. By default, CloudWatch Logs uses server-side encryption with 256-bit Advanced Encryption Standard Galois/Counter Mode (AES-GCM) to protect log data at rest.
  • As an alternative, you can encrypt a log group with a customer managed AWS KMS key. CloudWatch Logs supports only symmetric keys.
  • The key policy must allow the CloudWatch Logs service principal for the Region, which has the form logs.region.amazonaws.com.
  • After you associate a key with a log group, CloudWatch Logs encrypts all newly ingested data with it. If you later disassociate the key, new data goes back to the default encryption.
  • If you disable the key, CloudWatch Logs cannot read the data that the key encrypted.
  • CloudWatch Logs adds the log group’s Amazon Resource Name (ARN) to the encryption context, so you can limit key use to one account and one log group. AWS recommends a different key for each encrypted log group.
# Associate a key when you create the log group
aws logs create-log-group --log-group-name /flashcart/checkout --kms-key-id <key-arn>

# Associate a key with an existing log group
aws logs associate-kms-key --log-group-name /flashcart/checkout --kms-key-id <key-arn>

You cannot use the console to associate a key with an existing log group. Use the AWS Command Line Interface (AWS CLI) or an application programming interface (API) instead.

Exam trap

Logs are encrypted by default, so a question that asks only for encryption at rest needs no extra action. A question that asks for control over the key, key rotation, or an audit trail of key use points to a customer managed AWS KMS key. Also remember that the default retention is never expire, so logs and their cost grow until you set a retention period.

Memory hook

The group sets the rules. Retention, class, key, and filters belong to the log group, and every stream inside it follows them.

The security team sets the rules. No access keys may be stored on any server, every permission must come from a role, and the on-premises warehouse server that prints shipping labels must send its application log as well.

Your challenge:

  • List what each EC2 instance and the warehouse server need before their log files appear, and where each setting lives.

2.2 Logs From Servers

By default, no logs from an Amazon EC2 instance go to CloudWatch Logs. To send log files from an instance or an on-premises server, you need three things:

  • The CloudWatch agent installed on the machine (lesson 274.1, tab 4). AWS Systems Manager can install it on many machines at once (lesson 268.8).
  • An attached IAM role that allows the agent to write logs, which includes the permissions logs:CreateLogGroup, logs:CreateLogStream, logs:PutLogEvents, and logs:DescribeLogStreams. The CloudWatchAgentServerPolicy managed policy covers this.
  • An agent configuration file whose logs section lists the files to collect.

Each entry in the logs section names a file path, a log group, and a log stream. The placeholder {instance_id} creates one stream for each instance.

{
  "logs": {
    "logs_collected": {
      "files": {
        "collect_list": [
          { "file_path": "/var/log/application.log",
            "log_group_name": "/flashcart/checkout",
            "log_stream_name": "{instance_id}" }
        ]
      }
    }
  }
}

The older CloudWatch Logs agent could send only logs. The CloudWatch agent replaces it, and it sends metrics as well.

3. Exporting and Streaming Logs

Problem Statement

FlashCart produces about 80 gigabytes of checkout and payment logs a day during a sale, and about 10 gigabytes on a normal day. The auditors require seven years of retention. The finance team asks for the cheapest way to meet that, and the engineers want to keep only 30 days of logs in CloudWatch Logs for searching.

The security team runs an external analytics tool. During the last sale, an attack that sent thousands of failed logins went unnoticed for five hours, because the team’s nightly job copied the logs once a day. The goal is to see ERROR and failed-login events within a few minutes.

FlashCart also runs the store in two Regions, and the payments team uses a separate AWS account. The CTO wants one central place for all logs, but the payments team must keep control of its own account.

Your challenge:

  • Choose how to build the seven-year archive, and explain the limits of an export task.
  • Choose how to deliver failed-login events to the analytics tool within minutes, and name the destination service (lesson 273.6).
  • Explain how logs from two Regions and a second account can reach one central place.
  • Explain what happens to the stream of events if the destination returns an error.

3.1 Export to Amazon S3

An export task copies log data from a log group to an Amazon S3 bucket. Use it for custom processing, long-term archive, or analysis with other services, such as Amazon Athena (lesson 272.11).

  • Log data can take up to 12 hours to become available for export, and export tasks time out after 24 hours. For a timeout, reduce the time range of the task.
  • The bucket must be in the same Region as the log data. It can belong to the same account or to a different account.
  • You can export to buckets encrypted with AES-256 or with SSE-KMS (server-side encryption with AWS KMS keys). Buckets encrypted with dual-layer server-side encryption with AWS KMS keys (DSSE-KMS) are not supported. Exporting to buckets that use S3 Object Lock with a retention period is supported.
  • Each account can have only one running or pending export task per Region.
  • Time-based sorting inside an exported file is not guaranteed.
  • AWS recommends that you do not export regularly as a way to archive logs continuously. Use a subscription filter for that.
What has changed

Older study materials say that export tasks cannot use SSE-KMS buckets. The current AWS documentation supports them, so the course slides that list SSE-KMS are correct.

3.2 Subscription Filters

A subscription filter sends log events from a log group to a destination soon after CloudWatch Logs ingests them, usually in less than three minutes. The filter pattern selects which events to send.

  • Destinations in the same account: Amazon Kinesis Data Streams and Amazon Data Firehose (lesson 273.6), and AWS Lambda (lesson 273.1). You can also stream to Amazon OpenSearch Service, which can load CloudWatch Logs data through a subscription filter (lesson 272.14).
  • Events arrive at the destination Base64 encoded and compressed with GZIP.
  • Each log group can have up to two subscription filters. Each account can also have one account-level subscription filter per Region.
  • Subscriptions work only for log groups in the Standard class.
  • If the destination returns a retryable error, CloudWatch Logs retries for up to 24 hours. After a non-retryable error, the filter is disabled for up to 10 minutes, and logs sent in that period are skipped.
  • Delivery is at least once, so duplicate events can occasionally occur.
aws logs put-subscription-filter \
  --log-group-name /flashcart/checkout \
  --filter-name errors-to-firehose \
  --filter-pattern "ERROR" \
  --destination-arn <firehose-arn> \
  --role-arn <role-arn>

3.3 Cross-Account and Cross-Region Collection

  • Cross-account subscriptions: the sending account creates a subscription filter that points to a logical destination in the receiving account. The destination has an access policy that allows the sender. Kinesis Data Streams and Firehose are supported as logical destinations.
  • Several accounts and Regions into one place: subscription filters in many accounts and Regions can feed one Kinesis data stream or Firehose delivery stream, which then writes to Amazon S3 or OpenSearch Service.
  • Log centralization: CloudWatch Logs centralization can replicate log data from multiple accounts and Regions into one central location. It can add the fields @aws.account and @aws.region to show where each event came from.
  • Querying across accounts: with cross-account observability (lesson 274.1, tab 5), a monitoring account can query log groups in source accounts.

For batch analysis on a schedule, scheduled queries run Logs Insights queries automatically and deliver the results to destinations such as Amazon S3 or an Amazon EventBridge event bus.

Exam trap

An export task is a batch job, not a stream. It is not real time, and AWS does not recommend it for continuous archiving. A question that asks for near-real-time delivery of log events needs a subscription filter, not an export.

Memory hook

Export is a batch copy; a subscription is a live feed.

4. Logs Insights

Problem Statement

On the Friday of the sale, FlashCart’s support team receives 300 complaints in 20 minutes: customers click Pay, wait, and see an error. The evidence is in three log groups, /flashcart/checkout, /flashcart/payments, and the API access log that the team turned on in lesson 273.2. Together, the three groups hold about 25 million events from the last hour.

The on-call engineer knows only that something fails. She must find the failed events, see whether they started at a specific minute, find the message that appears most often, and report to the support lead within 15 minutes. She does not want to export anything or build a database.

Her first attempt covers the last 14 days of all three log groups and runs for a very long time. Her second attempt finishes fast, but it returns fewer events than she expected.

Your challenge:

  • Choose the tool, and explain why it fits better than exporting the logs.
  • Write the steps of a query that counts failed events per minute and ranks the most frequent messages.
  • Explain how to make the query faster and cheaper, and which limits could stop or cut short a query.
  • Describe how she could watch new events live while the engineers deploy a fix.

4.1 What Logs Insights Is

CloudWatch Logs Insights is an interactive query service for log data. It analyzes the data where it is stored, so you do not export it first. It is read-only, and it does not change log data.

  • You query one or more log groups over a time range, and the results appear as a table or as a visualization. Lesson 269.4 shows queries on VPC flow logs.
  • It automatically discovers fields in AWS service logs and in JavaScript Object Notation (JSON) log events. Fields that CloudWatch generates start with the @ character, such as @timestamp and @message.
  • You can save queries, add results to a dashboard (lesson 274.1, tab 5), and export results.
  • It is a query engine, not a real-time engine. For a live view of incoming events, use Live Tail (section 4.4).
  • Pricing depends on the amount of data that a query scans. Check the pricing page.

4.2 The Query Language

A Logs Insights query is a pipeline of commands that are separated by the pipe character. Data flows from one command to the next.

CommandWhat it does
fieldsSelects the fields to show, and can create new fields.
filterKeeps only the log events that match one or more conditions.
parseExtracts values from unstructured text into new fields.
statsCalculates aggregate statistics, such as count, sum, average, minimum, and maximum.
sortOrders the results.
limitSets the maximum number of events to return. It works well with sort for “top 20” results.
displayChooses the fields to show in the final output.
dedupRemoves duplicate results based on the fields that you name.

Other commands also exist. For example, pattern clusters log data into recurring patterns, diff compares time ranges, and anomaly uses machine learning to find unusual patterns.

4.2.1 Query Examples

Show the 20 most recent error events:

fields @timestamp, @message
| filter @message like /ERROR/
| sort @timestamp desc
| limit 20

Count error events every five minutes:

filter @message like /ERROR/
| stats count(*) as errorCount by bin(5m)
| sort errorCount desc

Extract a value from text, and calculate statistics for each minute:

fields @message
| filter @message like /INFO/
| parse @message "UploadedBytes=*" as bytes
| stats min(bytes), avg(bytes), max(bytes) by bin(1m)

To keep queries fast and low-cost, apply filter before expensive parse or stats commands, query only the log groups that you need, and use the shortest time range that answers the question.

4.3 Query Languages and Limits

  • Logs Insights supports three query languages: Logs Insights QL (the pipeline language above), OpenSearch Piped Processing Language (PPL), and OpenSearch SQL. The two OpenSearch languages are not supported for the Infrequent Access class.
  • For log groups in the Infrequent Access class, Logs Insights QL supports all commands except pattern, diff, and unmask.
  • A query started through the API can include up to 50 log groups.
  • Queries time out after 60 minutes of runtime. If a query times out, reduce the time range or split it into several queries.
  • The StartQuery API returns up to 10,000 events by default.

4.4 Live Tail

Live Tail lets you watch log events as CloudWatch Logs ingests them, which helps when you test a change. It is available only for the Standard log class.

Exam trap

Logs Insights answers questions; it does not watch continuously. It does not send alerts or create metrics by itself, and it cannot query logs that you have already exported to Amazon S3. Use a metric filter for continuous counting (tab 5), and Amazon Athena for exported data (lesson 272.11).

Memory hook

Insights asks a question now. A metric filter watches all the time.

5.1 Metric Filters

A metric filter looks for patterns in log events as they arrive and publishes a value to a CloudWatch metric each time it finds one. You can then graph the metric, put it on a dashboard (lesson 274.1, tab 5), or alarm on it (tab 6). Lesson 269.4 applies metric filters and alarms to VPC flow logs.

ElementMeaningExample

Metric namespaceThe namespace that holds the metric.FlashCart/Checkout

5.1.1 Filter Patterns

A filter pattern can match a term in free text, or fields in JSON log events. Matching is case-sensitive.

Log formatExample patternMatches
Free textERROREvents that contain the term ERROR.
JSON{{ $.statusCode = 500 }}Events whose statusCode field equals 500.

The same pattern syntax is used by metric filters, subscription filters, and Live Tail.

5.1.2 Rules and Costs

  • Filters are not retroactive. A filter publishes data points only for events that arrive after you create it.
  • Metric filters work only for log groups in the Standard class. A log group can have up to 100 metric filters.
  • Metrics extracted from log events are charged as custom metrics.
  • Do not use high-cardinality fields, such as an IP address or a request ID, as dimensions. Each different value becomes a separate metric with its own charge. CloudWatch Logs can disable a filter that generates 1,000 different dimension name and value pairs within one hour.
  • You can view these metrics with any CloudWatch statistic. Percentile statistics are not available when any value of the metric is negative.

5.2 Embedded Metric Format

An application can write log events in the embedded metric format, a structured JSON layout that tells CloudWatch which values are metrics. CloudWatch extracts the custom metrics automatically, so the application does not need a separate PutMetricData call. This feature works only with the Standard log class.

5.3 Contributor Insights

Contributor Insights analyzes log data to show the top contributors, such as the IP addresses, users, or API paths that cause the most errors. It also reports the number of unique contributors. Lesson 269.4 lists it among the ways to analyze VPC flow logs.

  • A rule evaluates JSON or Common Log Format logs from up to 20 log groups.
  • A rule analyzes only new log events that arrive after you create it.
  • Built-in sample rules exist for logs such as Amazon API Gateway, Amazon Route 53 public DNS query logs, VPC flow logs, and container service logs.
  • Matching of field names and values is case-sensitive.
{
  "Schema": { "Name": "CloudWatchLogRule", "Version": 1 },
  "LogGroupNames": [ "/flashcart/checkout" ],
  "LogFormat": "JSON",
  "Contribution": {
    "Keys": [ "$.ip" ],
    "Filters": [ { "Match": "$.level", "In": [ "ERROR" ] } ]

6. CloudWatch Alarms

Problem Statement

The alarm sits in a gray state that nobody understands, and a dashboard widget turns from green to gray. A second alarm watches the central processing unit (CPU) of the checkout instances and flips between OK and ALARM every few minutes during the sale, so the team starts to ignore it.

Two more teams ask for alarms. The database team wants a page only when CPU is high and the number of connections is high at the same time. The marketing team wants an alarm on order volume that fits a normal daily pattern, which is low at night and high at lunchtime, without anyone choosing a fixed number.

Your challenge:

  • Choose the alarm settings (statistic, period, evaluation periods, datapoints to alarm, and threshold) that meet the CTO’s rule, and write them down.
  • Explain the gray state at 3 a.m., and choose how the alarm should treat missing data.
  • Choose the alarm type for the database team’s rule and for the marketing team’s order-volume alarm.
  • Explain how the team can stop the CPU alarm from flipping every few minutes.

6.1 What an Alarm Does

A CloudWatch alarm watches one metric, or the result of a metric math expression, over a period of time. It compares the values with a threshold and sets its state. When the state changes, the alarm can run actions, which tab 7 covers. An alarm does not fix a problem by itself; it reacts to the data. The metric can come from any source, including AWS services (lesson 274.1), custom metrics, and the metric filters from tab 5.

A metric alarm has three states:

  • OK: the metric or expression is within the defined threshold.
  • ALARM: the metric or expression is outside the defined threshold.
  • INSUFFICIENT_DATA: the alarm has just started, the metric is not available, or not enough data is available to decide the state.

When you create an alarm, CloudWatch first sets it to INSUFFICIENT_DATA, then evaluates it and sets the correct state. Alarm actions run when the alarm changes to a state, not at every evaluation.

6.2 Evaluation Settings

When you create an alarm, you choose these settings:

SettingMeaningExample
StatisticThe aggregation that CloudWatch applies to the data points in each period.Sum, Average, Maximum, p95
PeriodThe length of time that is used to create each data point, in seconds. It should not be shorter than the resolution of the metric (lesson 274.1, tab 2).60
Evaluation Periods (N)The number of the most recent periods, or data points, that the alarm looks at.3
Datapoints to Alarm (M)The number of data points within the evaluation periods that must be breaching to cause the ALARM state. They do not have to be consecutive.2
Threshold and operatorThe value to compare with, and the comparison, such as greater than.Greater than 20
Treat missing dataHow the alarm handles periods that have no data (section 6.3).notBreaching
  • When Datapoints to Alarm equals Evaluation Periods, every evaluated data point must breach, such as 3 out of 3. When the two values differ, you have an “M out of N” alarm.
  • The evaluation interval is the number of evaluation periods multiplied by the period. For example, 4 out of 5 data points with a period of one minute gives an evaluation interval of five minutes.
  • For any period of one minute or longer, CloudWatch evaluates the alarm every minute, on a sliding window that moves forward by one minute. You can instead align the window to wall clock boundaries.
  • High-resolution alarms use a period of 10, 20, or 30 seconds, are evaluated every 10 seconds, and cost more.
  • If the evaluation periods multiplied by the period exceed one day, the alarm is a multi-day alarm, and CloudWatch evaluates it once per hour.

The alarm below meets the CTO’s rule from the Problem Statement. It goes to ALARM when the error count is above 20 in two of the last three one-minute periods, so a single bad minute is ignored.

aws cloudwatch put-metric-alarm \
  --alarm-name checkout-errors-high \
  --namespace FlashCart/Checkout --metric-name ErrorCount \
  --statistic Sum --period 60 \
  --evaluation-periods 3 --datapoints-to-alarm 2 \
  --threshold 20 --comparison-operator GreaterThanThreshold \
  --treat-missing-data notBreaching \
  --alarm-actions <sns-topic-arn>

6.3 Missing Data

Metrics sometimes have no data points, for example when no events match a metric filter. You choose how the alarm treats those periods. If you do not choose, CloudWatch uses missing.

SettingMeaningTypical use
missing (default)Missing data points are not considered. If all data points in the evaluation range are missing, the alarm goes to INSUFFICIENT_DATA.Alarms that run EC2 actions (tab 7)
notBreachingMissing data points count as within the threshold.Error counts and other sparse metrics
breachingMissing data points count as breaching the threshold.Heartbeat metrics, where silence is a problem
ignoreThe alarm keeps its current state while data is missing.Avoiding state changes during short gaps

For the error metric from tab 5, there are two good answers. Set the alarm to notBreaching, or set the metric filter’s default value to 0 so that a data point exists every minute. AWS also recommends the missing setting for alarms that run EC2 actions, because a brief gap in the metric should not recover or reboot a healthy instance.

6.4 Alarm Types

TypeWhat it watchesNotes
Metric alarmOne metric, compared with a static threshold.The most common type. Actions: Amazon Simple Notification Service (Amazon SNS), Lambda, EC2, EC2 Auto Scaling, Systems Manager.
Metric math alarmThe result of a metric math expression, such as an error rate (lesson 274.1, tab 3).Lets you alarm on a calculated value.

6.4.1 Composite Alarms

A composite alarm has a rule expression that uses the states of other alarms, which can be metric alarms or other composite alarms. The rule uses the functions ALARM(), OK(), and INSUFFICIENT_DATA() with the operators AND, OR, and NOT. A rule can include up to 100 underlying alarms.

aws cloudwatch put-composite-alarm \
  --alarm-name db-under-pressure \
  --alarm-rule 'ALARM("HighDbCpu") AND ALARM("HighDbConnections")' \
  --alarm-actions <sns-topic-arn>
  • Use a composite alarm to cut noise: it goes to ALARM only when the conditions in the rule are met, and you set actions on the composite alarm only.
  • A rule such as ALARM("HighCpu") AND NOT ALARM("KnownNetworkIssue") avoids paging the team for CPU while a known network problem is under way.
  • A composite alarm can also suppress its actions while another alarm, the suppressor, is in ALARM state.

6.4.2 Anomaly Detection Alarms

An anomaly detection alarm compares a metric with the band of expected values from lesson 274.1, tab 3. It needs no fixed number, so it suits the marketing team’s order-volume metric, which has a daily pattern. The alarm can trigger when the metric goes above the band, below it, or outside it, and you set the width of the band in standard deviations. A wider band gives fewer alarms.

Exam trap

INSUFFICIENT_DATA is not the same as a failure. A new alarm and an alarm on a metric that stopped reporting both show it, and the default missing-data setting is missing. Another common trap: composite alarms and anomaly detection alarms cannot start every kind of action. A composite alarm cannot run EC2 or Auto Scaling actions, and an anomaly detection alarm cannot run Auto Scaling actions.

Memory hook

M of N means that M of the last N periods must breach. A composite alarm waits for the rule, and an anomaly detection alarm waits for the band.

  1. Create the log group in the US East (N. Virginia) Region, and create a resource policy that allows Route 53 to write to it.
  2. Install the CloudWatch agent on the Route 53 name servers.
  3. Create the log group in the same Region as the company’s VPC.
  4. Turn on VPC flow logs for the hosted zone.
Show the answer

Correct answer: A. Public DNS query logs go to a log group in US East (N. Virginia), and Route 53 needs a resource policy to write to it.

OptionResult
AYes — this meets both requirements for public DNS query logging.
BNo — you cannot install software on Route 53 name servers.
CNo — the log group must be in US East (N. Virginia), whatever Region the VPC uses.
DNo — a hosted zone is not a VPC resource, and flow logs record network traffic.

Trigger 2: “API Gateway access logs”
→ CloudWatch Logs; turn on access logging for the stage.

Trigger 3: “Keep logs in Amazon S3 but query them later”
→ Export or Firehose to Amazon S3, then Amazon Athena.

Trigger 4: “Load balancer access logs”

10. Knowledge Check

Answer each question in your own words before you open the model answer.

  1. Explain how a log event, a log stream, and a log group relate to each other. Which settings belong to the log group?

    Show the model answer

    A log event is one record, with a timestamp and a message. A log stream is a sequence of events that share the same source, such as one instance or one log file. A log group is a collection of streams that share the same settings.

    The log group carries the retention setting, the log class, the encryption key, metric filters, subscription filters, and access control. Every stream in the group follows them.

  2. A log group has been collecting logs for two years, and storage cost keeps growing. Compliance requires 90 days of logs. What should the team do, and what would have prevented the problem?

    Show the model answer

    Set the log group’s retention period to 90 days. CloudWatch Logs then deletes older events automatically.

    The cause is the default retention, which is never expire. Setting a retention period when the log group is created would have prevented the growth.

  3. Describe how to encrypt a log group with a customer managed key, and name two limits to remember.

    Show the model answer

    Create a symmetric AWS KMS key, and update its key policy to allow the CloudWatch Logs service principal for the Region. Then associate the key with the log group, either when you create it or later with the associate-kms-key command.

    Two limits: only symmetric keys are supported, and the console cannot associate a key with an existing log group. CloudWatch Logs encrypts only newly ingested data after the association.

  4. The checkout logs from EC2 instances never appear in CloudWatch Logs, while Lambda logs do. Explain why, and list what the instances need.

    Show the model answer

    Lambda publishes its logs to CloudWatch Logs on its own, but an EC2 instance sends no logs by default.

    The instances need the CloudWatch agent, an attached IAM role that allows writing logs (for example, one with the CloudWatchAgentServerPolicy managed policy), and an agent configuration file whose logs section names the files, the log group, and the log stream.

  5. Compare an export task and a subscription filter. Which one would you use for a security team that needs events within minutes, and which for a seven-year archive?

    Show the model answer

    An export task is a batch copy to an Amazon S3 bucket in the same Region. Data can take up to 12 hours to become available, so it is not real time. A subscription filter streams matching events to Kinesis Data Streams, Firehose, or Lambda, usually in less than three minutes.

    Use a subscription filter for the security team. For the archive, an export task works for periodic copies, but AWS recommends a subscription filter that delivers to Firehose and Amazon S3 for continuous archiving.

  6. Write the Logs Insights query steps to count ERROR events per five minutes from the last hour. Which limits could stop the query?

    Show the model answer

    Select the log groups and a one-hour time range. Then use a query such as: filter @message like /ERROR/ | stats count(*) as errorCount by bin(5m) | sort errorCount desc.

    Limits to check: a query started through the API can include up to 50 log groups, and queries time out after 60 minutes. For a timeout, reduce the time range or split the query.

  7. FlashCart wants to be alerted when checkout errors rise, and wants to know which IP addresses cause them. Which features do you use, and what should you avoid?

    Show the model answer

    Use a metric filter to publish a value for each ERROR event, and then alarm on the metric (tab 6). Use Contributor Insights to rank the IP addresses that cause the most errors.

    Avoid using the IP address as a metric filter dimension, because each value becomes a separate custom metric with its own charge. Remember that both features act only on new events.

  8. Design a logging architecture for a company with two Regions and a separate payments account. Logs must be searchable for 30 days, kept for seven years, and streamed to a security tool.

    Show the model answer

    Send all logs to CloudWatch Logs, and set a 30-day retention period on the log groups for interactive search with Logs Insights.

    Use subscription filters, including cross-account subscriptions to Kinesis Data Streams or Firehose, to stream events to the security tool and to a central Amazon S3 bucket for the seven-year archive. S3 lifecycle rules can then manage the cost. Log centralization or cross-account observability can give one place to query the accounts and Regions.

  9. Explain how Period, Evaluation Periods, and Datapoints to Alarm work together. How would you set them to ignore one bad minute but react within two minutes?

    Show the model answer

    The period is the length of each data point. Evaluation Periods is the number of the most recent periods that the alarm looks at, and Datapoints to Alarm is how many of those must breach. When the two numbers differ, the alarm is an M out of N alarm, and the breaching points do not have to be consecutive.

    For the rule, use a period of 60 seconds, three evaluation periods, and two datapoints to alarm. One bad minute is ignored, and two bad minutes put the alarm in ALARM state.

  10. An alarm on an error metric shows INSUFFICIENT_DATA at night. Explain why, and give two ways to fix it.

    Show the model answer

    The metric filter publishes data only when events match, so at night there are no data points. With the default missing-data setting, the alarm goes to INSUFFICIENT_DATA when all points are missing.

    Set the alarm to treat missing data as notBreaching, or set the metric filter’s default value to 0 so that a data point exists every minute.

  11. Compare metric, composite, and anomaly detection alarms, and name an action that one of them cannot run.

    Show the model answer

    A metric alarm compares one metric with a static threshold. A composite alarm combines the states of other alarms with AND, OR, and NOT to reduce noise. An anomaly detection alarm compares a metric with a band of expected values that CloudWatch learns from past data.

    A composite alarm cannot run EC2 or Auto Scaling actions, and an anomaly detection alarm cannot run Auto Scaling actions.

  12. Design the automatic response for a failing instance and for a billing surprise. Which actions, metrics, and Regions do you use?

    Show the model answer

    For a hardware failure, alarm on StatusCheckFailed_System with the recover action. For an operating system failure, alarm on StatusCheckFailed_Instance with the reboot action. Use the missing-data setting missing, and act only in the ALARM state.

    For billing, turn on billing alerts, and create the alarm in the US East (N. Virginia) Region on the EstimatedCharges metric. Use an SNS topic to notify the finance team.
