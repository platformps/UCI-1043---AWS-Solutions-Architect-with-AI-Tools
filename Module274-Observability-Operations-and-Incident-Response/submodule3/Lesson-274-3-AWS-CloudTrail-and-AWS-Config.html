AWS CloudTrail and AWS Config

How AWS records who did what in an account with CloudTrail, and how resources are configured, changed, and checked for compliance with AWS Config: event types, trails and long-term storage, reacting to recorded activity, configuration history, rules, remediation, and conformance packs.

Lesson Overview

This lesson covers two services of Amazon Web Services (AWS) that answer the questions that metrics and logs cannot: who did what in an account, and how resources were configured over time. It builds on the metrics lesson (lesson 274.1) and on logs and alarms (lesson 274.2). In this lesson, you will study:

  • What CloudTrail Records: events, event types, and the 90-day event history.
  • Trails and Long-Term Storage: trails, organization trails, log file integrity validation, encryption, and how to analyze old records.
  • Using CloudTrail Events: investigating changes, reacting with Amazon EventBridge, alarms through CloudWatch Logs, and CloudTrail Insights.
  • AWS Config: configuration items, the recorder, history, aggregators, and advanced queries.
  • Config Rules and Remediation: managed and custom rules, evaluation modes, automatic fixes, and conformance packs.
  • Where It Fits: which audit question each service answers, and which services use their data.
  • Comparison and Scenarios: a comparison of CloudWatch, CloudTrail, AWS Config, and AWS X-Ray, and a cheat sheet for the AWS Certified Solutions Architect – Associate (SAA-C03) exam.
  • Knowledge Check: open-ended questions with model answers.

Learning Objectives

By the end of this lesson, you will be able to:

  1. Define management event, data event, network activity event, Insights event, trail, and configuration item.
  2. Describe what the event history contains and how long CloudTrail keeps it.
  3. Explain the difference between event history, a trail, and CloudTrail Lake, including the availability change for CloudTrail Lake.
  4. Compare CloudTrail and AWS Config by the question that each one answers.
  5. Configure a trail with log file integrity validation, and deliver it to Amazon Simple Storage Service (Amazon S3) and CloudWatch Logs.
  6. Apply EventBridge rules, metric filters, and CloudTrail Insights to react to API activity.
  7. Differentiate managed rules, custom rules, and conformance packs, and detective from proactive evaluation.
  8. Evaluate an audit or compliance requirement, and choose the service, event type, and remediation that meet it.
  9. Design an audit and compliance setup that spans many accounts and Regions, with long-term storage, alerts, and automatic fixes.

1. What CloudTrail Records

Problem Statement

At 2:07 a.m. on Sunday, a DynamoDB table that holds six months of FlashCart order history (lesson 272.3) disappears from the production account. On Monday morning, three engineers say that they did not delete it. About 20 minutes before the deletion, a rule that opened port 22 to the whole internet also appeared on the bastion host’s security group (lesson 269.5). It stayed for 40 minutes and then vanished.

The CloudWatch graphs from lesson 274.1 show nothing unusual: central processing unit (CPU) use, network traffic, and error counts are normal. The CTO asks four questions: who did it, what exactly did they do, when, and from where. Nobody has turned on anything for auditing, and the team does not know whether the answer exists at all.

The security team adds two more questions. Can the team also see which AWS Identity and Access Management (IAM) user or role was behind each action, whether it came from the console, the AWS Command Line Interface (AWS CLI), or an AWS software development kit (SDK)? And could it have seen who read a specific invoice file in an Amazon Simple Storage Service (Amazon S3) bucket (lesson 271.2) last Tuesday?

Your challenge:

  • Explain which service answers “who deleted the table,” and why CloudWatch metrics could not.
  • Describe where the engineers can look today without creating anything, and how far back the data goes.
  • List the details that each recorded action gives you.
  • Explain why the team might not be able to see who read the invoice file, and what would be needed.

1.1 What AWS CloudTrail Does

AWS CloudTrail helps you audit, govern, and prove compliance for an AWS account. Actions that a user, a role, or an AWS service takes are recorded as events, and most of them are application programming interface (API) calls. The actions can come from the AWS Management Console, the AWS Command Line Interface (AWS CLI), an AWS software development kit (SDK), or another AWS service. In short, CloudTrail records who did what, when, and from where.

CloudWatch metrics describe how a resource performs (lesson 274.1). They do not say who deleted it. When a resource is deleted or changed, investigate CloudTrail first.

1.4 Event History

Event history is a viewable, searchable, downloadable, and immutable record of the past 90 days of management events in an AWS Region.

  • You get access to it automatically when you create the account. You do not set anything up.
  • There is no CloudTrail charge for viewing it.
  • You can search by filtering on a single attribute, such as the event name or the user name.
  • It covers only management events. It cannot show data events, and it cannot go back further than 90 days.
Exam trap

Do not read “CloudTrail is enabled by default” too far. Event history is automatic, but it is only 90 days of management events. To keep events longer, or to log data events, you must create a trail (tab 2). A question about who read an S3 object always needs data events to be turned on before the read.

Memory hook

CloudTrail is the diary of actions: who did what. AWS Config, in tab 4, is the photo album of resources: what they looked like.

2. Trails and Long-Term Storage

Problem Statement

After the incident, FlashCart’s auditors ask for two things: every API call kept for seven years, and proof that nobody changed the records afterward. FlashCart now has 14 AWS accounts for development, test, production, and the payments team, and it runs the store in two Regions. The security team wants all the records in one place, and it wants new accounts to be covered automatically.

An engineer turns on object-level logging for the invoice bucket. Within a week, that one setting produces about 30 million events a day, and the finance team asks why the audit bill grew. The legal team also asks who can delete the audit records, and whether the records can be encrypted with a key that the security team controls.

For the last 90 days, the team can use the console history, but nobody has a plan for queries on records that are two or three years old.

Your challenge:

  • Choose how to keep the records beyond 90 days, and explain what the 90-day history cannot do.
  • Choose how to cover all accounts and both Regions with one setup, including accounts that are created later.
  • Describe how to prove that a log file was not changed, and how to protect and encrypt the files.
  • Decide which events to record, and explain why object-level events need careful scoping.
  • Choose how to query records that are years old, and explain why CloudTrail Lake is not the first answer for a new account.

2.1 Trails

A trail is a configuration that delivers CloudTrail events to an Amazon S3 bucket that you choose, so that you can keep them for as long as you need and record more than management events. A trail can also send events to CloudWatch Logs (lesson 274.2) and can send an Amazon Simple Notification Service (Amazon SNS) notification when it delivers a log file.

  • CloudTrail delivers compressed JSON log files to the bucket. Delivery is not instant: expect the files within about 5 to 15 minutes of the activity.
  • The bucket’s retention depends on your S3 lifecycle rules (lesson 271.2), because a trail has no retention limit of its own.
  • The first copy of management events in each Region is delivered at no charge. Additional copies, data events, network activity events, and Insights events are charged. Check the pricing page.
Trail typeWhat it coversUse it when
Single-Region trailEvents in one Region.You need records only for one Region.
Multi-Region trailEvents in all Regions. This is the default when you create a trail in the console.You want one setup for every Region, including Regions that you add later.
Organization trailEvents of all accounts in an AWS Organizations organization, from one trail.You want every member account covered, including accounts created later.

2.2 Protecting the Logs

  • Encryption: CloudTrail encrypts log files with Amazon S3 server-side encryption by default. You can use an AWS Key Management Service (AWS KMS) key for the trail instead.
  • Log file integrity validation: CloudTrail creates a hash for every log file and delivers a signed digest file to the same bucket, about once an hour. CloudTrail uses SHA-256 for hashing and SHA-256 with RSA for digital signing, so changing, deleting, or forging a log file without detection is computationally infeasible.
  • Checking the files: run the validate-logs command in the AWS CLI. It reports modified or deleted log files and digest files. If you turn validation off, the chain of digest files breaks after one hour.
  • Access: restrict who can read and delete the logs with IAM policies and the bucket policy.
aws cloudtrail create-trail \
  --name flashcart-audit \
  --s3-bucket-name <audit-bucket> \
  --is-multi-region-trail \
  --enable-log-file-validation

aws cloudtrail validate-logs \
  --trail-arn <trail-arn> \
  --start-time 20261101T000000Z

NeedOption

What has changed

AWS CloudTrail Lake stopped being open to new customers on May 31, 2026. Existing customers can keep using it, but it receives only critical bug fixes and security updates. For similar capabilities, AWS recommends CloudWatch, and it offers a way to import existing Lake event data stores into CloudWatch. Older study materials still teach CloudTrail Lake as the analysis tool, so recognize it on the exam, but design new setups with Amazon S3 and Athena or with CloudWatch.

Exam trap

The 90-day event history cannot be extended. Only a trail keeps events longer, and only a trail can record data events. Another common trap: a trail alone does not prove that logs are unchanged. You must turn on log file integrity validation. Finally, a new design should not depend on CloudTrail Lake.

Memory hook

Event history is the window. A trail is the archive. Validation is the seal.

3. Using CloudTrail Events

Problem Statement

FlashCart’s security team wants three alerts. The first is an alert within minutes when anyone deletes a database table or changes a security group. The second is an alert whenever the root user signs in. The third is an alert when an API is called unusually often, such as a sudden burst of calls that terminate instances.

An engineer proposes to check the console history every morning. A second engineer proposes a script that downloads the log files from Amazon S3 every hour. A third wants to use the CloudWatch Logs tools from lesson 274.2. The security lead also asks how the AWS threat-detection service from lesson 268.10 gets its data, and whether FlashCart needs to feed it.

During a drill, the team must also investigate a suspicious sign-in from two years ago. The logs sit in Amazon S3, and nobody wants to download thousands of files.

Your challenge:

  • Choose the way to react to one specific API call, such as a table deletion, within minutes.
  • Describe how to turn API calls recorded in CloudWatch Logs into an alarm.
  • Explain how the team can learn about unusual API activity without defining a threshold for every call.
  • Choose how to search two-year-old logs in Amazon S3 without downloading them (lesson 272.11).

3.1 Investigating a Change

When something changes, follow the same steps:

  1. Search the event history for the event name or the resource, if the change is within the last 90 days.
  2. For older changes, query the trail’s log files in Amazon S3 with Amazon Athena (lesson 272.11), or the trail’s log group with Logs Insights (lesson 274.2).
  3. Read userIdentity, sourceIPAddress, and requestParameters to answer who, from where, and on what.

Other lessons already point to CloudTrail for the same reason. Amazon Relational Database Service (Amazon RDS) API calls, such as who created or deleted a database, appear in it (lesson 272.1), and so do changes to a bastion host’s security group and Session Manager session starts (lesson 269.5).

3.2 React With Amazon EventBridge

An API call that CloudTrail records can match an Amazon EventBridge rule (lesson 273.3). The rule can send a notification or run code, so the team learns about a risky call within minutes. An event pattern for API calls uses the detail type “AWS API Call via CloudTrail,” and it names the service and the call:

{
  "source": ["aws.dynamodb"],
  "detail-type": ["AWS API Call via CloudTrail"],
  "detail": {
    "eventSource": ["dynamodb.amazonaws.com"],
    "eventName": ["DeleteTable"]
  }
}

Confirm the exact pattern for each service in the EventBridge documentation before you use it.

3.3 Alarms Through CloudWatch Logs

A trail can deliver events to a CloudWatch Logs log group. There, a metric filter (lesson 274.2, tab 5) can count matching events, and an alarm (lesson 274.2, tab 6) can notify the team when the count passes a threshold. The filter pattern for the deletions could be { $.eventName = "DeleteTable" }.

3.4 CloudTrail Insights

CloudTrail Insights detects unusual activity without a threshold that you define for each call.

  • Insights analyzes your normal management events to create a baseline of API call volume and error rates, and then it continuously analyzes write events for patterns outside that baseline.
  • Examples of unusual activity are a burst of IAM actions, a sudden jump in calls that terminate instances, unexpected resource provisioning, and calls that hit service limits.
  • Insights events appear in the CloudTrail console, are delivered to Amazon S3, and generate an EventBridge event for automation.
  • Insights is turned on separately, works on management events, and is charged.

3.5 Related Services

Amazon GuardDuty (lesson 268.10) reads CloudTrail management events, VPC flow logs, and DNS logs on its own, so FlashCart does not need to feed it. It turns unusual API calls and unauthorized deployments into findings.

4. AWS Config

Problem Statement

Six months after the deletion incident, the auditors return with new questions that CloudTrail alone cannot answer easily. On March 3, was a specific security group open to the whole internet on port 22? How did the configuration of the API load balancer change over the last six months? Which Amazon Elastic Block Store (Amazon EBS) volumes in all 14 accounts and both Regions are not encrypted today?

The team could replay hundreds of thousands of CloudTrail events to rebuild what a resource looked like on a given day, but that would take days and would miss resources that were never changed. The platform team also learns that its current setup in the first Region does not cover the second Region at all.

The security lead wants one place that shows what exists, how it is configured, and how it has changed, and wants to receive a notification when a resource changes.

Your challenge:

  • Explain what AWS Config records, and why that is different from what CloudTrail records.
  • Describe how to see a resource’s configuration on a past date.
  • Choose how to list all unencrypted volumes across 14 accounts and two Regions with a single query.
  • Explain why the second Region was not covered, and where the recorded data is delivered.

4.1 What AWS Config Does

AWS Config tracks and records the configuration state of your AWS resources over time. It helps you answer what resources exist, how they are configured, and how they have changed. It is a Regional service, so you turn it on in each Region that you want to cover.

Question that AWS Config can answerExample
Is any security group open to the whole world on port 22?0.0.0.0/0 on port 22
Are any Amazon S3 buckets public?A bucket that anyone can read
Which resources have no tags?Resources that are missing a cost tag
Is any Amazon Relational Database Service (Amazon RDS) database not Multi-AZ?A single-instance database
How has a load balancer’s configuration changed over time?A listener or target setting changed last month

4.2 The Recorder and Configuration Items

  • The configuration recorder records resource changes. By default, a customer managed recorder records all supported resource types in the Region where AWS Config runs. You can narrow the scope.
  • A configuration item is a record of a resource’s configuration at one moment. Its components are metadata, attributes, relationships, current configuration, and related events. AWS Config creates one whenever it detects a change to a recorded resource type.
  • You can record continuously, which captures every change as it happens, or periodically, which captures the state once a day. Periodic recording costs less, but a problem that appears and is fixed within the same day may never produce a configuration item.
  • You pay for each configuration item that is recorded. Check the pricing page.

4.3 Configuration History and the Timeline

For each resource, AWS Config shows the configuration over time, the compliance over time, and the CloudTrail events that touched the resource. Together, these let an auditor see what a security group looked like on March 3 and which API call changed it.

AWS Config can deliver configuration changes as notifications through Amazon SNS, and it can store configuration snapshots in an Amazon S3 bucket.

4.4 Aggregators and Advanced Queries

  • Aggregators: a configuration aggregator collects configuration and compliance data from many accounts and Regions into one view.
  • Advanced queries: you can run SQL-like queries on the current configuration of your resources, for one account and Region or across an aggregator. The console offers sample queries.
SELECT resourceId, awsRegion
WHERE resourceType = 'AWS::EC2::SecurityGroup'
Exam trap

AWS Config records configuration state, not API calls and not performance. It tells you what a resource looked like, not who changed it, although the timeline links to the CloudTrail event that did. AWS Config is also Regional and is charged for each recorded item, so it is not free to turn on everywhere.

Memory hook

CloudTrail is the diary, and AWS Config is the photo album. The diary says who did what. The album shows how the room looked.

5. Config Rules and Remediation

Problem Statement

The security team wants to know the moment anyone creates an unencrypted volume, a security group that allows Secure Shell (SSH) access from anywhere, or an Amazon S3 bucket that allows public reads. The finance team also wants every resource to carry cost-allocation tags. Today, the team finds such problems only when an auditor asks.

An engineer proposes to use AWS Config rules to block the creation of unencrypted volumes. A second engineer wants resources to be fixed automatically as soon as they are found, but worries that an automatic fix could break production. The platform team also needs the same rules in all 14 accounts, including accounts that join the organization later. CloudFormation StackSets from lesson 296.1 are one option that the team already knows.

The last requirement comes from the network team: they want to be told about a violation in the chat tool, not only in the Config console.

Your challenge:

  • Choose the rule type for each of the three security checks and for the tagging check.
  • Explain whether Config rules can block an action, and name the setting that evaluates before deployment.
  • Design automatic remediation, including what runs the fix and what permission it needs (lesson 268.8).
  • Choose how to deploy the same rules and fixes to all accounts, and how to send violations to the chat tool.

5.1 Config Rules

A Config rule defines a desired configuration. AWS Config evaluates your resources against it and marks each one as compliant or non-compliant.

Rule typeWhat it isExamples
Managed ruleA predefined, customizable rule that AWS creates. AWS keeps a long list, far longer than the “over 75” on some course slides.restricted-ssh, s3-bucket-public-read-prohibited, rds-multi-az-support, required-tags, multi-region-cloudtrail-enabled
Custom ruleA rule that you write from scratch, either as an AWS Lambda function or as a policy in the Guard language.A check that every EBS volume uses one type, or that every instance uses an approved size

5.2 When Rules Evaluate

  • On a configuration change: the evaluation runs after AWS Config sends a configuration item change notification. You choose which resources start an evaluation by setting the rule’s scope.
  • Periodically: the evaluation runs at a regular interval, which suits checks that do not depend on a change.
  • Evaluation modes: detective evaluation checks resources after they exist, and proactive evaluation checks resources before they are deployed.

5.3 Rules Detect; They Do Not Prevent

A Config rule reports non-compliance. It does not deny the action, so it cannot stop someone from creating an unencrypted volume. Use IAM policies or other preventive controls to stop an action, and use Config rules to find and fix the resources that slip through.

5.4 Remediation and Notifications

  • Remediation actions fix non-compliant resources by running AWS Systems Manager Automation documents (lesson 268.8). You can use AWS managed documents or write your own, and a document can call a Lambda function.
  • You can set remediation to run automatically or to run manually.
  • You can configure retries, with a maximum number of attempts and a retry interval, for a resource that is still non-compliant after a fix.
  • The Systems Manager execution role needs permission to change the resource, so scope that role with care.
  • To be told about violations, use EventBridge (lesson 273.3) to route a non-compliance event to Amazon SNS, AWS Lambda, or Amazon Simple Queue Service (Amazon SQS), for example to post in a chat tool.

5.5 Conformance Packs and Many Accounts

  • A conformance pack is a collection of Config rules and remediation actions that you deploy and monitor as one unit. You define it in a YAML template.
  • You can deploy conformance packs centrally to all member accounts of an AWS Organizations organization.
  • CloudFormation StackSets (lesson 296.1) can also deploy Config rules across accounts and Regions.
  • AWS Security Hub and AWS Firewall Manager need AWS Config to be turned on (lessons 268.9 and 268.10), because they read resource configuration from it.
Exam trap

Config rules detect problems; they do not block actions, so a question that says “prevent” does not point to a Config rule. Remediation needs a Systems Manager Automation document and a role with permission to change the resource. Also, AWS Config must be turned on and recording before a rule can evaluate anything.

Memory hook

Config rules judge, and remediation fixes. Neither one is a wall.

8. Knowledge Check

Answer each question in your own words before you open the model answer.

  1. Explain what CloudTrail event history is and what it does not cover.

    Show the model answer

    Event history is a viewable, searchable, downloadable, and immutable record of the past 90 days of management events in a Region. It is available automatically and has no CloudTrail charge.

    It does not cover data events, it does not go back further than 90 days, and it cannot be extended. To keep events longer or to log data events, you must create a trail.

  2. Compare management events, data events, network activity events, and Insights events. Which of them does a trail log by default?

    Show the model answer

    Management events record control-plane actions such as creating a bucket or an instance. Data events record object-level or item-level actions such as reading an S3 object. Network activity events record API calls through VPC endpoints. Insights events record unusual activity found by analyzing management events.

    A trail logs management events by default. Data events, network activity events, and Insights events must be turned on, and they are charged.

  3. FlashCart must keep every API call for seven years and prove that the records were not changed. Describe the setup.

    Show the model answer

    Create a multi-Region trail, or an organization trail for many accounts, that delivers to an Amazon S3 bucket. Turn on log file integrity validation so that CloudTrail delivers signed digest files, and check the logs with the validate-logs command.

    Encrypt the files with an AWS KMS key if the key must be controlled, restrict who can delete them, and use S3 lifecycle rules to control cost over the seven years.

  4. A new team asks to use CloudTrail Lake for analysis. What do you tell them?

    Show the model answer

    AWS CloudTrail Lake stopped being open to new customers on May 31, 2026. Existing customers can continue to use it, but it receives only critical fixes.

    For a new setup, deliver the trail to Amazon S3 and query it with Amazon Athena, or deliver it to CloudWatch Logs and use Logs Insights. AWS recommends CloudWatch for capabilities similar to CloudTrail Lake.

  5. Design two ways to be told within minutes when someone deletes a DynamoDB table.

    Show the model answer

    The first way is an EventBridge rule that matches the DeleteTable call recorded by CloudTrail, with an Amazon SNS topic as the target.

    The second way is to deliver the trail to CloudWatch Logs, create a metric filter for the DeleteTable event, and create an alarm on the metric that notifies an SNS topic.

  6. For each question, say whether CloudTrail or AWS Config answers it: who changed a security group, and how that security group looked on a past date.

    Show the model answer

    CloudTrail answers who changed the security group, because it records the API call, the user, and the source address. AWS Config answers how the security group looked on a past date, because it keeps configuration history.

    The AWS Config timeline also links the CloudTrail events that touched a resource, so the two answers connect.

  7. Describe how Config rules, evaluation modes, and remediation work together. Can a rule stop an action?

    Show the model answer

    A Config rule evaluates resources against a desired configuration and marks them compliant or non-compliant. It can run when a configuration changes or periodically. Detective evaluation checks resources that exist, and proactive evaluation checks them before deployment.

    A non-compliant result can start remediation, which runs a Systems Manager Automation document, with retries if needed. A rule reports a problem and does not deny the action, so use IAM or other preventive controls to stop it.

  8. Design the audit and compliance setup for 14 accounts and two Regions. Include CloudTrail, AWS Config, storage, alerts, and automatic fixes.

    Show the model answer

    Create an organization trail that is multi-Region, with log file validation, delivering to a central Amazon S3 bucket and to CloudWatch Logs. Use Athena for old records, and use EventBridge rules, or metric filters and alarms, for alerts on risky API calls. Turn on CloudTrail Insights for unusual activity.

    Turn on AWS Config in each account and Region, collect it in an aggregator, and deploy an organization conformance pack with managed rules and automatic remediation through Systems Manager Automation. Route non-compliance events through EventBridge to the team’s notification tool.
