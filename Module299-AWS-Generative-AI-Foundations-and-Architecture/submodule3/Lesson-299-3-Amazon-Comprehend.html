Amazon Comprehend

How Amazon Comprehend finds meaning in text: language, entities, key phrases, sentiment, custom models, personal data and toxicity, and the architecture, security, and cost of a text analysis pipeline.

Lesson Overview

Amazon Comprehend is a managed natural language processing (NLP) service. It uses machine learning (ML) to find meaning and insights in text: the language, the people, places, and brands that are mentioned, the key phrases, and whether the writer is positive or negative. You call it through an application programming interface (API), so you need no NLP expertise. This lesson follows FlashCart Inc., a fictional online marketplace that gets thousands of customer reviews, support emails, and chat messages every day. In this lesson, you will study:

  • Introduction to Amazon Comprehend: what the service does, how you call it, the languages it supports, and common use cases.
  • Built-In Text Analysis: language detection, entities, key phrases, sentiment, targeted sentiment, and syntax.
  • Custom Models, PII, and Toxicity: custom classification, custom entity recognition, personally identifiable information (PII) detection and redaction, and toxicity detection.
  • Architecture, Security, and Cost: real-time, batch, and asynchronous processing, an event-driven pipeline, throttling, access control, data privacy, and the pricing model.
  • Comparison and Scenarios: how Comprehend compares with other AWS AI services, and an SAA-C03 cheat sheet.
  • Knowledge Check: open-ended questions with model answers.

Learning Objectives

At the end of this lesson, learners will be able to:

  1. Define Amazon Comprehend and NLP, and state where Comprehend fits in the AWS AI layers.
  2. Describe the languages that Comprehend supports, and how Amazon Translate extends them.
  3. Explain how confidence scores help you interpret Comprehend results.
  4. Apply language detection, entity recognition, key phrase extraction, sentiment analysis, targeted sentiment, and syntax analysis to a text analysis need.
  5. Differentiate custom classification from custom entity recognition, and describe how a custom model is trained and used.
  6. Choose PII detection and redaction or toxicity detection for a privacy or moderation need.

  8. Design an event-driven text analysis pipeline that addresses security, privacy, throttling, and cost.

1. Introduction to Amazon Comprehend

Problem Statement

FlashCart Inc. gets thousands of product reviews, support emails, and social media posts every day. Two analysts read a small sample and write a weekly summary, so the company hears about a problem with a product days after customers start complaining.

The engineering manager wants every message analyzed as it arrives: which language it is in, which products and places it mentions, whether the customer is happy, and what the main points are. The team has no machine learning or NLP engineers.

She also asks which languages the service can read, because FlashCart sells in several countries.

Your challenge: Advise the manager. Your answer should:

  • Explain what Comprehend does and why it needs no NLP expertise.
  • Name the insights that it returns, and how to judge whether to trust a result.
  • Say which languages it supports and what to do for other languages.

1.1 What Amazon Comprehend Is

  • Amazon Comprehend is a natural language processing (NLP) service that uses machine learning to find meaning and insights in text.
  • NLP is a way for computers to analyze, understand, and get meaning from text. It can extract important phrases, sentiment, syntax, key entities such as a brand, a date, a place, or a person, and the language of the text.
  • It is fully managed and continuously trained, so you do not manage scaling, code maintenance, or training data.
  • You call the Comprehend APIs and give the text, or the location of the source documents. The APIs return entities, key phrases, sentiment, and language in a JSON format.
  • It sits in the artificial intelligence (AI) services layer, with Amazon Rekognition and Amazon Textract, which you studied in Lessons 299.1 and 299.2.

1.2 Where the Text Comes From

The source of the text can be web pages, social media feeds, emails, or articles. Comprehend reads data from Amazon Simple Storage Service (Amazon S3), and you can write the results to a storage service, a database, or a data warehouse.

1.3 How You Call Comprehend

  • Comprehend analyzes text in UTF-8 format with its built-in models. It offers synchronous and asynchronous operations (tab 4).
  • Requests to the API and the console use a secure connection, and AWS Identity and Access Management (IAM) controls who can call each action.
  • For text analysis APIs, an HTTP status code of 200 means that the text was processed. If the text cannot be processed or goes over a service limit, you get an error code.

1.5 Languages

  • Comprehend can analyze text in German, English, Spanish, Italian, Portuguese, French, Japanese, Korean, Hindi, Arabic, Chinese (Simplified), and Chinese (Traditional).
  • Language detection identifies text in more than 100 languages.
  • For a language that Comprehend does not analyze, use Amazon Translate to convert the text into a supported language first, and then use Comprehend. Amazon Translate is the topic of Lesson 299.4.
  • Support differs by feature, so check the supported languages page for the feature that you plan to use.

1.6 Confidence Scores

  • Comprehend returns a confidence score for each result. A low score means that the service has low confidence that the result is correct.
  • A high score, close to 1, means high confidence. Comprehend scores run from 0 to 1.
  • Use the score to decide what to trust. For example, send low-confidence results to a person, or ignore them.

2. Built-In Text Analysis

Problem Statement

FlashCart’s marketing team collects reviews in many countries. They want to know which language each review is in, which brands and places it mentions, the main talking points, and whether the customer is happy.

A review says, “I loved the burger, but the service was slow.” The overall feeling is mixed, but the support team wants to know exactly what was good and what was bad, so that they can fix the right thing.

The analytics lead also asks whether Comprehend can tell a noun from a verb, because a search team wants to index only the important words.

Your challenge: Match the needs to Comprehend features. Your answer should:

  • Name the feature for the language, the entities, the key phrases, and the overall sentiment.
  • Explain how targeted sentiment differs from sentiment analysis.
  • Say what syntax analysis returns.

2.1 Language Detection

  • The language detection API identifies the language of text in more than 100 languages.
  • It returns the dominant language, as a language code, with a confidence score. For example, a short paragraph in Italian returns the code it and a score of 1.0.
  • Run it first when your reviews come from many countries. Then send each text to the right analysis, or to Amazon Translate.

2.2 Entity Recognition

  • The entity recognition API returns the named entities in the text, such as people, places, and organizations, grouped into categories automatically.
  • Each entity comes with a category and a confidence score. For example, in a short company description, “Amazon.com, Inc.” is an organization, “Seattle, WA” is a location, and a founding date is a date.
  • Use it to find which brands, products, places, and dates a message mentions.

2.3 Key Phrase Extraction

  • The key phrase API returns the key phrases, or talking points, in the text, with a confidence score for each one.
  • For a long review of cameras, it returns phrases such as “my instant film camera” and “power and convenience.”
  • Use it to summarize what a message is about, and to build search filters.

2.4 Sentiment Analysis

  • The sentiment analysis API returns the overall sentiment of a text: positive, negative, neutral, or mixed.
  • It also returns a score for each of the four values. A review that praises the quality but complains about the fit can return a high score for mixed.
  • It gives one answer for the whole text.

2.5 Targeted Sentiment

  • Targeted sentiment gives more detail. It finds the entities in the text and returns the sentiment toward each one.
  • For “I loved the burger, but the service was slow,” it returns positive for the burger and negative for the service, while the writer, “I,” is neutral.
  • Use it to find what customers like and dislike about each product or part of the experience.

2.6 Syntax Analysis

  • The syntax API tokenizes the text, which means that it finds the word boundaries, and it labels each word with a part of speech, such as a noun, a verb, or an adjective.
  • For “I love my fast, new Kindle Fire!” it labels “I” and “my” as pronouns, “love” as a verb, “fast” and “new” as adjectives, “Kindle” and “Fire” as proper nouns, and the comma and the exclamation mark as punctuation.
  • It also returns where each word begins and ends in the text, and a confidence score.
  • Use it when you need to know the grammar, for example to index only the nouns.

2.7 Choosing the Right Feature

You want to knowUse

Exam trap

Sentiment analysis gives one result for the whole text, so a mixed review hides which part was good and which part was bad. Use targeted sentiment to get the sentiment for each entity. Also remember that Comprehend returns scores, not certainty: keep the confidence score with the result.

Memory hook

Sentiment is the weather of the whole text. Targeted sentiment is the weather for each place in it.

3. Custom Models, PII, and Toxicity

Problem Statement

FlashCart’s support inbox mixes three kinds of messages: questions about an order, return and refund requests, and product questions. A person sorts them by hand. The team wants an automatic router that uses FlashCart’s own categories, which no general service knows.

FlashCart’s seller protection program also uses claim numbers, such as CLM-4821, that Comprehend’s built-in entity types do not recognize. And support tickets often contain names, addresses, and card numbers that analysts should not see.

Finally, the seller chat has a few abusive messages, and the community manager wants them flagged automatically.

Your challenge: Choose the right Comprehend feature for each need. Your answer should:

  • Name the feature that sorts tickets into FlashCart’s own categories, and the feature that finds claim numbers.
  • Say how to remove personal data before analysts read the tickets.
  • Say how to flag abusive chat messages.

3.1 Custom Classification

  • Custom classification lets you build your own text classification model with your business-specific labels, without learning machine learning.
  • To train it, you give example texts, each marked with the label that applies. A comma-separated values (CSV) file with the text and the label is the typical form. Comprehend trains a custom model for you.
  • Then you submit new text, and you get back the labels with a confidence score for each match.
  • Typical uses are to categorize inbound requests by problem type, to moderate website comments, to triage customer feedback, and to organize workgroup documents.
TextLabelConfidence score

3.2 Custom Entity Recognition

  • Custom entity recognition customizes Comprehend to find terms that are specific to your domain, such as policy numbers, claim numbers, or product codes.
  • It uses AutoML. Comprehend learns from a small set of examples, such as a list of claim numbers, and trains a private custom model.
  • The model then finds those terms in other text, including text in PDF, plain text, and Microsoft Word documents.
  • Example: in “My policy code is 456-YQT,” the model returns 456-YQT as a Policy_ID entity with a confidence score.

3.4 PII Detection and Redaction

  • Comprehend can detect and redact personally identifiable information (PII) in customer emails, support tickets, product reviews, social media posts, and more. It needs no machine learning experience.
  • A common design analyzes support tickets and knowledge articles, finds the PII, and redacts the text before the documents go into a search index. The search then holds no PII.
  • Examples of what it finds: a name, a credit or debit card number, a date and time, a bank account number, and a bank routing number, each with a score.
  • Redacting PII helps you protect privacy and follow local laws and regulations.
  • PII detection works on English and Spanish text. You can detect PII with real-time analysis or with an asynchronous job.
  • AWS says that its use of text inputs to improve its services does not apply to Comprehend Detect PII.

3.5 Toxicity Detection

  • Toxicity detection is an NLP-based way to find toxic content in text.
  • It works out of the box, so you can moderate conversation between people on an online platform, and the inputs and outputs of generative AI.
  • It returns an overall toxicity score between 0 and 1, where 1 is the highest confidence, and a score for each category of toxic content: graphic, harassment or abuse, hate speech, insult, profanity, sexual, and violence or threat.
  • Toxicity detection currently supports English only. A request can hold up to 10 text strings, and each string can be up to 1 KB.
  • Choose a threshold, and flag or block messages above it.

4. Architecture, Security, and Cost

Problem Statement

FlashCart wants every review analyzed within seconds of arrival, and the support team must be alerted when a customer is very upset. Volume is uneven: a product launch can send a flood of reviews in an hour.

The security team asks who can call Comprehend, what AWS does with the text, and whether personal data stays protected. The data team also has a large archive of past reviews that they want to analyze once, in bulk.

The architect must choose the processing mode for each case and draw the pipeline.

Your challenge: Design the solution. Your answer should:

  • Choose real-time, batch, or asynchronous processing for new reviews and for the archive.
  • Show how a review leads to analysis, storage, and an alert.
  • Describe access control, data privacy, throttling, and the billing model.

Use real-time calls for new reviews that need an answer now. Use asynchronous jobs for large archives and for scheduled runs, such as daily, weekly, or monthly text analytics. Check the guidelines and quotas page for the current limits.

4.2 An Event-Driven Text Analysis Pipeline

  1. A review is saved to an Amazon S3 bucket.
  2. The upload event starts an AWS Lambda function.
  3. The function calls Comprehend, for example sentiment analysis and PII detection.
  4. The function stores the redacted text and the results, for example in Amazon DynamoDB.
  5. If the sentiment is strongly negative, the function publishes a message to an Amazon Simple Notification Service (Amazon SNS) topic, and the support team gets an alert.

For call recordings, Amazon Transcribe turns the speech into text first, and Comprehend then analyzes the text. Amazon Transcribe is covered later in this module.

4.3 Throttling

  • Comprehend applies dynamic throttling to real-time requests. It gradually allows more requests when processing capacity is available.
  • To control how your application uses real-time operations, turn on billing alerts or add rate limiting in the application.
  • For large volumes, use batch calls or asynchronous jobs.

4.4 Security and Access Control

  • Use IAM policies and roles to control who can call each Comprehend action and which resources they can use.
  • Requests to the API and the console use a secure connection.
  • AWS says that it protects content with encryption at rest and in transit, and that only authorized employees can access it.
  • Give the Lambda function a role with only the Comprehend actions that it needs, and give an asynchronous job only the bucket access that it needs.

4.5 Data Privacy

  • Comprehend may store and use the text that it processes to provide the service and, unless you opt out, to improve Comprehend and other Amazon AI technologies. This does not apply to Amazon Comprehend Medical and Comprehend Detect PII.
  • To opt out, use an AWS Organizations AI services opt-out policy.
  • Processed content is encrypted and stored at rest in the Region where you use Comprehend. A portion may be stored in another Region for improvement of the service.
  • You always own your content, and AWS uses it only with your consent.

4.6 Calling Comprehend From SQL With Aurora Machine Learning

The course slides describe a way to use Comprehend without leaving the database. Amazon Aurora machine learning lets an application call ML services directly from SQL queries, with no application-level ML code. Aurora supports Amazon SageMaker AI and Amazon Comprehend, for example for sentiment analysis.

  • Aurora does not train or host the models. The inference runs in the AWS ML service.
  • The data stays in Aurora, and only the fields that are needed go to the ML service.
  • Typical uses are fraud detection, ads targeting, sentiment analysis, and product recommendations.

Check the Aurora documentation for the supported database engines and Regions.

4.7 The Cost Model

  • Prices depend on the feature that you use and on how much text you analyze, and there are pricing tiers and discounts. Check the pricing page.
  • A real-time endpoint for a custom model is a resource that you create and manage. Delete endpoints that you do not need.
  • Analyze each piece of text once, and store the results instead of calling Comprehend again.
  • Use asynchronous jobs for bulk work, and send only the text that you need to analyze.
Exam trap

Asynchronous jobs read from and write to Amazon S3, and they need an IAM role that lets Comprehend access the buckets. Real-time calls have small document size limits, so do not send a long document to a real-time sentiment call. Also remember that Comprehend may store and use your text to improve the service unless you opt out with an AWS Organizations policy.

Memory hook

Small and urgent, go real-time. Big and scheduled, go asynchronous.

5.5 Lesson Summary

  • Amazon Comprehend is a fully managed, pre-trained NLP service in the AI services layer. It finds meaning and insights in text, with no NLP expertise.
  • The built-in features return the language, entities, key phrases, sentiment, targeted sentiment, and syntax. Every result has a confidence score from 0 to 1.
  • Custom classification and custom entity recognition learn your own labels and terms from your examples. PII detection and redaction removes personal data, and toxicity detection flags toxic text.
  • Real-time calls handle one document or up to 25 in a batch, with small size limits. Asynchronous jobs read documents from Amazon S3 and write the results to Amazon S3, which suits large archives.
  • A typical design uses an S3 event, a Lambda function, Comprehend, a store for the results, and Amazon SNS for alerts. Comprehend analyzes text only, and it may use your text to improve the service unless you opt out.

6. Knowledge Check

Answer each question in your own words before you open the model answer.

  1. Explain what Amazon Comprehend is, and why FlashCart can use it with no NLP engineers.

    Show the model answer

    Comprehend is a fully managed natural language processing service that uses machine learning to find meaning and insights in text. FlashCart calls an API with the text, or the location of text files, and reads a JSON response with entities, key phrases, sentiment, and language. AWS trains and runs the models, so the team needs no NLP expertise.

  2. Which languages does Comprehend support, and what do you do for another language?

    Show the model answer

    It can analyze German, English, Spanish, Italian, Portuguese, French, Japanese, Korean, Hindi, Arabic, Chinese (Simplified), and Chinese (Traditional). Language detection works for more than 100 languages. For a language that Comprehend does not analyze, use Amazon Translate to convert the text into a supported language first.

  3. What does a confidence score tell you, and how would you use it?

    Show the model answer

    A confidence score shows how likely a result is to be correct. Comprehend scores run from 0 to 1, and a score close to 1 means high confidence. Use it to decide what to trust, for example by sending low-confidence results to a person.

  4. Name the built-in insights that Comprehend returns, and what each one answers.

    Show the model answer

    Language detection answers which language the text is in. Entity recognition finds people, places, organizations, and dates. Key phrase extraction finds the talking points. Sentiment analysis gives the overall feeling. Targeted sentiment gives the feeling toward each entity. Syntax analysis labels the words with parts of speech.

  5. How does targeted sentiment differ from sentiment analysis? Use the sentence “I loved the burger, but the service was slow.”

    Show the model answer

    Sentiment analysis gives one result for the whole sentence, which is mixed. Targeted sentiment finds the entities and gives the sentiment toward each one: positive for the burger and negative for the service. It shows exactly what to fix.

  6. When would you use custom classification, and when would you use custom entity recognition?

    Show the model answer

    Use custom classification to sort whole texts into your own categories, such as order status, returns, and product questions, by training on labeled examples. Use custom entity recognition to find your own terms inside text, such as claim numbers, by training on a small set of examples. Both create private models, and you need no machine learning expertise.

  7. How would you remove personal data from support tickets before analysts read them?

    Show the model answer

    Use PII detection and redaction. It finds personal data, such as names, card numbers, and bank account numbers, and masks it. Do this before the tickets are indexed or shared, so that the search holds no PII. AWS says its use of inputs to improve services does not apply to Comprehend Detect PII.

  8. What does toxicity detection do, and how would you use it?

    Show the model answer

    It finds toxic content in text and returns an overall toxicity score between 0 and 1, plus scores for seven categories. It currently supports English only. You can use it to moderate chat between people and the inputs and outputs of generative AI. Choose a threshold, and flag or block messages above it.

  9. Compare real-time, batch, and asynchronous processing in Comprehend.

    Show the model answer

    A real-time call takes one document and returns the result at once. Size limits are small, such as 5 KB for sentiment. A batch call takes up to 25 documents, each up to 5 KB, in one request. An asynchronous job reads documents from Amazon S3 and writes results to Amazon S3, with an IAM role for access, and each operation supports up to 10 active jobs. Use asynchronous jobs for large archives.

  10. Draw a pipeline that analyzes every new review and alerts support when a customer is very upset.

    Show the model answer

    A review is saved to Amazon S3. The upload event starts an AWS Lambda function, which calls Comprehend for sentiment and PII detection. The function stores the redacted text and the results in Amazon DynamoDB. If the sentiment is strongly negative, the function publishes to an Amazon SNS topic, and the support team gets an alert.

  11. What does AWS do with the text that Comprehend processes, and how can an organization opt out?

    Show the model answer

    Comprehend may store and use text inputs to provide the service and, unless you opt out, to improve Comprehend and other Amazon AI technologies. This does not apply to Comprehend Medical and Comprehend Detect PII. You keep ownership of your content. To opt out, use an AWS Organizations AI services opt-out policy.

  12. How can a database application call Comprehend, and how does the data move?

    Show the model answer

    With Amazon Aurora machine learning, an application calls Comprehend, for sentiment analysis, directly from a SQL query. Aurora does not train or host the models. The data stays in Aurora, and only the fields that are needed are sent to the ML service.

  13. When would you choose Comprehend, Textract, or Rekognition?

    Show the model answer

    Choose Comprehend for text that is already machine-readable. Choose Textract for scanned documents, forms, and tables, and then send the text to Comprehend if you need meaning. Choose Rekognition for photos and video.
