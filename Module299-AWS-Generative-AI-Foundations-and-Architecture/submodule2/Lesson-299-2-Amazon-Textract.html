Amazon Textract

How Amazon Textract extracts text, forms, tables, and data from documents: detecting and analyzing documents, invoices, receipts, and ID documents, and the architecture, security, and cost of a document processing pipeline.

Lesson Overview

Amazon Textract is a managed document analysis service. It reads printed text and handwriting from scanned documents and photos of documents, and it also finds the structure: form fields, tables, signatures, and layout. You call it through an application programming interface (API), so you need no machine learning (ML) expertise. This lesson follows FlashCart Inc., a fictional online marketplace that wants to stop retyping data from supplier invoices, seller applications, and identity documents. In this lesson, you will study:

  • Introduction to Amazon Textract: what the service does, how it differs from simple optical character recognition (OCR), how you call it, and the formats and languages it supports.
  • Detecting and Analyzing Documents: reading plain text, and the Forms, Tables, Queries, Signatures, and Layout features, with synchronous and asynchronous operations.
  • Invoices, Receipts, and ID Documents: the specialized operations for expenses, identity documents, and lending packets.
  • Architecture, Security, and Cost: an event-driven pipeline, throttling, access control, data privacy, and the pricing model.
  • Comparison and Scenarios: how Textract compares with Amazon Rekognition and Amazon Comprehend, and an SAA-C03 cheat sheet.
  • Knowledge Check: open-ended questions with model answers.

1. Introduction to Amazon Textract

Problem Statement

FlashCart Inc. receives supplier invoices as PDFs and phone photos, seller applications as scanned forms, and identity documents for seller verification. Three people retype this data into the finance system, and every week a typing error causes a wrong payment.

The engineering manager asks for automation. The team has no machine learning engineers, and the manager points out that an older OCR tool they tried only returned a wall of text: it did not know which number was the invoice total.

She asks what Textract adds beyond plain OCR, which kinds of documents it accepts, and how the team would call it.

Your challenge: Advise the manager. Your answer should:

  • Explain what Textract does and how it differs from simple OCR.
  • List the document formats and the languages that it supports.
  • Say how the team can tell which results to trust.

1.1 What Amazon Textract Is

  • Amazon Textract is a document analysis service. It detects and extracts printed text, handwriting, structured data such as fields and their values, and tables from images and scans of documents.
  • Its machine learning models were trained on millions of documents, so it recognizes and processes virtually any document type that you upload.
  • It is fully managed and pre-trained. You call it from the AWS Management Console, the AWS Command Line Interface (AWS CLI), or the API.
  • It sits in the artificial intelligence (AI) services layer, with Amazon Rekognition, which you studied in Lesson 299.1. Both services need no machine learning expertise.

1.2 Textract Compared With Simple OCR

Simple OCRAmazon Textract
OutputA block of text.Text plus structure: lines, words, form fields, tables, and layout.
HandwritingUsually not handled.Recognizes English handwriting.
Key-value dataYou write rules to find fields.Returns form data as key-value pairs.
TablesRows and columns are lost.Returns rows, columns, and cells, including merged cells.
TrustNo signal about quality.A confidence score and a bounding box for every result.

Textract does perform OCR with the DetectDocumentText API. The AnalyzeDocument API goes a step further and keeps the structure of the document.

1.3 How You Call Textract

  • Textract supports Portable Network Graphics (PNG), Joint Photographic Experts Group (JPEG), Tagged Image File Format (TIFF), and Portable Document Format (PDF) files. It does not read every kind of file, even though it reads almost any kind of document.
  • For synchronous operations, you can send an image as an object in Amazon S3 or as a byte array. For asynchronous operations, the document must be in Amazon S3.
  • If a file is already in a supported format, upload it as it is. Do not convert it or reduce its resolution first.
  • Use the best quality that you can. AWS suggests at least 150 dots per inch (DPI). The smallest text that Textract detects is 15 pixels high, which at 150 DPI is the same as an 8-point font.
  • JPEG and PNG files can be up to 10 MB, and an image can have up to 10,000 pixels on each side. PDF and TIFF files can have one page in a synchronous operation, and up to 3,000 pages and 500 MB in an asynchronous operation.
  • A PDF cannot be password protected, and PDFs that are based on XFA forms are not supported.
  • Access uses AWS Identity and Access Management (IAM) policies, so only authorized users and roles can call the APIs.

1.4 Confidence Scores and Bounding Boxes

  • A confidence score is a number from 0 to 100 that shows how likely a prediction is to be correct. Textract returns one for each element that it identifies.
  • A bounding box is a polygon that fully frames each piece of data. It shows where a word or number appears on the page.
  • Use the score to decide what to trust. For example, when you extract data from tax documents, you can add a rule that flags any value with a score below 95.
  • The bounding box lets you trace a result back to its place on the source page, or draw the result over the image for a person to check.

Exam trap

Textract is for documents. It is not for photos of scenes, such as a street sign, where Amazon Rekognition text detection fits. Also, Textract is not “any file”: it accepts PNG, JPEG, TIFF, and PDF only, and handwriting, invoices, identity documents, and Queries work in English only.

2. Detecting and Analyzing Documents

Problem Statement

FlashCart’s legal team has thousands of scanned contracts and only wants them to be searchable, so they need all the text but no structure. The vendor team has a different need: supplier application forms with fields, a table of items, and a signature at the bottom.

The finance lead asks for one more thing. She does not want to learn each supplier’s layout. She wants to ask, in plain language, “What is the total amount due?” and get the answer. The marketing team also has a two-column newsletter, and its text must come back in reading order.

The architect must decide which Textract operation and which features fit each need, and whether to call them synchronously or asynchronously.

Your challenge: Match the needs to Textract features. Your answer should:

  • Say when plain text detection is enough and when analysis is needed.
  • Name the feature for fields, tables, signatures, reading order, and plain-language questions.
  • Explain how an asynchronous job reports that it is finished.

2.1 DetectDocumentText

  • DetectDocumentText is Textract’s OCR operation. It returns the text of a document as pages, lines, and words.
  • It does not look for fields, tables, or other structure.
  • Use it when you need only the text, for example to build a search index of scanned contracts.

2.2 AnalyzeDocument and Its Features

The AnalyzeDocument operation analyzes a document for relationships between the items that it detects. You choose the features in the FeatureTypes list, and you can use them alone or in any combination.

FeatureWhat it answersExample
FormsWhat are the field names and their values? It returns key-value pairs, checkboxes, and other selection elements.“First Name” and the value “Jane Smith.”
TablesWhat is in this table? It returns rows, columns, and cells, including merged cells, even when the table spans pages.The items, quantities, and prices on an order.
QueriesWhat is the answer to my question? You ask in natural language, and the answer comes back in the response.“What is the customer name?” returns “Jane Doe.”
SignaturesWhere is the signature? It returns the location of each signature.A signature at the bottom of an agreement.
LayoutHow is the page organized? It identifies titles, headers, section headings, paragraphs, lists, figures, page numbers, and footers, and returns the content in reading order.A two-column newsletter read in the right order.

2.3 Queries in Detail

  • A query is a question in natural language, for example “What is the total amount due?” Textract finds the answer, wherever the data sits on the page and however the document is laid out.
  • To write a good query, ask a natural question that uses words from the document.
  • Queries are processed for each page. A synchronous request supports up to 15 queries per page, and an asynchronous request supports up to 30.
  • Queries work in English.
  • Custom Queries let you improve accuracy on documents that are specific to your business. You train an adapter. The training content is processed in the Region where you train, it is encrypted, and it is deleted when training finishes.

2.4 Getting the Best Results

  • Use a document in a language that Textract supports (tab 1, section 1.5).
  • Provide a high-quality image, ideally at least 150 DPI, and do not convert or reduce the resolution of a supported file.
  • Tables work best when they are visually separate from the rest of the page, not placed over an image or a complex pattern, and when the text in the table is upright.
  • Handwriting, invoices and receipts, identity documents, and Queries are in English only.
  • Text must run horizontally. Textract reads horizontal text at any rotation, including a 45-degree tilt, but it does not support vertical text, such as the vertical lines that are common in Japanese and Chinese.

2.5 Synchronous and Asynchronous Operations

SynchronousAsynchronous
OperationsDetectDocumentText and AnalyzeDocumentStartDocumentTextDetection and StartDocumentAnalysis, with GetDocumentTextDetection and GetDocumentAnalysis
How you get resultsIn the response to the same call.You start a job, and read the results later with the job ID.
Where the document isAn S3 object or a byte array.An S3 object.
Maximum size10 MB. A PDF or TIFF file can have one page.10 MB for JPEG and PNG. A PDF or TIFF file can be up to 500 MB and 3,000 pages.
Queries per pageUp to 15.Up to 30.
  1. Call a Start operation. It returns a JobId at once, not results.
  2. When the job finishes, Textract publishes a completion status to the Amazon Simple Notification Service (Amazon SNS) topic that you named in NotificationChannel. A role that you supply lets Textract publish to the topic.
  3. If the status is SUCCEEDED, call the matching Get operation with the JobId to read the results.

Use a ClientRequestToken so that the same job is not started twice by accident, and a JobTag to identify the job in the completion message. If you start too many jobs at once, a Start call fails with a limit error until some jobs finish.

Exam trap

Choosing DetectDocumentText when you need fields or tables is a mistake: it returns only text. Use AnalyzeDocument with the Forms or Tables feature. Also, an asynchronous Start call returns a JobId, not results. Wait for the SNS completion status, and then call the Get operation.

Memory hook

Detect reads the words. Analyze understands the page. Start, wait for SNS, then Get.

3. Invoices, Receipts, and ID Documents

Problem Statement

FlashCart’s finance team gets invoices from hundreds of suppliers, and no two look alike. On some, the vendor name appears only in a logo. On others, the line items have no column headings. Staff now retype each one.

The seller onboarding team asks sellers to upload a picture of a driver’s license or a passport, and they type the name and address into a form. FlashCart’s seller financing program also receives loan application packets that mix many kinds of documents.

The architect knows that AnalyzeDocument can extract forms and tables, but she asks whether Textract has operations built for these three document types, so that nobody has to write templates.

Your challenge: Choose the right operation for each document. Your answer should:

  • Name the operation for invoices and receipts, for identity documents, and for lending packets.
  • Say what each operation returns, and what it needs no templates for.
  • State the language limits.

3.1 AnalyzeExpense: Invoices and Receipts

  • The AnalyzeExpense operation extracts explicitly labeled data, implied data, and line items from an itemized list of goods or services, from almost any invoice or receipt in English, with no templates or configuration.
  • It can find the vendor name on a receipt even when the name appears only in a logo and is not labeled “vendor.”
  • It can find items, quantities, and prices that have no column headings.
  • It returns normalized key names and column headings, so that downstream applications can easily compare the output of many different documents.

3.2 AnalyzeID: Identity Documents

  • The AnalyzeID operation understands the context of identity documents, such as U.S. passports and driver’s licenses, with no templates or configuration.
  • It extracts specific data, and implied data such as names and addresses, from English-language identity documents.
  • Businesses that verify identity, and companies in finance, healthcare, and insurance, use it to automate account creation, appointment scheduling, and employment applications. The customer submits a picture or a scan of the document.

The picture simplifies the result. The point is the same: Textract turns a scan of an identity document into labeled data that an application can use.

3.3 AnalyzeLending: Lending Documents

  • Lending analysis works on a packet of lending documents. It classifies and analyzes the documents in the packet.
  • It is asynchronous: you start the job with StartLendingAnalysis on a document in Amazon S3, and Textract publishes the completion status to the Amazon SNS topic that you name.
  • Check the Textract documentation for the document types that it supports.

3.5 Textract and Rekognition for Identity Verification

In Lesson 299.1, Rekognition used text detection to read key text on a photo of an ID card, as part of an identity verification workflow. Textract’s AnalyzeID is the document service for the same job: it returns structured data from a passport or a driver’s license. Use Textract when you need the fields, and Rekognition for the face checks, such as liveness and face comparison.

Exam trap

AnalyzeExpense is for invoices and receipts, and AnalyzeID is for identity documents. Do not pick AnalyzeDocument with Forms for them just because they look like forms: the specialized operations need no templates and return normalized fields. Also remember that these operations work in English only.

4. Architecture, Security, and Cost

Problem Statement

FlashCart wants to process every supplier invoice within minutes of upload. The volume is uneven: very few documents arrive at night, and thousands arrive on the first day of the month. During the first test, many requests failed with throttling errors.

The security team asks who can call Textract, what AWS does with the documents, and whether the service can be reached without the public internet. The finance team asks how Textract is billed.

The architect must draw the pipeline and answer both teams.

Your challenge: Design the pipeline. Your answer should:

  • Show how an upload leads to extraction, storage of fields, and a check of doubtful results.
  • Explain how to avoid throttling when traffic is uneven.
  • Describe access, data privacy, logging, and the billing model.

4.1 An Event-Driven Document Pipeline

  1. A supplier uploads an invoice to an Amazon S3 bucket.
  2. The upload event puts a message in an Amazon Simple Queue Service (Amazon SQS) queue. The queue smooths uneven traffic.
  3. An AWS Lambda function reads the queue and calls Textract, for example AnalyzeExpense.
  4. The function stores the extracted fields, for example in Amazon DynamoDB.
  5. Fields with a confidence score below your threshold go to a review queue, where a person on your team checks them.

Use synchronous calls for single images and small documents. Use asynchronous jobs with Amazon SNS for large or multi-page files, up to the size limits in tab 2.

4.2 Avoiding Throttling

  • Implement retry logic for throttling errors, as the error handling guidance describes.
  • Use exponential backoff and jitter with the retries. This raises the throughput that you can achieve.
  • Smooth the traffic. Spiky traffic lowers throughput, so use a queue, or another way, to make the flow of requests steady.
  • Manage your service quotas in the AWS Service Quotas console, and estimate what you need with the Textract Service Quota calculator. You can request an increase from the console.

4.3 Security and Access Control

  • Use IAM policies and roles to control who can call Textract. Give the Lambda function a role with only the Textract actions it needs and read access to the bucket.
  • Textract supports AWS CloudTrail logging for these actions: DetectDocumentText, AnalyzeDocument, StartDocumentTextDetection, StartDocumentAnalysis, GetDocumentTextDetection, and GetDocumentAnalysis.
  • Textract supports Amazon Virtual Private Cloud (Amazon VPC) endpoints through AWS PrivateLink, so that you can call Textract from inside a VPC without using the public internet.
  • AWS says that it protects content with encryption at rest and in transit. For asynchronous jobs, you can supply an AWS Key Management Service (AWS KMS) key for the output.
  • Textract is eligible for the Health Insurance Portability and Accountability Act (HIPAA) when you have a Business Associate Agreement with AWS. It is also compliant with PCI, ISO, and SOC programs.

4.4 Data Privacy

  • Textract may store and use the documents and images that it processes to provide the service and, unless you opt out, to improve Textract and other Amazon AI technologies.
  • To opt out, use an AWS Organizations AI services opt-out policy.
  • Processed content is encrypted and stored at rest in the Region where you use Textract. Unless you opt out, a portion may be stored in another Region for improvement. If you opt out, your content is not stored in another Region.
  • You always own your content. You can ask AWS Support to delete the document and image inputs that are linked to your account.

4.5 The Cost Model

What you useHow it is billed

Counting pagesAn image (PNG, TIFF, or JPEG) counts as one page. Each page of a PDF counts as one page.

  • Process each document once, and store the results instead of calling Textract again.
  • Choose the cheapest operation that meets the need. For example, use DetectDocumentText when you need only text.
  • Pick a confidence threshold that avoids needless reviews.

Exam trap

Throttling errors do not mean that Textract is broken. They mean that your traffic is spiky or your quota is low. Add retries with exponential backoff and jitter, smooth the traffic with a queue, and request a quota increase. Also remember that Textract may store and use your documents to improve the service unless you opt out with an AWS Organizations policy.

5.5 Lesson Summary

  • Amazon Textract is a fully managed, pre-trained document analysis service in the AI services layer. It extracts printed text, handwriting, form fields, tables, signatures, and layout, and it needs no machine learning expertise.
  • It accepts PNG, JPEG, TIFF, and PDF files. Every result has a confidence score and a bounding box, so you can decide what to trust and trace each result to the page.
  • DetectDocumentText returns only text. AnalyzeDocument adds Forms, Tables, Queries, Signatures, and Layout. AnalyzeExpense, AnalyzeID, and AnalyzeLending handle invoices and receipts, identity documents, and loan packets.
  • Synchronous calls return results in the response, up to 10 MB. Asynchronous jobs take documents in Amazon S3, up to 500 MB for PDFs, and report completion through Amazon SNS before you call the Get operation.
  • A typical design uses an S3 event, an SQS queue, a Lambda function, Textract, and a store for the fields. Add retries with backoff and jitter, an Amazon VPC endpoint if needed, and an opt-out policy if you do not want AWS to use your documents to improve its services.

6. Knowledge Check

Answer each question in your own words before you open the model answer.

  1. Explain what Amazon Textract is, and how it differs from simple OCR.

    Show the model answer

    Textract is a fully managed, pre-trained document analysis service. It detects and extracts printed text, handwriting, structured data such as fields and values, and tables from images and scans of documents. Simple OCR returns only a block of text. Textract also returns the structure, with a confidence score and a bounding box for each result.

  2. Which document formats, languages, and limits does Textract support?

    Show the model answer

    Textract supports PNG, JPEG, TIFF, and PDF. It reads printed text in more than 40 languages and English handwriting. Forms work in English, Spanish, Italian, Portuguese, French, and German. Invoices and receipts, identity documents, and Queries work in English only. A synchronous call can take a document up to 10 MB, with one page for a PDF or TIFF file. An asynchronous job takes a PDF or TIFF file of up to 500 MB and 3,000 pages.

  3. What are a confidence score and a bounding box, and how would you use them?

    Show the model answer

    A confidence score is a number from 0 to 100 that shows how likely a prediction is to be correct. A bounding box is a polygon that frames each piece of data and shows where it appears on the page. You can flag any value below a threshold, such as 95, for a person to check, and use the bounding box to show the result on the source page.

  4. When would you use DetectDocumentText, and when would you use AnalyzeDocument?

    Show the model answer

    Use DetectDocumentText when you need only the text, for example to make scanned contracts searchable. Use AnalyzeDocument when you need structure: Forms for key-value pairs, Tables for rows and columns, Queries for answers to questions, Signatures for signature locations, and Layout for titles, paragraphs, and reading order.

  5. How do Queries work, and what are their limits?

    Show the model answer

    You write a question in natural language that uses words from the document, such as “What is the customer name?” Textract returns the answer, however the page is laid out. A synchronous request supports up to 15 queries per page and an asynchronous request up to 30. Queries work in English. Custom Queries use an adapter that you train to improve accuracy on documents specific to your business.

  6. Describe how an asynchronous Textract job works, and when you would use one.

    Show the model answer

    Put the document in Amazon S3 and call a Start operation, such as StartDocumentAnalysis, which returns a JobId. Textract runs the job and publishes a completion status to the Amazon SNS topic that you named. When the status is SUCCEEDED, call the matching Get operation with the JobId. Use asynchronous jobs for large files, such as PDFs above 10 MB, up to 500 MB.

  7. Which operation would you use for supplier invoices, for driver’s licenses, and for loan application packets?

    Show the model answer

    Use AnalyzeExpense for invoices and receipts, AnalyzeID for identity documents such as U.S. passports and driver’s licenses, and AnalyzeLending for packets of lending documents. The first two need no templates and work in English.

  8. Draw an event-driven pipeline that processes every uploaded invoice, and say how it copes with uneven traffic.

    Show the model answer

    A supplier uploads an invoice to Amazon S3. The upload event puts a message in an Amazon SQS queue, which smooths the traffic. An AWS Lambda function reads the queue, calls AnalyzeExpense, and stores the fields, for example in Amazon DynamoDB. Fields below the confidence threshold go to a review queue for a person. The function retries with exponential backoff and jitter if Textract throttles a request.

  9. Why do throttling errors happen, and how do you reduce them?

    Show the model answer

    They happen when traffic is spiky or the request rate goes above the quota. Add retries with exponential backoff and jitter, smooth the traffic with a queue, and manage the quota in the AWS Service Quotas console, using the Textract quota calculator to estimate what you need and requesting an increase if necessary.

  10. What access control, logging, and network options does Textract offer?

    Show the model answer

    Use IAM policies and roles to limit who can call it. AWS CloudTrail logs actions such as DetectDocumentText, AnalyzeDocument, and the Start and Get operations. An Amazon VPC endpoint through AWS PrivateLink lets you call Textract without the public internet. Content is encrypted at rest and in transit, and Textract is HIPAA eligible with a Business Associate Agreement.

  11. What does AWS do with the documents that Textract processes, and how can an organization opt out?

    Show the model answer

    Textract may store and use document and image inputs to provide the service and, unless you opt out, to improve Textract and other Amazon AI technologies. You keep ownership of your content. To opt out, use an AWS Organizations AI services opt-out policy, and ask AWS Support if you need stored inputs deleted.

  12. How is Textract billed, and what are two ways to control cost?

    Show the model answer

    Textract is billed by the number of pages and images processed. An image counts as one page, and each page of a PDF counts as a page. Process each document once and store the results, and choose the cheapest operation that meets the need, such as DetectDocumentText when you need only text.

  13. When would you choose Textract, Rekognition, or Comprehend?

    Show the model answer

    Choose Textract for scanned documents, forms, and tables. Choose Rekognition for photos and video, including text in scenes such as street signs. Choose Comprehend for text that is already machine-readable. A common pipeline uses Textract to get the text and Comprehend to analyze what it means.
