Amazon Translate

How Amazon Translate translates text and documents: real-time, document, and batch translation, custom terminology and Active Custom Translation, and the architecture, security, and cost of a translation pipeline.

Lesson Overview

Amazon Translate is a managed neural machine translation service. It translates text between supported languages with deep learning, and you call it through an application programming interface (API), so you need no machine learning (ML) expertise. This lesson follows FlashCart Inc., a fictional online marketplace that is opening stores in new countries and must translate product pages, reviews, support chat, and documents. In this lesson, you will study:

  • Introduction to Amazon Translate: what the service does, its languages, how you call it, and common use cases.
  • Translating Text and Documents: real-time text translation, document translation, and asynchronous batch jobs, with their formats and limits.
  • Customizing Translations: custom terminology, Active Custom Translation, formality, profanity masking, and brevity.
  • Architecture, Security, and Cost: patterns that combine Translate with other AWS services, access control, data privacy, throttling, and the pricing model.
  • Comparison and Scenarios: how Translate compares with other AWS AI services, and an SAA-C03 cheat sheet.
  • Knowledge Check: open-ended questions with model answers.

Learning Objectives

At the end of this lesson, learners will be able to:

  1. Define Amazon Translate and neural machine translation, and state where Translate fits in the AWS artificial intelligence (AI) layers.
  2. Describe the languages, the input formats, and the size limits of real-time, document, and batch translation.
  3. Explain how Translate detects the source language by using Amazon Comprehend.
  4. Choose between real-time text translation, document translation, and asynchronous batch translation.
  5. Apply custom terminology to keep brand names and key terms consistent.
  6. Differentiate Active Custom Translation from custom terminology, and describe formality, profanity masking, and brevity.
  7. Judge when raw machine translation is good enough and when human post-editing is needed.
  8. Design a translation pipeline that addresses security, privacy, throttling, and cost, and combines Translate with other AWS AI services.

1. Introduction to Amazon Translate

Problem Statement

FlashCart Inc. is opening stores in four new countries. It must translate thousands of product pages, the help center, and a stream of customer reviews that arrive in many languages. A human translation agency quoted a price and a timeline that the business cannot accept.

The engineering manager wants to try machine translation. The team has no machine learning engineers. She worries about two things: how many languages the service supports, and what to do when the source language of a message is not known.

She also wants to know how good the output is, and which content still needs a person to check it.

Your challenge: Advise the manager. Your answer should:

  • Explain what Amazon Translate is and why it needs no machine learning expertise.
  • Say which languages it supports and how it handles an unknown source language.
  • Say when the raw output is enough and when a person should review it.

1.1 What Amazon Translate Is

  • Amazon Translate is a neural machine translation service for translating text between supported languages. It uses deep learning to give high-quality, affordable, and customizable translation.
  • Its neural network takes into account the context of the source sentence and the translation that it has produced so far.
  • It is a fully managed service with an API, so you can use it for real-time or batch translation of text from a source language to a target language.
  • You can start in the console, call it from the AWS Command Line Interface (AWS CLI), or use an AWS software development kit (SDK).
  • It sits in the AI services layer, with Amazon Rekognition, Amazon Textract, and Amazon Comprehend, which you studied in Lessons 299.1 to 299.3.

1.2 Languages

  • Amazon Translate supports translation between 75 languages, and the list is growing. It supports translation between all supported languages, so a source and a target can be any two of them.
  • Examples are Arabic, Chinese (Simplified), Chinese (Traditional), English, French, French (Canada), German, Hindi, Japanese, Korean, Portuguese, Portuguese (Portugal), Spanish, and Spanish (Mexico), among many others.
  • If you ask for a language or a pair that is not supported, Translate returns an unsupported language pair error.
  • Check the supported languages page in the documentation for the current list and the language codes.

1.3 How You Call Translate

  • You send the source text, a source language code, and a target language code. Translate returns the text in the target language.
  • If the source language is unknown, set the source to auto. Translate identifies the language with Amazon Comprehend behind the scenes and reports it back along with the translation.
  • Real-time translation takes plain text in UTF-8 format.
  • Access uses AWS Identity and Access Management (IAM) policies, so only authorized users and roles can call the APIs.

1.4 The Console

The AWS Management Console is the quickest way to try Translate. You choose a source language, which can be auto, enter text, and choose a target language. The console counts the bytes that you use against a limit, and it has a Text tab and a Document tab.

1.6 How Good Is the Output?

  • Machine translation fits best when the volume is high, speed matters, and minor imperfections are acceptable. You can publish the raw output for a first draft, or for gist, such as survey responses.
  • With light human post-editing, you can use it for content such as specifications, FAQs, and support articles.
  • With more extensive post-editing, you can use it for high-value branded content, such as advertising, marketing materials, and contracts.
  • You do not have to credit the translation, but AWS suggests that you tell your customers that it was machine translated.
Exam trap

Translate does not read images or scanned pages. A scanned manual needs Amazon Textract first, and recorded speech needs Amazon Transcribe first. Also, raw machine translation is not a substitute for review on high-value content such as contracts: plan post-editing for it.

Limits change. Check the guidelines and quotas page before you design around them. Note that the Amazon Translate FAQ still says 5,000 bytes for a real-time call, while the console and the quotas page show 10,000 bytes. Use the quotas page, which is the Developer Guide’s current statement.

To translate a long text in real time, split it into sections and paragraphs, and call the API for each part.

2.3 Batch Translation

  • You upload the input files to an Amazon S3 folder, and you call StartTextTranslationJob with the input and output locations, the source language, and the target languages.
  • You give the job an IAM data access role, so that Translate can read the input and write the output.
  • You can input documents with different source languages. Set the source language to auto, and Translate detects the source language of each document.
  • Translate translates each input document into each target language.
  • Check on the job with DescribeTextTranslationJob, list jobs with ListTextTranslationJobs, and stop a job with StopTextTranslationJob.
  • The output file has the same format as the input file.

2.4 Automatic Source Language Detection

  • Translate takes plain text and language codes. If the source language is unknown, it identifies the language with Amazon Comprehend and returns that language with the translation.
  • In a batch job, auto works for each input document, so one job can handle documents in several languages.
Exam trap

Do not send a long text to the real-time API in one call: it has a size limit. Split the text, or use a document operation or a batch job. Also, a batch job is asynchronous. It needs an IAM data access role and S3 folders, and the results arrive in the output folder, not in the response.

3. Customizing Translations

Problem Statement

FlashCart’s first translated pages are live, and the brand team is unhappy. The product line “FlashCart Express” is sometimes translated word by word, and “Flash Deals” becomes a phrase that means something else in one language.

The marketing team also wants a formal tone on the Japanese and German pages and a friendly tone in chat. The community manager wants profanity in user reviews masked. The mobile team needs shorter translations for small buttons.

The architect knows that Translate has settings and customization features, and she must pick the right one for each request.

Your challenge: Choose the right customization for each need. Your answer should:

  • Name the feature that keeps brand and product names consistent.
  • Say how to adapt translations to FlashCart’s own style by using its own examples.
  • Name the settings for tone, profanity, and length.

3.1 Custom Terminology

  • Custom terminology defines how you want Translate to translate specific terms, such as brand names and product names.
  • You import a terminology file that lists example source terms and the desired translation of each term. Translate keeps it as a terminology resource in your account.
  • You name the terminology in a request: a TranslateText or TranslateDocument call, or a batch job. A request can use one terminology resource.
  • The response reports which terminologies Translate applied.
  • You manage terminologies with ImportTerminology, GetTerminology, ListTerminologies, and DeleteTerminology.
QuotaLimit
File size20 MB.
Files per account in a Region100.
Target languages in one file30.
Length of a term200 bytes, for the source and for the target text.

3.2 Active Custom Translation

  • Active Custom Translation (ACT) lets you bring your own data, called parallel data, to customize the translated output to your needs.
  • Parallel data is a set of examples of source text with the translation that you want. You create a parallel data resource from a file in Amazon S3.
  • A parallel data resource has one source language. If a job has several target languages, the file must include translations for all of them.
  • You add one parallel data resource to a batch translation job. That makes it an Active Custom Translation job.
  • ACT jobs are priced at a higher rate than jobs that do not use parallel data.
  • It gives an effect similar to a custom model that you train with your own examples, but you do not train a model. To change the output, you update the parallel data.
  • ACT is available only in some Regions, so check the documentation.
  • Quotas: a parallel data input file can be up to 5 GB, a single segment can be up to 1,000 bytes, and an account can hold up to 1,000 parallel data resources in a Region.

Custom terminology changes only the terms that you list. It does not teach Translate your style. For that, use Active Custom Translation with parallel data, which costs more and runs as a batch job. 4. Architecture, Security, and Cost

Problem Statement

FlashCart wants three things at once: translate every support chat message in real time, translate the review database so that the analytics team can read it in English, and translate a folder of manuals overnight.

The security team asks who can call Translate, what AWS does with the text, and whether the traffic can stay off the public internet. The finance team asks how Translate is billed, and whether texts that are already in the target language cost money.

The architect must draw the designs and answer both teams.

Your challenge: Design the solution. Your answer should:

  • Show how Translate combines with other AWS services for reviews and chat.
  • Describe access control, privacy, throttling, and network options.
  • Explain the billing model and two ways to control cost.

4.1 Three Ways to Use the API

  • Inside an application: localize highly dynamic parts, such as multi-participant chat.
  • With other services: string Translate together with other AWS services for language-independent processing. For example, a Lambda function can read user-generated reviews and forum posts from a database such as Amazon Relational Database Service (Amazon RDS) and localize them.
  • In batches of documents: for example, financial firms translate and monitor news in any language, legal teams search materials in many languages for eDiscovery, and patent attorneys search patent repositories worldwide.

4.2 Translate With Comprehend and Transcribe

  1. Reviews in many languages are saved to Amazon S3.
  2. The upload event starts an AWS Lambda function.
  3. The function calls Translate, with the source language set to auto, to get English text.
  4. The function calls Amazon Comprehend to find the sentiment, entities, and key phrases in the English text.
  5. The function stores the original text, the translation, and the insights, for example in Amazon DynamoDB.
  • Translate and Amazon Comprehend together let you analyze text such as social media and news feeds in many languages.
  • Translate and Amazon Transcribe together make subtitles and live captions available in many languages. Amazon Transcribe is covered later in this module.
  • For scanned documents, use Amazon Textract first to get the text.

4.3 Throttling

  • Translate scales to serve customer traffic. If you see sustained throttling, contact AWS Support.
  • The job APIs have request rate limits, for example 5 requests per second for starting a batch job and 10 for describing or listing jobs. A batch account can run up to 10 concurrent jobs and queue up to 1,000.
  • Add retries with exponential backoff and jitter, and use a queue to smooth bursts.

4.4 Security and Access Control

  • Use IAM policies and roles to control who can call Translate. Give a batch job a data access role with access only to its input and output folders.
  • Translate supports virtual private cloud (VPC) endpoints through AWS PrivateLink, so that you can call it without the public internet.
  • AWS says that it protects content with encryption at rest and in transit, and that only authorized employees can access it.
  • For information about compliance programs, see AWS Compliance and the list of services in scope.

4.5 Data Privacy

  • Translate may store and use the text that it processes to provide the service and, unless you opt out, to improve Translate and other Amazon AI technologies.
  • To opt out, use an AWS Organizations AI services opt-out policy.
  • Processed content is encrypted and stored at rest in the Region where you use Translate. A portion may be stored in another Region for improvement of the service.
  • You always own your content. You can ask AWS Support to delete your stored data and to stop storing future data for the account, but doing so can reduce translation quality.

4.6 The Cost Model

  • Translate is priced by the amount of text that it translates. Check the pricing page for current rates.
  • A request is not charged when the source language equals the target language, or when an error occurs and no translation comes back.
  • A request with content that cannot be translated, such as a string of symbols, is charged.
  • Active Custom Translation jobs cost more than standard jobs.
  • Translate once and store the result, instead of translating the same text again.
  • Use custom terminology for brand terms, and use batch jobs for large volumes.

Machine translation costs a fraction of human translation, which is why teams can translate content that they could not afford to translate before.

Exam trap

A batch job needs an IAM data access role and S3 folders, and the results arrive in the output folder. Also remember that Translate may store and use your text to improve the service unless you opt out with an AWS Organizations policy, and that deleting stored data can lower the quality of your translations.

Memory hook

Translate first, then analyze. Translate once, then store.

5.5 Lesson Summary

  • Amazon Translate is a fully managed neural machine translation service in the AI services layer. It translates between 75 languages with no machine learning expertise.
  • Real-time TranslateText handles up to 10,000 bytes. TranslateDocument handles one text, HTML, or Word document. Batch jobs translate folders of files in Amazon S3, with an IAM data access role, and write the results to an output folder.
  • Setting the source language to auto makes Translate use Amazon Comprehend to detect it. Custom terminology fixes specific terms, and Active Custom Translation adapts the style with your parallel data. Formality, profanity masking, and brevity tune the output.
  • Raw output suits high volume and speed. Add light or extensive human post-editing for FAQs, branded content, and contracts.
  • Translate combines with Textract, Transcribe, and Comprehend. It may store and use your text to improve the service unless you opt out, and a VPC endpoint keeps calls off the public internet.
Memory hook

Pictures go to Rekognition. Documents go to Textract. Text goes to Comprehend. Words in another language go to Translate.

  7. How does Active Custom Translation differ from custom terminology?

    Show the model answer

    Active Custom Translation uses parallel data, which is a set of examples of source text and the translation that you want, to adapt the style and wording of the whole output. It applies to batch jobs and costs more. Custom terminology fixes only the specific terms that you list, and it applies to real-time, document, and batch requests.

  8. What do formality, profanity masking, and brevity do, and what are their limits?

    Show the model answer

    Formality sets a formal or informal register, for target languages that support it. Profanity masking hides profane words, in languages that support it. Brevity shortens the output for most translations, and it is supported for real-time text translation only.

  9. When is raw machine translation enough, and when do you need a person?

    Show the model answer

    Raw output suits high-volume, time-critical content where minor imperfections are acceptable, such as gist from surveys or a first draft. Use light human post-editing for specifications, FAQs, and support content. Use more extensive post-editing for high-value branded content, such as advertising and contracts.

  10. Draw a pipeline that analyzes the sentiment of reviews in many languages.

    Show the model answer

    Reviews are saved to Amazon S3. The upload event starts an AWS Lambda function, which calls Translate with the source language set to auto to get English text. The function then calls Amazon Comprehend for sentiment, entities, and key phrases, and stores the original text, the translation, and the insights in Amazon DynamoDB.

  11. What does AWS do with the text that Translate processes, and how can an organization opt out?

    Show the model answer

    Translate may store and use text inputs to provide the service and, unless you opt out, to improve Translate and other Amazon AI technologies. You keep ownership of your content. To opt out, use an AWS Organizations AI services opt-out policy. You can also ask AWS Support to delete stored data, but that can reduce translation quality.

  12. How is Translate billed, and what are two ways to control cost?

    Show the model answer

    Translate is priced by the amount of text translated, and Active Custom Translation jobs cost more. Requests with the same source and target language, or that fail with no translation, are not charged. Translate once and store the result, and use batch jobs and custom terminology instead of repeating work.

  13. How do you call Translate without the public internet, and how does it work with other AI services?

    Show the model answer

    Use a VPC endpoint through AWS PrivateLink. Translate works with Amazon Comprehend to analyze text in many languages, with Amazon Transcribe to produce subtitles in many languages, and after Amazon Textract for scanned documents.
